## 2. Admin scene-edit/regenerate API (backend, detailed in section 1 controller/service above — summarized here for cascade clarity)

| Action | What it mutates | Cascade |
|---|---|---|
| `PATCH .../scenes/:index` | Any subset of scene fields / `lines[]` | Marks touched top-level keys in `scene.locked`; marks touched `lines[i].locked = true`. **No** downstream clearing — old image/video/audio stay until an explicit regenerate call. |
| `POST .../regenerate-detail` | Re-runs `generateStudioScenarioScene`, merges onto scene preserving `locked` fields/lines | Clears `imageUrl`, `predictionId`, `startedAt`, `videoUrl` if `imagePrompt`/`motionPrompt` actually changed (unlocked); clears `narrationUrl` and unlocked lines' `audioUrl` if `lines` text changed |
| `POST .../regenerate-image` | Re-runs `generateStudioReferenceShotFromPrompt` with current `imagePrompt` | Always clears `predictionId`, `startedAt`, `videoUrl` (video is downstream of image) |
| `POST .../regenerate-video` | Re-runs `atlas.startImageToVideo` with current `imageUrl`/`lockMotionPrompt(motionPrompt)`/`durationSeconds` | If `order.status === "DELIVERED"`/`"FAILED"`, flips to `GENERATING` (clears `videoUrl`/`deliveredAt`/`confirmDueAt`) so the tick worker's existing prediction-polling and final-render branches finish the job asynchronously — **no duplicate polling loop added to the controller** |
| `POST .../lines/:lineIndex/regenerate-audio` | Re-runs `firstMedia.synthesizeLineAudio` for one line, rebuilds `narrationUrl` synchronously (fast — a handful of short mp3s) | If the new measured narration duration exceeds the current `scene.durationSeconds`, raises it (up to `SCENE_VIDEO_MAX_SECONDS`) and applies the same `videoUrl`-clearing + `DELIVERED→GENERATING` flip as `regenerate-video`, since the video would otherwise be shorter than its own narration track |

This intentionally reuses the tick worker's async prediction-polling and `renderFilm` call for anything that touches video, rather than adding a second polling implementation in the HTTP layer — the only new synchronous-inline work is image generation and TTS, both of which are already synchronous provider calls today.
