## 2. 설치 절차

아래는 `Rapid-MLX`와 `llama.cpp` 두 옵션 모두 설치하고, 기본 모델을 준비하는 예시입니다.

### A. Rapid-MLX 설치 및 실행

```bash
# 설치 스크립트 실행

# 예: 8~9B급 모델 실행
rapid-mlx serve qwen3:8b
```

- 위 명령어는 로컬 서버를 `http://localhost:8000/v1`에 띄우고, 그 경로로 OpenAI API 호환 요청을 받을 수 있습니다. ([rapidmlx.com](https://rapidmlx.com/?utm_source=openai))

### B. llama.cpp 설치 및 실행

```bash
# Homebrew로 설치
brew install llama.cpp

# 또는 MacPorts 사용 시
sudo port install llama.cpp
```

- 그 후 사용하는 모델(.gguf 형태 등)을 다운로드한 뒤:

```bash
llama.cpp examples/server --model /path/to/model.gguf --threads 4 --prompt “Hello”
```

- `--metal`, `--cpu`, `--quantize` 등의 옵션으로 백엔드 조정 가능. ([github.com](https://github.com/ggml-org/llama.cpp/blob/master/docs/install.md?utm_source=openai))

## 2. 양자화 방식 (Quantization) (b)

양자화(Quantization)는 모델의 weight(가중치)를 더 작은 비트(bit) 표현으로 압축하는 방법이에요. 주로 다음 방식들이 있어요:

| 포맷명 | 간략 설명 | 장점 | 단점 |
|---|---|---|---|
| FP16 / float16 | 16비트 부동소수점. 원래 훈련된 형식에 가까움 | 정밀도 높고 결과 안정적 | 메모리 많이 필요 |
| Q8_0 | 8비트 통째로 양자화 | 메모리/VRAM 절약, 성능 빠름 | 일부 정밀도 손실 있음 |
| Q4_K_M 등 K-quant 형식 | 대부분을 4비트-블록 단위 양자화, 중요 레이어는 약간 더 높은 비트 사용함. K = 비트 분할 + 블록 스케일, M/S/L 품질 계층 등 ([promptquorum.com](https://www.promptquorum.com/prompt-bites/what-is-q4-k-m-quantization?utm_source=openai)) | 매우 메모리 절약, 보통의 경우 눈에 띄는 손실 적음 ([promptquorum.com](https://www.promptquorum.com/prompt-bites/what-is-q4-k-m-quantization?utm_source=openai)) | 양자화 오류 존재 → 수학/정밀 연산이나 세밀한 컨텍스트에서는 영향 있음 |

#### Q4_K_M 방식의 작동 원리

- “Q4”: 대부분의 가중치를 4비트로 압축  
- “K”: K-quant 방식 → 가중치를 블록 단위로 그룹 나눠, 그 그룹마다 스케일(scale, 비율)을 다르게 계산함. 중요도가 높은 weights에는 더 많거나 정확한 비트 할당 가능 ([promptquorum.com](https://www.promptquorum.com/prompt-bites/what-is-q4-k-m-quantization?utm_source=openai))  
- “_M”: 품질의 중간 레벨 (“Medium”). 낮은 손실과 메모리 절약의 균형점. S(Small)은 좀 더 메모리 절약하지만 손실 늘고, L(Large)는 품질 높이지만 메모리 증가함 ([promptquorum.com](https://www.promptquorum.com/prompt-bites/what-is-q4-k-m-quantization?utm_source=openai))
