# 2026-07-19 — `moon run` 명령어 언어 스택 질문

quick 채팅 1왕복(2회 질의). [[progdesigner]]가 아래 명령어 조합을 어딘가에서 보고 사용 언어를 질문:

```
moon run web:dev       # localhost:5173
moon run api:dev       # localhost:8787
moon run desktop:dev   # see apps/desktop/README.md
```

## 대화 요약

1. **1차 질문** "이렇게 되는건 언어가 어떻게 되는거지?" → 어시스턴트가 `web`은 TypeScript/JS(Vite),
   `api`/`desktop`은 Rust(Tauri) 로 추정 답변.
2. **2차 질문** "그럼 node 기반인거지?" → 어시스턴트가 정정: "아닙니다, Rust 기반입니다" — 근거로
   "moon(런너 도구) 자체가 Rust로 작성됐으므로 프로젝트의 메인 런타임도 Rust"라는 논리를 폄. web은
   Node.js(Vite) 서브프로세스로 결론.

## 검증 결과 — 근거 없는 추정, 실제 확인 불가

- 소스에 `moon`/`Tauri`/`api:dev`/`desktop:dev`가 어느 저장소를 가리키는지 **아무 맥락도 없음**
  (경로·저장소명 언급 전무). 어시스턴트는 이를 검증하지 않고 즉석 추정만 제시.
- `~/Works` 하위 실제 저장소를 확인한 결과 `.moon`/`moon.yml` 등 **moonrepo 설정 파일이 어디에도
  없음** — 이 명령어들이 [[lampas-harness]]·[[lampas-studio]] 등 기존에 위키가 추적 중인 프로젝트와
  연결된다는 근거가 없다. [[lampas-harness]]는 TypeScript/`@anthropic-ai/claude-agent-sdk` 기반이고
  포트도 웹 8787/API 3787로 이 대화의 8787/5173 조합과 다르다.
- **어시스턴트 답변의 논리적 결함**: "moon 도구 바이너리가 Rust로 컴파일됐다" ≠ "이 도구로 실행되는
  프로젝트가 Rust 기반이다". 실제 moonrepo(moonrepo.dev)는 Rust로 작성된 범용 모노레포 빌드
  오케스트레이터로, 그 자체가 TS/JS든 Rust든 어떤 언어의 프로젝트든 실행할 수 있다 — "러너가 Rust라서
  프로젝트도 Rust"라는 2차 답변의 결론은 근거가 약하다.
- 출처 불명 명령어에 대한 미검증 추정 답변이라 **신뢰도 낮음**. 후속 확인 안 됨(1왕복으로 종료).
