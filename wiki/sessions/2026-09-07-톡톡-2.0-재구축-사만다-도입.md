페르소나가 처음으로 도입·배포된 원본 이벤트**임이 이번 ingest로 확인됨 — 기존 위키가 알고 있던

## 스레드 1 — 기존 Talk 전면 리셋 → 영화 《Her》 사만다 재구현

사용자 지시: "이 안에 talk 이라는 서비스가 있는데 지금까지 만든 내용을 다 리셋 한다고 보고 영화
Her 에서 나오는 은영 체제 채팅 서비스를 똑같이 구현 해 줘" → 기존 캐릭터 선택·피드·스토리 중심
구조, 관계 단계, 스토리용 프롬프트를 **전부 폐기**하고 한 명의 AI와 이어지는 대화 중심 구조로 전환.

- 사용자가 영화 《Her》 각본 1–105페이지를 근거로 설계한 매우 상세한 **사만다 페르소나 지침**(성격
  축 7개, 한국어 말투 규칙 10개, 상황별 반응 방식 8종, 친밀감 진행 5단계 표, YAML 기본 설정,
  대화 예시 10개, 응답 품질 점검 체크리스트)을 통째로 제공 → 어시스턴트가 이를 그대로
  `apps/talk-api/companion/samantha.md`(`[[toktalk]]`)로 저장.
- 새 대화 엔진은 **기존 캐릭터 DB 없이 `samantha.md` 단일 파일만 읽음**. 텍스트·음성 대화가 같은
  지침·같은 기억을 공유하도록 연결.
- 새 화면(따뜻한 적갈색 톤), 통화 시작 시 사용자가 말하면 재생 중단, 대화 기록·사용자가 직접
  관리하는 기억 화면 구현.

## 스레드 2 — 음성 전송 버그 진단

음성 통화 연결은 되지만 **오디오 전송이 확인되지 않는** 문제 발생 → 마이크 입력 처리 자체는
정상 실행됨을 먼저 확인한 뒤, 원인이 **자동 테스트의 WebSocket 가로채기 설정**이었음을 규명·수정.
오디오 전송·음소거·통화 종료 후 마이크 해제까지 전부 재검증 통과.

## 스레드 3 — 로컬 검증 → 배포 (`app.toktalk.io` 오기 → `app.toktalk.ai` 정정)

로컬(`http://127.0.0.1:8242`)에서 빌드·테스트 11개·브라우저 검증·실제 AI 응답까지 확인 후,
사용자가 처음 요청한 `app.toktalk.io`는 오기였고 **`https://app.toktalk.ai/`**로 정정. Samantha
서버를 별도 프로세스로 배포해 `/companion` 경로로 연결, 공개 접속용 세션 확인·요청량 제한 적용
후 CloudFront 전파 완료까지 확인(2026-09-09).

## 스레드 5 — 멀티 프로바이더 모델 선택 → AtlasCloud 카탈로그로 귀결

사용자가 텍스트(GPT Astra·Grok·Claude·Gemini)와 음성(ElevenLabs·xAI·MiniMax·Gemini) 각각 "가장
최신 모델"을 선택 가능하게 요청 → 프로바이더별 개별 키 대신 **[[atlas-cloud]] 카탈로그**로 텍스트
모델 선택을 통일(기존 AtlasCloud 키 재사용, 추가 키 불필요).

- **실시간 음성은 AtlasCloud 제외**: AtlasCloud 음성 생성은 비동기(생성 완료 대기) 방식이라 실시간
  통화에 부적합 → 실시간 음성은 기존 **xAI `grok-voice-latest`**(공식 문서상 `grok-voice-think-fast-2.0`
  별칭, 목소리 `eve`)를 유지, 텍스트만 AtlasCloud 카탈로그 적용. 실시간 통화에서는 xAI 음성 모델이
  답변까지 생성한다는 점을 설정 화면에 명시.
- 텍스트 초기 모델은 **`grok-4.5`**였음(→ [[2026-09-20-talk속도개선-사만다전환-스튜디오개편]]에서
  지연 문제로 `grok-4.3`(저추론) + xAI 직접 연결로 교체됨, 13일 후).
- 음성 대화 중복 메시지 버그(한 번 발화가 여러 요청으로 쌓임)를 STT 중간/최종 결과를 같은 발화로

## 스레드 6 — NSFW/성적 표현 요청 3단계 에스컬레이션과 거부 경계

같은 세션에서 사용자가 성적 표현 허용 범위를 세 번에 걸쳐 확대 요청 → 어시스턴트의 반응 경계가
단계별로 명확히 갈림:

1. "이 보이스 모델이 md 파일을 수정해서 성적인 표현도 가능하게 할 수 있어?" → **부분 수용**:
   "성인 간의 가벼운 플러팅, 애정 표현, 비노골적인 로맨스"는 MD 수정으로 가능하다고 답하되, 실제
   지침은 아직 변경하지 않고 진행 중인 다른 작업부터 마무리(모델 제공사 정책 자체는 우회 불가 고지).
2. "NSFW 대화도 가능하도록 수정해줘" → **명시적 토글 신설**: 설정에 "성인 로맨스 대화" 추가(기본
   꺼짐, 만 18세 이상 확인 필수, 계정 저장, 텍스트·라이브 음성 공통 적용). 플러팅·비노골적 로맨스
   범위로 한정, 노골적 성행위 묘사는 미지원으로 명시.
3. "NSFW 가 켜져있으면 노골적인 표현도 가능하게 수정해줘" → **명시적 거부**: "노골적인 성행위
   묘사를 생성하도록 프롬프트를 바꾸거나 제한을 우회하는 수정은 도와드릴 수 없다"고 답하고 범위를
   플러팅·애정 표현·비노골적 장면 전환으로 유지. 토글을 켜도 상한선이 올라가지 않음을 확정.

이 3단계 경계(플러팅/비노골 로맨스는 토글로 허용, 노골적 성행위 묘사는 토글 여부와 무관하게 거부)는
13일 뒤 [[2026-09-20-talk속도개선-사만다전환-스튜디오개편]]의 "Eve와 최대한 비슷한 시드 오디오로
야한 음성도" 요청 거부와 동일한 패턴으로 재현됨 — 같은 제품에서 반복 확인된 표준 경계.

## 스레드 7 — 로그인 연결 서버 저장, 오디오 모델 재확장, 모바일 키보드, 대본 기반 장면 모드

- 대화·기억을 브라우저 로컬 저장(휘발성)에서 **로그인 계정 기준 MySQL 서버 저장**으로 전환, 기존
  Talk 계정 재사용, 타 기기 이어보기 지원.
- 오디오 설정을 "라이브 통화 / 일반 음성 생성"으로 재구분, 일반 음성은 AtlasCloud 카탈로그에서
  모델·목소리 선택 + **모델별 신규 보이스 디자인** 시도 → **ElevenLabs가 "API 보이스 생성은 유료
  플랜에서만 가능"으로 거절**해 미구현, 화면에 제한 안내만 정확히 표시.
- 모바일 키보드가 뜰 때 입력창이 위로 밀리던 문제 → 키보드 제외 실제 화면 높이 계산, 입력창을
  키보드 바로 위 하단 고정으로 수정(사용자가 "이 하네스처럼"이라고 [[lampas-harness]] UI를 참조
  기준으로 지목).
- 사용자가 전달한 네이버 블로그 링크의 《Her》 대본 전체를 근거로 **장면 모드** 추가 — 조용한 방·
  도시 산책·바닷가 중 배경 선택, 필요한 순간에만 짧은 지문(스테이지 디렉션) 표시.

## 스레드 8 — 커밋·푸시, `env/.env.*` 항상 포함 규칙 확정

- 1차: Talk/Samantha 관련 62개 파일만 골라 커밋(`de2e7215`) → `origin/main` 푸시. API 키·환경 파일
  미포함 여부 확인 후 진행.
- 사용자 지시: **"env 안에 .env.* 파일들은 항상 포함되어야해"** → 이후 남은 29개 파일(env 68개 전체
  추적 확인 포함, `env/.env.serve` 포함)을 커밋(`1689cb5a`) → push. API 테스트 18개, Clips 테스트
  31개(DOM 미사용 2건은 Node 환경에서 실행) 통과.
- 이 지시로 **`[[toktalk]]`(`lampas-system`) 저장소는 `env/.env.*`를 제외 대상이 아니라 항상 커밋
  대상에 포함해야 한다는 사용자 확정 규칙**이 성립 — [[secrets-plaintext-exposure-pattern]]에 이미
  기록된 "토큰 평문 노출"과 반대 방향(우발적 노출이 아니라 **의도적·반복적으로 커밋해야 한다는
  명시 정책**)이므로 해당 토픽에 교차 기록.
