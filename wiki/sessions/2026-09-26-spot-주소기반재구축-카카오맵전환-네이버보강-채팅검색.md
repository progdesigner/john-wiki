# 맛집 사이트 개선 — spot.lampas.io "주소 기반 재구축" + 카카오맵 전환 + 네이버 보강 + Jev 채팅검색 (2026-09-26)

`Tool: claude` 세션(08:31:28Z 시작, 작업 디렉터리 `lampas-system`). [[2026-09-26-카카오-지도-api-키-발급]]
세션이 시작하기 불과 83초 전에 시작됐고, 사용자의 첫 메시지에 이미 카카오 JS 키·REST API 키 표가
붙여넣기돼 있다 — 두 세션이 사실상 짝을 이뤄 거의 동시에 진행됐다는 뜻(그 세션이 "실제 발급
담당", 이 세션이 "발급된 키를 받아 기능 구현" 역할로 추정되나 정확한 선후 관계는 두 소스만으로
확정 불가).

이 세션은 [[lampas-web-spot]] 페이지가 남겨둔 미해결 질문(2026-09-24/25 "OpenStreetMap 단일 경로
확정" vs 2026-09-26 "카카오 키만 발급, SDK 교체는 별도")에 **직접 답한다**: 이 세션에서 실제로
카카오맵 SDK 교체가 일어났고, 서비스 성격 자체가 "수집한 데이터 전시"에서 "주소만으로 맛집 데이터를
생성하는 서비스"로 바뀌었다.

## 핵심 변경 — 데이터 파이프라인 전면 재설계

- **블루리본·다이닝코드 표기 완전 제거** 지시로 시작. 기존 데이터(738곳 중 502곳 지도 표시,
  [[lampas-web-spot]] 2026-09-24/25 기록)를 그대로 보여주는 방식을 버리고, 주소를 입력하면
  **카카오 REST API**(주소→좌표·행정구역, 카카오 장소 검색으로 전화·카테고리·장소 URL)로 기초
  정보를 맞춘 뒤:
  1. 블로그·웹 검색 발췌를 [[jev-typed-classification|Jev]](System One)로 "이 식당에 대한 글인가"만
     typed 판정으로 걸러내고,
  2. 이미지 검색 후보를 비전 LLM이 음식/내부/외관/메뉴 적합도로 판정해 최대 6장 선택,
  3. 최종적으로 LLM이 **사실과 발췌만 근거로 완전히 새로 쓴** 소개(한 줄 요약·본문·특징 태그·대표
     메뉴·팁)를 생성한다.
  외부 원문은 비공개 `notes`에만 남기고, 공개 필드는 전부 AI가 다시 쓴 글 — 저작권 회피 + 출처
  은폐를 동시에 노리는 설계.
- **lampas-api 신규 `spot` 모듈**, 신규 테이블 `spot_places`. 구 데이터 856곳을 운영 워커가
  자동 보강(동시 처리 3, `SPOT_ENRICH_CONCURRENCY`).
- **관리자 웹 `/spot`**(`admin.lampas.io/spot`, [[lampas-web-admin]] 신규 모듈) — 주소 찾기→카카오
  후보 선택→등록, "이름 | 주소" 일괄 등록, 상태별 목록, 재수집, 숨김·삭제, 등급·소개·사진 순서 편집.
  등록 즉시 워커 우선 처리로 보통 30초 내 지도에 반영.
- **지도 프로바이더 — 카카오맵 Web SDK로 확정 전환**(SDK 실패 시 OSM 폴백 유지). [[lampas-web-spot]]
  페이지의 "최종 OSM 확정" 기록은 이 세션으로 뒤집힌다 — 아래 엔티티 갱신에서 모순 해소로 반영.

## 두 번째 요청 — 주소 직접 추가 + 네이버 보강 + 관리자 모드

- **공개 spot 웹에 "장소 추가" 기능 신설** — 사용자가 직접 주소(또는 "가게 이름+동네")만 넣어도
  카카오·네이버 후보에서 골라 등록 가능.
- **네이버 검색 API(지역·블로그·이미지) 클라이언트 추가** — 키가 설정되면 자동 활성화되는 구조로
  구현. **이 세션 시점엔 `NAVER_CLIENT_ID`/`SECRET` 키가 아직 없어 비활성 상태**로 남음(developers.naver.com
  에서 발급 안내만 전달). 네이버 장소 링크·후기·이미지는 키가 들어와야 켜진다.
- **신고→즉시 숨김, 복원은 관리자만** — 기존([[lampas-web-spot]] 2026-09-24/25 기록)엔 신고자 본인이
  개인 화면에서 숨김·복원 모두 가능했는데, 이 세션에서 **사용자 자가 복원 기능을 제거**하고 서버가
  신고 즉시 `visible=false` 처리, 복원은 spot 웹 관리자 모드 또는 admin `/spot`에서만 하도록 뒤집음
  — 기존 기록과의 정면 변경이라 [[lampas-web-spot]]에 모순으로 명시.
- **spot 웹 자체에 관리자 모드 신설** — 헤더 "관리자" 버튼 → admin.lampas.io와 동일한 관리자
  비밀번호 입력 → 브라우저 로컬 세션으로 관리자 권한 부여(주소로 장소 추가, 숨긴 장소 복원, 재수집,
  삭제). `admin.lampas.io/spot`과는 별개의 **두 번째 관리 진입점**.
- 신고 스팸 취약점 인지: IP당 분당 10회 제한만 있음 — 악용되면 "신고 2회 이상일 때 숨김"으로 조정
  가능하다고 남김(미구현).

## 흔적 제거 — "크롤링한 게 티나지 않게 하는 게 핵심"

사용자가 "별도 제거해줘 티나잖아"라고 명시적으로 요구. 기존 블루리본 리본 수에서 옮겨온 ★ 등급
표시(공개 화면·공개 API `grade` 필드·등급 필터)를 전부 제거(관리자 화면에만 참고용 유지), 공개
API의 `legacyId`(블루리본·다이닝코드 원본 id)도 해시 `ref`로 교체 — 즐겨찾기 이전 호환은 유지하되
원본 식별자는 숨김. 운영 응답을 문자열로 훑어 `grade`/`legacyId`/`bluer`/`diningcode`/"리본" 미노출
확인. 카테고리 문구(예: "우대갈비, 돼지고기구이")는 원본 출처 텍스트가 남아있지만 일반적인 음식
분류라 출처 특정이 어렵다고 판단해 남김 — 완전 제거하려면 카카오 분류로 재작성하는 추가 작업 필요.

## Jev 채팅 검색 — 자연어 질문으로 맛집 추천

"송파구에서 기념일에 가면 좋은 곳을 추천해줘" 같은 자유 문장 검색 요청에 대응해 `POST /v1/spot/search`
신설:
1. 질문에서 시도·시군구·동을 **규칙으로** 추출, 조사·요청 표현을 걷어내고 상황 사전으로 연관어 확장
   (기념일→데이트·와인·프라이빗·코스·야경 …).
2. 지역 필터 + 규칙 점수로 후보 60곳 추림.
3. [[jev-typed-classification|Jev]](System One)가 후보마다 "요청에 얼마나 맞는가"를 4단계 typed 판정
   (30곳씩 병렬) — Jev는 문장 생성을 못하므로 답변 문장·파싱은 모두 규칙 기반, Jev는 순수 적합도
   게이트로만 쓰임.
- 배포 중 "송파구"가 "송파동"에도 매칭되는 파싱 버그 발견 → 정식 행정동 이름을 먼저 제거하도록 수정
  후 재배포.
- 운영 확인: "송파구 기념일" → 적합도 0.76~0.98 5곳·1초, "조용한 한정식" → 룸 한정식집 상위,
  "혼밥 라멘" → 라멘 전문점만 상위.
- 한계: 보강 미완료(소개 없음) 장소는 순위에 잘 안 오름, "근처"/현위치 기준 검색 없음, 지역 없는
  질문은 전국 대상.

## 지도 UX 반복 개선 (사용자 스크린샷 피드백 기반, 4회)

1. 클러스터·등급 핀의 숫자(1·2·3) 제거 → 단색 핀 + ★ 텍스트만(이후 ★ 자체도 위 흔적 제거 단계에서
   삭제).
2. 길찾기·장소 링크를 **네이버/카카오 선택 팝업**으로 통일(좌표 있으면 대중교통 길찾기, 없으면
   이름+주소 검색), 주소 복사 버튼을 주소 줄 옆 아이콘으로 이동.
3. 겹친 핀이 최대 확대에서도 뭉치는 문제 → 클러스터 숫자 클릭 시 "이 위치 N곳" 목록 패널(근접
   배율·12곳 이하일 때), 먼 거리에서는 기존처럼 확대.
4. 선택한 장소가 지도 어디 있는지 안 보이는 문제 → 소속 클러스터 원을 주황색으로 강조 + 목록 패널
   자동 열림 + 스크롤 이동. 단독 핀은 테두리 강조 유지.
5. 클러스터 숫자 정중앙 정렬 버그(스크린샷 제보) — 원인은 3px 테두리가 크기에 더해지는데 줄 높이는
   고정 40px이라 숫자가 우하단으로 치우침. 테두리 포함 크기로 재계산해 수정.

## 발견·수정한 버그 2건 (재사용 가능한 교훈)

- **Gemini 3.5 flash 사고(thinking) 토큰이 `maxTokens`를 잠식해 JSON 응답이 잘림** — writer·이미지
  판정 호출이 자주 JSON 검증 실패. 모델 원문을 직접 받아 원인 확인 후 토큰 한도 상향 + 재시도로
  해결 → 신규 스킬 [[gemini-thinking-tokens-eat-maxtokens-budget]].
- **운영 배포 번들이 `.env.local`의 `VITE_API_URL=localhost`를 물고 나감** — 운영 집계 수(857)가
  로컬 DB 레코드 수와 같아서 발견. 운영 env에 API 주소를 명시적으로 넣고 재배포 → 신규 스킬
  [[vite-build-env-precedence-local-leaks-into-prod]].
- **다른 세션의 미완성 변경이 API 배포에 섞임** — packaging 모듈(copy-tones 등) 미커밋 변경이 워킹
  트리에 있어 deploy 스크립트가 그대로 빌드. 이후 턴부터는 **별도 클린 워크트리에서 자기 커밋만
  배포**하는 방식으로 전환(auth·signup-domain·packaging의 다른 세션 변경은 운영에 안 나감) —
  [[selective-hunk-commit-shared-file]]의 기존 패턴과 동일 계열. 이 세션이 만든 `spot_places` 신규
  테이블은 이후 [[2026-09-26-studio5도메인분리-models카탈로그-packaging플랫폼-유튜브]] 세션에서
  **반대 방향 사고**(다른 세션이 `git add apps/lampas-api`로 이 세션의 미완성 `spot` 변경을 실어
  나른 것)의 원인이 된 그 "spot" 작업 자체이기도 하다 — 두 세션은 같은 날 같은 모노레포를 동시에
  건드린 사례로 연결된다.
