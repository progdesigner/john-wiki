## 처리한 요청 (순서대로)

1. **터미널 스크롤 개선** — Claude Code 2.1.263이 켜는 마우스 추적(`?1000h ?1002h ?1003h ?1006h`)
   때문에 휠 스크롤이 xterm 스크롤백 대신 이벤트별 HTTP 요청으로 새 나가 끊기던 문제. 배칭 도입 +
   서버 스냅샷 SGR 인코딩 복원으로 근본 수정.
2. **데몬 재시작 요청** → 실행.
3. **커밋·푸시 요청** → `57f4aaa`. 원격에 선행 커밋(`862058b`, 남이 만든 문서 커밋)이 있어 리베이스 후 재푸시.
4. **드래그 텍스트 복사 안 됨** — xterm이 마우스 추적 중엔 자체 선택을 끄는 것이 원인. 일반 드래그를
   xterm 강제 선택 경로(Mac Option / 그 외 Shift 합성 이벤트)로 우회해 해결.
5. **모델 변경하면 바로 반영되게** — "다음 메시지부터 적용"이 아니라 대부분 상황에서 **변경 자체가
   오류로 실패**하고 있던 게 실제 원인으로 드러남. `modelChangeBlocker` 신설로 근본 수정.
6. **정지 기능 없음** → 입력창 옆 정지 버튼 + Esc 키 구현. 같은 요청 처리 중 대화 목록 드래그 정렬도 구현.
7. **Tailscale 새 계정으로 재연결** — 로그아웃 후 새 계정 로그인, Funnel 재설정, DNS 전파 지연 진단·해소.
8. **문서 커밋 + 전체 커밋 푸시**, 이어서 **접속 안 됨 재확인**(로컬 KT 리졸버 문제로 특정) →
   **포트 8443 추가**(사용자가 그쪽으로 접속하길 원함) → **main에 전부 머지**(fast-forward).

## 핵심 결정/발견

- **스크롤 지연의 원인은 "이벤트 하나당 HTTP 요청 하나"였다** — 트랙패드 스와이프 하나가 수십 개의
  개별 POST를 큐에 쌓아 스크롤이 손 뗀 뒤에도 계속 밀림.
- **모델 변경 버그의 진짜 원인은 "적용 시점"이 아니라 "적용 자체가 실패"였다** — 진단해 보니 세 가지
  상황(입력 대기 중 힌트 문구 오인, 응답 중 무조건 거부, 확인창 미처리)이 겹쳐 대부분의 시도가 조용히
  실패하고 있었다.
- **헤더의 "■ 정지" 버튼은 이 세션이 만든 게 아니라 같은 작업 트리에서 동시에 돌던 다른 세션
  (Codex "하네스 개발 (GPT)")이 `#interrupt`로 추가한 것**이었다. 이 세션은 그 버튼을 걷어내고
  입력창 옆 버튼 + Esc 키로 재구현했다 — 같은 저장소에 여러 에이전트(Claude 터미널 세션 + Codex
  터미널 세션)가 동시에 편집을 넣고 있었다는 직접 증거.
- **Tailscale DNS "레코드 없음" 진단이 두 번 뒤집혔다**: A(IPv4) 레코드가 없다 → AAAA(IPv6)는
  있는데 A만 없다 → 실제로는 A도 발행돼 있고 어시스턴트가 계속 조회하던 권한 서버
  `ns1.dnsimple.com` 한 대만 전파가 늦었을 뿐이었다. 최종 실사용 접속 실패(사용자 쪽)도 같은 계열
  원인으로, KT 기본 리졸버 `168.126.63.1`이 그 지연된 서버 응답(NXDOMAIN)을 캐싱하고 있었다.
- **포트는 원인이 아니었다** — 443/8443 모두 같은 DNS 문제에 걸렸다. 사용자가 8443을 요청해 최종적으로
  443과 8443 둘 다 열어 둠.

## 검증

- tsc/vite 빌드, 헤드리스 프로브(`tools/probe-sgr-mouse.mjs`, `probe-terminal-selection.mjs`,
  `probe-model-real.mjs`), 단위 테스트(`terminal-models.test.ts`, `terminal-order.test.ts`),
  전체 스위트 53→54개 통과.
- Playwright로 실제 세션 화면에서 드래그선택/클립보드, 정지버튼 표시·클릭, 드래그 정렬을 직접 확인.
- Tailscale: 4개 권한 서버(ns1~ns4) + 공개 리졸버(구글/클라우드플레어/Quad9/ISP) 교차 조회, 8443/443
  양쪽 HTTPS 200 + API 응답 확인.

## 알려진 한계 (미해결로 남은 것)

- `opus[1m]`(1M 컨텍스트 변형) 모델은 연속 전환 직후 Claude 피커가 그 항목을 목록에 안 띄우면 실패 —
  CLI 자체의 피커/카탈로그 불일치라 하네스에서 안전하게 우회 불가, 명확한 오류로 처리.
- `ns1.dnsimple.com` 지역 인스턴스 전파 지연과 KT 리졸버 캐싱은 Tailscale/dnsimple·ISP 쪽 문제라
  서버에서 조치 불가 — 사용자 기기/공유기 DNS를 8.8.8.8·1.1.1.1로 바꾸는 우회만 제시.
