# 2026-09-26 — 브라우저 탭/좌표클릭/원격 직접입력 구현 + 위키 아카이브 백필 + `.env` 노출 발견 + 맥북 빌드 동기화 진단

`Tool: claude` 세션(작업 폴더 `lampas-harness`, 02:43Z 시작). [[2026-09-26-lampas-browser-구축-harness이전]]이
`apps/browser`로 이관을 마친 직후 이어지는 세션 — 이관된 브라우저 패널에 실제 기능을 쌓고, 같은 날 발견된
위키 저장 누락 버그를 고치고 백필하고, 커밋·푸시 도중 원격 히스토리에서 평문 비밀 노출을 발견하고,
마지막엔 맥북 로컬 실행이 안 되는 문제를 빌드 산출물 동기화 문제로 진단한, 요청 9개가 이어진 긴 세션.

## 1. 브라우저 패널: 버튼 제거 + 탭 UI

- "표 수집"/"CSV 저장" 버튼을 패널에서 제거(AI는 MCP 도구로 계속 사용 가능, 수집 결과 표시는 유지).
- 주소 입력 후 "새 탭"으로 새 사이트를 열 수 있게 하고, 탭마다 × 닫기 버튼 + 활성 탭 강조 + 로딩
  표시(⟳) 추가.
- **주소창 경쟁 조건 수정**: 활성 탭 URL이 실제로 바뀔 때만 주소창을 갱신하도록 해, 옛 URL로 되돌아가던
  버그를 없앰.

## 2. 화면 캡처 클릭 = 좌표 클릭 (`click_at`)

- 새 도구 `click_at`(CSS 픽셀 좌표)을 프로토콜·Electron 앱·MCP에 추가. 스크린샷 응답에 뷰포트
  width/height를 함께 반환해 AI도 좌표를 계산해 클릭할 수 있게 함.
- 웹 패널에서 캡처 이미지를 클릭하면 그 좌표를 브라우저에서 클릭하고 재캡처. AI가 요청한 좌표 클릭도
  기존 클릭 도구와 동일하게 승인 대상.
- Electron 사이드 패널의 "탐색은 여기서…" 안내 블록 제거, 세션 한 줄 + 작업 로그만 남김.

## 3. 위키 아카이브 저장 누락 버그 발견·수정·백필

- **원인**: 웹의 "대화보관"이 세션 중지 후 **숨기기(hide)만** 호출하고 **위키 저장(archive) 요청은
  보내지 않았음** — 보관된 70건 중 **68건**에 저장 잡이 아예 없었다.
- **수정**: 서버가 숨김 처리 직후 자동으로 위키 저장 잡을 큐에 넣도록 변경. 트랜스크립트를 못 찾으면
  이유를 세션에 기록, 설정 화면 "위키 아카이브" 버튼 hover 시 그 이유가 보임.
- **백필**: 운영 데몬의 archive API로 기존 68건을 재처리 — **55건 큐에 넣음, 13건 트랜스크립트 없음**
  (대부분 "테스트"·"하네스 현재 폴더 선택" 같은 초단문 세션, codex 세션은 rollout 파일 바인딩 실패로
  원본 미발견). 잡 1건당 약 $0.7, 총 40달러 안팎 예상. **`WIKI_DIR`은 `john-wiki`로 확정**(`llm-wiki`
  폴더는 존재하지 않음 — [[2026-07-11-기억-요약-wiki-경로-확인]]이 남긴 경로 불일치 우려를 이 세션이
  실측으로 해소).
- 두 번째 사용자 요청("13건도 모두 저장되게 해줘 + 데몬 재시작")에 따라 13건을 재조사했으나 **정말로
  저장할 대화가 없음**으로 확정 — 남은 화면 스냅샷 전부가 Codex 업데이트 안내·Claude 폴더 신뢰 확인·
  빈 프롬프트 종료 같은 CLI 시작 화면뿐이었다.
- **재시작-백필 연동 스크립트**: 재시작 예약 시 재시작 순간 실행 중이던 저장 잡은 데몬 규칙상 "고아"
  실패 처리되는데, 재시작 직후 실패 상태인 보관 세션을 스크립트가 찾아 archive API로 재큐잉한다.
  결과는 `logs/server.log`의 `[restart-archive]` 접두사로 기록됨.

## 4. 원격 직접 입력(사용자 전용 키 입력 도구) 설계·구현

사용자 질문 "원격 브라우저에 내가 직접 아이디 비번을 입력할 수는 없나?"에서 시작.

- 기존엔 원격 웹 패널에서 보낼 수 있는 입력이 주소 이동·탭 조작·좌표 클릭뿐이라 **키보드 입력 경로
  자체가 없었다**. AI용 텍스트 입력 도구도 비밀번호·파일 필드를 의도적으로 제외.
- **설계**: 좌표 클릭으로 입력창 포커스 → 웹 패널의 입력줄에 적은 문자열을 **실제 키 이벤트**로
  브라우저에 흘려보냄(DOM 값 직접 변경 아님 — 비밀번호 필드에도 들어감, 한글도 그대로 입력됨).
  **서버가 요청 출처(웹 패널 vs AI)를 구분**해 이 도구를 웹 패널 출처만 받도록 강제 — AI는 호출 자체가
  불가능하고 MCP 도구 목록에도 노출되지 않음. 입력값은 승인 카드·활동 로그·이벤트 어디에도 안 남고
  글자 수만 기록.
- **구현 완료**(주소줄 아래 입력 줄 신설, 기본 가려짐+"보이기" 토글, 전송 후 입력칸 비움, Enter 동시
  전송 옵션). 같은 프로토콜 파일에 **다른 세션이 동시에 추가한 `google_append_rows` 도구**는 그대로
  유지한 채 위에 얹어 빌드 — 이 저장소가 여러 세션에서 동시 편집되는 패턴이 이번에도 재현됨
  ([[lampas-harness]] 09-19~24 절의 Codex/Claude 동시 편집 사례와 같은 계열).
- 검증: 브라우저 세션 테스트·서버/Electron 타입 검사 통과, 통합 스모크(실 Chromium, 창 표시 모드)에서
  입력칸 클릭→직접 입력까지 전 구간 통과. AI 출처 요청 거절·MCP 목록 미노출도 테스트로 확인.
- 로그인 후 세션별 브라우저 프로필에 쿠키가 남아 같은 세션 내 재입력 불필요.

## 5. 계정 정보 별도 보관(제안만, 미구현)

- "계정 정보를 별도로 보관해서 활용하는 거 가능할까?" → "대신 암호화해서 저장해야겠지?" 두 질문에 대한
  설계 응답. **구현은 이 세션 안에서 진행되지 않음** — 제안 단계로 세션이 끝남.
- 권장안: **macOS 키체인**에 비밀번호 직접 저장(그 자체가 암호화 저장소, 디스크에 평문 없음). 서버는
  사이트 주소+계정 이름만 JSON으로 보관, 비밀번호는 채우는 순간에만 키체인에서 꺼내 메모리에서 버림.
  파일 저장 대안은 기각(키를 결국 키체인에 둬야 해 관리 부담만 늘어남).
- 안전장치 설계: 현재 탭 사이트 주소와 저장된 계정이 일치할 때만 채움(피싱 방지), AI는 계정 목록 조회·
  채우기 모두 불가(사용자 전용 규칙 재사용), 활동 기록엔 "어떤 계정을 썼다"만 남고 값은 없음.
- 남는 위험을 솔직히 명시: 로그인된 맥미니에 직접 접근 가능한 사람은 어떤 저장 방식이든 비밀번호를
  꺼낼 수 있다 — 암호화는 디스크·백업 유출만 막는다.

## 6. 커밋·푸시 + 원격 히스토리 `.env` 평문 노출 발견 ⚠️

- "지금까지 하네스 작업된거 모두 커밋 하고 푸시해줘" 요청이 세션 재시작으로 한 번 끊겼다가 재요청됨.
  첨부파일·임시 폴더를 `.gitignore`에 추가, 전체 테스트 **88/88 통과** 후 커밋.
- **푸시 거부** → 원격에 새 커밋 있어 fetch로 확인하는 과정에서 **9월 20일자 원격 커밋이 `.env`
  파일 전체를 저장소에 커밋해 두었다는 사실을 발견**. 그 안에 Claude OAuth 토큰, Anthropic·OpenAI·
  Google·ElevenLabs API 키, 하네스 토큰의 **실제 값**이 들어 있었다.
- 대응: 그 커밋 위에 이번 작업을 얹어 푸시하고, **`.env` 추적을 해제하는 커밋을 추가로 생성**. 로컬
  `.env`는 백업 후 그대로 복원해 데몬 설정은 변경되지 않음.
- **한계 인지**: 추적 해제는 앞으로의 커밋만 막을 뿐, 키는 이미 히스토리에 남아 있음. 로그인 없이
  GitHub 접근 시 404(비공개로 보임)이지만, 저장소 접근 권한이 있는 누구든 히스토리에서 키를 볼 수 있음.
- **사용자 결정 필요 사항으로 남김**: (1) 노출된 키 5개+하네스 토큰 재발급 — 가장 확실한 방법, (2)
  히스토리에서 해당 커밋의 `.env`를 지우고 강제 푸시 — 다른 클론이 있으면 재클론 필요. 이 세션 소스
  안에서는 사용자의 선택이 확인되지 않음.
- → 반복되는 비밀 노출 패턴에 7번째 사례로 추가: [[secrets-plaintext-exposure-pattern]]
- 결과: 변경 파일 80개, 커밋에는 세션 브라우저 전체(탭·좌표클릭·직접입력), 위키 자동 저장, 웹 검색
  MCP, 첨부파일·네이티브 질문, Google 문서 도구, 위키 뷰어, 브랜딩 페이지, 스모크 스크립트가 포함됨.

## 7. 맥북 로컬 실행 시 브라우저 기능 안 보임 — 빌드 산출물 미동기화 진단

사용자가 스크린샷과 함께 "코드 최신화 한거 맞아? 맥북에서 로컬 실행하면 브라우저 작업 등이 안되는데?"
질문.

- 확인 절차: GitHub 최신 커밋을 **빈 폴더에 새로 클론**해 설치·빌드를 전부 재현 — 서버·웹·브라우저 앱
  빌드 모두 성공, 웹 번들에 "작업 유형(브라우징)" 항목이 정상 포함됨을 확인. **푸시된 코드는 최신이
  맞다**는 결론.
- **근본 원인**: 코드가 아니라 **빌드 산출물** — 서버 `dist/`, 웹 `apps/web/dist/`, 브라우저 앱
  `apps/browser/dist/`와 그 의존성이 모두 git 제외 대상이라 `git pull`만으로는 옛 빌드가 그대로
  실행됨. 스크린샷의 대화상자는 브라우징 기능이 들어가기 전 웹 번들 상태였다.
- 안내한 절차: `git pull` → `npm install` → `npm run build` → 람파스 데몬 재시작(서버 빌드 반영에
  필수). 브라우저 앱 빌드는 Electron 다운로드 때문에 최초 1회 몇 분 소요.
- 추가 경고 2가지: (a) 전체 빌드는 **서버→브라우저 앱→웹 순서로 이어지므로** 브라우저 앱 단계에서
  실패하면 웹 번들이 갱신 안 돼 지금과 같은 화면이 재현됨 — 빌드 로그 끝에 세 단계 모두 성공했는지
  확인 필요. (b) 이번에 `.env` 추적을 해제했으므로, 맥북에서 pull하면 git이 추적하던 로컬 `.env`가
  **삭제될 수 있음** — pull 전 백업, 사라졌으면 복원 안내.
- → 이 유형의 함정(다른 개발 머신에서 소스는 최신인데 빌드 산출물만 안 갱신)을 [[self-hosted-agent-server-ops]]
  함정 4에 새 변종으로 추가.

## 왜 중요한가 (사서 메모)

- [[lampas-browser]](이관 후 `apps/browser`)가 하루 만에 이관→탭/좌표클릭/직접입력 3종 기능까지 쌓인
  속도가 이 세션에서 드러난다 — "AI 전용 브라우저"에서 "사람이 직접 로그인할 수 있는 원격 제어 콘솔"로
  범위가 확장된 시점.
- 위키 아카이브 저장 누락(68/70건)은 이 위키(john-wiki) 자체의 신뢰성에 직결되는 버그였다 — 이
  세션 이전까지 "보관했다고 생각한" 대화 대부분이 실제로는 장기 기억에 들어오지 않고 있었다는 뜻.
  55건이 백필 큐에 들어갔으므로, 이후 야간 ingest나 수동 ingest 때 오래된 "미확인 세션"이 대량으로
  등장할 수 있음을 감안할 것.
- `.env` 평문 노출은 [[secrets-plaintext-exposure-pattern]]의 기존 5개 사례와 달리 **저장소 관리자가
  키 5종+토큰 재발급 여부를 아직 결정하지 않은 채로 세션이 끝난** 활성 위험 상태다 — 다음 세션에서
  재발급 여부를 반드시 확인할 것.
