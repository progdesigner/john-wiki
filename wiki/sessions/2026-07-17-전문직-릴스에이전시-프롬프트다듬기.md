# 2026-07-17 전문직 대상 릴스 제작 에이전시 프롬프트 다듬기

1왕복 quick 채팅 (2026-07-17 06:31~06:32 UTC). 코딩 아님 — [[lampas]]를 카피/프롬프트 엔지니어링 보조로 사용.
[[harness-as-business-assistant]] 패턴군 사례.

## 요청
사용자가 이미 작성해둔 초안 프롬프트를 그대로 붙여넣고 "다듬어줘"라고 요청. 초안 내용:
- 타깃: 의사·회계사·변호사 등 **전문직**
- 목적: **퍼스널 브랜딩** + 본인 사업 **홍보/마케팅**
- 서비스: 방향성 설계 → 콘텐츠 기획/제작 → 영상 촬영까지 **올인원**
- 강조점: "전문성을 신뢰해서 사업 홍보가 잘 될 수 있도록 돕는 에이전시", 말을 잘 못하는 사람도
  맡기면 **스피치 연습~이미지 컨설팅**까지 커버
- 지시: "이 회사에 맞는 문구로 모든 문구를 바꿔줘"

## 어시스턴트 응답
원문 정보 손실 없이 **회사 소개 → 제공 서비스 → 핵심 강조 포인트 → 지시사항** 4단 구조로 재정리한
프롬프트를 제시. 이어서 결과 품질을 높이기 위해 사용자에게 3가지 후속 정보를 되물음:
1. 어떤 문구인지 (홈페이지 카피 / 인스타 소개글 / 광고 문구 / 상담 스크립트 — 톤이 크게 달라짐)
2. 원하는 톤 (신뢰감 있고 묵직한 톤 vs 친근하고 쉬운 톤)
3. "모든 문구를 바꿔줘"라 했으니 실제로 바꿀 **원본 문구 목록**

트랜스크립트는 이 질문에 대한 사용자 답변 없이 종료 — 실제 최종 카피 산출은 미확인.

## 관찰
- 사업 상담(포지셔닝 분석)이 아니라 **프롬프트 자체의 구조·완성도를 개선**해달라는 메타 요청 —
  [[harness-as-business-assistant]] 패턴군 중 가장 "프롬프트 엔지니어링"에 가까운 케이스.
  기존 사례들(올리브유·아우보카사 등)은 이미지/데이터를 해석하는 컨설팅이었던 것과 대비.
- 정보 손실 없이 구조화 + 실행에 필요한 누락 정보를 질문으로 되묻는 절차가 재사용 가능해 보여
  [[prompt-structuring-for-execution]] 스킬로 추출.
- 에이전시 이름·구체 브랜드는 소스에 미상 — 임의 엔티티 생성하지 않음.
