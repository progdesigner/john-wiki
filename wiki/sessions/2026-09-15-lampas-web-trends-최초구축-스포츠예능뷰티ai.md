## 진행 순서

1. **소스 조사**: Google Trends RSS, Google 뉴스, 연합뉴스, JTBC 피드가 실제 응답하는지 확인.
   검색 급상승과 기사 언급 집계를 함께, 예능은 방송·프로그램 키워드로 필터링하기로 설계.
2. **JTBC 피드 제외**: 내용 확인 결과 2024년 기사에서 갱신이 멈춰 있어 집계 제외. 최신 기사가
   확인된 **조선일보 스포츠·연예 피드**로 대체.
3. **수집 주기**: AWS에서 5분마다 자동 실행하도록 설계(페이지를 열어두지 않아도 갱신).
4. **최종 7개 피드**로 스포츠·예능 데이터 수집 확정 — 같은 기사가 여러 피드에 등장해도 중복
   집계하지 않도록 디듀프, 수집 실패 시 최근 캐시+오류 상태 표시로 폴백.
5. **화면**: 분야별 순위, 키워드별 근거 기사, 출처 상태를 한 화면에서 확인.
6. **배포 장애물**: 빌드·테스트는 통과했으나 **AWS 계정에 Lambda·스케줄러 생성 권한이 없어**
   Lambda 기반 수집기 계획을 접고, **기존 API 서버에서 수집기를 별도 프로세스로 운영**하는
   방식으로 전환.
7. **운영 반영**: 도메인 연결(`trends.lampas.io`) + 서버 수집기 실행 완료, 첫 운영 수집에서 7개
   피드 모두 정상 응답. 브라우저에서 분야 전환·검색·키워드 저장/복원·모바일 레이아웃 확인.
8. **배포 검증**: 실제 주소에서 데이터 표시·검색·출처 필터·저장·모바일 상세 보기·통신
   오류/수집 지연 안내 정상 동작 확인. 이후 두 번째 자동 수집(약 300초 후, 5분 주기)에서도
   7개 피드 정상 확인 — 관심 추이 그래프가 실제 관측 데이터로 누적되는 것도 확인.
9. **키워드 추출 보정**: 키워드 별칭·불필요한 표현을 거르는 마지막 보정 반영.

## 1차 완료 (스포츠·예능)

`trends.lampas.io` 배포 완료:
- 스포츠·예능 분야별 트렌드 키워드
- Google Trends·Google 뉴스·연합뉴스·조선일보 **7개 피드를 5분마다 자동 수집**
- 순위·관심 추이·관련 기사·출처 표시
- 검색, 출처 필터, 키워드 저장, 모바일 지원
- 순위는 원시 검색량이 아니라 수집 데이터 기반 **자체 집계 관심 지수**(검색량과 구분해 표시)
