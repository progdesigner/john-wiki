# 2026-07-13 — 대화 보관 시 자동으로 장기기억(john-wiki) 저장

`[[progdesigner]]`가 "보관하게 되면 장기 기억에 저장하도록 하는 기능으로 개선해줘"라고 지시.
`[[lampas-harness]]`의 **대화 보관(🗄) 동작에 memory-ingest 자동 큐잉을 연결**한 짧은 구현 세션
(2026-07-13 14:28~14:33, 원본 트랜스크립트는 어시스턴트 진행 요약만 남아 코드 상세는 요약 서술 기준).

## 배경

- 기존에는 `🧠 기억에 저장` 버튼을 **수동으로** 눌러야 위키로 ingest됐고, 보관(🗄)은 단순히 대화를
  `chats/archive/`로 이동만 했다. → 보관해도 장기기억엔 안 남는 괴리.
- 이 개선으로 **보관 = 아카이빙 + 장기기억 저장**이 한 동작으로 묶임. 이는
  `[[long-term-memory-architecture]]`의 **저장 계층**(john-wiki에 이력 축적)을 자동화하는 배선이다.

## 구현 내용 (어시스턴트 요약 기준)

### 백엔드 — `src/server.ts` (`POST /api/sessions/archive`)
- 파일을 `chats/archive/`로 이동하기 **전에** `rememberedAt`을 기록(아카이브로 함께 이동).
- 이동 **후** 경로(`chats/archive/<id>.md`)를 입력으로 `memory-ingest` 잡을 큐잉.
  - **핵심 함정**: 보관은 트랜스크립트 파일을 곧 이동시키므로, ingest 입력 경로를 **이동 후 경로**로
    지정해야 한다. 이동 전 경로를 주면 ingest가 없는 파일을 가리키게 된다.
- 응답에 `remembered` 플래그 추가.
- **멱등 게이트**: 트랜스크립트가 있고 **아직 저장한 적 없거나 저장 후 대화가 더 이어진(변경된)**
  경우에만 ingest. 이미 최신 상태로 저장돼 있으면 건너뛴다(중복 ingest 방지). 판단은
  `rememberedAt` vs 트랜스크립트 변경 시각 비교로 추정.

### 프런트엔드 — `apps/web/index.html`
- 보관 버튼 툴팁을 "…장기 기억에 저장합니다"로 수정.
- 보관 후 안내 문구에 저장 여부 표시.
- `apps/web/dist`로 빌드(서버가 `dist`를 서빙하므로 빌드해야 반영).

### 검증
- 타입 체크 통과. 웹 빌드·서버 빌드 모두 갱신.
- 실행 중/대기 중인 대화 보관은 여전히 **409로 거부**(변경 없음).

## 반영·배포 주의

- 백엔드 변경은 **서버 재시작 후** 활성화. 어시스턴트는 자기 턴 안에서 재시작하면 출력·권한 채널이
  끊기므로([[self-hosted-agent-server-ops]]의 restart-kills-own-turn) **직접 재시작하지 않음**.
- 재배포 명령: `launchctl kickstart -k gui/$(id -u)/io.lampas.harness`
- 어시스턴트는 "이 개선은 코드에 남으므로 별도 장기 기억 저장은 안 하겠다"고 판단(코드=자기문서화).

## 결정·관찰

- **결정**: 보관 동작에 장기기억 저장을 통합한다. 단, 중복 ingest는 `rememberedAt` 게이트로 방지.
- 이로써 위키 저장 진입점이 (1)수동 🧠 버튼, (2)보관 🗄 자동, (3)야간 자동 ingest 잡 — 셋으로 늘어남.
  세 경로 모두 같은 `memory-ingest` 잡을 큐잉하며 `rememberedAt`/source 키로 중복을 막는다.
- 미확정: 재시작이 세션 종료 후 실제로 수행됐는지(트랜스크립트는 재시작 전 종료).
