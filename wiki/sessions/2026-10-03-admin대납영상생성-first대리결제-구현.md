# 2026-10-03 — admin 대납 영상생성 + First 대리결제 구현

`Tool: claude` 세션(10:50:23Z 시작, 작업 폴더 `lampas-system`). 서로 다른 두 "관리자가 대신
처리" 기능을 연달아 구현·운영 배포·커밋·푸시까지 완료한 운영 세션. 소스:
[[raw/conversations/2026-10-03-admin대납영상생성-first대리결제-구현]].

## 기능 1 — admin.lampas.io `/jobs` "대납 생성" (커밋 `6d3dfe8c`)

사용자 요청: "admin 에서 대신 결제해서 영상 생성 시도를 할 수있게 해줘". 어시스턴트가 이를
**"사용자 크레딧을 전혀 건드리지 않고 플랫폼이 Atlas 비용을 부담하는 방식"**("대납")으로
해석해 [[lampas-web-admin]]에 구현:

- `/jobs` 상단에 모델·길이·프롬프트·이미지 URL·추가 파라미터(JSON) 입력 폼 + "대납 생성" 버튼.
  초당 단가가 있는 모델은 예상 대납 크레딧을 미리 표시.
- `userId`(선택) — 입력하면 완료 시 그 사용자 갤러리에 저장, 비우면 job에 결과 URL만 남음.
- 실패 job에 "대납 재시도" 버튼 — 그 job의 모델·프롬프트·userId로 폼이 채워짐(일반 사용자
  요청 job은 입력 이미지 URL이 저장돼 있지 않아 직접 입력 필요).
- **기록 범위**: 크레딧 원장·사용 기록(파트너 수익 집계)에는 전혀 남지 않음. job 목록에
  source `ADMIN`으로만 표시, 대납 크레딧은 job metadata에만 저장(생성 직후 안내 문구에만 노출,
  job 카드에는 안 보임).
- API: `POST /v1/admin/ai/generate-video {userId?, request}`.
- 검증 범위: 유닛 테스트 통과 + 운영 라우트가 인증 없이 401로 응답하는 것까지만 확인.
  **실제 영상 생성은 시도하지 않음**(Atlas 비용 발생 우려로 보류).
- 동시 작업 중이던 [[lampas-agent]] 변경분은 이 커밋에 포함하지 않고 분리함.

## 기능 2 — admin.first.dalar.ai 주문 상세 "대리 결제" (커밋 `2fa984f5`)

사용자가 특정 주문 링크(`admin.first.dalar.ai/orders/b780750b-b722-4eb9-a1d2-eafc4647efac`)를
주며 "결제 처리를 할 수 있어야해 크레딧이 있는 경우에만"이라고 요청. 기능 1과 **반대로 동작**
— 주문자 **본인 크레딧에서 차감**(플랫폼 부담 아님), 일반 결제와 동일 규칙:

- 미결제 주문에서 버튼 클릭 → 확인 창 → 주문자 크레딧에서 주문 금액(이 상품 기본 5만, 가격
  변천사는 [[dalar-web-first]] "가격 체계" 절) 차감 후 제작 시작.
- **크레딧이 있을 때만 버튼 활성화**: 잔액이 주문 금액 미만이면 버튼이 꺼지고 "보유/필요/모자란
  크레딧"을 옆에 표시, 서버도 같은 조건으로 거부(클라이언트·서버 이중 가드).
- 그 밖의 조건: 시트가 완성된 결제 대기 주문만 가능, 이미 결제된 주문엔 버튼 자체가 안 보임.
- **기록**: 크레딧 원장에 "관리자 대리 결제"로 정상 기록됨(`createdBy: admin:first`) — 기능 1과
  달리 원장에 남는다는 점이 핵심 차이.
- 검증 범위: 유닛 테스트 통과 + 401 가드 확인까지만. **실제 결제는 눌러보지 않음**, 링크로 준
  주문(`b780750b…`)이 결제 대기 상태인지·주문자 잔액이 충분한지도 확인하지 않음(모자라면
  `/users`에서 선지급 후 누르라고 안내).

## 두 기능의 대비 — "대납" vs "대리결제"

같은 날 연달아 나온 두 기능이 "관리자가 대신 처리"라는 표면적 요청은 같지만 회계상 정반대다:

| | 대납 (기능 1, lampas admin) | 대리결제 (기능 2, First admin) |
|---|---|---|
| 비용 부담 | 플랫폼(회사) | 주문자 본인 크레딧 |
| 원장 기록 | 없음(job metadata만) | 있음(`관리자 대리 결제`) |
| 전제조건 | 없음(크레딧 무관) | 주문자 잔액 ≥ 금액 |

→ 일반화한 절차는 [[admin-initiated-payment-two-patterns]] 스킬로 추출.

## 열린 문제 — 세션 종료 시 어시스턴트가 직접 제기

1. **기능 1의 해석이 틀렸을 가능성**: 첫 요청("admin 에서 대신 결제해서 영상 생성")을 lampas
   admin 쪽으로 해석해 만들었는데, 바로 다음 요청이 실제로는 First 주문 결제였던 것을 보면
   첫 요청도 First 관련이었을 가능성이 있다. 어시스턴트가 "필요 없으면 제거하고 재배포하겠다"고
   확인을 요청한 채 세션이 끝남 — **사용자 응답 미확인**.
2. **배포 정책 충돌**: First 상품은 과거에 "컨펌 후 배포"를 요청받은 적이 있다고 어시스턴트가
   언급했으나, 이번엔 직전 메시지의 "마무리하고 배포·커밋·푸시" 일반 지시를 First 작업에도
   적용해 컨펌 없이 바로 배포했다. 이 "First는 컨펌 후 배포" 규칙은 이 세션 이전에 이 위키에
   별도로 기록된 적이 없어 **출처 미상 자기보고**로만 남긴다 — AI_CONTEXT.md의 기존 전역 규칙
   "배포까지 진행하면 항상 커밋한다"(2026-09-24 확정)와 상충 가능성이 있는 제품별 예외로 플래그.
