# 2026-07-16 — 람파스 개발일지 블로그 초안 작성 + SEO 최적화

`[[progdesigner]]`가 "지난주까지 진행한 내용을 바탕으로 하네스와 관련한 블로그 글을 하나 작성해봐"라고
요청(04:28~04:30, 2왕복). [[naver-blog-tag-seo]] 스킬의 기존 절차(사용자가 붙여넣은 **기존 발행 글**의
태그를 추천)와 달리, 이번엔 **아직 존재하지 않는 새 글을 어시스턴트가 처음부터 작성**한 사례.

## 진행
1. 어시스턴트가 **지난 한 주(7/9~7/16) git 커밋 47개**를 직접 조회해 4개 주제로 클러스터링:
   ① 실시간 음성 입력 완성([[realtime-voice-mic-buffer-before-connect]]),
   ② Auto 모델 자동 선택([[model-selection]]),
   ③ 대화 관리 UX 개선([[destructive-action-inline-confirm]]),
   ④ 기억 시스템 자동화([[long-term-memory-architecture]]).
   → 이 클러스터링을 바탕으로 개발일지 톤의 초안을 작성(네이버 에디터 제약상 소제목은 `◆` 기호로 대체,
   [[naver-blog-mcp]]의 plaintext-only 제약과 동일).
2. 사용자가 "SEO에 최적화되도록 수정해줘" 요청 → 제목·도입부·소제목에 키워드(`개인 AI 비서`,
   `Claude 기반 AI 에이전트`, `실시간 음성 입력` 등)를 자연스럽게 녹인 개정판 + **[[naver-blog-tag-seo]]
   절차대로 태그 30개**(대표어/핵심주제어/롱테일 3구간) 생성.
3. 어시스턴트가 발행 여부·톤 조정 여부를 되물으며 종료 — **`naver_blog_create_post`로 발행 가능하다고
   제안만 했을 뿐, 이 트랜스크립트 안에서 실제 발행이 확인되지는 않음** (발행 승인/실행 로그 없음).

## 새로 드러난 사실
- 이번 글의 대상은 기존 연재([[2026-07-13-블로그-ai기억글-해시태그]]의 "AI 장기기억 만드는 법")와 달리
  **주간 개발일지** 성격 — `study-ai-what` 연재가 아키텍처 소개 1편에서 **정기 개발일지 형식으로 확장**되는 정황.
  - **본문 중 "다음 주 계획"이 능동 기억 조회(recall) 완성 + Tailscale 원격 접속 안정화라고 명시** —
    기존 [[long-term-memory-architecture]]의 "방법 C(능동 조회) 미완" 관찰과 일치.
  - **"외부 MCP 서버(네이버 블로그, Threads)를 람파스 세션에 노출해 블로그 글을 그 안에서 바로 쓰고
    발행"**한다고 서술 — [[harness-mcp-bridge]]에 이미 기록된 다중 MCP 노출 사실의 실사용 확인.
    Threads MCP는 별도 엔티티 문서화는 아직 없음(구체 활용 사례 미확보).
- 절차 관점에서 **git 커밋 로그를 직접 읽어 블로그 개발일지를 작성하는 패턴**이 처음 관찰됨 →
  스킬 신설: [[dev-log-blog-from-git-log]].
