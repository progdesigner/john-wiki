# 2026-09-29 — PostHog 구축 및 연동

`Tool: codex`, 작업 폴더 `lampas-system`(2026-09-29T20:35:45Z 시작).

## 요청
"`us.posthog.com`에 로그인해서 PostHog로 `first.dalar.ai`부터 시작해 모든 서비스의 사용자 여정을
분석하게 해줘, 특히 결제까지 가는 서비스를 분석할 수 있게." — [[dalar-web-first]]를 시작점으로 전체
`lampas-system` 모노레포 서비스에 결제 전환 분석 체계를 요구한 세션.

## 진행 경과

1. **기존 계측 확인**: First의 방문→제작→결제 이벤트와 Dalar·Lampas 공통 GA4 계측이 이미 준비돼
   있음을 먼저 확인 — PostHog는 이 기존 이벤트 구조에 올라타는 형태로 설계됨.
2. **Google 로그인 장벽(1차)**: PostHog Google 로그인 화면은 열었으나 브라우저에 로그인된 계정이
   없고, **브라우저 도구가 비밀번호 입력을 지원하지 않아** 사용자에게 직접 로그인을 요청 — 그동안
   연동 코드만 먼저 준비.
3. **공통 연동 코드 선반영**: Dalar·Lampas 웹 **30개**가 쓰는 공통 계측 모듈에 PostHog 연결 코드
   추가. First·결제 페이지는 서버가 확인한 동일 사용자 ID로 로그인 전후 여정을 연결하도록 설계.
   이 시점엔 프로젝트 키가 없어 수집은 비활성.
4. **Google 로그인 장벽(2차 — 추가 본인 인증)**: 사용자가 Gmail 로그인은 했으나 "사이트와 링크가
   끊긴 듯"이라 제보 → 재확인 결과 브라우저 연결·Gmail 로그인은 정상이었고, Google이 **패스키·
   휴대전화 승인·OTP 중 하나의 추가 본인 인증**을 요구하는 상태였음. 다시 사용자에게 직접 완료를
   요청.
5. **로그인 완료 후 프로젝트 연결**: 사용자가 "로그인 완료해써" 확인 → PostHog 로그인·미국 리전
   프로젝트(이벤트 없는 새 프로젝트) 확인, First·결제 페이지 연결 + 방문→결제 시작→결제 완료·제작
   단계 이탈을 볼 수 있는 구조로 설정 진행.
6. **배포**: 운영 반영은 저장소 배포 스크립트 사용(First 소스에 포함된 기존 변경분도 함께 반영).
   First·결제 웹 배포 완료 후 실제 방문 이벤트 수신 확인, 구매·제작 퍼널 3개 + 매출 차트를 PostHog에
   구성.
7. **전체 서비스로 확장**: Dalar·Lampas·Talk([[toktalk]])·Iileex 웹에도 공통 계측 반영. Talk의
   자체 결제 흐름도 함께 점검. 로그아웃 시 사용자 식별 해제, 여러 경로의 캐시 갱신도 보완.
8. **최종 상태**: `deploy.json`(배포 설정)이 있는 **웹 36개 전체**에 공통 분석 코드 반영 완료.
   First 전용 대시보드 + 전체 서비스 대시보드(방문·이동 경로·결제 전환·결제 실패·매출 비교) 저장.
   First·결제 화면·Talk·Music·Iileex 실제 이벤트 수신 확인.

## 미해결·제외 범위
- **실제 결제 완료 수신은 검증되지 않음** — 결제 완료는 서버 승인 성공 기준으로 수집하도록만
  만들어뒀고, 실제 유료 결제를 발생시켜 테스트하지는 않았다. 데이터는 이제부터 쌓인다.
- **토스(Toss) 내부 미니앱 3개는 이번 웹 적용 범위에서 제외**됨(`talk-app-toss-*` 등 — 웹 기반
  계측만 36개 대상이었고 Toss 미니앱 전용 트래킹은 별도 작업 필요).
- 구매 중복 집계 방지, URL의 토큰·개인정보 제거는 테스트 10개로 검증됨(상세 구현은 소스에 코드
  없이 서술만 있어 미확인).

## 브라우저 자동화 한계 — 세 번째 독립 재현
Google OAuth 로그인(비밀번호 입력 불가 + 추가 본인 인증/OTP)에 막혀 사람에게 위임한 패턴은
[[lampas-browser]]에서 이미 두 차례(Meta 개발자 콘솔, 카카오 개발자 콘솔) 확인된
[[browser-automation-human-handoff-for-blocked-ui]] 스킬과 동일하다. 다만 이 세션은 **`Tool: codex`
자체 브라우저 도구**(lampas-harness의 `apps/browser`/`lampas-browser`가 아님)에서 일어난 사례라,
이 한계가 특정 구현(lampas-browser)이 아니라 **AI가 조작하는 브라우저 자동화 도구 전반의 구조적
한계**임을 도구를 바꿔서도 재확인한 셈이다.
