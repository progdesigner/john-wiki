# 2026-07-18 — web-ai 배포·등록플로우 2단계화·사진 우선 분류 구현

운영+구현 세션.

## 1) "배포해줘 web ai" (05:57~05:58)
`lampas-web-ai` 단독 배포. pnpm이 PATH에 없어 corepack shim(`pnpm@10.32.1`)으로 우회 →
`deploy-web.sh lampas-web-ai` 실행 → 빌드(94 모듈, JS 327KB/gzip 100.6KB) → `s3://lampas.io/ai/production/`
업로드 → CloudFront(`E2CVB6NRDH40V1`) `/*` 무효화. 정리 중 corepack 실행 과정에서 `ln -sf`로 잘못 생긴
`.bin` 심볼릭 링크를 발견·제거 — 기존 [[deploy-sandbox-pnpm-shim]] 절차에 없던 새 함정 사례.

## 2) "최신 코드로 업데이트" → git pull 확인 (06:03)
사용자 지시가 모호("최신 코드로 업데이트")해 어시스턴트가 4가지 후보(git pull/pnpm update/특정
배포/기타)로 명확화 요청 → 사용자가 git pull 선택. Pull 결과 주요 변경:
- 앱 디렉터리 **`lampas-app-toss` → `lampas-app-photobooth`** 이름 변경(기능 명확화, 토스 미니앱이
  실제로는 포토부스 앱).
- 백엔드 **Space 모듈 확장**(DTO·컨트롤러·서비스 구현 추가) — [[lampas-studio]]가 2026-07-15~16에
  설계·구현한 Space 엔티티의 후속 확장.
- `lampas-web-ai`: `actorFlow.ts` 대폭 확장(781줄 증가), 채팅 저장소·타입 개선.
- `lampas-web-www`: landing 페이지 전면 재디자인(기존 컴포넌트 제거 → `landing/` 폴더 신규).
- `lampas-web-product`: `SpaceCreation` 컴포넌트 개선.
- 설계 문서 3건 추가(`docs/superpowers/specs/`): landing 재디자인, web-ai 온보딩, www entity landing.

## 3) "업데이트 된 건 배포 해 줘" — 4앱 순차 배포 (06:04~06:07)
순서: **lampas-api**(PM2 재시작, Space 모듈 백엔드 반영) → **lampas-web-ai**(S3+CloudFront, actorFlow
확장 반영) → **lampas-web-www**(S3+CloudFront, landing 재디자인 반영) → **lampas-app-photobooth**(토스
미니앱 빌드+배포, 구 lampas-app-toss).

**lampas-web-product는 이번에도 배포 제외** — `deploy-web.sh` 지원 목록에 없고 S3/CloudFront 인프라
미발급(기존 이슈, [[2026-07-16-lampas-web-product-신규앱-구현]] 참고).

**Space 백엔드는 배포됐지만 Space는 아직 완전히 서비스되지 않음**: [[lampas-studio]] 메모(2026-07-15~16
세션)엔 "Space 3앱(API+SDK+web-ai) 모두 배포 필요"라 기록돼 있었는데, 이번에 배포된 건 API뿐이고
**Space 생성 UI가 있는 `lampas-web-sdk`는 이번 pull·배포 대상에 등장하지 않음** — 여전히 미배포로 추정
(이 세션 소스로는 확인 불가, 다음 세션에서 재확인 필요).

## 4) "web-ai 새 대화를 하면 등록하기/촬영하기 두개로만 나뉘어 시작하고" (07:45~07:49)
`actorFlow.ts` 새 대화 시작 구조를 2단계로 변경 (배포는 이 단계에서 하지 않음, 타입체크·빌드만 통과):
- 새 대화 시작 시 **📝 등록하기 / 📸 촬영하기** 2개 칩만 표시.
- **등록하기** → "무엇을 등록할까요?" + 기존 3개 메뉴(✨ Actor / 📦 Object / 🏞 Space 만들기).
- 텍스트 "등록"/"만들어줘" 입력도 동일 분기, "액터 만들어줘" 등 대상이 명확한 입력·사진 업로드 자동
  분기(제품→Object, 공간→Space)는 기존 동작 유지.
- 플로우 종료·취소·세션 복원 시 칩도 2개 구성으로 통일.

## 5) "등록하기 에 사진만 먼저 등록하면 Actor/Object/Space 인지 구분해서 분석" (07:50~07:58)
등록하기를 **"사진 먼저 → Gemini Vision 자동 분류 → 해당 등록 플로우 연결"** 구조로 재구현. 아직
커밋·배포 전 상태로 세션 종료(배포는 다음 항목 6에서 진행).

**새 동작 흐름**
1. 등록하기 → "등록할 사진을 올려주세요 📷" 안내(사진 없이 진행할 Actor/Object/Space 선택 칩도 병기).
2. 사진 업로드 → Gemini Vision이 인물(Actor)/제품(Object)/공간(Space) 중 분류 + 한 문장 근거.
3. 분류 결과로 자동 라우팅:
   - **Actor** → 사진을 닮은꼴 레퍼런스로 자동 첨부(반영도 게이지) + 이름부터 묻는 시작 — **이 사진 기반
     Actor 시작 경로는 이번에 신규**.
   - **Object/Space** → 기존 사진 업로드 시작 플로우(특성 분석→이름 입력)로 연결.
4. 사진과 함께 "공간이야"/"액터로 등록해줘" 등 키워드를 적으면 분류 API를 건너뛰고 직행.
5. 분류 API 실패 시 사진을 잃지 않고 수동 선택 칩으로 폴백.

**변경 파일**
- `lampas-api` — `GeminiService.classifyRegistrationSubject`(비전 분류) + `POST
  /actors/classify-registration-photo` 엔드포인트·DTO 신설. 타입체크 중 로컬 Prisma 클라이언트가
  오래돼 있던 것을 `prisma generate` 재실행으로 해결(기존에도 반복된 이슈).
- `lampas-web-ai` — `api.ts`에 `classifyRegistrationPhoto` 추가, `actorFlow.ts`에 분류 연결·
  `startActorFlowWithPhoto`·실패 폴백 추가. 첫 인사말도 "사진을 올리면 자동으로 구분해 등록을
  시작해요"로 갱신.

이 기능은 **API와 web-ai 둘 다 배포해야 완전 동작**(웹만 배포하면 분류 실패 시 수동 선택 폴백으로만
동작).

## 6) "배포해줘" (14:04~14:06)
항목 4·5(2칩 시작 메뉴 + 사진 우선 분류 플로우)를 API→web-ai 순으로 배포:
- **lampas-api** — rsync 후 pm2 재시작, `lampas-api` 프로세스 online 확인. `POST
  /actors/classify-registration-photo` 엔드포인트 활성화.
- **lampas-web-ai** — S3 업로드 + CloudFront 전체 무효화(`/*`), 1~2분 후 반영.

변경분은 이 세션 종료 시점까지 **git 커밋 전** 상태(어시스턴트가 커밋 필요 여부를 사용자에게 안내만
하고 세션 종료) — 다음 세션에서 커밋 여부 확인 필요.
