# 2026-09-20~24 — 하네스 터미널: Jev 검색 연동 + Codex 질문 선택 UI + 세션 제한/보관종료 버그 + 파일 첨부

(`logs/terminals/archive/92b53a0b-90a9-4da4-a0a0-e265a1e4e6cb.md`에서 회수, 소스는 Codex 자체 rollout
jsonl). `environment_context`가 2026-09-20 → 09-21 → 09-24로 세 번 갱신되며 같은 터미널 하나가 나흘에

UI가 아니라 Codex/Claude CLI를 직접 띄우는 터미널 화면).

## 1. (09-20) Jev/TypeSafe 기반 검색 연동
사용자가 TypeSafe API 키 + 공식 문서 링크를 주며 "이 키로 하네스 검색을 하게 해달라"고 요청. 어시스턴트가
문서를 확인해 **TypeSafe는 웹 검색 API가 아니라 주어진 문서의 관련성을 평가하는 API**임을 먼저 정정하고,
"기존 DuckDuckGo 검색 결과를 이 키로 재정렬할지, 다른 검색 서비스를 의도한 것인지" 역질문 — 코드·키 설정
변경 전에 확인부터 구하는 절차를 지켰다. 사용자가 `github.com/superagents-lab/jev-search` 참고 저장소를
지목하자, 그 구현이 **Jev가 검색 의도 해석·결과 평가를 맡고 실제 검색은 Search1API가 수행**하는 구조임을
확인하고 하네스에 동일 패턴 적용: 기본은 별도 키 없이 DuckDuckGo, `Search1API` 키를 설정하면 그쪽으로 전환,
제공된 TypeSafe 키로 검색 의도 분석·관련성 재정렬을 연결. 제공된 키로 **실제 검색 호출까지 확인**. 새
검색 배선은 이후 새로 열리거나 재개되는 Codex/Claude 터미널부터 적용(기존 실행 중 세션은 재시작 전까지
구버전 유지).

- **같은 날, 다른 저장소의 비슷하지만 별개인 Jev/TypeSafe 사용**: `lampas-system`
  ([[2026-09-20-jev-typesafe-어댑터-dalar의도분류-sportswiki게이트-구현]])에서도 같은 날 TypeSafe 키를
  붙이는 작업이 있었지만, 그쪽은 `POST /v1/ai/systemone` typed 분류 게이트웨이([[jev-typed-classification]])
  방식이고 이 세션은 **jev-search 패턴(문서 관련성 재정렬 + 별도 검색 프로바이더)** 을 하네스 자체의
  에이전트 웹 검색 도구에 적용한 것 — 저장소도 다르고(하네스 vs lampas-system) 통합 방식도 다르다. 우연히
  같은 날 같은 벤더 키가 두 곳에 각각 연결된 경우.

## 2. (09-20) Codex 질문 선택 UI
"codex에서 질문 옵션이 뜨면 직접 선택할 수 있는 UI를 만들어달라"는 요청으로, Codex CLI가 터미널 화면에
띄우는 대화형 질문+선택지를 하네스가 인식해 **클릭 가능한 버튼**으로 표시하고, 클릭 시 해당 터미널
세션에 응답을 전달하도록 구현. 질문이 이미 바뀌었거나 중복 클릭된 요청은 서버에서 차단. 모바일 화면
클릭 동작까지 검증. 검색 연동과 함께 **테스트 67개 + 빌드 통과**로 마무리, 실행 중이던 터미널 12개를
보호하기 위해 배포는 유휴 시 자동 재시작으로 예약.

## 3. (09-20) "새 세션이 안 열린다" → 동시 세션 상한 12개 진단
사용자가 "Codex로 새 세션이 시작 안 된다"며 원인이 (a) 위 하네스 작업 중이라 그런지 (b) Codex 자체
업데이트 때문인지 물음. 어시스턴트가 로그·실행 인자를 직접 확인해 **하네스의 동시 실행 세션 상한
12개**가 원인임을 특정 — 실제 오류 메시지("실행 중인 세션이 12개입니다. 먼저 세션을 종료하세요")까지
인용해 근거로 제시. 결론: **Codex 업데이트도, 방금 한 하네스 수정 작업도 원인이 아니다** — 하네스가
Codex 실행 자체를 사전에 차단한 것. 중요한 세부사항: **입력을 기다리며(대기 중인) 열려 있는 세션도
"실행 중"으로 카운트**된다 — 단순히 활성 작업 중인 세션 수만 세는 게 아니다. 진단 과정에서 기존 세션은
임의로 종료하지 않는 절제를 지켰다.
- 일반화: 새 CLI/에이전트 세션이 원인 불명으로 안 열릴 때, 도구 자체의 버전이나 직전 작업 변경을
  의심하기 전에 **호스트가 스스로 건 동시성 상한**부터 확인하는 게 빠르다 — 이 진단 패턴은
  [[self-imposed-vs-provider-limit-diagnosis]](결제/한도 케이스)와 같은 계열이지만 대상이 외부
  제공자가 아니라 **자체 세션 슬롯**이라는 점이 다르다.

## 4. (09-20) 보관(archive) → 세션 종료 연동 — 1차 수정
사용자가 "대화를 보관하면 세션도 닫혀야 하는데 열려 있는 것 같다"고 제보, "보관하면 실제로 닫히도록
고치고 지금 대화 중인 세션 말고는 모두 닫아달라" 요청. 조사 결과 **보관은 목록에서 숨기기만 하고
PTY 프로세스는 계속 실행되게 돼 있던** 것이 원인. 수정: 보관 시 프로세스도 함께 종료, 복구 시엔
자동 재실행하지 않고 "이어서 실행" 버튼으로만 재개. 현재 대화 세션을 정확히 식별해 보존한 뒤 **나머지
11개 세션을 모두 종료**. 테스트 11개·브라우저 검증 통과, 웹 화면만 바뀌어 새로고침으로 즉시 반영(재시작
불필요).

## 5. (09-21) 파일 첨부(이미지 외) 추가
"이미지 첨부 말고 파일 첨부도 가능하게 해달라"는 요청으로, 기존 이미지 첨부 UI(`+` 버튼·드래그·붙여넣기)를
PDF·문서·코드·압축파일 등 **일반 파일**까지 받도록 확장. 파일은 변환 없이 원본 그대로 작업 폴더에 저장해
에이전트(Codex/Claude 세션)에 전달, 이미지 미리보기는 그대로 유지. 제한은 **이미지+파일 합쳐 최대 4개,
파일당 10MB**. 테스트 69개·브라우저 검증 통과했으나 **서버 재시작 필요** — 실행 중 세션 7개를 보호하기
위해 기존 자동 재시작 예약을 그대로 유지(이 시점엔 재시작이 실제로 일어나지 않아 8번 항목의 버그로
이어짐).

## 6. (09-24) 보관→세션종료 연동 — 회귀 재발 → 근본 수정(2차)
"여전히 보관할 때 세션이 종료되지 않는 것 같다"는 재제보. 조사 결과 **4번 항목의 수정이 실제로는 종료
요청만 보내고 응답(실제 종료 완료)을 기다리지 않은 채 곧바로 보관을 진행**하고 있었다 — 이건 위
[[self-hosted-agent-server-ops]] 함정 2가 2026-09-07 세션에서 코드 분석만으로 예측했던 정확히 그
레이스 컨디션("`kill()`은 신호만 보내고 완료를 기다리지 않는다")이 실제 버그로 재현된 사례다. 이번엔
**종료가 실제로 확인된 뒤에만 보관을 커밋**하도록 수정 — 종료 확인에 실패하면 보관하지 않고 오류
표시. 서버 쪽도 "종료+화면 저장이 끝난 뒤에만 보관 상태 기록"으로 동일 순서 적용. 보관된 채 실행
중이던 세션 2개를 소급 종료(종료 후 0개 확인). → 재사용 가능한 절차로 신규 스킬
[[verify-effect-before-state-commit]] 추출.

## 7. (09-24) Shift+Enter / Alt+↑ 질문 열기 버튼
사용자가 스크린샷 첨부와 함께 "Shift+Enter도 키로 입력할 수 있게 해달라" 요청. 터미널 입력 버튼에
**Shift+Enter**(조합키 입력) 추가. 화면에 이미 있던 "질문 열기" 단축키가 `Alt+↑`임을 확인하고, 모바일에서
누를 수 있도록 **Alt+↑ 버튼**도 함께 추가. 모바일 버튼 동작 검증 후 새로고침만으로 반영.

## 8. (09-24) 파일 첨부 안 됨 → 서버 배포 드리프트 발견 → 재시작
"파일 첨부가 안 된다"는 제보로 5번 기능을 재점검 — **화면(클라이언트)만 최신이고, 서버는 파일 첨부를
지원 안 하는 이전 버전으로 계속 실행 중**이었다. 5번 항목에서 걸어둔 "유휴 시 자동 재시작" 예약이
**열린 세션들 때문에 한 번도 발동하지 않은 채** 쌓여 있었던 것 — [[self-hosted-agent-server-ops]] 함정
1(옛 프로세스가 최신 코드를 안 읽음)의 또 다른 변종. 사용자에게 "실행 중 12개 세션이 끊긴다"는 영향
범위를 명시하고 재시작 여부를 확인받은 뒤(앞서 "현재 대화는 유지해달라"던 요청과 상충 가능성 고려),
승인받아 **10초 지연 재시작**을 실행([[detach-long-job-nohup]] 패턴) — 재시작 후 파일 첨부 활성화
자동 확인까지 포함. 세션은 재시작 실행 직후 종료돼 실제 반영 확인은 소스에 없음.
