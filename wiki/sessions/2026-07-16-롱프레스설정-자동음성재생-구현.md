# 2026-07-16 — 배경 롱프레스 설정 열기 + 자동 음성 재생(브라우저 TTS) 구현

`[[lampas-harness]]` 웹 채팅에 두 가지 기능을 요청 → 구현 → 커밋(`3d16ed5`) → origin/main
push까지 한 세션 안에 완료(03:38:47~03:42:08, `apps/web/index.html`만 변경).

## 요청
1. 채팅의 텍스트 없는 빈 배경을 꾹 오래 누르면 설정 모달이 뜨게.
2. 설정에 "자동 음성 재생" 토글 추가 — 켜져 있으면 람파스가 답변을 마칠 때 그 내용을 읽어줌.

## 구현

### 1. 배경 롱프레스 → 설정 열기
- 채팅의 빈 배경(메시지·버튼·입력창이 아닌 영역)을 약 0.5초간 누르면 설정 모달 오픈.
- 누른 채 10px 이상 움직이면 스크롤 제스처로 간주해 발동 취소. 설정이 이미 열려 있으면 무시.
- 메커니즘은 [[destructive-action-inline-confirm]] 변형 B(롱프레스+8px 이동취소)와 동일한
  pointerdown 타이머 패턴이지만, **이 트리거는 되돌리기 쉬운 비파괴적 동작(설정 열기)이라 확인창
  없이 즉시 실행** — 같은 제스처 메커니즘이 파괴적 액션 확인용과 비파괴적 네비게이션 열기용
  둘 다에 재사용될 수 있음을 보여준 사례.

### 2. 자동 음성 재생 토글 (브라우저 Web Speech API)
- 설정 모달 "소통 언어" 아래에 **"자동 음성 재생"** 섹션 추가. 체크 상태는
  `localStorage`에 저장([[localstorage-ui-preference-persistence]] 패턴 재사용).
- 켜져 있으면 `done` 이벤트(봇 응답 완료 시점)에 `bot._md` 원문을 브라우저 내장 음성 합성
  (`SpeechSynthesis`/Web Speech API)으로 읽음 — **서버·API 비용 없음**.
- 읽기 전 마크다운 기호·링크·코드 블록을 걷어내 다듬고, 한국어(`ko-KR`) 음성 우선 선택.
- **지금 보고 있는 대화(`viewing()`)의 답변만** 읽음(백그라운드 대화 제외), 토글을 끄면 즉시 정지.
- 알려진 제약: 일부 브라우저는 페이지 로드 직후 `getVoices()`가 빈 배열일 수 있으나, `lang=ko-KR`
  지정만으로 브라우저가 적절한 음성을 자동 선택해 재생 자체는 문제없음.

## 관찰 — 앞선 tts-stream(ElevenLabs) 시도와의 관계
같은 날 약 1시간 전 세션([[2026-07-16-tts-stream-elevenlabs-구현착수]], 02:42~02:47)에서 사용자가
"ElevenLabs로 봇 메시지를 실시간 읽어주는 `tts-stream` 기능"을 요청했으나, 참고 예시(`dbs/talk-system`)
접근 불가로 표준 API 구현에 착수한 직후 **완료 여부 미확인 상태로 소스가 끝났었다**.

이번 세션의 요청은 그 기능과 **목표는 같지만(봇 답변을 소리로 읽어주기) 방식은 다르다** —
ElevenLabs 언급이 전혀 없고, 브라우저 내장 Web Speech API로 별개의 경량 구현을 완성·커밋까지
마쳤다. 두 세션의 관계로 가능한 해석 두 가지, 소스만으로는 확정 불가:
- (a) 사용자가 ElevenLabs 방식을 포기하고 무료·경량 대안으로 방향을 바꿨다.
- (b) 사용자가 두 기능을 별개(고품질 유료 TTS vs 기본 무료 TTS)로 원해 둘 다 요청했다.

**확정 사실**: 이 세션의 브라우저 TTS 자동재생은 **구현·빌드·커밋·push까지 완료**됨(`3d16ed5`).
ElevenLabs `tts-stream`은 여전히 **구현 여부 미확인**으로 남아 있다 — 재개 시 `src/server.ts`에
ElevenLabs 관련 라우트가 있는지 먼저 확인할 것.
