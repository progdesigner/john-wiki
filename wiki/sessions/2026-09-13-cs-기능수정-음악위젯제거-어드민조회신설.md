# CS 기능 수정 — 배경음악 어시스턴트 제거 + lampas-web-admin CS 조회 화면 신설

`Tool: claude`, 2026-09-13T13:48:32Z 시작, 작업 디렉터리 `lampas-system`([[lampas-studio]]).
소스: `raw/conversations/2026-09-13-cs-기능수정-음악위젯제거-어드민조회신설.md`
(원본 경로: `lampas-harness/logs/terminals/archive/02e30983-77b0-4373-aa0e-332e9bb41a56.md`)

## 요청
사용자가 CS 채팅 화면 스크린샷(첨부 이미지)에서 특정 영역(배경음악 재생 위젯)을 가리키며 "이 영역을
제거하는 방향으로 CS 기능을 다시 만들고, `lampas-web-admin`에서 CS 문의 내용을 볼 수 있게 해달라"고
요청.

## 조사 (서브에이전트 병렬 탐색)
착수 전 "Explore CS feature and admin structure" 에이전트를 먼저 띄워 전체 구조를 조사 —
[[parallel-survey-before-feature-gap-analysis]] 패턴과 동일하게 **삭제/구현 전에 조사를 먼저, 한 번에
끝내는** 접근. 조사 결과 핵심 발견 2가지:

1. **CS 배경음악 어시스턴트**(`apps/lampas-api/src/modules/cs/cs-music-assistant.service.ts`)가
   채팅 메시지를 키워드 프리필터→Grok 인텐트 파싱(`SET_GENRE`/`GENERATE`/`NONE`)으로 분석해 자동으로
   음악을 생성·게시하고 있었음. 세션당 생성 상한 3회. 프론트 위젯은
   `apps/lampas-web-cs/src/components/MusicPlayer.tsx` 단 하나뿐 — [[lampas-web-music]] 모듈
   (`MusicService.publish`)의 소비자 중 하나(`source:'CS_CHAT'`)였을 뿐, `music` 모듈 자체나 수동 재생
   위젯과는 결합이 약해 분리 제거가 쉬움.
2. **CS 관리자 API가 이미 존재하지만 web-admin이 재사용할 수 없는 구조**였음 — `cs.controller.ts`의
   `/cs/admin/sessions*`가 `AdminTokenGuard`(CS 전용 `CS_ADMIN_TOKEN` 단순 Bearer 대조)로 보호되고
   있어, web-admin이 쓰는 로그인 JWT `AdminGuard`([[lampas-web-admin]])를 받아들이지 않음. 반면
   `music` 모듈은 이미 `admin-music.controller.ts`가 `AdminGuard`를 쓰는 정확히 같은 패턴으로
   web-admin과 통합돼 있어, 이 CS 조회 화면도 그 패턴을 그대로 따르기로 결정 →
   [[admin-guard-precedent-reuse]] 스킬로 추출.

## 구현 — 배경음악 어시스턴트 완전 제거
[[full-stack-feature-removal-audit]] 절차와 동일한 순서(UI→API→백엔드→저장소 필드)로 진행:
- 백엔드: `cs-music-assistant.service.ts` 파일 삭제, `cs.module.ts`에서 provider/import 3종
  (`CsMusicAssistantService`/`AiModule`/`MusicModule`/`GrokModule` 중 CS 전용 부분) 제거,
  `cs.controller.ts`의 fire-and-forget 호출 1줄과 생성자 주입 제거, `cs.service.ts`의
  `setMusicGenre`/`incrementMusicGenCount` 메서드, `cs.types.ts`의 `musicGenre`/`musicGenCount`
  필드 정리.
- 프론트(`apps/lampas-web-cs`): `MusicPlayer.tsx`·`lib/music.ts` 삭제, `App.tsx`의 마운트 라인·
  `ChatRoom.tsx`의 `musicGenre` 리렌더 감지 제거, `lib/api.ts`의 `musicGenre` 필드 제거.
- `music` 모듈 자체(`MusicService.publish`, `GET /music/tracks`)는 건드리지 않음 —
  [[lampas-web-music]]이 독립적으로 계속 사용.

## 구현 — lampas-web-admin CS 조회 화면 신설
기존 `music`/`reviews` 모듈과 동일한 `AdminGuard`(관리자 로그인 JWT) 패턴으로 신규 `admin/cs/*`
컨트롤러(엔드포인트)를 새로 만듦(레거시 `CS_ADMIN_TOKEN` 가드 컨트롤러는 그대로 두고 신규 경로 추가한
것으로 보임 — 레거시 경로 폐기 여부는 소스에 명시 안 됨, 확인 필요).
`apps/lampas-web-admin`에:
- 타입 추가, `lib/api.ts`에 CS API 함수(파일 끝 smoke-run 섹션 근처에 추가),
- `CsSessionsPage.tsx`(목록) · `CsSessionDetailPage.tsx`(상세+답장) 신설 — 기존
  `MusicTracksPage.tsx`/`DisputesPage.tsx`를 템플릿으로 재사용(`useState`+`useCallback reload`+
  로딩/에러 패턴),
- 라우팅·상단 네비게이션에 "CS 문의" 메뉴 추가(`/cs`, `/cs/:id`).

## 검증·배포
- `lampas-api` 빌드·테스트 통과, `lampas-web-cs`·`lampas-web-admin` 빌드 통과.
- 로컬: 세션 생성 → "재즈 틀어줘" 전송(음악 반응 없음 확인) → 관리자 API로 목록/상세 조회·답장까지
  curl로 실제 검증.
- 배포 순서: `lampas-api` → `lampas-web-cs`(cs.lampas.io) → `lampas-web-admin`(admin.lampas.io),
  프로덕션 상태 확인까지 완료.
- git status에 있던 `lampas-web-scenario` 변경분은 무관한 기존 작업이라 건드리지 않음(다른 진행 중
  작업 보존 판단).

## 위키에 새로 드러난 사실
- `lampas-web-cs`(`cs.lampas.io`)·`lampas-web-admin`이 [[lampas-studio]] AGENTS.md 9앱 목록에
  이름만 있었던 상태에서 **이 세션으로 첫 상세 노출** → 각각 독립 엔티티 페이지 신설
  ([[lampas-web-cs]], [[lampas-web-admin]]).
- CS 세션 데이터는 DB 없이 `data/cs-store.json`(`CS_DATA_DIR` env, 300ms debounce flush)에
  저장 — `CsSession`/`CsMessage` 두 배열만 있는 단순 구조, [[lampas-studio]] 메인 도메인의
  PostgreSQL/MySQL 모순([[lampas-studio]] 참고)과 무관한 별도 저장 방식.
