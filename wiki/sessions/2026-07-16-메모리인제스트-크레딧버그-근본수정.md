# 2026-07-16 — memory-ingest 크레딧 버그 근본 수정 + 실패 35건 재처리

`[[progdesigner]]`가 "대화를 보관하면 위키에 저장되지 않는 거 같다"고 제보한 데서 시작된 세션(02:42~02:48 UTC).
[[long-term-memory-architecture]]가 2026-07-15에 관찰만 하고 미해결로 남겨뒀던 "API 크레딧 소진이
`memory-ingest`도 실패시킨다"는 문제의 **근본 원인 규명과 실제 수정**이 이뤄진 세션이다.

## 무슨 일이 있었나

1. **제보** — 보관 버튼을 눌러도 위키에 안 쌓이는 것 같다.
2. **원인 규명** — `queue/failed/`를 확인해 오늘(07-16) 08:33 이후 `memory-ingest` 잡이 전부
   `"Credit balance is too low"`로 실패 중임을 발견. 보관 버튼 자체(enqueue)는 정상 — 큐 작업을
   **실행**하는 `src/runner.ts`가 문제였다.
   - `runner.ts`가 Claude Agent SDK 호출 시 크레딧 0인 `ANTHROPIC_API_KEY`를 **그대로 상속**해 API
     종량 과금으로 시도하다 죽음.
   - 반면 채팅창 인터랙티브 대화는 `server.ts`의 `claudeAuthEnv()`가 이 키를 명시적으로 지워
     구독(OAuth) 과금으로 강제하기 때문에 멀쩡했다 — **큐 작업 실행 경로에만 이 처리가 빠져 있었다.**
   - 오늘 07:27 이후 **보관한 대화 35건 전부**가 이 이유로 `queue/failed/`에 쌓여 위키에 못 들어감.
3. **수정 적용**
   - `src/runner.ts` — 큐 작업 실행 시에도 `ANTHROPIC_API_KEY`를 지우고 구독 과금을 강제하도록 수정,
     빌드 완료(`claudeAuthEnv()`와 동등한 처리를 실행 경로에도 적용).
   - `jobs/memory-ingest-daily.job.json` — 매일 05:30 자동 실행되는 안전망 잡이 `chats/` **최상위만**
     훑고 `chats/archive/`는 빠뜨리고 있던 것을 확장 — 이제 보관된 대화도 훑는다. 앞으로 보관 시점
     ingest가 또 실패해도 다음날 새벽 안전망이 다시 저장한다.
4. **재시작 확인 요청** — 수정 반영에는 큐 데몬(`io.lampas.harness.daemon`) 재시작이 필요한데, 이
   데몬이 **지금 이 채팅을 서빙하는 바로 그 프로세스**라 재시작 전에 사용자 확인을 구함
   ([[self-hosted-agent-server-ops]] 함정2 패턴). 확인 없이 진행하지 않고 수동 실행 명령 두 줄을
   안내만 함.
5. **사용자가 "재처리해줘"를 7회 연속 전송**(02:47:03~02:47:44) — 확인 응답이 늦게/반복 도착. 두
   번째 시도에서 어시스턴트가 재시작 + 실패 작업 재큐잉을 실행, 완료 확인(02:48:28) — 데몬 재시작 후에도
   이 대화의 응답 전달이 이어졌다(launchd KeepAlive 즉시 재기동 덕).

## 핵심 결론

- **근본 원인**: 큐 작업 실행기(`runner.ts`)가 인터랙티브 채팅과 달리 `ANTHROPIC_API_KEY` 제거 처리가
  없어, 크레딧 0 상태에서 API 종량 과금 시도 → 실패. → [[sdk-claude-code-vs-api-billing]]의 "크레딧
  소진의 파급 범위" 절이 예견했던 정확히 그 문제.
- **영향 범위**: 2026-07-16 07:27~08:33+ 사이 보관된 대화 35건이 위키에 미반영 상태로 누적.
- **수정 2건**: (1) `runner.ts`에 `claudeAuthEnv()`류 처리 추가, (2) 야간 안전망 잡 범위에
  `chats/archive/` 포함.
- **재처리**: 데몬 재시작 후 실패 35건을 `queue/failed/`→`queue/`로 이동해 즉시 재큐잉, 처리 시작 확인.
