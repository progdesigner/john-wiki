# 2026-09-14 — lampas-web-www 로고 교체 + 메타 정보 개편

`Tool: codex` 세션. 작업 폴더 `/Users/progdesigner/Works/lampas/lampas-system`(=[[lampas-studio]]).
같은 날 안에 4왕복에 걸쳐 로고 교체 → 배포 → 사용자 피드백 → 재조정 → 재배포가 반복된 짧은 브랜딩
작업 세션.

## 진행 순서

1. **로고 교체 요청** — 사용자가 이미지 1장(`bbe0b8e6-…png`) 첨부, "배경이 검을 땐 흰색으로", 기존
   "선 3개" 심볼 로고 완전 제거하고 새 로고로만 교체 + `lampas-web-www` 메타 정보(SEO·공유 미리보기)를
   사이트 성격(스포츠 콘텐츠·채널 운영·AI 플랫폼)에 맞게 수정 요청.
2. **1차 구현** — 첨부 로고를 흰색 SVG로 재구성해 헤더·푸터에 적용, 기존 선 3개 로고·마침표 제거,
   파비콘·공유 이미지(OG 이미지)도 새 로고 기반으로 통일. AI 이미지 생성 시안 가장자리에 잡티가
   보여 **웹 사용본은 원본 글자 형태를 따라 그린 SVG로 정리**(래스터 시안이 아니라 벡터 재작도 채택).
   빌드·타입체크 통과 확인 후 **배포는 하지 않고 사용자 확인 대기**.
3. **1차 배포** — "배포해줘" 요청으로 `./scripts/deploy-web.sh lampas-web-www` 실행,
   `www.lampas.io`에 반영(테스트 4개 통과).
4. **피드백 1 — 크기·라임 점 누락** — "로고가 너무 크고, 녹색 점이 빠지니 안 어울린다". 로고 크기
   축소 + 기존 브랜드 라임색 점을 워드마크 옆에 작게 재도입, PC/모바일 균형 확인 후 재배포.
5. **피드백 2 — 섹션 제목 위치** — 스크린샷 3장 첨부, "THE HUMAN SIDE" 같은 섹션 라벨이 구분선
   위로 오도록 레이아웃 조정 요청(구현 결과 확인은 소스에 명시적으로 남지 않음).
6. **피드백 3 — 로고 90% 축소 + 라벨 밑줄 위치** — "로고 조금만 작게 90% 정도". 조사 중 라벨 위에
   보이던 선이 `overline`(글자 위 선) 스타일 때문임을 확인 → 같은 라벨들의 선을 텍스트 **아래**로
   옮기는 수정도 함께 반영(요청받지 않았지만 원인 규명 중 발견해 자발적으로 포함).
7. **최종 배포** — 로고·라임 점 90% 축소 + `THE HUMAN SIDE`/`THE LAMPAS SIDE`/경기 단계 라벨의 밑줄
   위치 수정을 기존 배포 스크립트로 재배포, PC·모바일 확인.

## 관찰

- **반복 재조정 패턴** — 로고 교체 같은 시각 요소는 1차 배포로 끝나지 않고 "크게 보인다 → 축소 →
  포인트 요소(라임 점) 빠짐 → 재도입 → 다시 %비율로 미세조정" 식으로 실제 배포된 사이트를 보고서야
  나오는 피드백 루프가 여러 차례 이어짐. 매번 `[[deploy-sandbox-pnpm-shim]]` 절차의 배포 스크립트
  (`./scripts/deploy-web.sh lampas-web-www`)만 재사용, 별도 인프라 변경 없음.
- **오류 원인 규명 후 자발적 확장** — 6번 항목에서 사용자는 "로고만 작게" 요청했는데, 어시스턴트가
  같은 조사 과정에서 라벨 밑줄이 `overline` CSS 속성 때문임을 발견하고 요청받지 않은 수정(밑줄
  위치를 글자 아래로)까지 같이 처리 — 근본 원인 조사 중 발견한 부수적 결함을 요청 범위에 자연스럽게
  편입시킨 사례.
- 이 세션은 [[lampas-studio]] 페이지의 2026-07-18 "`lampas-web-www` landing 페이지 전면 재디자인"
  절의 후속(약 2개월 뒤) — 그때 새로 만든 컴포넌트 구조 위에서 로고·톤 미세조정이 이뤄진 것으로
  추정.
