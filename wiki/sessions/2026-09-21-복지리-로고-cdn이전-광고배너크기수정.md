# 2026-09-21 — 복지리 회사 로고 CDN 이전(cdn.dbs.best→cdn.bokziri.com) + 광고 배너 크기 수정

`Tool: claude`, 작업 디렉터리 `~/Works/bokziri/bokziri-system`([[bokziri-system]] 최초 상세 노출).
서로 무관한 두 문제를 이어서 처리한 세션.

## 1. 로고 깨짐 → CDN 도메인 전면 이전
[[progdesigner]]가 토스앱·웹 양쪽에서 회사 로고 없을 때 쓰는 placeholder 대신 아이콘이 깨진 스크린샷
첨부. 조사 결과 원인은 회사 로고들이 전부 **완전히 죽은 도메인 `cdn.dbs.best`**(DNS 자체가 안 풀림)를
가리키고 있었던 것 — placeholder 파일 자체는 정상이었음.

- **S3 복사**: 옛 버킷 `cdn.dbs.best/production/` 전체(13,815개 객체, ≈1.5GB)를
  `s3://bokziri.com/cdn/production/`로 서버사이드 복사, 키 목록 대조로 누락 없음 확인(폴더 마커 8개
  제외).
- **CloudFront 신규 생성**: 배포 ID `E3VOBEVVHUEUN0`, 별칭 `cdn.bokziri.com`, 인증서 `*.bokziri.com`
  (신규 발급 아닌 기존 와일드카드 재사용), OAC 방식. 버킷 정책에 배포 ARN 추가.
- **운영 DB 경로 치환**: `cdn.dbs.best` 두 형태(직접 도메인/`s3.ap-northeast-2.amazonaws.com` 경유)를
  전부 `cdn.bokziri.com`으로. `bokziri_company.logo`(3,620행)·`community_post.content/resources`
  (6,707/6,775)·`resource.resource_url/resource_thumbnail_url`(8,933/8,933)·`user.resources`(174)·
  `inquiry.resources`(9). 변경 전 원본은 `scratchpad/db-backup-cdn-dbs-best.ndjson`(9.4MB)에 백업.
  `resource` 테이블 20행은 원래부터 `/undefined/` 경로로 깨져 있어 손대지 않음.
- **코드 변경**: `CompanyIcon.tsx`(www·toss)에 이미지 로드 실패 시 placeholder 대체 `onError` 추가,
  `company-logo.ts`(www·toss)·API `company.service.ts`에서 `cdn.dbs.best` 판별 제거하고
  `bokziri.com`만 허용, API `company.seeds.ts` 시드 URL 일괄 치환.
- **DNS 병목**: `bokziri.com` DNS가 Route53이 아니라 **Squarespace**에 있어 어시스턴트가 직접
  CNAME을 추가할 수 없었음 — `cdn` → `ddn5a9blwn0eq.cloudfront.net` CNAME을 사용자가 직접 등록해야
  하는 구조. 등록 전까지는 onError 처리로 복어 placeholder가 뜨는 것으로 임시 방어.
- **왕복 3회**: (1차) 웹·토스앱 배포 → (2차, 사용자 "로고가 거의 안 보인다") DNS 미등록 상태 재확인,
  CloudFront 기본 도메인 임시 우회 제안 → (3차, CNAME 등록 확인 후) 토스앱 재배포(0.2.6→0.2.7)로
  전파 반영. 최종적으로 Google(8.8.8.8)·Cloudflare(1.1.1.1) 양쪽 리졸버에서 정상 확인.
- 마지막으로 "최신 코드 받고 지금 반영된 건 유지한 채 재배포 후 커밋·푸시"까지 요청받아 origin/main
  신규 커밋 67개 병합(package.json 버전 충돌만, upstream 값 채택) → www 0.8.36, toss 0.2.8 재배포 →
  커밋 `4cb0952`로 push.
- 절차를 [[dead-external-cdn-domain-migration]] 스킬로 추출(같은 저장소 CLAUDE.md에 명문화된 배포
  스크립트 경유 원칙은 [[new-subdomain-cloudfront-wildcard-deploy]]와 공유하나, "죽은 외부 도메인에서
  이전"이라는 시나리오와 "DNS가 IaC 밖 3rd-party(Squarespace)에 있어 사용자 개입이 필수"라는 제약이
  달라 별도 스킬로 분리).

## 2. AdSense 배너가 작게 보이는 문제
같은 세션에서 이어서 "광고가 너무 작게 표시된다" 스크린샷 제보.

- **원인**: 8월 말 커밋에서 AdSense를 "CSS 고정 크기" 방식으로 바꾸며 `ins`에 높이 50px·너비 100%를
  지정 — 고정 크기 모드에서 Google은 지정 크기에 맞는 **표준 크리에이티브만** 내려주는데, 높이 50px에
  맞는 표준 크기는 320×50 하나뿐이라 화면이 넓어도 항상 그 크기만 채워짐. 여기에 `ins`가
  `inline-block`+좌측 정렬이라 컨테이너(최대 544px) 안에서 왼쪽에 붙어 더 작아 보임.
- **수정** (`apps/bokziri-web-www/src/components/ads/AdBanner.tsx`): 뷰포트 폭 미디어쿼리로 표준 크기
  전환(500px 미만 320×50, 이상 468×60 — 레이아웃 최대 576px−좌우 여백 16px 기준), 컨테이너 가운데
  정렬, 래퍼 높이도 같은 미디어쿼리로 동기화(빈 여백 방지). 사이드바형(320×100)은 크기 유지하고
  정렬만 적용.
- www 0.8.36→0.8.37 배포, 커밋 `985a926` push. 새 크기(468×60) 요청 초기엔 Google 인벤토리가 덜
  채워져 빈 자리·작은 배너가 섞여 보일 수 있음을 사용자에게 미리 안내. 무관한 기존 타입 오류
  (CompanySearchDialog, CommunityPage)는 빌드가 통과해 이번엔 손대지 않음.
