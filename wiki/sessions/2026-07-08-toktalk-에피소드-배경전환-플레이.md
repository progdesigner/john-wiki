# 2026-07-08 — TokTalk 에피소드 배경 전환·플레이 시스템 세션

`[[progdesigner]]`가 `[[toktalk]]`(AI 캐릭터/보이스 챗 제품, `apps/talk-*` 모노레포)의
**에피소드 플레이(beat 기반 시나리오)** 배경 전환 동작을 하루 동안 반복 다듬은 세션.
`[[lampas]]`(에이전트)가 `[[lampas-harness]]` 웹 채팅으로 이 제품 코드베이스를 편집·검증·배포했다.
축은 (1) 문서 최신화, (2) 배경 선(先)전환, (3) 선택지 없는 beat 직접 전환, (4) 배경 sticky 유지 버그, (5) AI 다시쓰기 로딩 버그.

기간: 2026-07-08 18:12 ~ 18:42 (트랜스크립트 기준). 원본: [[raw/conversations/2026-07-08-toktalk-에피소드-배경전환-플레이.md]]

## 흐름 (시간순, 요청 단위)

1. **프로젝트 문서 최신화** — 루트 `README.md`가 초기 "Voice Chat" 프로토타입(web/·api/ 2폴더, 포트 3701/5174) 시절 그대로였음. 현재는 7개 앱 pnpm 모노레포라 전면 재작성. `docs/ARCHITECTURE.md`의 낡은 포트·env 예시만 실제 값으로 수정, 업데이트 날짜 2026-07-09. → 제품 구조는 [[toktalk]] 참고.
2. **배경 선(先)전환** — 배경 구간이 시작되는 beat에서 지문/대사와 배경 전환이 **같은 탭에서 동시에** 일어나던 것을, 전환을 별도 단계로 분리. 탭하면 ① 배경만 먼저 전환 → ② 다음 탭에서 지문/대사 시작. 연출 구간이 끝나 장소 이미지로 복귀할 때도 동일. → `[[episode-beat-play-system]]`
   - `apps/talk-web-app/src/utils/beatPlay.js` — `pendingSceneShift()` 헬퍼 추가, `resolveSceneBackground()`가 새 히스토리 항목 `sceneShift` 인식.
   - `apps/talk-web-app/src/pages/PlayEpisodePage.jsx` — `revealNext()`가 전환 필요 시 `sceneShift` 항목만 쌓고 리턴(탭 1회 소비), 채팅 영역엔 렌더 없음.
   - 어드민 테스트 플레이 동일 반영: `apps/talk-web-admin/src/studio/beatPlay.ts`, `.../episodes/[id]/play/page.tsx`.
3. **플레이 선택지에서 콘텐츠 미리보기 제거** — 선택지 버튼의 연출 이미지/비디오 썸네일 제거, 스포일러성 연출 이름도 배지에서 제거(배지는 `🖼️ 배경 전환 · 5C` 크레딧 안내만). 안 쓰게 된 `.play-choice-thumb` CSS 정리. **어드민 테스트 플레이 썸네일은 제작자용이라 유지.**
4. **선택지 없이 beat 실행 시 배경 전환** — 플레이 로직에 이미 있던 레거시 경로 `beat.actionId`(beat에 연출 직접 연결)를 정식 기능으로 되살림. 플레이 화면은 추가 수정 없이 그대로 동작(선전환 규칙 그대로 적용, **크레딧 차감 없음** — 연출 카드 "배경 구간"과 동일 성격). → `[[episode-beat-play-system]]`
   - `apps/talk-web-admin/src/studio/types.ts` — `EpisodeBeat.actionId`의 `@deprecated` 해제, "이 beat 실행 시 배경 전환할 연출" 필드로 재문서화.
   - `.../episodes/[id]/page.tsx`(시나리오 흐름 편집기) — 각 지문/대사 아래 "🖼️ 배경 전환 — 이 지문/대사가 실행되면" 선택 박스(연출 드롭다운 + 제작자용 썸네일, 콘텐츠 미생성 연출 비활성). 연출 카드 "배경 구간"이 이미 있으면 그 설정 우선 ⚠ 경고. "적용 범위" 라벨이 beat 연결 구간도 표시.
   - API는 beats를 자유 구조 JSON으로 저장(`studio.dto.ts`)하므로 **서버 변경 불필요**.
5. **선택지 배경이 다음 beat에서 되돌아가는 버그** — `resolveSceneBackground`가 beat 공개 때마다 배경을 "그 beat 스크립트 배경, 없으면 장소 이미지"로 무조건 재계산 → 배경 구간 미지정인 선택지 연출이 바로 다음 beat에서 장소로 리셋됐음. **다음 배경 구간이 명시적으로 시작되기 전까지 sticky 유지**하도록 수정. `pendingSceneShift`는 "다음 beat 공개 상태"를 같은 함수로 시뮬레이션해 비교(유지 규칙이 선전환 판정에도 반영 → 불필요한 "장소 복귀 전환 탭" 제거). → `[[episode-beat-play-system]]`
6. **AI 다시쓰기 로딩 스피너 미표시 버그** — 요청은 실제 전송·처리되는데 스피너가 안 떠 "작동 안 함"처럼 보임. 원인은 **로딩 상태 키 불일치**: `runBeatAi`는 busy 키에 count 접미사(`-1`)를 붙여 저장(`beat-ai-replace-{beatId}-1`)하는데, 버튼 3곳은 접미사 없는 키로 비교. beat 단위 작업(beatId 있음)은 count 접미사를 붙이지 않도록 키 생성 수정(beatId만으로 유일). beatId 없는 전체 추가 버튼(`beat-ai-append-1/3/5`)은 기존대로 count 유지. → `[[loading-state-key-mismatch]]`
7. **Commit & Push** — `.env`·Firebase 서비스 계정 JSON이 커밋에 포함됨을 확인·고지 후 사용자 지시로 그대로 푸시. 커밋 `0664ea9` → `origin/main`.

## 핵심 결정사항

- **선전환은 별도 탭 단계** — 배경 전환과 지문/대사를 분리해 연출을 먼저 보여준다. 배경 구간 진입·복귀 모두 동일 규칙.
- **선택지 배경은 sticky** — 선택지로 해금한 연출은 다음 배경 구간이 시작되기 전까지 유지. beat마다 장소로 리셋하지 않는다.
- **beat 직접 전환은 무료** — 선택지형 연출과 달리 크레딧 차감 없음. 레거시 `actionId` 경로를 정식 기능으로 승격(우선순위: 연출 카드 배경 구간 > beat actionId).
- **플레이어에겐 스포일러 숨김, 제작자에겐 노출** — 플레이 선택지 썸네일·연출 이름 제거, 어드민 테스트 플레이는 제작자 도구라 썸네일 유지.
- **웹앱·어드민 플레이 로직 공유** — `beatPlay.js`(JS) / `beatPlay.ts`(TS) 두 헬퍼를 **동일 로직으로 동시 수정**해야 함(중복 구현). 한쪽만 고치면 테스트 플레이와 실제 플레이가 어긋남.
- **beats는 자유 구조 JSON** — API가 스키마 검증 없이 저장하므로 클라 구조 변경에 서버 배포 불필요.

## 검증 방식
- talk-web-app `vite build`, talk-web-admin `tsc --noEmit`, 변경 파일 ESLint.
- 배경 sticky 수정은 **Node로 플레이 흐름 시뮬레이션**해 3케이스 확인(① 선택지 전환 후 유지, ② 새 배경 구간에서만 전환, ③ 일반 진행 회귀 없음).
