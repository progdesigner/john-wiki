# 2026-09-26 — 람파스 가입 도메인 필터·크레딧 회수·이상 가입 대시보드 + 어드민 레이아웃/크레딧 버튼 통합

`Tool: claude`, 작업 디렉터리 `lampas-system`([[lampas-studio]]). 원본:
[[raw/conversations/2026-09-26-람파스-가입도메인필터-크레딧회수-대시보드-레이아웃]].

## 요청 배경
`gehuy.biz.id` 같은 특정 도메인 이메일로 가입 보너스 크레딧을 노린 대량 가입(어뷰징)이 발생 —
사용자가 세 가지를 한 번에 요청: (1) 도메인별 가입 상한 필터, (2) 기존 가입자는 유지한 채 크레딧만
회수, (3) 이런 이상 가입 상황을 대시보드에서 볼 수 있게.

## 구현 내용 (1차 턴, 커밋 `a23f94c1`)

**1. 가입 도메인 필터** ([[lampas-studio]] `lampas-api` auth)
- 관리자가 등록한 도메인(서브도메인 포함)의 이메일 계정이 상한(기본 10, 0이면 전면 차단)에 닿으면
  신규 가입 403. 구글·이메일·토스·로컬 가입이 모두 지나는 단일 지점에 게이트 삽입, 규칙에
  차단 횟수·마지막 차단 시각 누적.
- 규칙에 없는 도메인은 카운트하지 않아 일반 가입 성능에 영향 없음.

**2. 크레딧 회수** (유저 정보는 유지)
- 도메인 단위 일괄 회수 + 유저 단건 회수. `보너스만`(미회수 가입 보너스, 잔액 한도) vs `전액`(잔액 0)
  두 모드.
- 유저 행·로그인 유지, 잔액만 차감 + 원장에 관리자 차감으로 기록. 재실행 시 회수할 잔액이 없는
  계정은 스킵(idempotent, 중복 차감 없음).

**3. 대시보드 이상 가입 감지** ([[lampas-web-admin]])
- "이상 가입 감지" 섹션: 이메일 도메인별 24h/7d/30d/누적 가입 수 + 잔액 합. gmail 등 흔한 공급자
  제외, 24h 3개·7d 5개·누적 10개 이상이면 "의심" 표시.
- 각 행 "필터에 추가" 버튼 → 도메인 프리필된 신규 `/signup-domains` 페이지(등록·상한 수정·소속
  유저 조회·일괄/개별 회수·삭제). 유저 상세 화면에도 회수 버튼 추가.

**검증**: API jest 21건 추가(admin 46·auth 11 전체 통과), web-admin vitest 5건. 로컬 API 데몬
재기동 후 실제 흐름 확인 — 상한 3 설정 → 가입 3개 허용 → 4번째(서브도메인) 403+카운트 → 보너스
회수로 3,000 크레딧 회수 → 재실행 시 전부 스킵 → 대시보드 의심/필터 표시 → 원장 기록 확인. 스모크
데이터 정리 완료. → [[signup-domain-abuse-rate-limit-and-reclaim]] 스킬로 절차 추출.

## 운영 관련 주의 — 두 가지 교차 세션 오염
- **다른 세션의 spot 커밋(`adb982af`)에 이 세션이 만든 `schema.prisma` 모델이 섞여 이미 운영
  배포(0.1.149)됨** — 배포된 코드가 그 모델을 쿼리하지 않아 무해함을 원격에서 직접 확인. 이 세션이
  "커밋 전에 schema.prisma가 변경 목록에 안 보이는 원인"을 조사하다 발견. →
  [[selective-hunk-commit-shared-file]]에 "반대 방향(내 변경이 남의 커밋에 섞임)" 변형으로 반영.
- 다음 API 배포가 안전하도록 운영 DB에 `signup_domain_rules` 테이블 DDL을 **미리 적용**(빈 테이블
  생성, 멱등) — [[prod-ddl-before-deploy-with-drift-check]] 절차의 재확인 사례.
- **배포는 1차 턴에서 보류**: 워킹트리에 다른 세션의 미커밋 packaging 변경이 `lampas-api` 안에 있어
  `deploy-api.sh`가 그것까지 함께 배포하게 되는 상황 — 그 변경이 정리된 뒤 배포하라고 명시.

## 2차 턴 — 어드민 전체 폭 레이아웃 (같은 날, 커밋 `5911f67d`)
사용자가 스크린샷 첨부해 "어드민 가로로 전체 화면 꽉 차는 레이아웃으로" 요청. 그 사이 운영 API가
다른 세션에 의해 0.1.154로 배포돼(가입 도메인 엔드포인트 반영 확인) 이 세션은 web-admin 레이아웃만
수정·배포:
- 상단 바·본문·리뷰 분쟁 페이지의 폭 제한 제거, 전체 화면 사용.
- 메뉴 글자 줄바꿈 방지("대시보 드"처럼 잘리던 문제 수정), 좁은 화면에서 메뉴 가로 스크롤.
- 배포 직후 web-admin 경로만 커밋. 운영 확인: 전체 폭 레이아웃·가입 도메인 페이지·"이상 가입 감지"
  섹션 모두 admin.lampas.io 새 번들에 반영, CloudFront 무효화 완료.

## 3차 턴 — 크레딧 지급/회수 버튼 통합 (커밋 `5ba07f9b`)
"크레딧 회수 기능이 지급 옆에 안 보인다" 피드백 → 사용자 목록의 "지급" 버튼을 **"크레딧"** 버튼
하나로 합침:
- 클릭 시 모달에서 **지급 / 회수** 탭 선택.
- 지급 탭: 기존 동일(프리셋·양수/음수 입력·사유 메모).
- 회수 탭: **잔액 전부 회수**(잔액 0) 또는 **가입 보너스만 회수**(미회수 보너스, 잔액 한도) 중 선택 →
  "회수" 클릭. 유저 정보 유지, 원장에 관리자 차감 기록, 잔액 0이면 버튼 비활성화.
- 처리 후 목록 잔액 즉시 갱신 + 상단 결과 문구. 사용자 상세 페이지의 기존 충전·차감 폼과 헤더
  "보너스 회수/전액 회수" 버튼은 그대로 유지(중복 경로).
- 배포·커밋 완료, admin.lampas.io 반영 확인.
