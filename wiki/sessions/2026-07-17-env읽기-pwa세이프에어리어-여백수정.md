# 2026-07-17 — .env 파일 읽기 + PWA 세이프 에어리어 여백 수정

짧은 코딩 운영 세션(2026-07-17 12:50~12:55 UTC). 무관한 두 화제가 한 채팅에 묶였다:
① `.env` 파일 평문 노출 사고, ② PWA 세이프 에어리어(safe-area-inset) CSS 여백 버그 수정.

## ① `.env` 파일 평문 노출 (⚠️ 보안 사고)

사용자가 "`.env` 파일을 그대로 읽어줘"라고 요청하자, 어시스턴트가 별도 위험 고지 없이
`CLAUDE_CODE_OAUTH_TOKEN`·`ANTHROPIC_API_KEY`·`OPENAI_API_KEY`·`GOOGLE_API_KEY`·
`ELEVENLABS_API_KEY`·`HARNESS_TOKEN` 전체 값을 표로 그대로 채팅 응답에 출력했다. 이 값들은
[[lampas-harness]] 채팅 로그(`logs/chats/archive/`)에 평문으로 영구 기록된 상태다.

- **이 위키 ingest 시 대응**: 원본 로그 파일(원본은 CLAUDE.md 규칙상 수정 금지)은 그대로 두되,
  이 위키의 `raw/` 사본과 세션 요약에는 **실제 키 값을 레닥트**했다(접두사만 남김) — 위키 자체가
  git 저장소라 그대로 옮기면 노출 범위가 한 곳 더 늘어나기 때문. 상세·다른 사례·권장 대응:
  → [[secrets-plaintext-exposure-pattern]] (이 사고를 계기로 신설한 토픽, [[toktalk]]·[[cwc-system]]의
  기존 유사 사고와 묶음)
- **미해결**: 노출된 키의 재발급(rotate) 여부는 이 ingest 시점 기준 확인되지 않음.

## ② PWA 세이프 에어리어 여백 수정

"PWA일 때 상단에 여백이 없어졌다"는 제보로 시작. 원인 진단·수정·배포까지 3턴 만에 완료:

- **상단**: `apps/web/public/index.html`의 `header` 규칙에 `env(safe-area-inset-top)`이 전혀
  적용돼 있지 않던 것이 원인. `padding-top: calc(10px + env(safe-area-inset-top))`로 수정 —
  일반 브라우저 탭에서는 `env()` 값이 0이라 기존 여백(10px)만 유지되고, PWA(홈 화면 추가) 모드에서만
  상태바/노치 영역만큼 추가 패딩이 붙는다.
- **하단**: 이어서 "하단은 그냥 여백 없게 해달라"는 후속 요청 — 이건 safe-area 대응이 아니라 단순
  제거 요청이라 `footer`의 패딩 `8px 16px 10px`에서 하단 값만 `10px → 0`으로 변경.
- **배포**: 웹 빌드(`npm run build:web` 추정) 후 서버 재시작(`PID 74969`로 정상 기동 확인). 사용자
  요청으로 어시스턴트가 직접 재시작까지 수행함 — [[self-hosted-agent-server-ops]]가 기록해온
  "자기 턴에서 재시작 시 채널 끊김" 함정과 달리 이번엔 문제없이 완료된 것으로 서술됨(재시작 스크립트가
  지연·분리 실행 방식으로 안전화된 상태였을 가능성, 근거: 같은 엔티티의 2026-07-15 기록).
- 재사용 가능한 절차로 스킬 추출: → [[pwa-safe-area-inset-padding]]
