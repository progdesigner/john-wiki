# 2026-07-16 — 네이버 데이터 API 콘텐츠 자동화 의사결정 상담

1왕복 quick 채팅 (2026-07-16 01:15~01:16 UTC). 코딩 아님 — [[lampas]]를 콘텐츠 자동화 전략
컨설턴트로 사용 → [[harness-as-business-assistant]] 사례.

## 배경 사실 (신규)
[[progdesigner]]는 이미 **네이버 데이터랩(DataLab) API를 연결한 자동화 사이클**을 운영 중이다:
검색 강도 높은 키워드 발굴 → 자동 글 작성 → 자동 배포까지 이어지는 파이프라인. 어느 저장소·
스크립트인지, [[naver-blog-mcp]](study-ai-what 개인 블로그 발행용)와 같은 시스템인지 별개
시스템인지는 이 세션만으로 불명 — "마케팅과 상품 얼라인"을 언급한 것으로 보아 개인 AI 기억
연재 블로그가 아니라 **상품/커머스 마케팅용 블로그**를 대상으로 하는 별도 파이프라인일 가능성이
높다(단정 보류, 임의로 엔티티 연결하지 않음).

## 질문
"인풋(키워드) → 아웃풋(발행) 사이 의사결정(마케팅-상품 얼라인, 시장적합도 판단)을 혼자 하고
있는데, 다른 사람들은 이런 자동화 파이프라인에서 이 의사결정을 어떻게 다루는가?"

## 답변 — 6-패턴 프레임워크
핵심 원칙: "혼자 하는 판단"을 없애는 게 아니라 **판단을 명시적 기준·게이트·피드백 루프로
옮겨서 사람은 배치 승인만 하는 구조로 전환**. → [[content-automation-decision-framework]]에
프레임워크 상세 기록(6패턴 + 권장 도입 순서).

1. **키워드 채점 게이트**: 검색량×상품연관성×구매의도×경쟁도 점수화(ICE 변형). 상품 연관성
   축은 포지셔닝 문서 기준 LLM 채점 — 람파스에 이미 있는 `product-marketing` 스킬
   (`.agents/product-marketing.md` ICP/포지셔닝 고정)이 정확히 이 용도.
2. **작성자·심사자 분리(LLM-as-judge)**: 페르소나 심사 에이전트가 발행 전 통과/반려 결정,
   반려 사유 로그화로 기준 정제.
3. **배치 승인**: 글 단위 대신 주 1회 "이번 주 키워드 N개+초안 요약"을 한 번에 O/X.
4. **루프 닫기**: 발행 후 성과(조회수·유입검색어·전환신호)를 다음 키워드 선정에 재투입 —
   현재 구조가 open-loop인 것이 가장 큰 공백으로 지목됨.
5. **포트폴리오 배분**: 검증 70% / 인접 20% / 실험 10%로 단일 판단 리스크 분산.
6. **신호 다변화**: DataLab 검색량은 후행·범용 신호 — 지식iN·커뮤니티·댓글의 "실제 질문 문장"을
   추가 축으로, 유입용 글(검색량 기반)과 전환용 글(상품 정렬)을 분리해 내부링크로 연결.

권장 도입 순서: ① 포지셔닝 문서 고정 → ② 키워드 채점 게이트 → ③ 주간 배치 승인 큐 →
④ 성과 피드백 루프. ①②는 기존 파이프라인에 프롬프트 단계 하나 추가하는 수준이라 즉시 적용
가능하다고 제안. 어시스턴트가 study-ai-what 블로그 기준으로 게이트를 실제 설계해주겠다고
제안했으나, 세션이 여기서 끝나 후속 여부 불명.
