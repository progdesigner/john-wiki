# 2026-09-25 — Fixs 업그레이드: 경로 그룹핑 + Jev 오류 유형 분류

`[[lampas-agent]]`의 **Fixs** 탭(재귀로 오류를 자동 수집·수정하는 기존 기능)에 두 가지를 추가해달라는
요청. 원 요청: `https://lampas-system.tail0e32ab.ts.net/fixs`를 보며 "재귀 오류 수정은 좋은데, 비슷한
경로는 묶고(`.../prediction/4617ffc8...` → `.../prediction/:id`), Jev로 오류 유형을 빠르게 감별해
분류하면 좋겠다".

## 구현 순서
공용 타입 → 경로 그룹핑 순수 로직 → Jev 분류(triage) → 스토어·HTTP·러너 배선 → 대시보드 → 테스트.
서버 사이드 Fixs 테스트 44건(마이그레이션·백그라운드 triage 포함) 통과 → 타입체크 통과 → 전체
스위트 415건 통과(이번 추가분: group 4·triage 4·store 3·http 2) → 마이그레이션을 라이브 DB 사본에
드라이런 → Jev를 실제로 한 번 호출해 응답 형태 확인 → 배포.

## 경로 그룹핑 (fingerprint)
- 메시지·스택 안의 URL/경로에서 uuid·hex·숫자·불투명 토큰·`run_xxx`·번들 해시를 `:id`/`:hash`로
  치환. `HTTP 500 GET /v1/ai/model/prediction/4617ffc8…`가 `…/prediction/:id` 한 건으로 누적되고,
  상세에 "원본 메시지 N종" 중 최근 5개가 남는 구조.
- 리포터가 만든 요청 오류(`HTTP nnn`·`Network request …`·`Resource load failed`)는 스택이 리포터
  프레임뿐이라 fingerprint에서 제외 — 브라우저 엔진별 스택 차이로 같은 401이 세 건으로 갈라지던 문제
  해결.
- 데몬 최초 기동 시 기존 레코드 한 번 재그룹: 운영 DB 69건 → 42건, 발생 횟수 합산·작업 기록 이관도
  함께 처리. 릴리스가 다르면 여전히 별건(수정 배포 후 재발 구분용 기존 규칙 유지).

## Jev 분류(triage)
- 접수된 오류마다 `POST /v1/ai/systemone`에 **typed 질문 4개**를 한 번에 질의: 유형(서버 오류·프론트
  버그·네트워크·인증·입력 검증·경로 없음·한도·외부 공급자·리소스·노이즈), 수정 위치(API·웹·인프라·
  외부·불필요), 심각도 4단계, 소스 수정으로 해결 가능한 확률.
- **텍스트 생성 없이 구조화 답만 받아 입력 토큰만 과금** — 비용 42크레딧/M 토큰 수준으로 무시 가능.
  이 "typed 질문으로 저비용 분류" 패턴은 `sports-wiki` ingest 게이트에서 쓰던 Jev와 같은 계열(용어
  자체가 이 세션 이전 `raw/conversations/2026-09-25-위키개선-스포츠경기엔티티-설계.md`에 "Jev 게이트"로
  먼저 등장했으나 상세 미문서화 상태였음 — 이 세션이 처음으로 구체적 형태를 드러냄) → [[jev-typed-classification]].
- 데몬이 5초마다 미분류 1건씩 처리(시도 2회 상한), 상세 화면에서 "다시 분류"로 재실행 가능. 목록
  카드에 심각도·유형·위치 배지, 상단에 유형 필터, Codex 프롬프트에도 힌트로 포함.
- 운영 실측: 서버 500 → 서버 오류/API/높음 99%, gtag 차단 → 리소스/외부/낮음, deprecation 경고 →
  노이즈, TypeError → 프론트 버그/웹. 건당 0.3~0.6초. 배포 시점 43건 중 37건 분류 완료·실패 0.

## 배포·운영 중 발견한 것
- **파트너 키 임시 조치**: 에이전트에 파트너 키가 없어(`AGENT_AI_API_KEY` 비어 있음) `env/.env.local`에
  신규 변수 `FIXS_AI_API_KEY`를 두고 **`talk-api`(toktalk) 운영 파트너 키를 임시로 복사**해 넣음.
  과금·사용량이 그 키 계정에 합산되므로 `platform.lampas.io`에서 Fixs 전용 키를 발급해 교체하는 게
  깔끔하다고 판단(비용 자체는 무시할 수준이라 급하지 않음) — 후속 확인 필요.
- 분류 중 운영 API가 nginx HTML 404를 순간적으로 세 번 반환 → 재시도 대상으로 처리하도록 고쳐 재배포,
  해당 세 건 재분류로 정상 라벨 확정.
- Jev 상류(TypeSafe)가 15초 타임아웃을 낸 502가 한 번 있었는데, 이건 `lampas-api` 자체 리포터가
  `HTTP 502 POST /v1/ai/systemone`으로 **Fixs 스스로에 접수**해 둔 것(자기 참조적 오류 케이스).
- 드라이런 중 DB 사본 복사가 WAL 파일을 놓쳐 재현 실패 → 제대로 된 SQLite 백업 방식으로 재복사.
