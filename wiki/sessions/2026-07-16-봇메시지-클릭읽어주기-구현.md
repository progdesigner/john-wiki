# 2026-07-16 — 봇 말풍선 클릭 읽어주기 구현 + 충돌 마커 정리 (커밋 전 단계)

`[[lampas-harness]]` 웹 채팅, 2026-07-16 09:10:47~09:17:28 UTC. 3왕복.
[[2026-07-16-봇메시지-클릭읽어주기-커밋푸시]](09:21~09:22, 4분 뒤)가 diff만 보고 커밋·푸시한
바로 그 기능의 **실제 구현 세션** — 그 세션이 소스 부재로 "미상"으로 남겼던 구현 방식
(Web Speech API vs ElevenLabs)을 여기서 확정할 수 있다.

## 요청 1 — "람파스(하네스)에게 받은 메세지를 클릭하면 읽어주는 기능도 만들어줘"

### 조사
- `apps/web`에는 `src` 디렉토리가 없음 — 순수 정적 파일(`public/index.html`이 빌드 시
  `dist/index.html`로 복사, vanilla JS). `quick.html`에는 TTS 관련 코드 없음.
- 기존 **자동 음성 재생(TTS)** 인프라 확인 ([[2026-07-16-롱프레스설정-자동음성재생-구현]]에서 구현됨):
  - 토글 상태: `localStorage.getItem("harness_tts")`
  - 재생 함수 `speak(md)` (line 1044-1056) — 마크다운/코드 기호 제거 후
    `new SpeechSynthesisUtterance`, `u.lang = "ko-KR"`, 한국어 보이스 우선, `synth.speak(u)`
  - 트리거: `streamChat`의 `done` 이벤트에서 `if (ttsOn && ...) speak(bot._md)`
  - 정지: `stopSpeech()` → `speechSynthesis.cancel()`
  - 부가: 채팅 빈 배경 롱프레스(500ms)로 설정 모달 여는 핸들러가 이미 `.msg, button, input, ...`을
    롱프레스 대상에서 제외하고 있어, `.msg` 클래스 기준 이벤트 위임이 이미 용이한 구조였음.
- 봇 말풍선 렌더링(`add(cls, text)`, line 722-740): 봇 메시지는 `div._md`에 원문 마크다운을
  보관한 `<div class="msg bot md">`로, 일반 클릭 리스너를 자유롭게 붙일 수 있는 구조.
- 클릭 충돌 지점 조사: 링크(`<a target="_blank">`, mdInline 정규식 치환)는 브라우저 기본 동작에
  위임·별도 JS 리스너 없음. 이미지(`.imgwrap`)는 `img.addEventListener("click", ...)`로 blob URL을
  새 탭으로 열고, 다운로드 버튼은 `e.stopPropagation()`으로 분리됨. 코드블록 복사 버튼은 없음.
  chat 컨테이너 전체 `click` 리스너는 없고, pointerdown 기반 롱프레스만 존재.

### 구현
기존 `speak()`/`stopSpeech()`를 재사용하되:
- 어떤 말풍선을 읽고 있는지 추적하도록 `speak(md, bubble)` 시그니처로 확장.
- 채팅 컨테이너에 클릭 위임 리스너 추가 — 봇 말풍선(`.msg.bot`) 클릭 시 그 메시지만 즉시 읽고,
  같은 말풍선 재클릭 시 정지(토글).
- 읽는 동안 말풍선에 파란 테두리 하이라이트, `cursor: pointer`, 툴팁("클릭하면 읽어줍니다
  (다시 클릭하면 멈춤)") 추가.
- 링크·이미지 클릭은 방해하지 않도록 예외 처리(클릭 위임 핸들러가 `a`, `.imgwrap` 등을 통과시킴).
- 자동재생(설정의 "자동 읽어주기" 토글, `done` 이벤트 트리거)도 새 시그니처에 맞춰 하이라이트를
  공유하도록 함께 수정 — 클릭 재생과 자동 재생 둘 다 같은 하이라이트/추적 메커니즘을 씀.

**결론: 이 기능은 브라우저 내장 Web Speech API 기반이며, ElevenLabs `tts-stream`
([[2026-07-16-tts-stream-elevenlabs-구현착수]])과는 무관하다.** 기존 자동재생 인프라를 그대로
재사용한 것이므로, [[2026-07-16-봇메시지-클릭읽어주기-커밋푸시]]가 미확정으로 남겼던 "어느 백엔드를
쓰는가" 질문이 여기서 해소된다.

## 요청 2 — "최신 코드 가져와줘"

- `package.json`과 `apps/web/public/index.html` 소스에 **병합 충돌 마커**
  (`<<<<<<< HEAD` / `=======` / `>>>>>>> origin/main`)가 그대로 커밋되어 있어 빌드가 실패.
  직전 병합 커밋 `dca1422`가 원인 — 이번 작업과 무관한 기존 문제. **[2026-07-16 후속 ingest로
  원본 확인]** `dca1422`를 만든 세션은 [[2026-07-16-잔여작업커밋-원격머지-재시작요청]](같은 날
  09:07~09:08, 이 세션 2~3분 전) — 그 세션에서 어시스턴트가 "완벽하게 해결됨"이라 자체 보고한
  직후 마커가 남은 채 push된 것이 이 세션에서 뒤늦게 드러났다.
- `package.json`: 버전 충돌 → **0.1.32**(origin/main 쪽, 더 높은 버전)로 확정.
- `index.html`의 `CATEGORIES` 배열 충돌 → origin/main이 추가한 비즈니스/브랜딩/마케팅 카테고리는
  유지하고, "일반" 카테고리 안내문구는 HEAD 쪽의 더 상세한 문구("람파스에게 지시하세요…")를 살림
  (양쪽을 병합, 어느 한쪽을 버리지 않음).
- 빌드(`npm --prefix apps/web run build`) 통과 확인.
- **Playwright로 실행 중인 8787 데몬에 접속해 실브라우저 검증**([[playwright-system-chrome-verify]]
  패턴): 말풍선 클릭 시 `speechSynthesis.speak` 호출(텍스트·`ko-KR` 확인) → 재클릭 시 정지 →
  링크 클릭은 읽기를 트리거하지 않음. 모두 의도대로 동작.
- **커밋하지 않음** — `package.json`, `apps/web/public/index.html` 두 파일이 수정된 채로 남음.
  "커밋 원하시면 말씀해 주세요"로 사용자에게 위임 → 4분 뒤 [[2026-07-16-봇메시지-클릭읽어주기-커밋푸시]]
  세션에서 "모두 commit 해줘"로 실제 커밋(`4cff973`→rebase→`9e45de9`, v0.1.36).

## 요청 3 — "재시작해줘"

- 병합 충돌 해결 여부를 다시 확인하는 절차를 반복(`package.json`은 이미 해결됨 확인,
  `index.html` 잔여 마커도 이미 해결된 것으로 확인) → 빌드 후 서버 재시작을 시작한다고 밝히는
  지점에서 소스 종료. 재시작 실제 완료 여부는 이 소스만으로 **미확인**.
