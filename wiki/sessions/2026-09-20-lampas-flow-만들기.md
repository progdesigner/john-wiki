## 2026-09-20 — Flow 신설·배포·SSO

- **요청**: `[[lampas-agent]]`(맥미니, Tailscale로 유튜브 영상 수집) → Clips(클립 폴더링) →
  `[[lampas-web-copy]]`(페르소나별 카피) → `[[lampas-web-reels]]`(편집 그룹) →
  Edit(템플릿 작업·내보내기) → 갤러리에서 선택해 Package로 전송, 이 6단계를 **"Work"** 개념 아래
  노드 그래프로 연결해 진행 상황·작업 공간 이동을 한 화면에서 관리하는 `flow.lampas.io` 신설.
- **설계 원칙**: Flow는 각 서비스가 만든 실제 결과물(클립·카피·편집 그룹·편집 세션·내보낸 영상)에
  노드를 연결하고, 서비스에서 작업 후 돌아오면 상태를 다시 조회해 갱신 — Flow 자체가 상태를 소유하지
  않고 각 서비스의 결과물 존재 여부로 완료를 판정.
- **맥미니 Agent 주소 확정**: `https://lampas-system.tail0e32ab.ts.net/` (Tailscale HTTPS, 사용자가
  직접 제공) — `[[lampas-agent]]`의 `/fixs` 엔드포인트와 같은 호스트, 기존 위키 기록과 일치.
- **구현**: Work 저장 API(다른 탭 변경 덮어쓰기 방지용 충돌 검사), 삭제된 결과물은 "확인 필요"로 표시,
  노드 추가·분기·드래그, 서비스별 작업공간 바로가기. 검증: 7개 앱 빌드 + 관련 테스트 578개, 브라우저
  캔버스·저장·분기·모바일 확인, Agent `/healthz` 200. **미완료**: 로컬 MySQL 개발 계정 접속 거부로
  DB 테이블·실데이터 연동 검증 불가, 운영 배포 아직.
- **배포**: Flow 변경만 담은 별도 체크아웃으로 API 배포, 운영 DB에 `flow_works` 테이블만 추가, 맥미니
  Agent·연동 웹앱 순서로 배포, CloudFront 신규 생성. `https://flow.lampas.io` 오픈, Work 생성·조회·
  수정·충돌검사 운영 확인.
- **막힌 지점 → SSO 후속 작업으로 이어짐**: Google이 신규 Flow 도메인의 로그인을 허용하지 않아, 기존에
  등록된 Reels 도메인에서 로그인 후 인증 결과를 Flow로 전달하는 임시 우회로 시작.

### 작업 공간 간 로그인 이어받기 (SSO)
사용자 요청: "Flow 간의 작업 이동 시 지금 로그인된 세션으로 로그인 다시 되도록". 서비스마다 로그인
저장소가 분리돼 있어, URL에 **로그인 토큰 대신 짧게 만료되는 일회용 교환 코드**를 전달하고 대상
서비스가 코드 교환 후 그 계정으로 로그인(대상에 다른 계정이 이미 로그인돼 있어도 전환)하는 방식으로
구현. 코드 만료·재사용 차단 테스트 통과, 실제 브라우저에서 Flow→Clips→Flow·Reels·Edit·Package
전환 확인, 코드는 이동 후 URL에서 제거됨. 맥미니 Agent는 **로컬 처리 세션**과 **운영 업로드 세션**이
따로 인증되는 구조라 두 세션을 함께 연결하도록 확장. → 절차 스킬: [[cross-subdomain-session-handoff]]

## 2026-09-20 (계속) — 유튜브 다운로드 느려짐 → Tailscale Funnel 병목 진단·수정

사용자: "agent 에서 유투브 다운로드가 느려졌는데 확인해줘" (다운로드 중 느려짐+재시도).

- **진단**: 영상(122MB)은 맥미니에 저장 완료됐지만 **맥미니→브라우저 전송**이 계속 진행 중이었음.
  같은 376KB 파일 기준 로컬 0.04초 vs Tailscale Funnel 6.1초 — 공개 Funnel 경로의 대역폭 제한이
  원인. 수신 제한 10분, 재시도 시 유튜브 다운로드부터 처음부터 재시작하는 구조였음.
- **수정**: 맥미니가 받은 영상을 **S3로 직접 업로드**, 브라우저는 S3에서 수신(Funnel 우회). 재시도는
  이미 받은 파일을 재사용. 화면에 "유튜브 다운로드"·"영상 보관"·"브라우저로 가져오기" 3단계를
  구분 표시.
- **배포 중 발견한 버그**: S3 서명된 업로드 URL에 중복 업로드 헤더가 붙어 충돌 — 헤더 제거로 해결.
- **검증**: 실영상 기준 다운로드 5초·S3 보관 약 1초·브라우저 수신 0.1초, 해시 일치. 128MB 대용량:
  S3 업로드 2.56초·수신 2.23초, 완료된 전송 재요청 시 같은 저장 파일 재사용 확인.
- → 절차 스킬: [[tailscale-funnel-large-payload-bypass]]

## 2026-09-20 (계속) — Flow "확인 필요" 상태 오표시 + 전사 지연

- **"확인 필요" 버그**: Flow 재작업 중 화면에 이전 실행의 "수집 취소" 상태가 남아 있던 문제.
  원인: 재시작한 작업에 Flow 연결 정보가 누락될 수 있는 경로, 그리고 **늦게 도착한 취소 알림이 새
  진행 상태를 덮어쓸 수 있는 구조**. 재시작 시 연결을 이어받고 실행(run)별로 상태를 구분하도록 수정.
- **전사(transcription) 지연**: 전사 시작 시 약 31MB 오디오 처리 엔진도 Funnel로 받고 있어 진행률
  0%인 채 오래 대기하는 구조였음(위 유튜브 다운로드와 같은 병목 계열). 엔진은 S3에서 직접 로드,
  오디오는 운영 API로 직접 업로드하도록 변경. 전사 구간을 최대 2개씩 병렬 처리, 완료된 구간은 저장해
  재시도 시 재사용. 추출·업로드·음성 인식 단계별 진행 상태 표시. Agent 테스트 369개 통과, 배포
  후 버전 **1.0.16**. 브라우저 검증: 엔진 로딩+30초 샘플 추출 약 0.75초. 늦은 취소 알림을 무시하고
  새 실행의 "전사 진행 중" 상태를 유지하는 것도 함께 확인.
- → 절차 스킬: [[execution-run-scoped-status-vs-stale-notification]] (확인 필요 버그) ·
  [[tailscale-funnel-large-payload-bypass]] (전사 엔진 로딩 병목, 유튜브 전송과 동일 계열)

## 2026-09-20 (계속) — Jev 노드 자동화 + 첫 노드만 바꾸면 전체 자동 실행

사용자 요청: 각 노드에 Jev를 활용한 대표 작업 자동 수행 + 프롬프트 편집·확인 가능 + 첫 노드(영상)만
바꾸면 전체가 자동으로 이어지게.

- **Jev의 역할 분리**: 저장소 내 Jev는 **선택·평가 모델**로 연결돼 있어 클립 선별·페르소나 추천·
  구성/템플릿 선택에 쓰고, 실제 카피 생성·영상 편집 실행은 각 서비스의 기존 기능이 담당.
- **기본 자동 제작 결과물**(사용자 확정): 추천 클립 3개 → 한국어 카피 → 세로 9:16 릴스 1개 → 패키지
  저장. 전체 실행/노드별 실행 모두 지원, 중단 시 저장된 결과를 재사용해 이어서 실행(재시도 시 카피·
  결과물 중복 생성 안 됨, 테스트로 검증).
- **부수 수정**: Reels가 편집 그룹 저장 시 카피 연결 정보를 누락하던 버그 함께 수정.
- **Jev 인증키(`TYPESAFE_API_KEY`) 반영**: 운영/로컬 env에 키가 없어 실제 Jev 호출이 막혀 있었고,
  사용자가 대화 중 키 값을 직접 제공 → `apps/lampas-api/env/.env.production`(git 미포함, 배포 전용
  설정)에 반영. **키 값 자체는 이 위키에도 기록하지 않음.** 실제 Jev 응답 성공 확인(테스트 장면 페르소나
  선택 약 0.5초). 화면 검증 중 "기본 프롬프트를 늦게 불러오면서 사용자 입력을 덮어쓰는" 버그를
  발견해 수정 후 최종 배포.
- 기존 Edit 계정 템플릿(SPOTV 등, `[[lampas-studio]]` "Edit 템플릿 에디터" 절 참고) 선택 연동도 함께
  구현.

## 2026-09-21 — Flow 30초 타임아웃 → Harness 개선요청 브리지

사용자: 오류가 나면 Flow에서 바로 `[[lampas-harness]]`에 개선을 요청할 수 있게 해달라 + 일단 이 오류가
안 나게 수정.

- **원인**: 자동 실행 요청이 Jev/AI 작업이 끝날 때까지 응답을 대기해 Flow의 **30초 요청 제한**에 걸림.
- **수정**: 실행 접수는 즉시 응답(운영 확인 **29ms**)하고 진행 상태는 별도로 폴링·조회. 반복 조회가
  AI 작업을 중복 실행하지 않도록 처리, 일시적 연결 지연과 실제 오류를 구분.
- **Harness 연결**: 오류 옆에 **"Harness에 개선 요청"** 버튼 추가 — 실행·노드·오류 정보를 담은 진단
  요청문을 만들어 수정·복사할 수 있고, Harness를 열어 붙여넣어 실제 전송은 사용자가 수행(Flow가 직접
  전송하지 않음). Flow 제품 버그를 `[[lampas-harness]]` 개발 루프로 바로 연결하는 최초 사례.
- → 절차 스킬: [[accept-then-poll-for-slow-ai-jobs]]

## 2026-09-21 — Pulse 트렌디 페르소나 근본 개선 (`[[lampas-agent]]`)

사용자: "pulse 에서 트랜디한 페르소나가 만들어져서 트랜디한 카피가 만들어지게 되어야 하는 데, 페르소나가
트랜디 하지 않는다."

> ⚠️ 이 절은 위키가 이미 기록한 [[lampas-agent]] "Pulse" 절의 **2026-09-24 채점 구조 확정
> 세션**([[2026-09-24-pulse-페르소나-카피점수-구조화-개선]])보다 **하루 앞선, 별개의 선행 수정**이다.
> 이전 위키는 "2026-09-24 이전엔 Pulse 상세 미확인"으로 기록돼 있었는데, 이 세션이 그 공백을 채운다 —
> 09-21에 먼저 근거 선정·페르소나 저장 구조를 고치고, 09-24에 이어서 4영역 채점 루브릭을 확정한
> 순서로 정정.

- **원인 3가지**: ① Pulse가 게시일 없이 **누적 조회수**만 보고 있어 오래된 고조회수 영상이 최신
  트렌드보다 우선됨. ② 모델이 인용한 **실제 댓글**이 저장 과정에서 사라짐. ③ Flow는 페르소나가
  하나뿐이면 이를 무시하고 **기본 캐릭터**로 대체.
- **수정**: 게시일 + 최근 7일 조회수 **증가 속도**를 함께 고려(수집 시점만으로 "최신"이라 판단하지
  않음). 페르소나에 **문장 리듬·훅 구조·카피 예시·피할 표현**을 저장해 Copy 생성·채점까지 전달.
  Pulse 화면에서 근거가 충분한지/재수집이 필요한지 표시.
- **검증**: 수정 경로 테스트 101개 + Pulse 화면 테스트 28개 통과. 댓글 인용·말투 정보가 JSON 응답
  처리 후에도 카피 생성·채점까지 유지되는지, 오래된 고조회수 영상보다 최신 근거가 우선되는지 확인.
  API+Pulse 배포, 운영 모델로 페르소나 4개 실제 생성·저장 확인. **기존 페르소나는 유지되며 새 기준은
  재생성해야 적용**.

## 2026-09-21 — "트렌드 분석" Work 신설 (키워드 기반 페르소나·카피 실험 + 평가 반복)

사용자: 특정 키워드로 유튜브 영상을 수집 → `[[lampas-agent]]` Pulse로 페르소나 생성 →
`[[lampas-web-copy]]`에서 페르소나별 카피 생성 → 페르소나·카피 각각 평가해 점점 더 잘 만들 수 있게.

- 기존 6단계 "Work"와 별개로 **원본 영상을 다운로드하지 않고**, 수집한 제목·캡션·댓글 근거만으로
  카피를 시험하는 새 Work 유형:
  1. **Pulse 수집** — 최근 7일 유튜브 영상을 키워드로 수집해 Work에 연결.
  2. **페르소나 생성** — 수집 근거로 4개 생성, AI 평가 동반.
  3. **카피 실험** — 페르소나별 10개씩 생성·독립 채점.
  4. **개선 반복** — 각 결과에 평점·수정 의견을 저장하고 "평가 반영 · 다음 실험 생성"으로 이전 평가를
     다음 생성 프롬프트에 반영.
- 평가는 **AI 점수**와 **사용자 평점·수정 의견**을 구분 저장. 회차(실험)별 결과·평가가 남아 비교 가능,
  Flow·Pulse·Copy 세 화면에서 같은 실험 기록을 열람. 긴 생성 요청은 백그라운드 처리(화면 이동·새로고침
  에도 진행 상태 유지). `[[lampas-agent]]`에 최근 7일 키워드 영상 수집 버튼 추가, 완료된 미션을 해당
  Work에 자동 연결.
- **배포 중 발견한 버그**: 수집 전에도 다음 노드가 "시작 가능"으로 잘못 표시(실행 자체는 정상 차단되고
  있었음, 표시만 부정확) — 함께 수정.
- 검증: 평가가 다음 생성 프롬프트에 반영되는 테스트, AI 채점 실패 시 기존 카피를 보존하고 채점만
  재시도하는 테스트 통과. Flow·Pulse·Copy·Agent 배포, 테스트 계정으로 재로그인 없이 동일 Work가
  세 화면에 표시되는지 확인.

## 2026-09-25 — Pulse 노드 "시작 버튼이 없다" 수정

사용자: 첨부 화면에서 시작 버튼이 안 보인다는 신고. 원인: Pulse 노드가 "시작 가능"으로 표시되지만
노드 상세에는 Pulse 작업 공간으로 **이동**하는 버튼만 있고 실제 **수집·생성 시작** 버튼이 없었음.
노드 상세에 수집·페르소나 생성·카피 생성 시작 버튼을 추가하고, 실행 불가 단계에는 필요한 선행 작업을
표시하도록 수정·배포(Flow 변경만 분리 배포). "키워드 수집 시작" 버튼 → Agent 수집 화면으로 이동 →
그 화면에서 다시 "키워드 수집 시작"을 눌러야 실제 수집이 시작되는 2단계 흐름.
