# 카카오 지도 API 키 발급 (2026-09-26)

`Tool: claude` 세션(08:32:51Z 시작, 작업 디렉터리 `lampas-system`). `[[progdesigner]]`가
`[[lampas-web-spot]]`(맛집 지도, `spot.lampas.io`)에 카카오 지도를 연동하려고 API 키 발급을
요청한 세션. [[2026-09-26-ai-dalar-인스타그램-토큰발급-메타앱생성]] 세션(같은 날 08:29:35Z 시작,
불과 3분 전)과 거의 동시에 진행된 별도 세션이며, 둘 다 "Harness 브라우징 패널"(→ [[lampas-browser]])을
사용했다.

## 진행 경과

1. **대상 앱 추정** — git 상태에 `lampas-web-spot`의 음식점 데이터가 수정 중인 것을 보고 이 앱으로
   짐작, 사용자에게 확인 요청과 함께 로그인 위임(카카오계정 QR 로그인 권장).
2. **새 앱 생성** — 기존 앱 20개 중 Lampas 관련 앱 없음 확인 → 이름 "Lampas Spot", 회사명
   "Elevino"(기존 소유 앱과 동일), 대표 도메인 `https://spot.lampas.io`로 신규 생성(앱 ID
   **1588569**).
3. **모달 스크롤 장벽** — "앱 생성" 모달 내부(카테고리 선택 목록, 하단 약관 체크박스)가 브라우저
   도구로 스크롤이 안 돼 막힘 → 사람에게 "카테고리를 식음료로 바꾸고 체크박스 켠 뒤 저장"이라는
   구체적 액션만 위임, 나머지는 이미 채워둠.
4. **키 3종 확보** — JavaScript 키(지도 Web SDK)·REST API 키(주소 변환·장소 검색)·네이티브 앱 키
   발급 확인(값은 원본 소스에만 보존, 이 요약에서는 생략).
5. **과금 문제 발견 → 활성화 일시 중단** — 카카오맵은 계정당 **최초 활성화 앱 1개에만 무료
   일간 쿼터**를 부여한다는 사실을 먼저 (잘못) 판단 — 같은 계정의 기존 `spark` 앱(ID 1052366,
   Editor 권한)이 이미 무료 쿼터 배지를 갖고 있다고 보고 활성화를 멈추고 3가지 선택지(①Lampas
   Spot 유료 진행 ②spark 앱 키 재사용 ③다른 계정으로 재생성)를 제시, ①을 추천.
6. **사용자가 ① 선택** → 진행 후 **직전 판단이 틀렸음이 드러남**: `spark` 앱의 무료 쿼터 배지는
   다른 소유자 계정 것이라 무관했고, `Lampas Spot`을 켜자 이 앱에 바로 일간 무료 쿼터가 부여됨
   (비즈월렛·유료 API 설정 불필요). 콘솔에서 비즈 앱 전환도 자동 확인됨.
7. **도메인 등록** — JavaScript 키 "Lampas Spot Web"에 `https://spot.lampas.io`와
   `http://localhost:8478`(spot 개발 포트) 등록, curl로 등록 도메인 Referer는 200·미등록 도메인은
   401로 검증.
8. **env 3곳 반영** — `apps/lampas-web-spot/env/.env.production`·`.env.local`·최상위
   `.env.local`(기존 빈 파일)에 `VITE_KAKAO_MAP_JS_KEY` 기입. REST API 키는 서버·스크립트 전용이라
   번들에 넣지 않음(README에 주석으로만 안내).
9. **README에 "카카오맵 연동" 절 추가** — 콘솔 위치, 키 종류, 도메인 추가 방법, REST 키 비번들
   원칙 문서화.

## 핵심 판단 — 도메인 제한 클라이언트 키는 공개 커밋 대상

JavaScript 키는 도메인 제한이 걸린 브라우저용 클라이언트 키라, 어시스턴트는 "다른 앱들이 공개
클라이언트 ID(예: Google Client ID)를 추적 env 파일에 커밋하는 관례와 같은 방식으로 다룬다"고
판단해 그대로 커밋했다. REST API 키(서버 전용, 도메인 제한 없음)는 반대로 env에 넣지 않고 문서화만
했다 — **같은 세션 안에서 "공개해도 되는 클라이언트 키"와 "노출되면 안 되는 서버 키"를 구분해
처리한 사례**로 [[secrets-plaintext-exposure-pattern]]에 반영.

## 미해결·후속 과제

- **spot 앱은 여전히 Leaflet + OpenStreetMap 사용 중** — 카카오 SDK로 실제 지도를 교체하는 작업은
  **별도로 미착수**. [[lampas-web-spot]] 페이지에 기록된 "2026-09-24/25 OpenStreetMap 단일 경로
  확정" 결정과 정면으로 상충하는 새 방향(카카오 재도입 준비) — 아래 엔티티 갱신에서 모순으로 명시.
- 커밋 안 함 — spot 디렉터리에 이 작업과 무관한 미커밋 변경(맛집 데이터, `package.json`)이 섞여
  있어 정리 필요.
- 새 개발 포트·도메인 추가 시 콘솔 플랫폼 키에 추가 등록 필요.

## 하네스 브라우징 패널 한계 — 세 번째 확인 사례

로그인 화면에서 비밀번호 입력이 막혀 사람에게 위임한 것은 기존 관찰([[lampas-browser]],
[[meta-oauth-token-console-popup-unreliable-in-automated-browser]])과 동일 패턴이지만, 이 세션은
**모달 내부 스크롤 불가**라는 새로운 구체적 한계를 추가한다(카테고리 목록·체크박스가 뷰포트 밖에
있어 도구가 닿지 못함). [[2026-09-26-ai-dalar-인스타그램-토큰발급-메타앱생성]]과 3분 간격으로
거의 동시에 발생한 별도 세션에서 각각 독립적으로 "막히면 정확히 필요한 만큼만 사람에게 위임" 전략을
쓴 것도 동일 — 일반화한 스킬: [[browser-automation-human-handoff-for-blocked-ui]].
