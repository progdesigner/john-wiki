# 2026-09-25 — status 서비스 구축·운영 배포

`Tool: claude` 세션(2026-09-25 22:04 UTC 시작). "status.claude.com 처럼 내 시스템의 스테이터스를
관찰하고 분석하는 status.lampas.io 를 만들어줘" 요청으로, `[[lampas-studio]]`(`lampas-system`) 저장소에
**상태 페이지 서비스를 처음부터 구현하고 운영까지 배포**한 세션. `[[lampas-agent]]` 엔티티 페이지에
"2026-09-25 첫 배포"로만 짧게 언급되어 있던 `[[lampas-web-status]]`의 원본 구현 세션이다.

## 만든 것

- **`apps/lampas-api/src/modules/status`** — 컴포넌트 레지스트리(40개: Lampas API 헬스·AI 게이트웨이·
  MySQL, 배포된 웹 도메인 전부(lampas.io/dalar.ai/toktalk.ai/iileex.com), 로컬 에이전트 `/healthz`,
  트렌드 S3 스냅샷 신선도, Atlas Cloud)를 60초마다 병렬 프로브. 원시 기록(7일 보존) + 한국시간 일 집계
  (90일 바) 2단 저장.
- **판정 규칙(순수 함수)**: 2xx/3xx 정상, 헬스 JSON은 `status:'ok'` 또는 `ok:true`, S3 스냅샷은 15분
  경과 시 저하·30분이면 장애, 응답 3초 초과는 저하로 판정.
- **자동 인시던트**: 3회 연속 실패 → 오픈(core 컴포넌트면 심각), 3회 연속 정상 → 자동 해결.
- **공개 API**: `GET /v1/status`(전체+그룹+90일 일별+1/7/30/90일 업타임+인시던트, 10초 캐시),
  `GET /v1/status/components/:id?hours=`(시간별 가용성·p50/p95·최근 프로브), `GET /v1/status/incidents`.
  관리용 `/v1/admin/status/*`(인시던트 CRUD·즉시 프로브).
- **`apps/lampas-web-status`**(포트 8461) — status.claude.com 형태 UI: 전체 상태 배너, 그룹별 90일
  업타임 바(툴팁), 행 클릭 시 드로어(응답시간 그래프·시간대별 가용성·이상 프로브), 분석 패널(느린
  곳·장애 일수·평균 복구 시간), 진행중/지난 14일 인시던트.
- **`lampas-web-admin` `/status`** 페이지 — 인시던트 수동 등록·업데이트·종료.
- 문서(루트 CLAUDE.md/AGENTS.md, API CLAUDE.md/LOG.md, 앱 README) + 루트 스크립트 갱신.

## 발견한 점 (배포 전)

- `photobooth.lampas.io`는 DNS가 없어 항상 장애로 잡혀 관측 대상에서 제외(`deploy.json`엔 남아 있음 —
  실서빙 계획 있으면 재확인 필요).
- Atlas Cloud는 루트 경로가 404라 `/v1/models`로 도달성 판정.
- API 전체 jest에서 **sports-wiki spec 9건 실패** — 작업본에 이미 있던 미커밋 sports-wiki 수정 때문이고
  이번 status 변경과 무관하지만, 배포 스크립트의 테스트 게이트를 막는 상태로 남음.

## 운영 배포 (사용자 지시 "배포 진행해"로 실행)

1. 운영 DB에 상태 페이지 테이블 4개 DDL 적용(`tools/apply-status-page-ddl.sh`).
2. **드리프트 검사에서 예상 밖 발견**: 작업본의 미커밋 sports-wiki 작업이 쓰는 `sports_wiki_games`
   테이블이 운영 DB에 없음을 발견 — 배포되는 API 코드가 이 테이블을 참조하므로, 기존에 있던 DDL
   파일로 추가 생성해 함께 반영. (`sports_wiki_games`는 [[2026-09-25-스포츠위키-경기엔티티-설계구현]]
   세션에서 신설된 테이블.)
3. `deploy-api.sh lampas-api` — 테스트 게이트 통과, PM2 재기동(버전 0.1.144).
4. `distibute-web.sh lampas-web-status` — CloudFront 신규 생성 + Route53 최초 연결.
5. `deploy-web.sh lampas-web-admin` → `deploy-web.sh lampas-web-status` 순 배포.
6. 커밋 `e1b0419d`로 상태 페이지 관련 변경 묶음.

## 알아둘 점

- **sports-wiki spec 9건은 재현 실패였다** — 단독 재실행에서 전부 통과. API 빌드와 동시에 실행되며
  생긴 일시적 실패로 결론, 배포 게이트도 이 재실행으로 통과시킴.
- **커밋 범위를 의도적으로 제한**: sports-wiki의 Prisma 모델·DDL만 커밋(운영에 테이블이 생겼으니
  저장소 스키마와 맞추기 위해). sports-wiki 코드 변경 자체와 copy·agent 등 나머지 작업본 변경은
  그대로 미커밋 상태로 남겨둠.
- 자동 인시던트는 3회 연속 실패(≈3분 뒤) 오픈, 3회 연속 정상이면 닫힘. 수동 등록은
  admin.lampas.io "상태 페이지" 메뉴.
- **새 서비스 추가 시 등록 지점**: `apps/lampas-api/src/modules/status/lib/status-components.ts`에
  한 줄 추가. 빠뜨리면 `deploy.json`과 비교하는 spec이 잡아줌.
