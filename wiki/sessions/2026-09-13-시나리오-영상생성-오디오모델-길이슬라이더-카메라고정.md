# 2026-09-13 — 시나리오 영상생성: 오디오모델 선택·길이 슬라이더·카메라 고정

`Tool: claude`, 작업 폴더 `lampas-system`. `[[progdesigner]]`가 `[[lampas-web-scenario]]`(신규 노출
앱, 아래 참고)의 컷별 영상 생성 기능에 3가지 개선을 한 번에 요청 — ① 이미지+텍스트+오디오를 함께
쓰는 다른 모델도 선택할 수 있게, ② 영상 길이를 10초 고정이 아니라 5~30초 슬라이더로(대본 기준
자동 추정), ③ 카메라 고정 지시가 모든 영상 프롬프트에 자동으로 들어가게. `[[lampas]]`가 구현 전
서브에이전트 3개를 순차로 띄워 조사한 뒤 한 번에 구현했다 — 이 저장소에 이미 있는
[[parallel-survey-before-feature-gap-analysis]] 절차의 변형 적용 사례.

## 조사 단계 (서브에이전트 3개, 순차)

1. **"Explore scenario video generation code"** — 프론트 트리거(`StoryboardGrid.tsx`
   "영상 만들기" 버튼)→핸들러(`ScenarioPage.tsx:handleGenerateSceneVideo`)→백엔드(전용 엔드포인트
   없음, `POST /v1/ai/model/generateVideo` 제네릭 게이트웨이 패스스루)→모델/길이 하드코딩 지점
   →프롬프트 조립 경로 전체를 한 번에 지도화. **결론: 이미지+텍스트+오디오 결합 모델(립싱크/아바타)은
   시나리오 앱에 전무** — 대사는 지금 텍스트 프롬프트에 "The subject speaks to camera in Korean:
   ..."로만 박혀 들어가고, 실제 오디오 파일을 넣는 경로는 없음. 길이 상한 "10"이 클라이언트 코드
   두 곳(`storyboard-video.ts`, `scenario-api.ts`)에 별도 하드코딩돼 있고 서버 clamp는 1~15초로
   달라 세 값이 서로 다름.
2. **"Check audio-driven video model schemas"** — Atlas Cloud 가격 카탈로그
   (`model-pricing.generated.ts`)에서 이미지+오디오 입력 후보 6개(`infinitetalk`,
   `avatar-omni-human-v1.5`, `kling-v2.6-pro/std avatar`, `sync/lipsync-v3`, `veed/lipsync`)를
   찾았지만, **카탈로그 타입(`ModelCapabilities`)엔 요청 필드 정보가 전혀 없음**(duration/resolution/
   aspect/generate_audio만 기록) — `usedFor` 설명 문장만으론 실제 body 스키마를 알 수 없다는 게 이
   세션의 핵심 발견. 저장소 전체에서 실사용 증거를 찾아 `lampas-web-tools`의
   `talking-photo.ts`(`kwaivgi/kling-v2.6-std/avatar`를 `{ image, audio }`만으로 호출, `prompt`
   없음)를 유일한 프로덕션 근거로 확보. → [[atlas-cloud]]
3. **"Research scenario shot audio and duration data model"** — `LineAudio`(대사 줄당 오디오,
   `sessions-api.ts`) 타입과 `shot.lineAudios` 배열이 이미 S3 URL을 들고 있어 오디오 기반 모델에
   바로 먹일 수 있음을 확인. `handleGenerateSceneVideo` 안에서 `shot.lineAudios`·
   `linesOfScene(scene)`·`characters`가 이미 스코프에 다 있어 추가 배선 없이 오디오 URL을 뽑아낼 수
   있다는 것, 그리고 `fetchVideoModels()`의 `image-to-video|i2v` 정규식 필터가 아바타/립싱크
   모델을 애초에 걸러낸다는 것(필터 확장 필요)까지 확정.

## 구현 (조사 종료 후 한 번에)

1. **오디오 구동 아바타 모델 4종을 드롭다운에 추가** — `kling-v2.6-pro/avatar`,
   `kling-v2.6-std/avatar`, `atlascloud/infinitetalk`, `bytedance/avatar-omni-human-v1.5`. 실제
   Atlas Cloud 라이브 OpenAPI 스키마를 직접 확인해(카탈로그가 기록 못 하는 부분) 이미지+오디오
   +선택적 텍스트 프롬프트를 함께 받는다는 걸 검증했다고 어시스턴트가 보고. 선택 시 그 컷의 대사
   오디오(기존 line-audio/TTS 기능 산출물)가 영상을 구동하고, 그 오디오가 없으면 "영상 만들기"
   버튼이 비활성+안내.
2. **길이 슬라이더 5~30초 + 대본 기반 자동 추정** — 기존 10초 고정 상한 제거. 신규
   `estimateSceneVideoDuration()`가 컷의 대사/모션 텍스트 길이로 추정(한글 초당 ~4.5자, 기존
   line-audio 추정과 동일 휴리스틱). 추정값이 슬라이더 기본값, 수동 조정 시 컷별 override로
   저장·재로드 유지. 오디오 구동 모델 선택 시엔 길이가 입력 오디오로 정해지므로 슬라이더 숨김.
3. **카메라 고정 지시 자동 삽입** — `CAMERA_LOCK_INSTRUCTION` 상수를 컷별/전체 스토리보드 영상
   프롬프트 양쪽 끝에 자동 추가, 고정 카메라·일관된 구도를 지시.

검증: `storyboard-video.test.ts`·`scene-lines.test.ts`·신규 `scenario-api.test.ts` 포함 131개
테스트 통과(신규 12개), `tsc --noEmit` 클린, vite 빌드 확인.

## 결정사항 / 관찰
- 카탈로그(`model-pricing.generated.ts`)는 **가격·duration/resolution 정보만** 갖고 있고 요청 body
  스키마(어떤 필드를 받는지)는 기록하지 않는다 — 새 모델을 붙일 때는 카탈로그 설명 문장을 믿지 말고
  라이브 Atlas OpenAPI 스키마나 저장소 내 실사용 코드를 근거로 확인해야 한다. → [[atlas-cloud]]
- 길이 상한이 여러 곳(client 2군데 10초, server clamp 1~15초)에 흩어져 서로 다른 값으로 하드코딩돼
  있던 것이 이번에 5~30초로 통일됨 — 다른 앱에서도 같은 흩어짐 패턴이 있을 수 있음(미조사).
