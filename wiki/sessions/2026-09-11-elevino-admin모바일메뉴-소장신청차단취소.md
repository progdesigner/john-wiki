## 1. elevino-admin 모바일 메뉴 즉시 닫힘 버그 수정
- 증상: "모바일에서 메뉴가 위로 안 떠서 이동을 못한다" — 메뉴를 열어도 바로 닫혀 항목 이동 불가.
- 근본원인: 메뉴를 열면 화면 크기를 재확인하는 코드가 다시 실행되며 곧바로 닫힘(리사이즈/화면폭
  체크 로직이 열림 상태를 되돌림).
- 수정: 즉시 닫힘 로직 제거, 메뉴가 본문(목록) 위에 표시되도록 z-index/레이어 조정, 항목 선택 후
  이동하며 메뉴가 닫히도록 정리.
- 검증: 작업 환경에서 React 타입 충돌 발견 → 배포 스크립트가 쓰는 독립 환경에서 운영 빌드 별도
  검증. 실제 Chrome 모바일 화면 크기에서 열림 유지·메뉴 이동·배경 터치로 닫기 확인.
- 배포: 기존 운영 파일 백업 후 [admin.elevino.io](https://admin.elevino.io)에 반영, 운영 주소
  재확인까지 완료.

## 2. 소장하기(신규 신청) 차단 + 관리자 기존 신청 취소 기능
- 요청 배경: "소장하기 신청 안 되도록" — 버튼을 누르면 **"더이상 지원하지 않습니다."** 메시지만
  뜨고 신청이 전송되지 않아야 함. 기존 결제 페이지로 직접 진입해도 신규 신청이 진행되지 않도록
  방어.
- 대상: `elevino-api`(API 레벨 신규 신청 차단), `elevino-web`(버튼 클릭 시 안내 메시지 표시).
- 관리자(`elevino-admin`) 후속 요청: "기존 소장 관련 기능도 보일 수 있게 메뉴 추가 — 잘못 신청한
  사람들 취소하려고". 조사 결과 관리자에서 소유권(소장) 관련 메뉴 자체가 숨겨져 있었고, 신청
  상세 화면에 취소 버튼도 없었음.
- 구현:
  - 관리자 **SUPPLY → 소장 신청 관리** 메뉴 신설.
  - 대기 중(승인 대기, 미결제) 신청만 상세 화면에서 **신청 취소** 가능 — 이미 결제된 내역은
    상태 확인을 거쳐 잘못 취소되지 않도록 방어.
  - API 검증 16개 통과, 3개 앱(api/web/admin) 빌드 통과.
- 검증: 모바일에서 버튼을 눌렀을 때 안내 메시지만 뜨고 신청 요청이 전송되지 않음 확인, 관리자
  메뉴→신청 상세→취소 확인창 흐름 검증.
- 배포: API·관리자 우선 배포, 웹 반영 후 캐시 갱신. 운영 API에서 신규 신청 차단, 관리자 인증
  없이는 취소 불가함을 운영 환경에서 재확인. **기존(이미 존재하던) 신청은 이 작업에서 직접
  취소하지 않았음**(관리자에게 취소 "가능하게" 만들었을 뿐).
