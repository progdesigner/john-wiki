# 2026-07-15 — Auto 모델 난이도 자동선택 기능 최초 구현

`[[lampas-harness]]` 웹 채팅 세션. 22:42~22:52 UTC, 6개 왕복(대부분 어시스턴트 단독 진행 로그).
**[[2026-07-15-auto모델-난이도판정-확인ux-개선]](23:23~23:31, 같은 날 31분 후)이 감사한 "기존
Auto 로직"의 실제 원본 구현 세션** — 그 세션이 인용한 커밋 메시지("feat: 모델 선택기에 Auto —
난이도를 분류해 Claude 모델 자동 선택", v0.1.25)가 이 세션의 결과물이다.

## 요청

"하단에 Auto 기능을 넣어서 작업의 난이도에 따라서 claude 모델을 다르게 자동으로 선택해주는 기능을
만들어주고 이를 판단하는 모델은 뭐가 좋을지 너가 잘 생각해서 적용해줘" — 기능 자체뿐 아니라 **판정에
쓸 모델 선택도 어시스턴트 재량**에 위임.

## 구현

- 모델 선택 UI(드롭다운)와 서버 모델 처리 흐름을 탐색 에이전트로 먼저 파악.
- `runChatTurn`이 `auto`를 해석하도록 서버 로직 신설, 프런트엔드 3곳 수정.
- 모델 드롭다운 맨 위에 **"Auto — 난이도 자동 선택"**을 모델 필터 설정과 무관하게 항상 노출.
- 실제 배정된 모델은 질문 말풍선에 `auto·claude-sonnet-5`처럼 표시. Auto는 항상 Claude로 해석되므로
  대화별 "API 사용" 과금 토글([[sdk-claude-code-vs-api-billing]])도 그대로 유효.
- 커밋 `802af89`. 진행 중이던 다른 대화 큐가 비면 데몬 자동 재시작으로 반영(이 세션 자체는 재시작을
  직접 실행하지 않음, [[self-hosted-agent-server-ops]] 패턴).

## 판정 모델 선택 근거

분류가 "한 단어 라벨링"이라 지능보다 속도·비용이 중요 → **Claude Haiku 4.5**를 1순위로 결정.

**검증 중 발견한 비자명한 사실**: `.env`에 `ANTHROPIC_API_KEY`는 있지만 **크레딧 잔액이 0이라 API
직접 호출이 400으로 거절**됨. 어시스턴트가 스스로 "비자명한 사실"로 판단해 기억에 저장.
→ 기존 [[sdk-claude-code-vs-api-billing]]·[[long-term-memory-architecture]]가 기록해 온 "API
크레딧 소진이 `/compact`·백그라운드 `memory-ingest`를 실패시킨다"는 관찰의 **근본 원인이 잔액 0임을
이 세션에서 최초로 명시적으로 확인**.

이 발견에 따라 3단계 순차 폴백을 설계:

1. **Haiku 4.5 (Claude API)** — 현재 크레딧 부족으로 실패
2. **rapid-mlx 로컬 LLM(Qwen3.5-35B)** — 현재 실제로 동작하는 판정 경로. 속도 ~250ms, 비용 0원
3. **휴리스틱(키워드·길이)** — 로컬 서버까지 꺼져 있어도 턴이 막히지 않는 최종 안전망

## 로컬 판정 검증

실제 예시 7건(인사, 블로그 글 다듬기, 기능 구현, 로그 조회, 이메일 초안, 보안 감사 등)으로 테스트해
7/7 기대대로 분류. 초기엔 "블로그 글 다듬기 → easy"로 오분류됐던 것을 프롬프트에 few-shot 예시를
추가해 수정. **설계 원칙**: 애매하면 상위 티어로 틀리게 설계 — 판정이 어긋나도 "약한 모델이 어려운
일을 받는" 최악의 경우는 피함. (같은 원칙이 31분 후 세션에서 extreme 티어 도입 시 "모호하면 hard"로
재사용됨.)

## 향후 자동 승격

Anthropic 크레딧을 충전하면 **별도 코드 수정 없이** 판정이 Haiku 경로로 자동 승격됨(호출당 비용은
원 단위 미만) — 폴백 체인이 이미 그렇게 설계돼 있기 때문.
