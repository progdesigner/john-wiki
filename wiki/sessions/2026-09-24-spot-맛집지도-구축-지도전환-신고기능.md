# spot.lampas.io 맛집 지도 구축 — 지도 프로바이더 3회 전환·데이터 2단계 확장·폐업 신고 (2026-09-24~25, codex 도구)

컨텍스트는 2026-09-25로 갱신되어 있어 **날짜를 넘겨 이어진 장시간 세션**. 원본:

## 요청 배경
[[progdesigner]]가 블루리본(`bluer.co.kr`) 맛집 사이트의 전체 주소를 수집해 네이버/카카오 지도
기반으로 `spot.lampas.io`에 맛집 지도를 만들어달라고 요청.

## 1단계 — 스크래핑 차단, 빈 지도로 선(先)배포
- 블루리본 메인·검색 페이지가 모두 **403**을 반환해 자동 수집이 시작부터 막힘.
- 카카오 지도 컨셉으로 검색·지역/리본 필터·즐겨찾기·카카오 길찾기 UI를 먼저 구현해
  `spot.lampas.io`에 준비 상태(맛집 0건)로 선배포.

## 2단계 — 엑셀 첨부 579곳 반영
- 사용자가 첨부한 `맛집 모음.xlsx`: 중복 없는 **579곳**(3리본 46·2리본 320·1리본 192·0리본 21),
  주소·원문 링크 포함, **좌표 없음**.
- 좌표가 없어 우선 목록(소개·주소·선정 정보)만 반영하고 각 항목에서 카카오맵 검색 링크로
  연결. 사용자가 "지도로는 못 보는 거야?"라고 재차 확인 → 링크 이동만 가능하고 **Spot 자체
  지도 위 표시는 미구현**임을 명확히 함.

## 3단계 — 지도 위 핀 표시 요구 → 오픈스트리트맵 채택
사용자가 "지도로 표시하는 기능 만들어줘" / "키가 필요해?"로 재차 요구하자, **네이버·카카오
지도는 사이트 내 삽입에 API 키가 필요**하지만 **OpenStreetMap은 키 없이 바로 가능**하다는
이유로 OSM을 우선 채택. 주소→좌표 변환은 Nominatim, 요청 정책(초당 1회 이하·결과 캐싱)을
지키며 진행 — 절차 상세는 [[nominatim-batch-geocode-progressive-rollout]] 스킬로 추출.

- 좌표가 주소·건물번호까지 정확히 일치하는 경우만 핀 표시(도로 위 대략 위치만 나오면
  "위치 미확인"으로 남김 — 오표시 방지).
- 진행 중 확인 건수를 단계적으로 배포: 130/175 → **200 핀 배포** → 219/300 → 275/375 →
  305/425 → 350/500 → 최종 **394/575 확인, 396핀 배포**(183곳은 목록에 카카오맵 검색
  링크로 유지).

## 4단계 — 네이버 지도 시도 → 인증 실패(401) → 자동 폴백
사용자가 네이버 클라우드 콘솔 스크린샷(Client ID)을 첨부하며 네이버 지도로 다시 만들어
달라고 요청.
- 신규·구(舊) 방식 두 SDK 경로 모두 구현했으나 `spot.lampas.io`에서 **401 인증 실패**.
  원인으로 네이버 클라우드 콘솔의 **Dynamic Map 미활성화** 또는 **Web 서비스 URL에
  `spot.lampas.io` 미등록**을 지목하고 사용자에게 확인 요청.
- 인증 실패 시에도 기존 OSM 지도로 **자동 전환**하는 폴백을 구현해 서비스 중단 없이 배포.
  Client Secret은 사이트에 포함하지 않음(Client ID만 프론트에 노출).
- **이 시점(2026-09-24 저녁)에 별도 세션이 원격 병합 커밋으로 이 앱을 처음 포착**했는데
  ([[lampas-web-spot]] 스텁 근거, 세션 [[2026-09-24-studio개선-seedance미니-노드툴바-멀티커밋푸시]]),
  당시 `.env.local`/`env/.env.production`에 남아있던 네이버 지도 클라이언트 ID가 바로 이 4단계
  작업의 산물 — 아직 제거되기 전 시점의 스냅샷이었다.

## 5단계 — 구글 시트 데이터로 738곳까지 확장
- 사용자가 구글 시트 링크 공유. 처음엔 비공개라 **401**로 읽기 실패 → 사용자가 "링크가
  있는 모든 사용자·뷰어"로 공개 설정 변경 후 재시도해 접근 성공.
- 시트 구성: 블루리본 통합 목록 **657곳** + 지역별 추가 탭 + 다이닝코드 90점 이상 **86곳**.
- 이름·주소가 일치하는 출처 간 중복 5건을 병합해 **579 → 738곳**으로 확장. 기존 지도 좌표
  396곳은 모두 유지. 출처별 필터(블루리본/다이닝코드), 동네 모음(석촌호수·광화문·압구정·
  도산공원·군자동), 다이닝코드 점수·영업시간·메뉴 표시를 추가.
- 신규 주소 좌표 확인을 이어가 최종 **738곳 중 502곳 지도 표시**(236곳 위치 미확인, 목록
  + 카카오맵 검색 링크로 유지).

## 6단계 — 네이버 지도 제거, 오픈스트리트맵으로 확정
사용자 지시 "네이버 지도는 제거하고 오픈 맵으로 그냥 하자" → 네이버 SDK·키 설정·인증
오류 안내 UI를 전부 제거하고 **OpenStreetMap 단일 경로로 확정**. 기존 데이터(738곳)와
지도 핀(502개)은 그대로 유지한 채 재배포.

**결론: `spot.lampas.io`는 최종적으로 카카오·네이버 지도가 아니라 OpenStreetMap 기반이다.**
[[lampas-web-spot]] 스텁이 병합 커밋 시점 env 파일 근거로 "네이버 지도 기반으로 추정"이라
기록했던 것은 이 세션의 **중간 단계(4단계) 스냅샷**이었을 뿐, 이 세션 자체의 최종 결정과는
다르다 — 아래 엔티티 갱신에 이 시점 차이를 명시.

## 7단계 — 폐업·정보 신고 기능
사용자 요청 "없어진 건 신고 해서 뺄 수 있게 해줘"에 따라:
- 맛집 상세에서 폐업/오류 신고(사유·설명 입력) → 접수 번호 표시.
- 신고 내용은 **기존 Lampas 관리자 문의함**에 저장(별도 인프라 신설 없음).
- 신고한 사용자는 즉시 **자신의 지도·목록에서만** 해당 장소를 숨김/복원 가능.
- **전체 목록 제외는 운영자가 문의함을 검토한 뒤 수동 반영**(자동 제외 아님).
- 운영자가 전체 제외 처리한 장소는 구글 시트 재동기화 후에도, 개인 숨김을 복원해도
  **다시 나타나지 않음**(제외 기록이 시트 재수입과 독립적으로 유지).
- 전송 실패 시 장소를 숨기지 않고 재시도 가능. 검증은 모의 신고로 진행해 실제 문의함에
  테스트 데이터를 남기지 않음.
