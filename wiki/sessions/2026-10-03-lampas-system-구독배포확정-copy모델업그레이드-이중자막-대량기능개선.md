## 1. 유튜브 플레이리스트 구독 자동 수집 — 배포·검증 완료
[[2026-10-03-lampas-agent-플레이리스트구독계획-codex원본]]이 Codex와 합의한 6단계 계획을 이어받아
구현 완료, **agent 1.0.30, 커밋 `766a52e8`로 배포**. 상세 → [[lampas-agent]] "실배포·검증 완료" 절.
핵심만: 개별 URL=즉시 큐, 재생목록 URL="구독"(1시간마다 전체 목록 확인, 개수 제한 없음), 영상ID 기준
중복 스킵(명시적 재등록은 예외), 처리는 전부 맥미니 yt-dlp+FFmpeg, 재시작 시 완료 단계 건너뛰고 이어감,
네트워크 오류 1→30분 3회 재시도, 비공개·삭제·크레딧부족은 사유 표시 후 정지. **실제로 확인됨**:
클립 3개 등록부터 강제종료 재기동 복구, 중복 미발생, 크레딧 부족→재개, 478개 테스트 통과까지. 아직
미검증: 200개 넘는 재생목록(이 세션 후반에 6,101개로 해소됨), 24시간 연속 운영, 브라우저 방식과의
직접 속도 비교.

**결정**: 완전 무인화를 위한 "운영 API Key 인증 확장" 제안을 사용자가 **명시적으로 거부** — "비용이
올라간다"는 이유. 어시스턴트가 "전사·라벨 크레딧은 API Key로 바꿔도 똑같이 계정에서 차감되므로 비용
자체는 안 바뀐다"고 정정했지만, **운영 API를 안 건드리는 쪽이 더 단순하다는 이유로 현재 로그인 토큰
방식(7일 갱신) 유지가 최종 결정**. 남은 과제 메모에서 "API Key 확장"은 "하지 않기로 한 결정"으로 정정.

## 3. 사고 — 다른 세션 미커밋 변경이 함께 배포됨 (포토부스 중복과금 수정)
위 1번 API 배포 시 "작업 트리 확인+배포"를 한 명령으로 이어 실행하는 바람에, [[2026-10-03-포토부스-transform-크레딧중복소진-환불]]
세션이 로컬에만 남겨둔 미커밋 수정(`credits/app-credit.guard`, `transforms`)이 **운영 0.1.171에
의도치 않게 함께 배포됨**. 되돌리면 중복 과금이 재발하므로 그대로 둠 — 이 세션의 커밋에는 넣지 않고
해당 세션에서 커밋하도록 남겨둠. **이 사고가 바로 그 세션의 "배포 여부 미확인" 열린 질문에 대한
사실상의 답**이다(의도한 배포는 아니었지만 실제로 운영에 나갔다). → 아래 "8. 전체 코드 커밋"에서
git 커밋까지 완전히 해소됨. 스킬 [[app-session-flat-fee-vs-server-metered-double-charge]] 갱신.

## 4. clips.lampas.io "영상이 다 안 보인다" / copy와 점수가 다르다 — 원인 진단 + 부분 수정
읍기 전용 조사 먼저(운영 클립 739개, 아무것도 안 고침) → 사용자 확인 후 수정·배포(커밋 `f5d8b727`).
**6가지 원인**(분야 필터 상시 적용, 소스 5개 분류 오류, 오늘 추가한 "업로드 소스 제외"의 과도 적용,
100개 페이지네이션, 80점 미만 카드 50% 흐림, 저장된 옛 필터)과 **점수 불일치 2원인**(clips는 블렌드
점수, copy는 저장된 훅 점수 / 정렬 범위 차이) 전부 진단. 실제 고친 것: 업로드 제외 기준을 "클립 1개
짜리만 제외"로 축소(숨겨졌던 9개 소스·332클립 복원), MLB 소스 3개(67클립) 재분류, clips 배지를 copy와
같은 훅 점수로 통일. 그대로 둔 것: 페이지네이션·흐림 표시·copy 기본 필터·계주팀 2개 소스(카테고리
미정)·훅 미계산 클립 40개. 상세 → [[lampas-web-clips]] "클립이 안 보이던 문제" 절.

## 6. copy.lampas.io — 모델 업그레이드 + 여러 페르소나 동시 생성 + 채점 타임아웃 수정
가장 비중이 큰 단일 작업(커밋 `055b6304`→`a6f70492`→`1af6902c`/`5c919b79`, agent 1.0.33):
- **모델 업그레이드**: 생성 GPT 6 Astra→**GPT 6.1 Sol**(단가 1/5, ~2배 빠름), 채점 Claude Opus 5→
  **Opus 5.5**(단가 20%↓이나 테스트에서 더 느림). 단가표 전체 재동기화(33개 추가·5개 제거).
- **여러 페르소나 동시 생성**: 3단계 다중선택+전체선택, 페르소나별 탭+종합 순위 탭, 생성 중에도
  추가 페르소나 선택 가능(중복 생성·중복 과금 방지), 조건 바꿔 재생성.
- **채점이 오래 걸리던 문제의 원인은 바로 오늘 올린 Opus 5.5**였다: 카피 10개를 한 번에 채점하면
  생각 토큰까지 합쳐 응답이 중간에 잘림(JSON 파싱 실패) → 폴백(Grok 4.6)으로 넘어가 5분 타임아웃.
  **2개씩 5묶음 동시 채점**으로 수정, 전체 ~1분으로 단축. 비용도 실측(~500크레딧/회)으로 화면에 정정
  표시. → 이 실패 패턴은 [[llm-batch-inference-timeout-tuning]] 스킬의 새 사례로 편입(모델 업그레이드
  직후 운영에서만 드러나는 배치 크기 문제의 재현). 상세 → [[lampas-web-copy]].
- 클립 미리보기 위치를 목록 **아래**로 이동(커밋 `deccbcfd`), 뷰티 하위 "피부"→"**스킨케어**" 리네임
  (커밋 `94845ff3`, 운영 DB 즉시 반영, 내부 키도 `skin`→`skincare`로 Pulse와 맞춤).

## 7. reels.lampas.io — 플랜 화면 2단계 재편
- `/plans`에서 소스를 고르면 **그 소스로만 만든 편집 그룹만** 표시(커밋 `9abb0d9f`) — 그룹 클립 정보
  100개 제한도 전체 조회로 수정(썸네일 비는 문제도 같이 해소).
- `/plans`에서 **페르소나 선택 단계를 완전히 제거**, 선택한 클립으로 만든 **모든 카피를 페르소나
  구분 없이 점수순**으로 보여주는 방식으로 교체(커밋 `991fc048`) — 단계가 6→5로 줄고, 같은 세션 앞서
  추가했던 "분야별 페르소나 선택" 기능이 이 변경으로 화면에서 함께 빠짐. → [[lampas-web-reels]].

## 8. edit.lampas.io — 템플릿 삭제 확인, 이중 자막, 세로정렬 아이콘, 템플릿 덮어쓰기
- 템플릿 ✕ 삭제에 확인창 추가(커밋 `be661877`).
- **이중 자막(한글+영문 동시 표시)**: 설계 먼저 확인("가능합니다, 아직 안 바꿨습니다")하고 사용자가
  "발화 언어 아래, 체크박스로 선택, 전사 시 추가 선택 가능"으로 확정한 뒤 구현·배포 — 별도 레이어가
  아니라 **큐 하나에 둘째 줄을 담는 방식**(시각 어긋남·겹침 방지). 번역 줄은 발화 줄 바로 아래 작은
  글자(기본 70%)로 미리보기·출력에 동일 적용, 자막 생성 시 전사→문장큐→번역을 한 번에 돌려 두 언어가
  처음부터 같이 나오게 함. 기존 자막에는 "번역 줄 추가" 버튼으로 재전사 없이 붙일 수 있음. 한계: 단어
  강조는 발화 줄에만, 둘째 줄 크기는 아직 템플릿에 저장 안 됨, 큐 반으로 나누면 둘째 줄은 안 나뉨.
- 자막 세로 정렬(위/가운데/아래)을 글자 칩 → **아이콘 3개**로 교체(커밋 `264e61a7`). 가로 정렬은
  "할 필요없음"으로 확정 — 현재도 항상 가로 가운데 고정.
- 템플릿에 **자막 사용 여부**·이중 자막 둘째 줄 크기/표시 여부 저장 추가, 템플릿 **덮어쓰기** 버튼
  신설(상단 바에서 선택 시 노출, 확인 후 현재 편집 상태로 그 템플릿 교체).
- 이 두 묶음의 배포(13개 커밋, 마지막 `c74437d7`)에서 **다른 세션의 미커밋 파일은 의도적으로 제외**
  (아직 실행 중이라는 이유). → [[lampas-web-edit]].

## 9. 마지막 — 전체 코드 커밋·푸시 (포토부스 수정 커밋으로 열린 질문 해소)
"모든 코드 커밋하고 푸시해줘" 요청 시점엔 그 다른 세션(포토부스 중복과금 수정 세션)이 **이미 종료**된
상태 — 남은 파일이 운영에 이미 나간 내용과 동일함을 재확인하고 **별도 커밋**(`0f375722`)으로 분리해
커밋 메시지에 "다른 세션이 작성, 이미 운영에 배포됨"을 명시하고 푸시. 작업 트리 깨끗함, 로컬=원격
확인. **환불 스크립트가 실제로 실행됐는지는 이 소스로도 미확인** — 이미 중복 차감된 크레딧 환불용
스크립트라 별도 실행이 필요할 수 있음. → [[app-session-flat-fee-vs-server-metered-double-charge]]
스킬의 "배포 여부" 질문이 이 지점에서 **완전히 해소**(사고 배포 3번 + 정식 커밋 9번, 두 단계로 완결).
