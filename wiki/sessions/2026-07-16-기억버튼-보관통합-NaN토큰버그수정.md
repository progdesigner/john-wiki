# 2026-07-16 — "기억에 저장" 버튼을 보관 통합 + NaN 토큰 버그 수정

`[[progdesigner]]`가 두 가지를 순서대로 요청한 짧은 운영 세션(02:36~02:41 UTC, quick 성격).

## 1. 상단 "기억에 저장" → "기억에 보관" 버튼 통합

**요청 원문**: "위 상단에 기억에 저장 버튼을 기억에 보관 버튼으로 바꾸고 누르면 기억(wiki)에 장기
저장 시키고 새 대화로 바꿔죠"

- 어시스턴트가 먼저 서버의 보관(archive) API가 **이미 위키 저장을 겸하는지** 확인(→
  [[2026-07-13-보관시-자동-기억저장]]에서 구현된 배선 재확인) 후, 새 엔드포인트를 만들지 않고
  **버튼의 대상 API만 교체**하는 방식으로 구현.
- 버튼 라벨: **"기억에 저장" → "기억에 보관"**.
- 클릭 동작: 확인창(`window.confirm` 계열) → 확인 시 기존 보관 API `/api/sessions/archive` 호출.
  이 API는 대화를 `chats/archive/`로 이동하면서 `memory-ingest` 잡을 자동 큐잉하므로(2026-07-13
  구현분), 버튼 하나로 **아카이빙 + 위키 장기 저장 + 새 대화 전환**이 동시에 일어난다.
  - 대화 목록 항목 롱프레스 보관([[destructive-action-inline-confirm]] 변형B)과 **동일한 흐름**을
    타므로, `rememberedAt` 기반 멱등 게이트(이미 저장했고 변경 없으면 재저장 안 함)도 그대로 적용.
  - 실행 중이거나 대기 메시지가 있는 대화는 기존 보관 규칙대로 거부("보관 실패" 안내).
- **옛 `/api/remember` 엔드포인트는 서버에 그대로 남아 있으나 UI에서 더 이상 호출하지 않음** —
  죽은 코드는 아니지만 프런트 진입점에서는 제거됨.
- 웹 빌드로 반영, 서버 재시작 불필요(프런트 전용 변경). 커밋은 세션 종료 시점까지 미완료
  (사용자에게 확인 요청한 채 세션 끝남).

### 아키텍처 영향 — 저장 진입점이 3개에서 실질 2개로 수렴

기존 [[long-term-memory-architecture]]는 위키 저장 진입점을 **(1) 수동 🧠 버튼(`/api/remember`,
저장만) · (2) 보관 🗄 자동(2026-07-13~) · (3) 야간 자동 ingest** 셋으로 기록해 왔다. 이 세션 이후:

- (1)과 (2)가 **UI 레벨에서 같은 API·같은 동작으로 통합**됨 — 이제 상단 버튼도 "저장만"이 아니라
  "보관(아카이빙+새 대화 전환)"을 수행한다. 순수 저장-only UI 경로는 더 이상 없음.
  - `wiki/topics/long-term-memory-architecture.md`, `wiki/entities/lampas-harness.md`,
    `AI_CONTEXT.md`의 "저장 진입점 3개" 서술을 이 사실에 맞춰 갱신함(아래 참고).

## 2. 오른쪽 아래 "◔ NaN 토큰" 표시 버그

**요청 원문**: "오른쪽 아래 NaN 토큰으로 뜨는 데 확인해줘"

- **원인**: 사용량 집계가 아직 없는 세션에서 서버가 `usage: null`을 반환. 클라이언트가
  `Object.assign({}, null, {압축 통계})`로 병합하면 `null`의 필드는 채워지지 않은 채 빈 객체가
  만들어지고, 이후 `input`/`output` 필드가 `undefined`로 남아 `undefined + undefined` 연산이
  **"◔ NaN 토큰"**으로 렌더링됨.
- **수정 (프런트, 2곳)**:
  - `loadUsage()` — 서버 응답에 `usage`가 없으면 빈 객체를 만들지 않고 **비워둠**. 버튼이 기본
    표시("◔ 컨텍스트")로 돌아가고, 모달도 "아직 사용 기록이 없습니다"를 정상 표시.
  - `updateUsage()` — `input`/`output`이 빠져도 방어적으로 **0으로 계산**하도록 수정 — 어떤
    경로로 들어와도 NaN이 재발하지 않게 함.
- 라이브 서버에서 반영 확인 완료(새로고침만으로 적용, 서버 재시작 불필요).
- **별건으로 관찰된 부수 오류**: 같은 화면에서 "Credit balance is too low" 압축 오류가 함께
  떴는데, 이는 표시 버그와 무관하게 **API 종량 결제 크레딧 0** 상태에서 압축 요청이 API 과금
  경로로 나갔을 가능성으로 추정(기존에 [[sdk-claude-code-vs-api-billing]]·
  [[long-term-memory-architecture]]에 기록된 "크레딧 소진이 압축·memory-ingest 둘 다 실패시킨다"는
  관찰과 같은 계열). 표시 버그 수정과 별개로 계속되면 크레딧 쪽을 따로 봐야 함 — 미해결로 남김.
