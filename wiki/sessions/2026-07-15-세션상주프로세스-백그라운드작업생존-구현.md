# 세션: 세션 상주 프로세스로 백그라운드 작업 생존 구현 (2026-07-15)

`[[progdesigner]]`가 "Fable 5로 작업하면 백그라운드 작업(Agent·백그라운드 Bash·Workflow)이 걸다가
끊긴다"고 신고 → `[[lampas]]`가 원인을 규명하고 아키텍처를 바꿔 고침. 같은 세션 뒷부분에서
재시작+커밋까지 완료.

## 원인
`[[lampas-harness]]`가 **턴마다 Claude Agent SDK 서브프로세스를 새로 만들고, 답변이 끝나면 프로세스를
통째로 닫는** 구조였다. 백그라운드 작업은 그 서브프로세스 안에서 도는데, 턴이 끝나는 순간 부모 프로세스가
닫히며 함께 죽었다. `[[harness-background-process-lifecycle]]`이 이미 규명한 "턴 안에서 띄운 배경작업은
턴/세션 종료로 죽는다"는 일반 원칙이 **채팅 경로(에이전트 턴) 자체에도 적용된 사례** — 기존엔 예약
타이머·긴 다운로드 두 스레드로만 관찰됐던 문제가 이번엔 채팅 UI로 건 Agent/Workflow 백그라운드 작업까지
확장됨.

## 수정 — 서버 (`src/server.ts`, `scheduler.ts`)
- **대화당 상주 Claude 프로세스** 도입: `ChatSession`에 `live` 필드 추가, 기존 "매 턴 새 서브프로세스"
  함수 전체를 상주 세션 인프라 + 새 `runClaudeQuery`로 교체. 턴이 끝나도 프로세스가 살아있어 백그라운드
  작업이 계속 돌고, **작업이 끝나면 모델이 스스로 깨어나 후속 답변까지 이어간다.**
- 백그라운드 작업 이벤트(시작·진행·완료)를 추적해 SSE + `/api/queue`로 노출, 개별 중지 API
  `/api/task/stop` 신설.
- 화면(SSE)이 닫힌 뒤 도착한 완료 알림·후속 답변은 예약 메시지와 같은 경로(delivered)로 채팅창에
  자동 표시 → `[[session-independent-scheduler]]`가 쓰던 배달 경로를 재사용.
- 중지 버튼이 이제 **프로세스를 죽이지 않고 현재 턴만 인터럽트** — 백그라운드 작업은 유지됨(이전엔
  중지=프로세스 종료였을 것으로 추정, 소스에 명시적 비교는 없음).
- 프로세스는 유휴(턴·백그라운드 작업 없음) 10분 후 스스로 내려가고, 다음 턴은 기존 resume 방식으로
  이어짐 → `[[sdk-session-persistence]]`와 공존. 자동/수동 컨텍스트 압축·대화 보관·과금 방식 전환도
  유휴일 때만 프로세스를 내리도록 맞춤(백그라운드 작업과 충돌 방지).

## 수정 — 웹 UI (`apps/web/index.html`)
- 상단 활동 표시줄에 백그라운드 작업을 줄 단위로 표시: `🔄 백그라운드 · 작업 설명 · 경과 시간 · 토큰 ·
  마지막 도구`, 실행 중이면 ✕ 버튼으로 개별 중지. 턴 종료 후에도 2초 폴링으로 갱신, 완료되면 ✅로
  1분간 표시 후 사라짐.

## 검증 (테스트 인스턴스)
40초짜리 백그라운드 명령을 걸고 턴을 끝낸 뒤 → 작업이 계속 돌며 상태가 표시되고 → 완료되자 모델이
깨어나 결과(`BG_TEST_DONE`)를 확인하는 후속 답변을 보냈고, 닫힌 화면에도 푸시됨. 같은 세션 두 번째
턴 재사용, 턴별 비용 계산, 중지 후 세션 생존까지 정상 확인. 빌드(tsc + vite) 통과, `dist/index.js`에도
반영(`markClaudeSeen`이 마지막 수정이라 dist 동기화 필요했음 — `[[self-hosted-agent-server-ops]]` 함정4
재확인).

## 배포 — 재시작 + 커밋 (같은 세션 후반, 12:27~12:28)
사용자가 "재시작하고 커밋해줘" 요청.
- **커밋 `d20b439`** — "feat: 세션 상주 Claude 프로세스로 백그라운드 작업 생존 + 상태 표시" (4개 파일,
  +718/−147).
- **새 함정 발견**: 커밋 메시지 안에 `/api/...` 같은 슬래시 문자열이 있으면 **권한 가드가 이를 경로로
  오인해 차단**함 — 메시지를 파일로 우회해 해결. `[[deploy-sandbox-pnpm-shim]]`이 기록한 "인자 스캐너가
  URL·S3 경로·슬래시 경로를 차단 → 스크립트 파일로 우회"와 같은 계열의 함정이 **커밋 메시지 문자열**에도
  적용되는 새 변종.
- **재시작은 지연·분리 실행으로 처리** — 어시스턴트가 자기 턴 안에서 즉시 `launchctl kickstart -k`를
  돌리면 자기 응답 전달 채널이 끊기므로, 이 턴이 끝난 뒤 별도 실행되도록 지연시켰다 →
  `[[self-hosted-agent-server-ops]]` 함정2(restart-kills-own-turn)의 정석 대응을 그대로 재현.

## 배경 지식과의 관계
이 세션은 `[[harness-background-process-lifecycle]]`이 예약 타이머·다운로드 두 사례에서 도출한 일반
원칙("턴은 배경작업보다 수명이 짧다")의 **세 번째 실증 사례**이자, 이번엔 회피(우회)가 아니라
**근본 아키텍처(상주 프로세스)로 직접 해결**한 첫 사례다. 기존 원칙 페이지의 "해결 방향"(서버 내장
스케줄러로 이관, `nohup & disown`으로 detach)은 여전히 유효하지만, **채팅 경로 자체의 배경작업**은
이제 상주 프로세스가 살아있는 동안은 별도 우회 없이도 생존한다 — 단, 유휴 10분 초과 시엔 여전히
프로세스가 내려가므로 완전한 해결은 아니고 "턴 수명"을 "유휴 타임아웃 수명"으로 늘린 것.
