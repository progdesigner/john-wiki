# 2026-09-27 — First "BY DALAR" 제거 + 톡톡 대사/답변 편집 다듬기 + 삭제 허용 + 음성대화 우선

`Tool: codex` 세션(2026-09-27T13:25Z 시작, 작업폴더 `lampas-system`). 짧은 요청 8개가 이어진
운영 세션으로, 전반부는 [[dalar-web-first]], 후반부는 [[toktalk]] 사만다 에피소드 스튜디오
(`admin.toktalk.ai`)와 `app.toktalk.ai` 홈 화면을 다룬다. 매 요청마다 수정→테스트/빌드→배포까지
완결.

## 1. `dalar-web-first` — 헤더·푸터 "BY DALAR" 문구 제거
첨부 이미지 지적으로 로고 옆 "BY DALAR" 문구와 관련 스타일을 제거, 타입체크 통과 확인 후
`first.dalar.ai`에 배포(테스트 14개·빌드 통과).

## 2. 톡톡 사만다 스튜디오 — 대사/답변 편집 UI 재배치
[[episode-beat-play-system]]의 2026-09-21 재설계(대사→선택지→대사 선형 구조)로 만들어진 편집
화면의 요소 순서를 사용자가 지정한 순서로 재배치:
- **대사**: 제목·흥분도 선택 → 입력창 → 음성 생성/다시 생성·듣기 버튼.
- **답변**: 제목·이동 위치 선택 → 흥분도 선택 → 입력창 → 음성 버튼.
- 타입체크에서 **이번에 수정하지 않은 다른 파일 3곳의 기존 오류**가 확인됐으나 보류(스코프 밖).
`admin.toktalk.ai`에 배포.

## 3. 답변 라벨 "↳ 1/2" → "답변 1/2"
숫자만 보이던 답변 라벨을 "답변 1", "답변 2" 형식으로 교체, 문구 길이에 맞춰 간격 조정 후 배포.

## 4. 음성 생성 버튼 비활성화 원인 조사 + 안내 토스트
**원인**: 음성 생성 API가 **서버에 저장된** 대사/흥분도를 읽어 생성하므로, 대사나 흥분도를
수정하면 저장 전까지 버튼이 비활성화된다. 사용자 질문("왜 저장해야 하지?")에 어시스턴트는 이것이
"버튼을 누르면 현재 입력값을 즉시 사용"하도록 바꾸는 게 더 자연스러운 **구현상의 제약**이라고
답했으나, 실제로 요청받은 수정은 더 작은 범위 — **비활성화된 버튼을 눌렀을 때 "저장을 먼저
눌러주세요" 토스트 안내**만 추가하고 배포. 근본적인 "입력값 즉시 사용" 리팩터는 미착수로 남음.

## 5. 대사 삭제 불가 조사 → 전면 허용
**삭제가 막히는 조건 4가지**(저장 여부와 무관): 시작 대사, 다른 답변의 이동 대상으로 연결된
대사, 전체 대사 2개 이하, 생성 작업 진행 중. 사용자 지시로 전부 해제:
- 삭제된 대사로 향하는 모든 선택지(이동 대상)를 자동 제거.
- 시작 대사가 삭제되면 시작 대사도 자동 재지정.
- **클라이언트뿐 아니라 서버도** 대사 2개 이상을 요구하고 있었음을 추가로 발견 — 편집 중에는
  **마지막 대사까지** 삭제·저장 가능하도록 양쪽 다 수정. 공개(발행) 시에는 대화 흐름 유효성 검사를
  그대로 유지(발행 가능한 최소 구조는 지킴).
- `dalar-web-first`/[[toktalk]] 웹+API 배포, 테스트 34개 통과.

## 6. `app.toktalk.ai` 홈 화면 — 로고 중심 + 에피소드 없으면 즉시 대화
"첫 화면에 로고만 나오게 하고, 공개 에피소드가 다 꺼지면 바로 대화할 수 있게" 요청:
- 인사말·설명 문구 제거, 로고+대화 입력창만 노출.
- 공개된 에피소드가 없으면 첫 메시지를 바로 전송하는 자유 대화로 즉시 진입(텍스트·음성 모두).
- 에피소드 공개 여부는 **대화 시작 시점에 다시 확인**(캐시된 상태로 판단하지 않음).
- 배포, 테스트 54개·빌드 통과.

## 7. 음성 대화를 기본값으로 전환
같은 홈 화면에서 "음성대화를 우선으로" 추가 요청:
- 기본 화면에 **음성 대화 시작** 버튼을 먼저 노출, **텍스트로 대화하기**를 눌러야 입력창이
  보조로 나타남.
- 대화 종료 후에도 음성 대화 시작 화면으로 복귀(텍스트 모드로 고정되지 않음).
- 배포, 테스트 19개·빌드 통과.
