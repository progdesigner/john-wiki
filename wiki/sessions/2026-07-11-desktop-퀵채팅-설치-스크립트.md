## desktop 설치 — 로컬 모델 결과물의 버그와 재작성

로컬 모델(`qwen3.5-35b-8bit` 계열)이 만든 `install-desktop.sh`는 **실행 자체가 불가능**했다:

- **root 소유 `/Library/LaunchAgents`에 sudo 없이 쓰기 시도** → 첫 줄부터 permission denied.
- **Electron 앱을 `node main.js`로 실행** 등록 — Electron은 전용 바이너리로 실행해야 함.
- **plist 로드→삭제→재로드 순서가 뒤바뀜**, `launchctl bootout`에 `gui/UID/` 도메인 누락.

상위 모델이 레포의 기존 launchd 패턴(`install-launchd.sh`)에 맞춰 재작성:

- `scripts/install-desktop.sh` — `~/Library/LaunchAgents`에 **사용자 LaunchAgent**로 등록.
  **Electron 바이너리**로 실행, GUI 앱용 **`LimitLoadToSessionType: Aqua`**,
  **크래시 시에만 재기동**(`KeepAlive={SuccessfulExit: false}` — Cmd+Q로 끄면 다시 안 뜸),
  로그 `logs/desktop.*.log`.
- `scripts/uninstall-desktop.sh` — 올바른 도메인(`gui/$(id -u)/<라벨>`)으로 서비스 해제 + plist·로그 정리.
- `scripts/self-update.sh` — desktop만 변경 시 서버 재시작 없이 `npm install` 후
  `launchctl kickstart -k`로 desktop 앱만 재기동 ("launchd가 알아서 재시작한다"는 잘못된 전제 제거).
- `scripts/restart-lampas.sh` — 로컬 모델이 넣은 desktop 상태 출력 블록이 항상 "중지됨"으로 오표시되는
  버그라 **원복**.

**검증**: 설치 실행 → launchd 등록(exit 0), Electron 프로세스 확인, 에러 로그 0바이트,
`http://localhost:8787/quick.html` 200 응답. Option+Space로 퀵 채팅 표시 확인.

## 관찰 / 주의

- **작은 모델의 반복 위임 응답**: git commit·복잡 작업 요청 시 로컬/작은 모델이 "상위 모델이 처리하는 것이
  적절합니다"라며 실행을 미룸 → 사용자가 동일 요청을 2~4회 재전송. 라우팅/에스컬레이션 UX가 사용자에게
  불투명한 신호(같은 요청 반복).

  실행 불가한 코드를 생성(권한·바이너리·순서 3중 오류). 도메인 지식이 필요한 devops 스크립트는 상위 모델 권장.
