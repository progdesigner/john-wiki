# 2026-09-26 — Lampas Browser 구축 → `lampas-harness/apps/browser`로 이관 + 세션 "브라우징" 통합

`Tool: codex` 세션(작업 폴더 시작은 `lampas-system`, 이후 상위 폴더 이동). 하루 안에 계획→독립 Electron
앱 구축→저장소 이관→하네스 세션 통합→배포 서버 불일치 진단·재시작까지 전 과정이 이어진 긴 세션.

## 1막 — "lampas-browser" 요청과 설계 (작업 폴더: `lampas-system`)

- 요청: "Aside처럼" 크롬 기반 사이드바 브라우저를 만들고 싶다는 질문에서 시작. 어시스턴트 추천:
  **Electron + Chromium(WebContentsView) 기반 MVP**, 브라우저 고유 기능이 더 필요해지면 그때 Chromium
  포크 검토. 전체 Chromium 포크는 "전담 브라우저 팀이 있을 때"로 명확히 배제.
- 구조 제안: `apps/lampas-browser/{main,preload,renderer}` — Electron 메인이 탭·세션·다운로드 수명주기를
  관리하고, React 렌더러는 UI(사이드바 탭/주소창/AI 패널)만 담당. **탭은 iframe이 아니라 탭마다
  `WebContentsView`** — AI가 나중에 조작할 실제 페이지와 UI 사이 경계를 처음부터 분리하려는 설계 의도.
- 요구사항 확정(사용자, 2단계): (1) 기본 브라우저 먼저, (2) Claude/GPT AI 패널로 화면 데이터 수집·영상
  다운로드·스프레드시트 작업, (3) `[[lampas-studio]]`(`lampas-system`)와 양방향 연동 — Lampas가 브라우저에
  작업을 보내고, 브라우저도 Lampas 생성 API를 호출해 결과를 되돌려줌.
- 설계 원칙 3가지가 이 세션 전체를 관통: **사람의 클릭과 AI의 명령이 같은 제어 모듈을 쓴다** / **AI가
  페이지를 "읽는 것"과 "조작하는 것"을 단계적으로 분리**(페이지 안 문구를 AI 명령으로 오인하지 않는
  경계 필요, 프롬프트 인젝션 방어 관점) / **웹사이트와 앱 권한을 철저히 분리**(외부 페이지에 Node/파일
  시스템 접근 금지, sandbox+contextIsolation, IPC 화이트리스트).

## 2막 — 실제 구축 (`apps/lampas-browser`, `lampas-system` 하위)

압축된 진행 로그(assistant 턴 다수, 세부 도구 호출은 소스에 없음) 기준 완료 보고 내용:

- Chromium 탭·워크스페이스·북마크·세션 복원(재시작 시 마지막 탭 복원).
- GPT/Claude AI 패널 — 페이지 본문·표 수집, 대화형 조작.
- 표 → 편집 가능한 시트 → **CSV 저장**(Google Sheets API 연동은 **미구현**으로 명시).
- 영상 **직접 URL 다운로드**만 지원(사이트별 스트리밍/DRM 추출은 **미구현**으로 명시 — 과잉 주장 경계).
- `[[lampas-studio]]` 생성 API(레퍼런스 이미지 생성 등) 연동 + **Relay/MCP 양방향 작업 제어**(서버가
  브라우저에 작업을 보내고, 브라우저가 결과·상태를 되돌리는 구조. 인증된 WebSocket 상시 연결 방식).
- 연동 점검 중 **기존 Lampas AI 게이트웨이가 AI 도구 호출(tool call) 응답을 누락하던 버그**를 발견해
  같이 수정했다고 보고(별도 회귀 테스트 통과 보고 — `[[lampas-studio]]`/`lampas-api` 쪽 변경으로 추정,
  이 세션 소스만으로 file:line 특정 불가, 다음 lampas-system 조사 시 확인 필요).
- macOS 앱 번들 생성, 실행 명령 `pnpm dev:lampas:browser`. 실 Electron 앱에서 탭 탐색·표 편집·CSV
  저장·영상 다운로드·암호화된 설정 저장·재시작 복원까지 검증했다고 보고. AI API 실호출은 **비용 회피
  목적으로 모의 응답으로만 검증** — 실사용 시 설정에서 API 키·모델 ID 입력 필요, 이 부분은 미검증으로
  명확히 구분해 보고됨.

## 3막 — `lampas-harness/apps/browser`로 이관 + 하네스 세션 "브라우징" 통합

사용자 지시: "지금 구축한 브라우저는 `lampas-harness`로 옮겨주고 api 기능이 필요하다면 하네스 방식으로
바꿔줘. `apps/browser`라고 해주고, 하네스에 새 세션 선택 시 브라우징 기능을 추가해서 브라우저를 원격으로
실행하고 일을 시킬 수 있게 해줘."

- **핵심 설계 전환**: `[[lampas-browser]]`가 자체 보유하던 별도 모델 API(Claude/GPT 키 직접 호출)와
  Relay 서버를, `[[lampas-harness]]`가 이미 가진 **Codex CLI/Claude Code 로그인·세션 구조**로 완전히
  대체. 즉 브라우저 전용 AI 인증·과금 경로를 없애고 하네스의 기존 세션·MCP 도구 체계에 얹었다.
- 위치: `lampas-harness/apps/browser`(소스 이동 완료로 보고).
- 하네스 새 세션 화면에 **"브라우징"** 선택지 신설 — 선택하면 그 세션 전용 브라우저 프로세스 + MCP
  도구가 연결됨. **세션마다 브라우저 프로필과 제어 권한을 분리**(다른 세션의 로그인·쿠키·작업 권한과
  섞이지 않게).
- 하네스 화면에서 원격 브라우저의 **화면 확인·표 수집 결과·작업 승인(사람 개입)·결과 파일(CSV·다운로드)
  다운로드**까지 가능하도록 연결.
- **원격 실행 토폴로지 확정**: "Harness가 돌아가는 컴퓨터에서 브라우저를 실행하고, 다른 기기의 Harness
  화면에서 제어하는 방식" — 브라우저는 항상 하네스 서버(맥미니)에서 로컬로 뜨고, 원격 접속자는 제어
  화면만 본다. 로컬 앱이 꺼져 있으면(과거 Lampas Browser 독립 실행 시절 언급된 "앱이 켜져 있어야 함"
  제약)이 서버 상주형으로 바뀌며 사실상 해소됨.
- 검증: 하네스 전체 테스트 **76개 → 이후 79개**로 통과(사이 3개는 Threads 제거+`apps/wiki` 신설과 겹치는
  같은 날 다른 세션 [[2026-09-26-threads기능제거-llm위키탐색기-apps-wiki-이전]] 작업분과 시간대가
  겹쳐 있어 정확한 증가분 귀속은 불가). 실 Electron·MCP·웹 화면 통합 검증(탭 이동, 표 수집→MCP로 시트
  수정→승인→CSV/영상 파일 반환)까지 통과 보고. **실제 Claude/Codex 모델에 지시를 내리는 엔드투엔드
  테스트는 세션 끝까지 미실시**로 명시적으로 구분 — 어시스턴트가 스스로 "확인된 것으로 말하진 않겠다"고
  선을 그은 점이 특기할 만함.
- 중간에 초기 화면 캡처 간헐적 오류 발견 → 시작 직후 화면 준비(warm-up) 처리 보완, 재검증.

## 4막 — 배포 사고: 옛 서버가 최신 빌드를 반영 못 함 (wiki.html 404 + 브라우징 옵션 없음)

- 사용자 보고: `https://lampas-harness.tail43b73a.ts.net/wiki.html` 접속 시 위키 안 뜨고, 새 세션에도
  브라우징 옵션이 없음.
- 원인 확정: 접속 중인 서버가 **9월 24일에 시작된 구버전 프로세스** — 최신 빌드 파일은 디스크에 있지만
  이 옛 프로세스가 로드하지 않은 상태. `[[self-hosted-agent-server-ops]]` 함정 1(옛 프로세스가 새 코드를
  못 보게 가로챔)의 새 사례 — 이번엔 EADDRINUSE 없이 그냥 "예전부터 떠 있던 프로세스가 여전히 서빙 중"
  이라는 단순 변형.
- 별도 검증 서버로 최신 빌드를 띄워 **위키 186개 문서 정상 + 브라우징 옵션 정상**을 먼저 확인(운영
  재시작 전 사전 검증) — [[2026-09-26-threads기능제거-llm위키탐색기-apps-wiki-이전]]에서 "반영은 서버
  재시작 대기 중"으로 남겼던 미확인 상태가 여기서 원인까지 특정됨.
- 재시작 시 **실행 중인 CLI 세션 3개가 끊긴다**는 점을 사용자에게 먼저 알리고 확인을 구한 뒤 재시작 —
  [[self-hosted-agent-server-ops]] 함정 2(자기 자신을 호스팅하는 서버 재시작 시 진행 중 턴이 끊김)의
  정석 대응 패턴 재현. 소스는 "재시작해줘" 승인 직후, 재시작 실행 시점에서 끝남 — **재시작 후 실제로
  wiki.html과 브라우징이 정상 노출됐는지는 이 세션 소스에는 없음**(다음 세션에서 확인 필요).

## 왜 중요한가 (사서 메모)

- `[[lampas-browser]]`는 이 위키에 처음 등장하는 프로젝트다. 처음엔 `[[lampas-studio]]` 쪽(`lampas-system`)
  제품으로 기획됐다가, **같은 날 안에 `[[lampas-harness]]`로 완전히 이관**되며 AI 실행 방식이 "자체 모델
  API 키"에서 "하네스 CLI 세션 재사용"으로 바뀌었다 — 짧은 시간에 아키텍처가 두 번 바뀐 사례라 향후
  "Lampas Browser의 AI는 어떻게 인증하나" 질문엔 **최종 상태(하네스 CLI 세션)** 기준으로 답해야 한다.
- [[self-hosted-agent-server-ops]] 함정 1의 발생 빈도가 계속 늘고 있다(2026-07-15 IPv6 변종, 이번
  "옛 프로세스 장기 방치" 변종) — 하네스처럼 자기 자신을 서빙하는 서버에서는 배포 후 "실제 접속 주소가
  최신 빌드를 서빙하는지" 확인이 구조적으로 반복되는 취약점으로 굳어지는 중.
- [[2026-09-26-threads기능제거-llm위키탐색기-apps-wiki-이전]]과 이 세션은 **같은 날 배포 지연 상태
  ("서버 재시작 대기 중")를 공유**한다 — 두 세션의 기능(위키 브라우저 + 브라우징 세션)이 같은 재시작
  한 번으로 동시에 반영될 예정이었다는 뜻. 이후 세션에서 재시작 완료 여부를 확인할 때 두 기능을 함께
  검증할 것.
