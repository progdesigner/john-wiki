# 2026-09-27 — 사만다 스튜디오: 선택지 점프→답변 구조 전환, 흥분도 음성 생성 반영, 비공개 전환, 음성 생성/듣기/재생성 분리

`Tool: codex` 세션(2026-09-27T13:03:57Z 시작, 작업폴더 `lampas-system`). [[toktalk]] 사만다 에피소드
스튜디오(`admin.toktalk.ai`)의 선택지 로직과 음성 기능을 다룬 4요청 연속 세션. **같은 날 13:25Z에
시작하는 [[2026-09-27-first로고문구제거-톡톡대사편집-삭제허용-음성우선]]보다 약 21분 앞서** —
그 세션이 전제로 다루는 "음성 생성 버튼" 3분리(생성/듣기/다시생성) 기능을 실제로 처음 만든 세션이
이쪽이다. 매 요청마다 수정 → 테스트/빌드 → 배포가 반복됐다.

## 1. 선택지 "점프"→"답변 후 이동" 구조 전환 + 흥분도 슬라이더(최초 요청, 오해 포함)
기존 사만다의 선택지는 고른 즉시 지정된 번호의 대사로 점프할 뿐 사만다의 반응(답변)이 없었다.
요청 두 가지를 한 번에 받음:
- 선택지마다 **선택적 사만다 답변**(있거나 없음)을 넣고, 그 뒤에 "**다음**" 또는 "**특정 번호**"로
  이동을 선택할 수 있게(선택박스 "… 로 이동").
- 대사에 **흥분도** 선택(가로 드래그)을 추가해 "대사를 도와줄 수 있게" — 어시스턴트는 이를
  **대사 문구를 AI로 다듬는 기능**으로 해석해 구현(2026-10-03 기준 돌아보면 **오해**, 7번 참고).
- 추가로 "한번 음성이 생성되면 재생만 할 수 있게" — 음성 생성/재생 분리의 최초 요청.

구현·배포 결과: 선택지별 답변 입력 또는 무답변, 다음/특정 번호 이동 선택박스, 흥분도 슬라이더+AI
대사 다듬기(이때는 다듬기로 구현), 생성된 음성은 저장 파일만 재생하도록 표시/처리 분리. 분기·음성
캐시 테스트 통과, 관리자 빌드 통과. **전체 타입체크는 기존 레거시 화면 3곳 오류가 그대로 남아
있으나 이번 수정 파일에는 오류 없음**(수정 스코프 밖으로 분류, [[2026-09-27-first로고문구제거-톡톡대사편집-삭제허용-음성우선]] 2절과 동일한 패턴).
브라우저로 선택별 답변 미리보기·다음/번호 이동·흥분도 조절·음성 버튼 3종·모바일 가로 넘침 없음을
확인 후 공식 배포 스크립트로 API+관리자 웹 배포 → `https://admin.toktalk.ai/studio`.

## 2. 공개 에피소드 비공개 전환 기능 추가
"공개한 걸 다시 비공개로 바꿀 수도 있게" 요청. 비공개 전환 후에는 **새 대화가 해당 에피소드로
시작하지 않지만, 이미 진행 중인 대화는 이어갈 수 있도록** 처리 — 발행 취소가 기존 유저 경험을
끊지 않는 설계.

## 3. 음성 "듣기"만 있던 것을 생성/듣기/다시생성 3분리로 재확정
"음성 듣기만 있는게 아니라 음성 생성, 그리고 듣기 이렇게 나눠서 적용해줘. 다시 생성도 가능하게"
요청(1절에서 이미 "재생만"으로 분리했던 것을 다시 세분화). 결과: **듣기**는 저장된 음성만 재생,
**다시 생성**을 눌렀을 때만 새 음성을 만들어 교체. 이 3분리 UI가 [[2026-09-27-first로고문구제거-톡톡대사편집-삭제허용-음성우선]] 4절에서 다뤄지는 "저장 전엔 생성 버튼 비활성화" 문제의 전제가 된다.

## 4~6. 중간 요약 배포 2회
1~3절 작업을 반영해 두 차례 중간 보고·배포:
- 분기·음성 캐시 테스트, 관리자 빌드 통과 보고(레거시 타입 오류 3건은 그대로).
- 브라우저 확인(선택별 답변 미리보기·다음 번호 이동·흥분도 조절·음성 버튼 3종·비공개 전환, 모바일
  가로 넘침 없음) 후 API+관리자 웹 배포, `admin.toktalk.ai/studio`에 반영 완료 보고. 요약 5줄:
  선택별 답변/무답변, 다음·특정번호 이동, 흥분도 슬라이더+AI 대사 다듬기, 음성 생성/듣기/다시생성
  분리, 공개 에피소드 비공개 전환. 테스트 30개 통과.

## 7. 사용자 정정 — 흥분도는 대사 다듬기가 아니라 **음성 생성**에 관여해야 함
> "흥분도는 대사를 다듬는게 아니라 대사를 음성으로 생성할 때 관여 하는 거야."

1절에서 어시스턴트가 "흥분도 → AI가 대사 문구를 다듬는다"로 잘못 구현한 것에 대한 정정. 올바른
의도는 **흥분도가 TTS 음성 생성 시 발화 강도·속도를 조절**하는 파라미터라는 것.

어시스턴트 대응:
- 대사 다듬기 버튼 **제거**.
- 음성 API가 지원하는 발화 강도·속도 조절 방식을 조사 후 흥분도 슬라이더 값을 그 설정에 연결.
- 실제 대화 재생에서도 각 대사·선택 답변에 저장된 흥분도가 음성 생성에 적용되도록 수정.
- 흥분도별 음성은 **별도로 생성·저장**(같은 대사라도 흥분도가 다르면 음성 파일이 다름 — 3절의
  생성/듣기/다시생성 분리와 자연스럽게 맞물림).
- 흥분도 0과 100 양극단에서 실제 음성 생성 성공 확인, 설정별 음성 저장과 대화 재생 테스트 통과.
- 어시스턴트가 명시적으로 "제가 잘못 이해했습니다"라고 인정하며 마무리 — 대사 내용은 바뀌지 않고,
  흥분도 조절 → 저장 → 음성 생성 순서로 사용하면 된다고 안내. 테스트 32개 통과, 배포 완료.
