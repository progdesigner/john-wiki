## 합의된 재구축 목표 — 유튜브 플레이리스트 구독 자동 수집
요청 자체: 플레이리스트에 새 영상이 추가되면 맥미니 하네스가 **1시간마다 확인**해 중복 없이 자동
수집. 합의된 6단계 계획:

1. **등록 방식 분리**: 개별 YouTube URL은 즉시 큐 등록, 플레이리스트 URL은 "구독"으로 저장해
   1시간 주기 폴링. 파일 업로드(선택·드래그)는 일시 제거.
2. **감시/처리 분리**: 감시기는 새 영상 ID만 기록해 작업 등록, 별도 처리 워커가 다운로드·분할·
   전사·라벨링·뱅크 등록을 수행. 기존 유튜브 목록 조회 200개 제한도 보완 대상.
3. **중복 규칙**: 구독은 영상 ID 기준 자동 재수집 스킵. 수동 재등록은 기존처럼 새 소스·새 클립
   생성(의도된 예외). 재시도 중복은 작업 ID로 차단.
4. **서버 파이프라인 전환**: 브라우저 처리(OPFS·Canvas 시킹·FFmpeg WASM)를 맥미니 네이티브
   FFmpeg로 이전. 브라우저는 등록·진행확인·취소·재시도 화면만 담당(처리 로직 없음).
5. **무인 운영·복구**: SQLite에 구독·작업·단계별 체크포인트 저장, 재시작 시 미완료 단계부터
   재개. 백오프 재시도·잠자기 방지·디스크 관리 포함.
6. **검증 범위**: 새 영상 감지, 중복 생략, 수동 재수집, 200개 초과 목록, 처리 중 프로세스 종료
   복구, 24시간 연속 운영.

## 어시스턴트의 판단 — 동시 편집 회피를 위해 아무 파일도 건드리지 않음
Codex가 **같은 워킹트리에서 지금도 편집 중**임을 확인한 어시스턴트는 조사 결과 보고 외에 어떤 파일도
만들거나 수정하지 않았고, 사용자에게 "이 작업을 이어받거나 계획 문서를 남기려면 Codex 세션을 먼저
멈추거나 역할을 나눠야 충돌이 없다"고 명시했다. [[readonly-recon-before-shared-repo-write]]가
정립한 "쓰기 전 읽기전용 조사" 절차의 한 단계 더 보수적인 변형 — 동시 프로세스가 **지금도 활성
상태로 확인되면**, 보고 후 재승인을 기다리는 것조차 건너뛰고 조사 자체에서 멈춘다. 상세는 스킬 페이지
"변형: 활성 동시 세션 확인 시 조사에서 즉시 멈추기" 절 참고.
