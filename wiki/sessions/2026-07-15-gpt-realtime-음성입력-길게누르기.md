# 2026-07-15 — GPT Realtime 음성입력(길게 누르기) 구현 세션

`[[progdesigner]]`가 `[[lampas-harness]]` 웹 채팅에 "말로 전달"(전송 버튼 길게 누르기 = push-to-talk)
기능을 요청, 이후 같은 날 세 차례 더 이어진 확인·버그 발견·개선 요청까지 하나의 소스 파일에 담긴
장시간(12:37~22:55) 연속 개발 세션. 소스: `raw/conversations/2026-07-15-gpt-realtime-음성입력-길게누르기.md`
(원본 경로 `logs/chats/archive/3df735b1-aebf-4c87-83af-2f20f8f70bae.md`).

## 타임라인 요약

1. **12:37~12:45 — 최초 구현.** 전송 버튼 길게 누르기 → OpenAI Realtime(`gpt-4o-transcribe`, 한국어 우선)으로
   실시간 음성 전사. 서버에 토큰 발급 라우트, 웹 UI에 누르고-말하기 UX 추가. 타입체크·빌드·E2E 검증(Yuna
   합성 음성)까지 완료, 커밋 `b9eac27`.
2. **12:49 — 같은 요청 재입력.** 사용자가 방금 완료된 요청을 다시 보냄(재시작 반영 여부 확인 목적으로 추정).
   어시스턴트가 "직전 턴에서 이미 구현·커밋 끝났다"고 답하되, **재시작 후에도 실제로 동작하는지가 별개
   문제임을 스스로 점검**해 두 가지 결함을 발견·수정:
   - **함정 A — `dist` 빌드 누락**: launchd 데몬은 컴파일된 `dist/index.js`를 실행하는데, 직전 턴에서
     `src`만 고쳐 새 라우트(`/api/voice/token`)가 반영 안 된 상태였다. `npm run build:server`로 해결.
   - **함정 B — 떠돌이 옛 서버가 포트 가로채기**: 7/12에 수동 실행된 옛 프로세스가 IPv6 와일드카드로
     8787/3787을 리슨하며 localhost 접속을 가로채 옛 코드를 서비스 중이었다. 진행 중 대화가 없을 때
     정리하고 데몬을 재시작하는 스크립트를 분리 실행(nohup)으로 예약, "이 대화가 끝나고 약 15~30초 뒤
     자동 반영" 안내.
   - → 두 함정 모두 [[self-hosted-agent-server-ops]]에 반영(함정 1 보강 + 함정 4 신설).
3. **15:23 — 재확인.** 같은 요청 세 번째 입력. 이번엔 실제로 반영·정상 동작 확인(옛 서버 정리 완료, 토큰
   API 정상, 리스너 단일화).
4. **15:29 — "요?" (한 글자만 도착).** 두 가지 별개 이슈 노출:
   - `/compact`가 **Anthropic API 크레딧 부족**으로 실패 — 대화 자체는 구독(OAuth) 과금이 기본이지만, 대화별
     "API 사용" 토글이 켜져 있으면 압축 요청도 API 키로 과금되는데 잔액 부족. 해결책 두 가지(토글 끄기
     / 크레딧 충전) 안내. → [[sdk-claude-code-vs-api-billing]]
   - 사용자가 보낸 "요?"는 음성 입력 중 버튼을 너무 빨리 뗀 테스트로 추정(말끝만 잡힘).
5. **22:27 — "확인해보자. 잘 돼?"** 전체 문장이 온전히 도착해 음성 파이프라인(마이크→전사→자동전송) 정상
   확인. **별개 문제 발견**: 백그라운드 **`memory-ingest`(위키 적재) 작업이 "Credit balance is too low"로
   반복 실패** — `/compact`와 같은 원인(API 크레딧 부족)이 야간 위키 적재 같은 백그라운드 작업에도 영향.
   → [[long-term-memory-architecture]]에 반영(이 위키 자신의 저장 파이프라인에 영향을 주는 사실이라 중요).
6. **22:28~22:30 — 시작 부분 끊김 버그 발견·수정.** 사용자가 "말하는 게 처음에 좀 끊기는지" 확인 요청.
   코드 분석 결과 **실제로 끊기는 구조**였음을 확인: 버튼을 눌러도 토큰 발급 → WebSocket 연결이 끝난
   *뒤에야* 마이크 캡처가 시작돼, "말하세요" 뜨기 전(0.5~1.5초) 말한 앞부분이 유실됨. **마이크를 먼저 열고
   연결 중 오디오를 로컬 버퍼에 쌓았다가 연결 직후 순서대로 플러시**하도록 수정, 커밋 `938d4e4`. 남는 한계는
   길게-누르기 판정(0.35초)+마이크 오픈 지연(0.1~0.3초) 합산 ~0.5초. → 재사용 가능한 패턴으로
   [[realtime-voice-mic-buffer-before-connect]] 스킬 추출.
7. **22:30~22:32 — 3단계 시각 피드백 추가.** 사용자가 "시작 부분을 버튼 상태로 다르게 보여주고, 인식되는
   순간부터 다른 표시" 요청. OpenAI Realtime의 `speech_started` 이벤트를 활용해 버튼을 노랑(준비중, 유실
   가능)→빨강(말하세요, 녹음중·유실없음)→초록(인식중, 실제 음성 감지)으로 3단계 색상화. 커밋 `7450997`,
   웹만 변경이라 재시작 없이 새로고침만으로 반영.
8. **22:40~22:41 — 재시작 요청 2회 연속.** 지연 분리 스크립트(`restart-lampas.sh`)로 예약, 재시작 완료
   확인(`/api/health` OK, 음성 토큰 발급 정상, 리스너 단일화). 재시작 직전 보낸 중복 요청은 추가 재시작
   없이 안내만.
9. **22:53~22:55 — 밀어내기 취소(swipe-to-cancel) 추가.** "누르다가 버튼에서 많이 벗어나면 발송 취소"
   요청 → 메신저 음성메시지 UX 차용: 버튼에서 60px 이상 벗어나면 회색 "✕ 떼면 취소"로 바뀌고, 그 상태에서
   손을 떼면 전송하지 않되 받아쓴 텍스트는 입력창에 남긴다. 버튼 근처로 복귀하면 원상태 복구. 커밋 `5182ee0`.

## 결정사항

- 음성 입력은 **OpenAI Realtime `gpt-4o-transcribe`** 기반, 브라우저가 서버 발급 **1분짜리 임시 키**로
  OpenAI에 직접 WebSocket 연결(키 노출 위험 없음, 서버는 전사 성공 여부를 로그로 알 수 없음).
- UX 확정: 길게 누르기(0.35초) 판정 → 3단계 색상(노랑/빨강/초록) → 손 떼면 자동 전송, 60px 이상 이탈 시
  회색 취소 상태.
- 커밋 4개: `b9eac27`(최초 구현) → `938d4e4`(시작부분 버퍼링) → `7450997`(3단계 색상) → `5182ee0`(밀어내기 취소).
