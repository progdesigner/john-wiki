# 2026-09-25 — Edit 템플릿 이미지가 다른 브라우저에서 안 붙는 문제 수정

작업 디렉터리: `/Users/progdesigner/Works/lampas/lampas-system` (=[[lampas-studio]]). 소스:
`raw/conversations/2026-09-25-edit-템플릿-이미지-s3-url-수정.md` (원본 아카이브
`4099981a-9dab-46fc-a0c4-8a1d8a9768ae.jsonl`, 이 위키 최초 노출 — "Edit" 템플릿 에디터 기능이
처음 문서화됨).

## 요청

에디터 상단 템플릿 선택기에서 **SPOTV** 템플릿을 고르면, 만든 브라우저에서는 로고 이미지가 적용되는데
**다른 브라우저에서는 적용이 안 됨**. 사용자는 원인을 "이미지 경로가 파일명으로만 되어 있어서"로
정확히 짐작하고, 이미지 파일 2장(`spotv-logo.png`, `disneyplus-logo.png`)을 첨부하며 S3 업로드로
해결 요청.

## 원인 (코드 확인)

템플릿의 이미지 슬롯은 두 가지 방식으로 파일을 찾는다:
- **`fingerprint`** — 그 이미지를 만든 브라우저의 **로컬 OPFS 저장 키**. 다른 브라우저엔 그 파일이 물리적으로
  없어 "파일 없음, 건너뜀" 처리됨.
- **`url`** — 공개 S3/CloudFront 주소. 있으면 로컬에 없을 때 여기서 받아온다.

서버에 저장된 SPOTV 템플릿이 **계정별로 2개** 있었는데, `progdesigner7` 계정 것은 이미 CloudFront
`url`이 채워져 있었고, **`rallycap.official` 계정 것만 파일명+fingerprint만 있고 `url`이 비어 있었다.**
다른 브라우저에서 실패한 건 이 rallycap 쪽 템플릿.

## 조치

- 첨부된 두 이미지의 MD5가 S3 `edit-templates/logos/spotv-logo.png`·`disneyplus-logo.png`와
  **완전히 동일** → 재업로드 불필요, CloudFront 응답도 200/CORS `*` 정상 확인.
- **코드 변경·배포 없이 서버 데이터만 수정**: rallycap.official 계정 SPOTV 템플릿의 두 이미지 슬롯에
  기존 CloudFront `url`을 넣고 파일명을 맞춤. `fingerprint`는 그대로 둬 원래 브라우저의 로컬 매칭도
  유지. `updatedAt` 갱신 → 다른 브라우저에서 로그인 후 에디터를 열면 서버 버전이 로컬 복사본을 덮어씀.
- 확인 방법: 다른 브라우저에서 rallycap 계정 로그인 후 에디터에서 SPOTV 템플릿 적용 → 로고 2장이
  CDN에서 내려와 붙어야 함. (로그아웃 상태에선 서버 템플릿 자체가 목록에 안 뜸 — 로그인 선행 필요.)

## 재발 방지 지식

드래그로 넣은 이미지로 템플릿을 만들면 **`url` 없이 저장**되어 같은 문제가 재발한다. 공용 로고는
S3 `cdn/production/edit-templates/logos/`에 올리고 URL로 라이브러리에 등록한 뒤 템플릿을 만들어야
어느 기기에서든 적용된다. → 스킬 [[template-image-slot-fingerprint-vs-url]]
