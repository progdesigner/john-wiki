# 2026-07-15 — 음성입력 앞부분 3~4초 잘림 수정 (단독 소스, 15:29~15:33)

`[[progdesigner]]`가 "들려?" 핑 확인 직후 "말을 하면 앞에 3, 4초가 잘린다"고 보고, 어시스턴트가
원인 분석→수정→빌드 반영까지 마친 짧은 왕복(15:29:49~15:33:37 UTC, 3턴).
소스: `raw/conversations/2026-07-15-음성입력-3-4초-잘림-수정.md`
(원본 경로 `logs/chats/archive/d2db463c-ceb1-486b-a8db-19586dddfb55.md`).

## 내용
- **증상**: 전송 버튼 길게 누르기(push-to-talk) 음성 입력에서 말한 앞부분 3~4초가 녹음되지 않고 사라짐.
- **원인**: 기존 코드가 토큰 발급 → WebSocket 연결이 끝난 뒤에야 마이크 캡처를 시작해, 연결에 걸리는
  시간(3~4초) 동안의 발화가 아예 녹음되지 않았음.
- **수정** (`apps/web/index.html`):
  1. 마이크 권한이 열리는 즉시 녹음 시작, 연결 전까지는 오디오를 로컬 버퍼(`pending`)에 적재 → 연결
     성립 시 버퍼를 한꺼번에 플러시한 뒤 실시간 스트리밍 전환.
  2. 버튼 "● 말하세요" 표시를 연결 완료가 아닌 **녹음 시작 시점**으로 앞당김.
  3. 연결이 열리기 전에 손을 떼도 최대 4초까지 연결을 기다렸다가 버퍼 내용을 전송(기존엔 그냥 폐기).
- 웹 전용 변경이라 `build:web`만으로 데몬 재시작 없이 반영. 커밋은 이 대화 안에서는 아직 안 됨("테스트해
  보고 괜찮으면 커밋해 드릴게요"로 종료).

## ⚠️ 기존 세션과의 중복/모순 — 기록
이 소스가 기술하는 버그·원인·해결책은 [[2026-07-15-gpt-realtime-음성입력-길게누르기]] 세션의
"6. 22:28~22:30 — 시작 부분 끊김 버그 발견·수정" 항목과 **내용이 사실상 동일**하다(같은 원인 서술,
같은 해결 방식 — 마이크 선오픈 + `pending` 버퍼 + 연결 후 플러시, 같은 "말하세요" 표시 타이밍 변경).
그러나 두 소스는 다음이 서로 다르다:

| | 이 세션 (d2db463c...) | 기존 세션 (3df735b1... 6번 항목) |
|---|---|---|
| 시각 (UTC) | 15:29:49~15:33:37 | 22:28~22:30 |
| 커밋 | 언급 없음("테스트 후 커밋" 예정으로 종료) | `938d4e4`로 커밋 완료 |
| 소스 파일 UUID | `d2db463c-ceb1-486b-a8db-19586dddfb55` | `3df735b1-aebf-4c87-83af-2f20f8f70bae` |

같은 날 같은 버그를 두 번 독립적으로 고쳤을 가능성도 있으나, 원인·해결책 서술이 문장 단위로 거의
동일한 점을 볼 때 **같은 편집 사건이 서로 다른 아카이브 파일에 다른 시각으로 기록된 것**일 가능성이
더 높다. [[2026-07-14-clara-바바라-위스키분쟁-번역]]에서 이미 관찰된 "아카이브 파일명 재사용/시각
불일치" 패턴과 같은 계열의 이상 정황으로 보인다 — 통합 정리: [[chat-archive-duplication-anomaly]].
**모순 처리 원칙에 따라 기존 세션 내용은 수정하지
않고 그대로 유지**하며, 이 세션은 새 소스로 별도 보관한다. 실제로 몇 번 커밋이 발생했는지(1회인지
2회인지)는 `apps/web/index.html`의 git 로그로 별도 확인이 필요하다(미확인).
