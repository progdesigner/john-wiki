# 2026-09-26 — 블루리본·식신·타베로그 맛집 수집, Spot 확장 (2026-09-26~10-02)

`lampas-system` 저장소에서 `codex` 하네스로 진행된 멀티데이 세션(2026-09-26T02:38Z 시작,
environment_context가 2026-09-27·09-28·10-02로 계속 갱신되며 이어짐). [[lampas-web-spot]]
(`spot.lampas.io`)에 들어가는 맛집 원시 데이터를 여러 평점 사이트에서 반복적으로 수집해
Google 시트(원본)·운영 DB에 누적 반영한 작업 로그. 원본: raw/conversations/
`2026-09-26-블루리본-식신-타베로그-맛집수집-spot확장.md` (서비스 계정 private key 레닥트).

## 핵심 내용

### 1) Google 서비스 계정 연동 — 보안 사고 포함
- 사용자가 채팅에 **elevino 프로젝트 서비스 계정 JSON(private key 포함)을 평문으로 붙여넣음** →
  이 위키 ingest에서 레닥트 처리(원본 소스는 무수정) → [[secrets-plaintext-exposure-pattern]] 9번째
  사례로 기록.
- 그 키는 Google 인증에서 `Invalid JWT Signature`로 거부돼 **실제로 쓰인 적이 없다** — 브라우저로는
  대상 시트가 보기 전용으로만 열렸음.
- 사용자가 새 서비스 계정 키(`lampas-crawler`, 첨부파일로 전달)로 교체 지시 → 인증·시트 편집 성공
  확인(임시 탭 생성·삭제 테스트 통과).
- 기존 elevino 키를 Google Cloud 콘솔에서 삭제(revoke)하려 했으나 **IAM API가 비활성화돼 있어
  삭제 실패** — elevino 프로젝트 관리자가 콘솔에서 직접 키를 지워야 완전히 폐기된다. 이 ingest
  시점까지 해결 여부는 소스에 없음(미해결로 남을 가능성).
- 과정에서 사용자가 "Google Drive API가 비활성 아니냐"고 다른 걸 의심했으나, 실제로 비활성화돼
  있던 건 `lampas` 프로젝트의 Drive API/IAM API였고 `lampas-crawler`는 처음부터 정상 작동 중이었음
  (혼선 사례로 기록 — 시트 읽기·쓰기에는 Sheets API만으로 충분했음).

### 2) 블루리본(bluer.co.kr) 맛집 수집 — Google 시트 ↔ Spot 동기화
- 기존 블루리본 통합 657곳(Google 시트) 기준으로 중복 없는 신규 맛집을 비로그인 공개 목록에서
  수집 → 로그인 후 재시도해 리본 등급·2026년 선정 여부까지 검증.
- `bluer.co.kr`이 연속 요청에 **빈 화면(흰 화면)으로 응답**하는 문제 발생 → 사용자 지시로 **15초
  간격** 요청으로 전환하자 재발하지 않음(이 패턴을 스킬로 추출 → [[list-site-scrape-rate-limit-dedupe-sync]]).
- 누적: 시트 657→675(+18)→743(+68, 15초 간격) / Spot 738→824(+86: 68+18)→856(+32, 검색 제한
  직전까지). 이후 "429 검색 횟수 제한"에 걸려 블루리본 수집은 중단, 남은 15곳은 보류.

### 3) 식신(siksinhot.com) 수집 — 평점 4.0 이상, 송파구·종로구
- 사용자가 소스를 블루리본에서 **식신으로 전환** 지시, 평점 4.0 이상만, 주소 중복 제외 기준으로
  송파구·종로구 수집.
- **중복 판정 기준이 세션 중 수정됨**: 처음엔 "같은 도로명 주소면 제외"로 18곳을 걸렀으나, 사용자가
  "같은 건물이라도 다른 식당이면 남겨야 한다"고 바로잡음 → 상호·주소·**지도 장소 ID(place ID)**까지
  비교하는 기준으로 변경, 과잉 제외됐던 매드포갈릭·갓덴스시·닥터로빈 등 10곳을 다시 추가.
- 추가로 **진짜 중복(동일 매장이 두 번 등록)** 3건(시카노이에, 가양칼국수버섯매운탕, 산청숯불가든
  을지로)을 주소·전화번호·장소 ID 일치로 찾아 삭제.
- 목록이 큰 구는 분류(한식/양식/고기/씨푸드/카페 등)별로 나눠 "더보기" 끝까지 확인하는 방식으로
  전환(대분류를 한 번에 펼치면 전면 광고가 막음). 최종적으로 송파 838/916, 종로 954/1,436까지
  확인(560곳 미확인으로 남김, 완료 보고 아님).
- 누적 반영: 37곳(14+23) → 10곳 → 99곳(27+72) → 10곳(중복 정리 후 재검증분) — Spot 전체 **995건**
  부근까지 증가.

### 4) 지역 확장 — 남양주시, 석촌동
- 남양주시: 기존 2곳 + 식신 4.0 이상 신규 14곳 = 총 16곳.
- 석촌동: 식신 목록 80곳을 끝까지 확인했으나 4.0 이상 조건을 만족하는 신규 후보가 없었음(기존
  빈티지1981·돈족골·송쉐프만 해당, 이미 등록됨) → 기준을 3.5로 낮출지 사용자에게 질문한 채 세션
  화제가 전환됨(미확정).

### 5) 해외 확장 — 도쿄(타베로그), 해외 주소 지원
- 사용자가 도쿄 맛집 검색 사이트 추천을 요청 → 타베로그·구글지도·구루나비 3곳 추천, **타베로그는
  3.5 이상이 "높은 평가"**(식신 4.0 기준과 다름)라고 안내.
- 타베로그 기반 도쿄 수집 결정 → Spot을 **해외 주소 등록 가능**하도록 확장: 소개는 한국어로
  새로 작성, 해외 장소는 **Google 지도**로 길찾기·장소 정보 연결(국내는 네이버·카카오 유지),
  한글명·영문명이 다른 동일 식당도 중복 방지 처리.
- 도쿄 3.5 이상 6곳(긴자·신주쿠·미나미아오야마·마루노우치) 수집·배포 → Spot 총 **1,021곳**.
- 사용자가 긴자 숙소(소테츠 프레사 인 긴자 나나초메) 사진을 주고 "근처 좋은 바"를 요청 → Google
  도보 경로로 거리 확인 후 바 4곳(모리 바 그란 2분·리틀 스미스 7분·믹솔로지 살롱 8분·긴자 텐더
  8분) 추가.

## ⚠️ [[lampas-web-spot]] 기존 페이지와의 모순 — 명시
`[[lampas-web-spot]]` 페이지는 **2026-09-26 08:31:28Z 시작 세션**
([[2026-09-26-spot-주소기반재구축-카카오맵전환-네이버보강-채팅검색]])을 근거로 "블루리본·다이닝코드
표기 전면 제거, 서비스가 **주소만 넣으면 AI가 새로 쓰는** 방식으로 재편됐다"고 기록했다.

이 세션은 **같은 날 02:38Z에 시작해 그 재편 세션보다 먼저 떠 있었고, 10-02까지 계속 이어지며**
블루리본→식신→타베로그로 소스를 바꿔가며 "명단(상호+주소+평점) 수집 → 중복 제거 → Google 시트
append → Spot 운영 데이터에 신규분만 추가"를 반복했다. 즉 **수집 파이프라인 자체는 재편 이후에도
폐기되지 않고 계속 돌았다** — 재편 세션이 말한 "구 데이터 856곳을 자동 보강 중"의 "구 데이터"가
이 세션에서 계속 늘어나는 숫자(856→995→1,021+)와 같은 것으로 보인다. 두 세션의 관계는 다음 중
하나로 추정되나 소스만으로는 확정 불가:
- (a) 이 세션이 **원시 후보(이름+주소) 공급 라인**이고, 재편 세션이 만든 Jev+LLM 파이프라인이 각
  신규 행에 대해 **공개용 소개를 자동 생성**하는 후속 단계 — 재편 세션 설명의 "운영 워커가 자동
  보강 중(동시 처리 3)"과 들어맞음.
- (b) 재편이 부분적으로만 적용돼 레거시 수집 경로가 남아있는 상태.

다음에 `lampas-web-spot` 코드를 다시 볼 때 **(a)가 맞는지, 공개 화면에 블루리본/식신/타베로그
출처 표기가 실제로 하나도 안 보이는지** 확인 필요.
