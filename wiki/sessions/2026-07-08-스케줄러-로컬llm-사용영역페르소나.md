# 2026-07-08~09 세션 — 예약 메시지 스케줄러 · 로컬 LLM 설치 · 사용 영역 페르소나

4개 스레드가 섞여 진행됐고, **"에이전트가 띄운 백그라운드 작업은 턴/세션이 넘어가면 죽는다"**는
하네스의 구조적 한계가 스레드 두 개(스케줄러·다운로드)를 관통한다 → [[harness-background-process-lifecycle]].

## 1. 세션 독립 예약 메시지 스케줄러

**문제 제기**: "10초 뒤에 메시지 줘봐". 첫 시도 실패 — 에이전트 턴 안의 `sleep 10` 타이머는
턴이 끝나면 하네스가 프로세스를 내려서 알림을 받아줄 주체가 사라진다. 알림이 유실됐다가
다음 사용자 메시지에 묻어서 도착. (세션이 살아 있는 동안엔 배경작업 완료→재호출→능동 메시지가 정상 동작.)

**해결**: 타이머를 에이전트가 아니라 **항상 살아 있는 람파스 서버에 내장**.
- `src/scheduler.ts` (신규): 예약을 `queue/scheduled/`에 **파일로 영속화**, 서버가 0.5초 간격 폴링,
  시각이 되면 채팅 히스토리에 메시지 적재. 서버 재시작에도 예약 생존, 지나간 예약은 기동 즉시 전달.
- 에이전트에 `schedule_message` / `list_scheduled` / `cancel_scheduled` MCP 도구 주입 +
  시스템 프롬프트에 "예약은 타이머 대신 이 도구를 써라" 지시.
- UI: 큐 패널에 "⏰ 예약 · N초 후" 카운트다운 + ✕ 취소, 전달 시각에 채팅창 자동 표시(폴링).
- **정확도**: 서버가 **사용자 메시지 도착 시각**을 기억해뒀다가 그 시각 + N초로 전달 시점 계산.
  에이전트가 도구를 늦게 호출/오래 생각해도 "10초 뒤"는 보낸 순간 기준 정확. 단독 테스트 +11ms 오차.
- 검증: 재시작 버퍼 포함 60초 예약이 새 빌드 재시작 후에도 살아남아 예정 시각(+60초)에 자동 도착.
- → 절차: [[session-independent-scheduler]]

## 2. 로컬 LLM 설치 (Rapid-MLX + qwen3.5-35b-8bit)

머신 사양: **Apple Silicon M4 Pro / 14코어 CPU / 20코어 GPU / 64GB 통합 메모리 / 2TB SSD**
(→ [[progdesigner]]. 하네스가 도는 맥미니 = Mac mini M4 Pro로 추정).

- 옵션 비교(a/b/c): **모델 크기**(7B/32B/70B) · **양자화**(FP16/Q8_0/Q4_K_M) · **백엔드**(Metal/MLX/CPU).
  Rapid-MLX(MLX 프레임워크, OpenAI 호환 서버) vs llama.cpp(C++/GGUF, `-DGGML_METAL=ON`) vs Ollama.
  → 상세: [[local-llm-on-apple-silicon]]
- **DeepSeek-V4-Flash 거부**: 284B(활성 13B) 모델, Q4_K_M로도 ~95GB 필요 → 64GB로 실행 불가. 어시스턴트가 솔직히 반려.
- **선택·설치**: `qwen3.5-35b-8bit` (= `mlx-community/Qwen3.5-35B-A3B-8bit`), 약 37.7GB(35.2GiB).
  Rapid-MLX 0.10.5. `rapid-mlx pull` → 다운로드.
- **다운로드가 8GB에서 반복 정지** — 에이전트가 백그라운드로 띄운 pull이 세션 넘어갈 때마다 죽음.
  `nohup ... > log 2>&1 & disown`으로 세션과 분리해 해결(HF 이어받기). → [[detach-long-job-nohup]]
- **상주화**: launchd `io.lampas.rapidmlx` 등록(재부팅 자동 기동), 응답 테스트 한국어 1.1초.
- **하네스 통합**: `server.ts`에 로컬 LLM 프로바이더 추가, 모델 선택기에 **"Local" 그룹**으로
  `qwen3.5-35b-8bit` 노출(로컬 서버 자동 감지). → [[model-selection]]

**관찰 — 로컬 모델 품질 저하**: 로컬 qwen 모델로 전환 후 "웹검색/날씨 돼?", "MCP 연결 돼?"
질문에 답이 눈에 띄게 약해지고 환각 발생 — "MC P"를 *Multi-Controller Protocol*로 지어냄.
로컬 35B 모델은 Claude 대비 지식·툴이 약하고(웹검색·MCP 미배선 시 불가), 환각 경향.

## 3. 사용 영역 페르소나 UI

- 1차: "사용 영역 선택 시 이미지 빼고 프롬프트 채우는 액션 버튼 칩 전부 제거".
- 2차: 각 사용 영역을 **전문가 페르소나 프롬프트**로 정의 + 설정에서 확인/수정.
  - 서버 프리셋을 6개 영역 페르소나로 재작성: 비즈니스(15년차 전략 컨설턴트), 브랜딩(브랜드 전략가+카피),
    마케팅(전환 중심 시니어), 이미지(아트 디렉터), 영상(영상 PD+작가), 일반(페르소나 없음=기본 람파스).
  - 조회·수정 API + 설정(⚙) "사용 영역 페르소나" 섹션 편집 UI. 수정본은 `presets.json`에 저장,
    다음 메시지부터 적용, 수정된 영역엔 ✏️ 표시, 초기화 가능.

## 4. 일본어 드리프트 버그 (코드 아님)

세션 중 어시스턴트가 갑자기 일본어로 응답(직전 2응답 + ScheduleWakeup 사유). 사용자가 원인 규명 지시.
- **진단**: 코드·설정 버그 아님. `currentLanguage()`는 저장값 없으면 `ko` 폴백,
  `languageInstruction()`도 "항상 한국어로 응답하라"를 시스템 프롬프트에 정상 주입 중.
  → **모델의 응답 생성 실수**(긴 코딩·영어 도구 출력 컨텍스트에 몰려 언어 드리프트).
- **해결**: 코드가 아니라 행동 문제 → 재발 방지 피드백을 어시스턴트 메모리에 기록, 이후 한국어 고수.
  ([[progdesigner]] 선호: 항상 한국어와 일치.)

## 핵심 결정 / 교훈
- 능동 예약은 **에이전트 타이머 금지, 서버 내장 파일 영속 스케줄러**로. 정확도는 사용자 메시지 도착 시각 기준.
- 긴 다운로드/작업은 **`nohup & disown`으로 세션과 분리**해야 턴 넘어가도 생존. HF 이어받기 활용.
- 64GB에는 35B급 8bit(~37GB)가 현실적 상한. 284B급(DeepSeek-V4-Flash)은 불가 — 사양 기준 솔직히 반려.
- 로컬 모델은 비용 0이지만 품질·툴이 Claude 대비 약함(환각 관찰).
- 언어 드리프트는 코드가 아닌 모델 행동 문제일 수 있음 — 코드 뒤지기 전에 실제 주입값부터 확인.
