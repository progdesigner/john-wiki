# 2026-09-14 — 돌잔치 AI 기능 보완 (장면 구조화·TTS 빌드/제거·어드민 개편)

Tool: claude (Claude Code). 작업폴더 `lampas-system`. 헤더상 시작 시각은
2026-09-14T09:15:30Z이지만, 대화 중간에 `/model` 커맨드로 두 차례 모델이 바뀌고
(`Fable 5.1`, 이어서 "high" effort로 재설정) 내용상 [[dalar-web-first]]의 09-20 확장
세션([[2026-09-20-lampas-first-장면가격체계-샘플영상-초대코드]])에서 다루는 후속
사건(주문 `23927984…`)까지 포함돼 있어, **실제로는 여러 날에 걸쳐 이어진 장기 세션**으로
추정된다. 이 위키에 처음 상세 노출되는 세션 — [[dalar-web-first]] 엔티티 페이지가
"최초 구축(09-13/14) 이후 09-20 확장 전까지 고정 12장면으로 약 1주일 운영됐다"고만 적어뒀던
공백 구간을 이 세션이 채운다. 상세 서술은 대부분 [[dalar-web-first]] 엔티티 페이지에
반영했고, 이 페이지는 시간순 요약·의사결정 지점만 정리한다.

## 핵심 흐름 (시간순)

1. **장면 수 5(실제 6)→12 요청** — 하드캡 3곳(`Math.min(10, sceneCount)`)과 토큰 상한
   (`scenarioMaxTokens = min(6000, 1500+scenes*450)`)이 먼저 막힘을 확인. 사용자가 "10컷에서
   대사가 점점 빨라졌다"고 원인을 제보 → **구조적 원인**(한 번의 LLM 호출로 전체 씬을 받다 보니
   뒤 씬일수록 남은 토큰 예산이 줄어듦)으로 진단.
2. **결제 딥링크**: `lampas-web-pay`에 `?credits=` 쿼리 지원 추가, `dalar-web-first`의
   "Lampas 크레딧 충전" 버튼이 패키지 선택 없이 바로 5만 크레딧 결제로 연결.
3. **구조적 해결 채택(사용자가 "2" 선택)**: "개요 1번 + 씬마다 독립 호출" 방식으로 전환 —
   씬이 몇 개든 마지막 씬도 첫 씬과 동일한 토큰 예산(900토큰)을 받도록. `SCENARIO_MAX_SCENES`
   상수 통일(10→12), DTO `@Max` 동기화. lampas-api 배포(v0.1.79).
4. **배포 문구 6→12 반영 누락 발견·수정**, 이어서 "특정 크레딧 결제 페이지에서 이미지/영상
   환산 문구 숨기기" 소소 수정.
5. **50,000 크레딧 정액 결제 vs 실제 생성 비용 조사(에이전트 위임)**: `first.worker.ts`가 호출하는
   시나리오/이미지/영상 생성 4종 모두 `deductUsageCredits()`를 거치지 않음이 확인됨 — 즉
   **첫 결제 50,000크레딧은 1회성 정액 요금이고, 실제 AtlasCloud/LLM 벤더 비용은 사용자 크레딧과
   완전히 분리(회사가 부담)**되는 구조. 재생성도 추가 차감 없음. 다만 벤더 비용이 어디에도
   기록되지 않는다는 부작용도 함께 지적.
6. **영상 비율 버그 발견**: 이미지 생성 API 파라미터엔 올바르게 `aspectRatio`가 전달되는데,
   같은 요청의 **프롬프트 텍스트 내 지시문**(`orientationHint`/`studioAspectRatioDirective`)이
   1:1·3:2 두 값만 처리하고 나머지 7개(16:9 포함)는 전부 "2:3 세로"로 잘못 안내 — 숫자 파라미터와
   텍스트 지시가 모순되는 버그.
7. **영상 비율 9:16 + 모델 Seedance 2.5로 교체** 요청 → 씬 이미지 `aspectRatio: "16:9"→"9:16"`,
   영상 모델 `bytedance/seedance-2.5/image-to-video` 추가, ffmpeg 렌더 캔버스
   `1280x720→720x1280`, 위 아스펙트 비율 프롬프트 버그도 함께 수정(`describeStudioAspectRatio`
   순수 함수로 일반화). lampas-api v0.1.80 배포.
8. **`admin.first.dalar.ai` 서브도메인 신설**: `*.first.dalar.ai` 커버 ACM 인증서 필요 →
   IAM 계정 `elevino`에 `acm:RequestCertificate` 권한 없어 1차 중단, 사용자가 권한을 열어준 뒤
   재시도로 완료(인증서 발급→DNS 검증→CloudFront 별칭→Route53). `first.dalar.ai`와 동일
   SPA 번들을 쓰며 호스트명 분기로 관리자 화면 노출.
9. **대규모 기능 요청** — lampas-web-scenario처럼 고정 12컷 인터뷰 대본(자막·인터뷰어 질문·
   아기 대사)을 쓰고, 이름 치환·캐릭터/레퍼런스시트 자동 생성·공통 비주얼 컨셉·카메라 고정·
   컷별 프롬프트 편집·**Seedance 2.5 영상**을 요구. 3개 조사 에이전트(admin/first 백엔드,
   레퍼런스시트/보이스/TTS 백엔드, lampas-web-scenario UI) 병렬 조사 후 설계 에이전트로 상세
   구현 계획 수립.
10. **구조 구현 (TTS 나레이션 포함, "구축해줘")**: 고정 대본 상수, 카메라 고정 후처리,
    컷별 독립 TTS 나레이션(무과금 `AiService.generateAudio` 직접 호출)→실측 길이로 컷 길이 확정
    →9:16 이미지→Seedance 2.5→ffmpeg 렌더(영상 자체 오디오 0.25 덕킹+나레이션 믹스), 관리자
    컷 편집 API 5종(필드별 잠금, 재생성 시 잠긴 필드/영상 보존)까지 구현·배포(lampas-api
    v0.1.81, 833→837 테스트).
11. **운영 사고 대응**: 주문 `b0385933…`이 9번 컷 LLM JSON 파싱 실패로 정지 →
    씬 상세 토큰 예산 확대(`900+글자×3+줄×40`), **워커 자동 재시도**(체크포인트당 3회, 20초×n
    백오프) 신규 도입, Prisma write-conflict(P2034) 3회 재시도, 고객 화면에 컷 이미지 미리보기
    추가 → [[resumable-worker-checkpoint-resume]] 계열의 또 다른(09-20보다 이른) 반복.
12. **대표 음성 도입**: 매 주문마다 다른 음성이 나오는 문제 → 여아=Gemini `Aoede`,
    남아=`Puck`, 인터뷰어=`Kore`(30대 여성 아나운서 톤) 3종 고정. 주문 폼에 성별 선택 추가
    (`first_orders.childGender`). 기존 진행 중 주문은 워커가 자동으로 대표 음성으로 재녹음.
13. **TTS 전면 제거** — 사용자가 lampas-web-scenario 세션 7 영상이 실제로는 TTS를 쓰지 않고
    Seedance 자체 오디오(`generate_audio: true`, 대사는 프롬프트 텍스트로만 전달)를 쓴다는 걸
    확인한 뒤 "필요 없으니 제거". **두 앱에서 동시 제거**: `dalar-web-first`/`lampas-api`
    (나레이션·오디오 믹스·줄별 음성 API·대표 음성·성별 선택 전부 삭제, `childGender` 컬럼도
    배포 후 DROP), `lampas-web-scenario`(별도 포크 에이전트로 `VoicePicker`/`voice-api.ts`
    삭제, 대사 텍스트는 유지)까지 병렬로 정리 → [[lampas-web-scenario]] 참고.
14. **레퍼런스 일관성 강화**: 배경(인터뷰 세트)·인터뷰어(손+마이크) 이미지를 결제 직후 미리
    생성해 개요·컷 이미지 생성 양쪽의 공통 참조로 사용.
15. **크레딧 원가 vs Atlas 실비용 조사**: 세션7(lampas-web-scenario)은 컷당 10~13초라
    ~$1.3~1.7인데, `b0385933…`은 컷 길이가 20~30초(대본에 대사가 몰려 LLM이 실제 발화
    길이보다 짧게 추정한 값이 실측으로 보정된 결과)라 컷당 비용이 2~3배. 사용자 결정: 상한
    유지·대본 유지·**해상도만 480p로 낮춤**, 영상 비율(9:16/16:9) 선택도 주문 폼에 추가.
16. **AtlasCloud 잔액 부족(402) 실사고**: 12번째(마지막) 컷 영상 제출 시점에 잔액 소진 →
    FAILED. 이미 제출된 11개 영상을 버리지 않도록 "완료 판정을 1시간 타임아웃보다 먼저 보는"
    수정을 긴급 배포.
17. **배경 이미지가 첨부 사진을 안 쓰던 문제 확인 후(배포 보류) → 다음 요청에 수정**: 배경·
    레퍼런스 이미지가 업로드 사진 속 "그 방"을 사람 없이 재구성하도록 프롬프트·참조이미지 변경.
18. **대본 재배분**: 주문 `23927984…`에서 10번 컷에 대사 11줄이 몰려 급해진 문제 + 대사 없는
    12번(엔딩 자막) 컷 제거 → 마지막 3컷(10/11/12)이 이름을 부르며 끝나도록 대본 재구성,
    `estimateLinesSeconds` 기반 "컷 길이 = max(LLM 추정, 대사 길이 추정)"으로 보정, 재발
    방지 테스트(모든 컷 발화 추정이 30초 이하인지 검사) 추가.
19. **admin.first.dalar.ai 전면 개편**: 탭마다 URL이 바뀌는 `/users`(정보+**크레딧 수동
    지급/차감**)·`/orders`→`/orders/:id`(에디터)·`/cs`→`/cs/:id`(first.dalar.ai 유입 CS만
    필터, 답변·종료/재오픈) 3구조로 재편. **1회차 이후 수동 편집 모드** 도입 — 컷을 다시
    손대도 기존 완성 영상은 유지되고, 관리자가 "최종 영상 편집"을 눌러야 다시 합쳐짐.
20. **컷 길이 상한 30초 하드캡** 전 경로 일괄 적용.
21. **회차별 제작 소요 시간 기록**(`rounds[]`) — 1회차는 결제~최종 업로드, 2회차 이후는
    수정 시작~재업로드. 처음엔 "완료 대기 중" 상태일 때 행이 사라지는 버그가 있어 재수정
    (진행 중에는 항상 표시, 제공 순간 확정).
22. **이전 최종 영상 보관**(`progress.films` 누적) — 재생성해도 예전 영상 URL이 남아 admin·
    고객 화면 모두에서 열람 가능.
23. **CloudFront 캐시 버그**: 최종 영상을 매번 같은 S3 키(`film.mp4`)에 덮어써서, 실제로는
    다시 렌더링했는데도 CDN이 첫 렌더를 계속 서빙 — "12번째 영상이 다르다"는 사용자 제보로
    발견. 렌더마다 새 키(`film-{시각}-{id}.mp4`)를 쓰도록 수정, 무효화로 즉시 해결.

## 의사결정
- 장면 수 12 확정, 다만 **"땜빵(캡+토큰 상한만 올림)" 대신 "구조적 해결(개요+씬별 독립 호출)"**
  선택 — 이후 컷 수를 다시 늘려도 같은 문제가 재발하지 않도록.
- 대사 길이는 원가와 무관하게 **그대로 유지**하기로 확정(첫 결정) → 이후 실사고로 **해상도만
  낮춰 원가 절감**, 상한·대본은 그대로 유지(재확정).
- TTS 나레이션 기능은 설계·구현·배포까지 마쳤다가, "web-scenario도 TTS 안 쓴다"는 사실 확인
  직후 **전면 제거** — 두 앱(`dalar-web-first`, `lampas-web-scenario`)에서 동시에.
- admin 실사용 오류는 전부 "관리자 상세 오류" 노출·수동 개입 경로를 남기는 방향으로 처리
  (자동 판단보다 사람 확인 우선), [[dalar-web-first]] 페이지의 Jev 연동 원칙과 일치.
