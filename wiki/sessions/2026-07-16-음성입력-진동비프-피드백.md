# 2026-07-16 — 음성입력 준비→녹음 전환 진동+비프 피드백 세션

`[[progdesigner]]`가 `[[lampas-harness]]` 웹 채팅의 전송 버튼 길게 누르기(push-to-talk) 음성 입력에서,
노랑(준비중)→빨강(녹음 시작) 전환 순간에 "더 콕 하는 느낌"(진동)이나 소리로 확실히 알 수 있게 해달라고
요청한 1왕복 세션. 소스: `raw/conversations/2026-07-16-음성입력-진동비프-피드백.md`
(원본 경로 `logs/chats/archive/58623de9-163d-408c-b9a5-fce33d5176d4.md`).

전날(2026-07-15) [[2026-07-15-gpt-realtime-음성입력-길게누르기]] 세션에서 만든 3단계 시각 피드백
(노랑/빨강/초록)에 촉각·청각 피드백을 얹는 후속 개선.

## 진행

1. `apps/web/index.html`의 `startVoice()` 함수를 찾아, 실제 캡처가 시작되는 지점인 1870번째 줄
   `setVoiceUi("live")`(노랑→빨강 전환) 호출 시점을 확인.
2. 그 지점에 `voiceStartFeedback()`을 신설해 두 가지를 동시에 발동:
   - **진동** — `navigator.vibrate(40)`. Android Chrome 등에서 짧게 떨림. **iOS Safari는 진동 API
     자체를 지원하지 않음**(무음 실패, 에러 아님).
   - **비프음** — 이미 열려 있는 마이크용 `AudioContext`를 재사용해 880Hz 짧은 삑(약 90ms), 클릭
     노이즈 없이 볼륨을 부드럽게 램프.
   - 진동과 비프를 **둘 다** 넣은 이유: 진동이 안 먹는 기기(iOS)에서도 소리로 대체되어 최소 한쪽은
     항상 피드백이 전달되게 하기 위함.
3. `apps/web`을 vite로 빌드해 문법 오류 없음 확인.
4. **배포 함정 재확인**: 데몬은 컴파일된 `dist`를 서빙하므로, 실제 반영하려면 `npm run build:web` 후
   데몬 재시작이 필요하다고 안내(이 세션 자체에서 재시작은 실행하지 않음). → [[self-hosted-agent-server-ops]]

## 결정사항

- 노랑→빨강 전환 피드백은 **진동+비프 동시 발동**(택일 아님) — 기기별 지원 여부가 갈리므로 중복 채널로
  최소 하나는 보장.
- 비프음은 새 `AudioContext`를 열지 않고 **음성 캡처용으로 이미 열려 있는 것을 재사용**.
