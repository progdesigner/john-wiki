# 2026-09-28 — Google Analytics 전사 적용 + First 전용 퍼널 구성 (미배포)

`Tool: codex`, 작업 폴더 `lampas-system`(Started 2026-09-27T15:04:37Z UTC = KST 2026-09-28
00:04). [[2026-09-29-분석사이트구축-ga4퍼널-이벤트카탈로그]]가 조사한 "로컬엔 준비됐지만 운영
미반영" 상태의 **원본 작업 세션** — 이 세션에서 만든 계측 코드와 GA4 Explore 퍼널이, 하루 뒤
세션에서 배포 여부를 재확인당한 대상이다.

## 1. GA4 전사 적용
사용자 요청: "dalar.ai 와 lampas.io 에 GA를 심어서 모든 서비스에 적용 + 퍼널 가능하도록 이벤트도
잘 심어줘." 기존 GA4 측정 ID를 코드에서 확인:
- **Dalar**: `G-7R1C9BXKTX`
- **Lampas**: `G-BR3R64CQB9`

두 도메인 계열 **웹 앱 30개**를 조사한 결과 태그 누락·페이지뷰 처리 방식 불일치를 확인, 공통
계측 모듈로 통일. 서비스 간 이동, 주요 작업 시작·요청 수락·실패를 같은 이벤트 기준으로 기록하도록
맞추고, 생성 완료는 실제 결과 확인 시점에 별도로 심음. **결제 URL의 인증값 등 민감 파라미터는
GA로 전송되지 않도록 정리**(PII·토큰 제거).

## 2. `first.dalar.ai` 전용 퍼널 구성 (브라우저로 GA4 조작)
후속 요청: "브라우저를 이용해 first.dalar.ai 에 대한 퍼널을 따로 만들어줘." 실제 사이트를
브라우저로 돌아보며 방문 → 로그인/가입 → 패키지 선택 → 결제 → 제작 요청 → 결과 확인 흐름을
확인하고, GA4 로그인 세션으로 DALAR 속성에 접근:
- **결제 화면 위치 문제 발견**: First의 결제는 `pay.lampas.io/first`에 있어 구조적으로 **Lampas
  측정 ID로 전송**되고 있음 → 이 구간도 Dalar 측정 ID로 보내도록 계측을 바꾸고, `first_*` 이벤트
  네이밍으로 다른 서비스 이벤트와 분리.
- 주문 생성·미리보기 확인·제작 시작·완성 영상 확인 단계를 실제 흐름에 맞춰 이벤트로 추가.
- 로그인 여부에 따라 일부 단계를 건너뛸 수 있는 점을 고려해 **구매 퍼널과 제작·결과 확인
  퍼널을 분리** — 하나로 합치면 이탈 지점이 가려지기 때문.

GA4 Explore에 `First · first.dalar.ai 전환 퍼널` 탐색을 저장, 3개 흐름 구성:

| 흐름 | 단계 |
|---|---|
| **구매** | 방문 → 결제 화면 → 결제 시작 → 완료 |
| **제작** | 주문 → 미리보기 → 제작 시작 → 결과 확인 |
| **시작** | 방문 → 만들기 → 로그인 확인 → 주문 |

저장 링크: [First 전용 GA4 퍼널](https://analytics.google.com/analytics/web/#/analysis/a402451861p547256216/edit/1ewF4tNmQ3-zrUbc41j_hw)

## 3. 검증 상태 — 코드는 완료, 운영 배포는 보류
- 웹 앱 30개 빌드·가입 판별 테스트 통과, API 빌드 통과.
- GA4 스트림 설정·저장된 퍼널 조건을 재확인하며 마무리.
- 새 이벤트가 아직 수집되지 않아(=아직 배포 전) **탐색 결과는 비어 있는 상태**로 세션 종료.
- **운영 배포는 이 세션에서 실행하지 않음** — 작업 트리에 First·Spot 등 기존 변경이 섞여 있어
  배포 범위를 구분해 정리하는 중이었다고 보고.

> 새 퍼널 데이터는 코드가 실제로 배포된 이후부터만 쌓인다는 점이 세션 마지막에 명시적으로
> 재확인됨 — 이 한계가 그대로 다음 날([[2026-09-29-분석사이트구축-ga4퍼널-이벤트카탈로그]])
> 조사에서 "운영 미반영" 사실로 확인된다.
