## 1. Auto 모델 난이도 판정 — 누가 판단하는가 (코드 감사)

사용자 질문: "메시지를 보내면 Auto가 알아서 난이도를 조정하는데, 그 판단을 누가 하는지 확인해줘."
어시스턴트가 `src/server.ts`를 file:line 근거로 조사.

**결론: 서버(백엔드) 100% 전담.** 클라이언트(`apps/web/index.html`)는 "Auto — 난이도 자동 선택"
옵션 표시(865-869행)와 서버가 내려준 결과 표시(`data.auto`, 1675행)만 하고 판단은 하지 않는다.

서버 로직 위치 (`src/server.ts`, 커밋 "feat: 모델 선택기에 Auto — 난이도를 분류해 Claude 모델 자동
선택", v0.1.25 도입):

| 로직 | 라인 | 설명 |
|------|------|------|
| `AUTO_JUDGE_PROMPT` | 641-653 | easy/medium/hard 분류 지시 프롬프트 |
| `heuristicTier()` | 661-667 | 휴리스틱 폴백 — 키워드/길이 |
| `judgeTierClaude()` | 669-690 | 1단계: Haiku 4.5로 판정 (Claude API) |
| `judgeTierLocal()` | 692-714 | 2단계: rapid-mlx 로컬 LLM으로 판정, 5초 타임아웃 |
| `resolveAutoModel()` | 716-737 | 세 방식 순차 폴백 (Claude API → 로컬 LLM → 휴리스틱) |
| `runChatTurn()` | 3300-3306 | auto 모델 감지 시 `resolveAutoModel()` 호출 |

**판정 기준**: easy=인사/잡담/짧은 사실질문/간단 번역·요약, medium=문서작성·편집/논리적 설명/작은
코드 수정/사진 설명, hard=기능구현/리팩토링/디버깅/배포/아키텍처 결정/다단계 작업. 휴리스틱은
`구현|리팩터|디버그|버그|고쳐|배포|deploy|fix|refactor|...` 키워드, 메시지 길이(>300자 hard,
>80자 medium), 사진 첨부 시 medium 이상.

**티어→모델 매핑** (env로 재정의 가능): easy→`claude-haiku-4-5`(`LAMPAS_AUTO_EASY`),
medium→`claude-sonnet-5`(`LAMPAS_AUTO_MEDIUM`), hard→`claude-opus-4-8`(`LAMPAS_AUTO_HARD`).

**안전성**: 판정 실패해도 턴을 막지 않음(휴리스틱 폴백). 검증 스크립트
`tools/probe-auto-judge.mjs`(일회성) 존재.

→ [[model-selection]] 갱신, 배경 스킬: [[config-flag-gate-audit]]과 유사한 "게이트/판정 로직 전수
추적" 접근을 코드 감사에 재사용(신규 스킬 추출은 안 함 — 이미 커버된 패턴).

## 2. Fable 5를 난이도 판정에 포함 — extreme 티어 신설

사용자: "난이도 판정에 페이블 5도 포함될 수 있게 수정해 줘." 어시스턴트가 3단계(easy/medium/hard)를
4단계로 확장:

- `AutoTier`에 `"extreme"` 추가 → `claude-fable-5` 매핑 (`LAMPAS_AUTO_EXTREME`로 재정의 가능)
- 판정 프롬프트에 extreme 기준 추가: 대규모 아키텍처 개편, 다중 시스템 교차 리팩터, 프로덕션 장애
  대응, 보안 설계 등 hard보다 명백히 상위인 경우로 제한. **모호하면 hard를 택하도록 명시**해 값비싼
  모델 남용 방지.
- **휴리스틱 폴백은 hard까지만** — extreme은 실제 LLM 판정(Claude API 또는 로컬 LLM)을 통해서만
  나오게 설계. LLM 판정이 모두 실패한 안전망 상태에서 근거 없이 최상위 모델로 튀지 않도록 하는
  의도적 비대칭.

서버 코드만 수정 (`npm run build:server` + 데몬 재시작 필요 — 이 세션에서는 바로 반영하지 않고
질문만 함, 재시작은 §5에서 처리).

## 3. 진행 중 턴 중지 버튼에 2단계 확인 추가

사용자: "중지 버튼 누르면 바로 실행되지 말고 컨펌 과정을 거치게 해줘."

`apps/web/index.html`의 활동바("■ 중지")·큐 패널 진행중 세션 중지 버튼 두 곳을 수정:
- 첫 클릭 → 버튼이 빨갛게 깜빡이며 "정말 중지?"로 전환, 3초 확인 창 시작
- 3초 안에 같은 버튼 재클릭 → 실제 중지
- 3초 안에 안 누르면 → 자동으로 "■ 중지" 원상태로 복귀
- 배경 작업 중지(`✕`)·대기 취소 등 다른 버튼은 건드리지 않음 — 진행 중인 턴을 멈추는 "■ 중지"에만
  적용

## 4. 대화 목록 보관을 hover 버튼 → 롱프레스 확인으로 전환

사용자: "마우스 오버하면 뜨는 보관 버튼 말고, 대화 목록을 꾹 누르면 보관하시겠습니까 컨펌이 뜨게
해줘."

- 기존 hover 시 노출되던 🗄 보관 버튼 제거
- 항목을 약 0.6초 꾹 누르면 → 누르는 동안 항목이 노랗게 강조(예고) → 0.6초 후
  `"이 대화를 보관하시겠습니까?"` 확인창 → 확인 시 보관(장기 기억 저장 포함, 삭제 아님)
- 짧은 탭은 기존대로 대화 열기
- 누르는 중 8px 이상 이동하면 스크롤/드래그로 간주해 보관 취소
- 롱프레스로 처리된 경우 뒤따르는 클릭(세션 전환) 억제
- `archiveSession` 동작·서버 연동 로직 자체는 안 건드리고 트리거만 교체

두 UI 패턴(§3 이중클릭 타임아웃, §4 롱프레스+다이얼로그)을 재사용 가능한 절차로 추출:
