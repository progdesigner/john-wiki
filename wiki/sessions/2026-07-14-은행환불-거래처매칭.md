# 2026-07-14 은행 환불 거래처 매칭 (quick 채팅)

[[lampas]] quick 채팅. [[progdesigner]](CWC)가 **은행 거래내역 스크린샷**과 **프로포마 인보이스**를
첨부해 "이 입금이 어느 결제/환불건인지" 해석을 요청하고, 거래처에 보낼 **영어 회신 초안**까지 정리한 세션.
코딩이 아니라 [[lampas-harness]]를 **업무 비서**로 쓴 사례. → [[harness-as-business-assistant]]

## 흐름
1. 은행내역 한 줄(`PRINC CR … FCFD 7010146961 … T/W FR ADV … 000005`) 해석 요청.
   - 첫 해석: 외화정기예금(FCFD) 원금 입금. `FR`을 "From"으로 읽음.
   - 사용자가 "프랑스發 자금 아니냐" → `FR`은 프랑스 ISO 코드, `T/W`=전신송금으로 재해석.
2. 프랑스 보르도 와인 네고시앙 프로포마 인보이스 2건 첨부 → 관련성 질문.
3. **핵심 반전**: 사용자가 "대금을 이미 지급 후 환불 요청했다"고 밝힘 →
   `PRINC CR / T/W FR ADV`를 **"프랑스 거래처에 선지급한 대금의 환입(refund)"**으로 확정 해석.
   수령액 **90,377.76**.
4. 금액 대조로 검증:
   - Mestrezat: **30,255.96 EUR**, Mähler-Besse: **53,173.20 EUR** → 합계 **83,429.16 EUR**.
   - 환입액 90,377.76 − 83,429.16 = **6,948.60 차액(설명 안 됨)**. 분할금 어떤 조합과도 안 맞음.
   - → 확신도 하향: 이 두 인보이스만의 환불이라 단정 못함. 통화 단위 불명(EUR 맞는지)·제3의 건 가능성.
5. 거래처 회신 초안(영/한) 정리: ① 발신 거래처 확인 요청 ② SRKK/Scott 건 진행 상황 설명.

## 결정·산출물
- 은행 거래코드는 표준화 안 됨 → 축약어만으로 단정 금지, "More details"·거래처 회신으로 최종 확인 원칙.
- 회신 초안 채택 방향: **금액 불일치를 근거로 거래처명·통화·대상 인보이스를 되물어** 매칭 후 마감.
- SRKK 건: Scott에게 설명·제안했으나 "너희 쪽에서 뭐가 잘못됐는지 먼저 확인하라"는 답으로 정체.

## 등장 엔티티

- 매도인(프랑스 보르도 네고시앙): **Mestrezat**, **Mähler-Besse** — EUR 결제.
- SRKK / **Scott** — 별건 진행 중 상대(맥락 미상, 추적 필요).

## 주의 / 미확정
- `FCFD 7010146961`, `000005` 등은 추정 해석 — 은행별 코드 관례 상이, 검증 안 됨.
- 90,377.76의 **통화 단위 미확인**, 인보이스 합계와 6,948.60 차액 미해소 → 매칭 미완결(거래처 회신 대기).
