# 2026-09-19~20 — Lampas Edit(에디터) 자막·큐·템플릿 대량 기능 개발

에디터 앱 **`[[lampas-web-edit]]`**(edit.lampas.io)가 이 위키에 처음 상세 노출되는 세션 — 버전
0.1.17→0.1.43, `lampas-api` 0.1.100→0.1.130까지 하루~이틀에 걸쳐 20개 이상의 기능 요청을 연속
처리한 장시간 세션(DDL 파일명이 `2026-09-20-layout-templates.sql`인 것으로 09-20까지 이어짐을 확인).

사용자는 매 요청을 짧은 한두 문장(대개 스크린샷 첨부)으로 던지고, 어시스턴트가 원인 진단→구현→
테스트→배포→커밋·푸시를 매번 한 세트로 완결한 뒤 보고하는 패턴이 반복된다. 자세한 기능별 내용은
[[lampas-web-edit]] 엔티티에 정리했고, 이 페이지는 세션 흐름과 특이사항 중심.

## 특이사항 — 병렬 세션과 커밋 범위 오염 (3회)

이 저장소(`lampas-system`)는 여러 Claude/Codex 세션이 동시에 작업하는 공유 워크트리다. 이 세션
중 최소 두 번, 경로 단위(`apps/lampas-api`, `apps/lampas-web-edit` 등)로 커밋했다가 그 경로에
**다른 세션이 미리 스테이징해 둔 파일**까지 함께 커밋·배포되는 사고가 발생:

1. **0.1.17 배포 커밋(`c86f8fb0`)**: scenario·www·trends·cs·admin·pay·dalar-web-first·lampas-agent
   일부 + API 12개 파일이 함께 커밋됨. 커밋 메시지는 web-edit 기준이라 내용과 어긋남. 이미
   origin/main에 푸시된 뒤라 되돌리지 않고 사실만 정정 보고.
2. **템플릿 계정종속화 커밋(`cce3ba8b`)**: 다른 세션(원격 커밋 `205bc54e`)이 동시에 API 0.1.115,
   에디터 0.1.37까지 배포하던 중이었는데, 같은 경로에 있던 그 세션의 미커밋 변경(API의
   ai·clips·credits·sports-wiki 모듈 일부, 에디터의 main.tsx·tsconfig·vite.config)이 같이
   커밋·배포됨. 완성 상태였는지 확인 불가하다고 명시.
3. **템플릿 보내기 기능 push 시 리베이스**: 다른 머신 커밋 3개와 `.gitignore` 충돌 → 리베이스 중
   다른 세션의 미커밋 작업 약 185개 파일이 자동 stash→복원됨. `.gitignore`만 양쪽 내용 병합해 해소.

이후 **0.1.40 배포부터는 "이번 작업 파일 6개만 골라 커밋"으로 방식을 바꿔** 재발을 피했다. →
스킬 [[selective-hunk-commit-shared-file]]에 이 사례를 변형으로 추가.
