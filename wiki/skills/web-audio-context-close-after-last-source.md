# Web Audio 컨텍스트는 "마지막 소스"가 끝난 뒤에 닫는다

## 언제 쓰는가
음악 재생과 타이머(동작 전환)·음성 카운트/내레이션을 **같은 AudioContext 시계**로 동기화하는
운동·리듬 앱 등에서, "운동 종료" 같은 하나의 이벤트를 기준으로 여러 오디오 소스(배경음악 +
마무리 멘트)가 동시에 걸려 있을 때. [[lampas-web-fit]]에서 완료 박(beat)에 음악이 끝나는 순간
오디오 컨텍스트를 바로 닫아버려, 같은 순간 시작하는 마지막 코치 멘트(ElevenLabs 음성)가 잘려
나가는 버그로 발견.

## 절차 (단계별)
1. **증상**: "완료" 타이밍에 음악 소스가 종료(`onended` 또는 예정된 정지 시각 도달)하는 순간
   `audioContext.close()`를 호출하도록 짜여 있으면, 같은 완료 타이밍에 재생을 "시작"하는 다른
   소스(마무리 멘트 등)는 컨텍스트가 닫히며 즉시 끊긴다.
2. **원인 진단**: 종료 로직이 "하나의 특정 소스(음악)가 끝났다"를 "세션 전체가 끝났다"와 동일시한
   것이 근본 원인 — 세션에 걸린 **모든 오디오 소스**를 추적하지 않았다.
3. **수정**: 음악·음성 소스를 전부 하나의 목록으로 추적하고, 그 목록의 **마지막 소스까지 실제로
   끝난 뒤에만** `close()`를 호출하도록 변경. 소스별 종료 콜백에서 "아직 끝나지 않은 소스가
   남아있는가"를 확인하는 카운터/Set으로 구현.
4. **마무리 멘트 자체도 설계에 포함**: 음악을 마지막 박에서 페이드아웃시켜 멘트만 또렷하게 들리게
   하는 등, 멘트가 "끊김 없이 들릴 시간"을 음악 쪽 설계에도 반영하면 더 자연스럽다.
5. **검증**: 실제 전체 세션(예: 1분 운동)을 끝까지 돌려, 마지막 멘트의 시작 시각과 재생 길이,
   컨텍스트가 실제로 닫히는 시각을 로그로 찍어 "멘트 재생 완료 시각 ≤ 컨텍스트 close 시각"인지
   확인한다. 단위 테스트로는 실제 AudioContext 타이밍을 완전히 재현하기 어려우므로 헤드리스
   브라우저로 풀 세션 재생 검증이 필요했다.

## 주의사항 / 함정
- 같은 틀린 가정("이 소스가 끝나면 전부 끝난 것")은 다른 동시성 종료 로직(예: 애니메이션, 다중
  타이머)에도 반복될 수 있는 패턴 — "종료" 이벤트를 단일 소스 기준으로 잡지 말고 전체 활성 소스
  집합 기준으로 잡을 것.
- Web Audio 소스 노드는 재사용 불가(1회성)라서, "아직 안 끝난 소스가 있는가"는 노드 자체가 아니라
  별도 상태(Set of ids, 카운터)로 추적해야 한다.
