# 자동화 브라우저가 막히면 "정확히 필요한 만큼만" 사람에게 위임한다

## 언제 쓰는가
[[lampas-browser]](하네스 "브라우징" 패널)처럼 AI가 직접 조작하는 브라우저로 콘솔·설정 화면을
진행하다가, 도구가 구조적으로 접근 못 하는 UI 요소에 부딪혔을 때:
- 비밀번호·2차 인증 입력 필드 (보안상 도구가 의도적으로 제외)
- 모달/패널 내부 스크롤 영역 (뷰포트 밖 요소에 도달 못 함)
- 팝업 창이 닫혀야 완료를 감지하는 OAuth 플로우 (자동화 브라우저에서 팝업이 별도 탭으로 열려
  안 닫힘 → [[meta-oauth-token-console-popup-unreliable-in-automated-browser]] 참고, 이건
  재시도로 안 풀리는 별도 하위 문제라 전용 스킬로 분리돼 있음)
- 좁은 입력란에 표시되는 시크릿 값 (`selection`·클립보드 경유 읽기 모두 실패 가능)

같은 날(2026-09-26) 3분 간격으로 독립 진행된 두 세션
([[2026-09-26-ai-dalar-인스타그램-토큰발급-메타앱생성]] — 비밀번호·팝업·좁은 필드,
[[2026-09-26-카카오-지도-api-키-발급]] — 비밀번호·모달 스크롤)이 각각 다른 구체적 장벽에서
동일한 대응 전략에 도달해 일반화함.

## 절차 (단계별)
1. 막힌 지점까지는 최대한 도구로 채워 둔다 — 폼 필드, 이름, 옵션 등 도구가 접근 가능한 부분은
   미리 입력해 사람이 할 일을 최소화한다.
2. 막힌 이유를 한 문장으로 진단한다 — "비밀번호라서", "모달이 스크롤 안 돼서", "팝업이 안 닫혀서"
   처럼 재시도로 풀릴 문제인지 구조적 한계인지 구분한다.
3. **재시도에 시간 쓰지 않는다** — 같은 클릭·스크롤·selection 읽기를 여러 번 반복하는 대신,
   구조적 한계로 판단되면 즉시 사람에게 넘긴다.
4. 사람에게 위임할 때는 **"이것만 해주세요"** 형태로 범위를 좁힌다 — 화면 전체를 대신 봐달라고
   하지 않고, "카테고리를 식음료로 바꾸고 체크박스를 켠 뒤 저장" 같이 구체적 액션 1~2개만 지정한다.
   이미 채워둔 값(표로 정리)도 함께 보여줘 사람이 다시 확인할 필요가 없게 한다.
5. 완료 확인은 **자연어 신호**로 받는다("저장했어", "로그인했어") — 도구가 상태를 자동 감지하지
   못하는 게 애초에 이 스킬을 쓰는 이유이므로, 사람의 한마디를 완료 신호로 삼고 바로 이어간다.
6. 이어지는 단계에서 다시 같은 종류의 장벽(예: 다음 모달)을 만나면 처음부터 이 절차를 반복한다 —
   한 세션 안에 여러 번 위임해도 된다.

## 주의사항 / 함정
- 팝업 기반 OAuth 완료 감지처럼 **재시도 자체가 답이 아닌 하위 문제**는 이 스킬로 계속 재시도하지
  말고, 코드 교환(curl) 등 UI를 우회하는 대안 경로가 있는지 먼저 확인한다 →
  [[meta-oauth-token-console-popup-unreliable-in-automated-browser]].
- 위임 요청에 이미 채운 값 표를 넣지 않으면 사람이 처음부터 다시 확인해야 해서 위임 비용이 커진다.
- 이 패턴은 [[lampas-browser]] 자체 결함이 아니라 **AI 조작 브라우저 일반의 구조적 한계**로 보인다
  (비밀번호 미조작은 보안 설계, 팝업/스크롤은 자동화 도구가 실제 사용자 제스처를 완전히 재현하지
  못하는 문제) — 새 서비스·새 콘솔에서도 재현될 것으로 예상하고 처음부터 이 절차를 1순위로 쓴다.
