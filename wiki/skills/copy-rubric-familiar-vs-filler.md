# 카피 채점 루브릭 — 익숙함과 빈말을 구분하기

## 언제 쓰는가
SNS 제목·광고 카피 등을 LLM 심사로 점수화하는 시스템에서, "범용적인 문구"를 감점하려다가
**짧고 익숙하지만 실제로 효과적인 제목까지 함께 탈락시키는** 문제가 생겼을 때.

## 절차 (단계별)
1. **"범용적"이라는 감점 기준을 도입하기 전에, 실제 좋은 제목 예시로 먼저 시험해본다.** 사람이
   "이 제목 좋다"고 느끼는 실제 사례(예: "드디어 돌아온 이정후")를 룰 초안에 넣어보고, 감점되면
   기준이 잘못 설계된 신호다.
2. **"익숙한 표현"과 "근거 없는 빈말/과장"을 서로 다른 축으로 정의한다.**
   - 익숙한 표현 = 짧고 관용적이지만 **대상을 구체적으로 지시**하고(누가·무슨 일) **감정을
     정확히 건드림**(기대·응원·아쉬움·호기심). 감점 대상 **아님**.
   - 빈말/과장 = "역대급", "충격적인 순간"처럼 **어떤 영상/제품에 붙여도 말이 되는** 표현, 또는
     **소재가 실제로 뒷받침하지 않는 주장**. 감점 대상.
   - 구분 기준은 "표현이 낯선가"가 아니라 "이 표현을 다른 소재로 바꿔도 그대로 성립하는가"다 —
     성립하면 빈말, 안 하면 (익숙해도) 유효한 훅.
3. **점수 상한(cap) 같은 기계적 페널티는 신중히 쓴다.** "범용 문구 → 총점 N점 상한" 식의 규칙은
   구현은 쉽지만, 2번 구분을 못 하면 좋은 후보를 조용히 떨어뜨린다. 상한을 걸어야 한다면 **1번
   구분이 끝난 축(빈말/과장·사실 불일치)에만** 걸고, "익숙함"이나 "설명 없음" 자체엔 걸지 않는다.
4. **평가 항목을 분해해 사람이 반박할 수 있게 만든다.** 총점 하나가 아니라 훅/이해도/적합성/
   자연스러움처럼 나누고, 각 항목에 **원문 구절 인용 + 채점 이유**를 붙인다. 사람이 "이 항목
   기준이 이상하다"고 짧게 반박할 수 있어야 잘못된 기준을 빨리 고칠 수 있다(이 사례에서도 사용자의
   "일반적인 제목이 더 좋아보이는데?" 한 마디로 기계적 상한 규칙이 통째로 철회됐다).
5. **생성 쪽도 채점 기준과 같은 방향으로 맞춘다.** 채점만 고쳐서는 생성물이 저절로 좋아지지
   않는다 — "직관적인 제목을 기본값으로 N개 중 M개 이상 만들라"처럼 생성 프롬프트에도 같은
   구분(익숙함 허용, 빈말 금지)을 명시해야 실제 출력이 바뀐다.

## 주의사항 / 함정
- LLM 심사관은 "구체적이고 분석적인 디테일"을 "좋은 카피"와 혼동하기 쉽다 — 카피는 짧고 직관적인
  것이 오히려 정답인 경우가 많다. 채점 기준을 설계하는 LLM 자신도 이 착각을 할 수 있으므로,
  예시로 실제 검증하는 1번 단계를 건너뛰지 말 것.
- 감점 규칙을 추가할 때마다 회귀 테스트에 "의도적으로 익숙하지만 좋은 제목" 케이스를 넣어, 다음
  번 규칙 추가가 다시 같은 실수를 반복하지 않게 고정한다.
