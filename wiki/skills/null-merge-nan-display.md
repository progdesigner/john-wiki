# null 병합 → NaN 표시 버그

## 언제 쓰는가
숫자를 계산·표시하는 UI 요소(카운터, 토큰/사용량 배지, 합계 등)가 **"NaN"**이나 빈 값으로 뜨는데,
데이터 자체는 정상적으로 서버에서 오고 있는 경우. 특히 "아직 데이터가 없는" 초기 상태(신규 세션,
빈 리스트 등)에서만 재현되고 데이터가 쌓인 뒤에는 정상으로 보이는 패턴이면 이 스킬을 의심한다.
[[lampas-harness]]에서 사용량 배지가 `usage: null`인 신규 세션에서 "◔ NaN 토큰"을 표시한 사례로
확립.

## 절차 (단계별)
1. 문제의 숫자가 만들어지는 **병합 지점**을 찾는다 — 보통
   `Object.assign({}, source, {extra})`나 `{...source, extra}` 스프레드 형태다.
2. `source`가 **null/undefined일 수 있는 경로**가 있는지 확인한다(예: 서버가 아직 집계가 없으면
   `null`을 그대로 응답). `Object.assign({}, null, {...})`은 에러 없이 조용히 `{extra}`만 담은
   객체를 만든다 — `source`의 필드는 전부 빠진 채로.
3. 그 결과 객체에서 **원래 `source`가 채웠어야 할 필드**(예: `input`, `output`)를 읽어 산술
   연산(`+`, 합계, 퍼센트 계산 등)에 쓰면 `undefined + undefined` → `NaN`이 되고, 그대로 문자열
   템플릿에 박히면 화면에 "NaN"이 노출된다.
4. 수정은 **두 지점에서 각각** 방어한다 — 한쪽만 고치면 다른 경로로 재발한다:
   - **생성/로드 측**: `source`가 없으면 빈 객체를 만들지 말고 상태를 아예 비워, UI가 "데이터
     없음" 기본 표시로 자연스럽게 돌아가게 한다(빈 객체를 억지로 만들지 않는 것도 방어책).
   - **표시/계산 측**: 필드를 읽을 때 `?? 0`(또는 동등한 널 병합)으로 **방어적 기본값**을 준다 —
     이렇게 하면 이 계산식으로 들어오는 어떤 경로에서도 NaN이 재발할 수 없다.
5. 새로고침(또는 재빌드)만으로 반영되는 프런트 전용 수정인지 확인 — 서버 응답 스키마 자체는
   안 바꾸는 경우가 많으므로 서버 재시작이 불필요할 수 있다.

## 주의사항 / 함정
- `Object.assign`/스프레드는 `null`을 넣어도 **에러를 던지지 않는다** — 조용히 해당 소스를 건너뛰고
  넘어가기 때문에, 콘솔에 단서가 안 남고 화면의 NaN만 유일한 증상이다. 에러 로그를 찾아 헤매지 말고
  병합식부터 의심한다.
- 생성 측만 고치고(빈 객체 안 만들기) 표시 측 방어(`?? 0`)를 빠뜨리면, 다른 진입점에서 같은
  필드가 여전히 `undefined`로 들어올 경우 재발한다 — 두 지점 모두 고쳐야 "어떤 경로로 들어와도"
  안전해진다.
- 비슷하지만 다른 버그로 [[loading-state-key-mismatch]](요청은 되는데 로딩 UI만 안 뜸)가 있다 —
  그쪽은 **키 문자열 불일치**가 원인이고, 이쪽은 **null 병합으로 인한 값 결손**이 원인이다. 증상
  ("반응이 없다"/"이상한 숫자가 뜬다")으로 먼저 구분한 뒤 절차를 고른다.
