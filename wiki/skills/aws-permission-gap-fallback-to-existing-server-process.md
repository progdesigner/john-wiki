# AWS 권한 부재 시 기존 서버 별도 프로세스 폴백

## 언제 쓰는가
주기 실행 작업(크론성 수집기·배치 파이프라인)을 Lambda + EventBridge(스케줄러) 등 서버리스로
설계했으나, 배포 시점에 AWS 계정에 해당 리소스를 **생성할 권한이 없다는 것**이 뒤늦게 드러났을 때.
빌드·테스트는 이미 통과한 상태에서 배포 방식만 막힌 경우.

## 절차 (단계별)
1. 서버리스 경로가 막혔음을 먼저 명확히 확인한다 — 권한 오류 메시지로 "설정 문제"와 "권한 자체
   없음"을 구분한다. 권한 요청은 별도 트랙(사람의 승인 필요)으로 두고 배포를 무한정 기다리지 않는다.
2. 같은 작업(주기 실행 + 결과를 API/DB에 반영)을 **이미 떠 있는 API 서버 프로세스**로 옮길 수 있는지
   확인한다 — 별도 인프라 없이 기존 PM2/systemd 등 프로세스 관리 하에 백그라운드 워커·크론 형태로
   추가.
3. 실행 주기는 서버리스와 동일하게 유지(예: 5분마다)하고, 서버 재시작 시에도 주기가 살아나는지
   확인한다.
4. 운영 반영 직후 최소 두 번의 실행 주기(예: 5분 간격 2회)를 관찰해 정상 동작을 재확인한다 —
   첫 사이클만 보고 끝내지 않는다.
5. 나중에 권한이 발급되면 서버리스로 이전할지 여부는 별개 결정 — 이 폴백 자체는 임시가 아니라
   운영 가능한 정식 경로로 취급해도 된다(과도한 재설계 금지).

## 주의사항 / 함정
- 권한 요청 승인을 기다리며 배포를 미루지 말 것 — 사람에게 권한을 요청하는 것과 별개로 대체
  경로로 먼저 서비스를 내보내는 것이 우선이다.
- 기존 서버에 얹을 때 기존 API 트래픽에 영향(CPU·메모리 경합)이 없는지 확인.
