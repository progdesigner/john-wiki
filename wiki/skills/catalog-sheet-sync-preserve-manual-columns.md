# 코드 스캔 카탈로그 → 구글시트 동기화 (사람 입력 열 보존)

## 언제 쓰는가
저장소 전체에 흩어진 정의(GA4 이벤트명, API 엔드포인트, 환경변수 등)를 한 번 스캔해 구글시트에
정리해두고, 이후 코드가 바뀔 때마다 다시 스캔해 갱신하고 싶은데, 그 사이 사람이 시트에 직접
채운 상태값·담당자·검증일·메모는 재동기화 때 사라지면 안 되는 경우.

## 절차 (단계별)
1. **읽기 전용 서비스 계정으로 접근**: 자동화 주체(하네스 등)의 구글 서비스 계정 이메일을 사람이
   타겟 시트에 편집자로 초대 — OAuth 로그인 흐름이 필요 없어 자동화 쪽에서 추가 인증 단계가
   생기지 않는다.
2. **코드 전수 스캔**으로 카탈로그 1차 적재: 이벤트명 등 식별자 기준 집계(예: "이벤트명 106개")와
   선언 위치 기준 집계(예: "앱별 정의 382행")를 **분리해서** 센다 — 같은 식별자가 여러 곳에서
   각자 정의되는 경우가 흔해, 두 숫자가 다른 게 정상이다.
3. **열을 "코드 유래" vs "사람 유래"로 구분**해 시트 스키마를 설계한다. 코드 유래(이벤트명·발생
   조건·파라미터·코드 위치)는 재스캔 때마다 덮어쓰는 열, 사람 유래(수집 상태·담당자·검증일·메모)
   는 재스캔이 건드리지 않는 열로 명확히 나눈다.
4. **재동기화 커맨드**(예: `pnpm analytics:catalog:sync`)는 식별자 기준으로 기존 행을 찾아
   코드 유래 열만 갱신하고, 매칭되는 기존 행이 없을 때만 새 행을 추가한다. 사람 유래 열은 항상
   그대로 둔다.
5. **"구현됐다"와 "운영에서 실제로 수신된다"를 별도 열로 분리**한다 — 코드 스캔은 전자만
   보장하므로, 후자를 같은 열에 합치면 실제 수집 여부를 코드만 보고 착각하게 된다.
6. 적재 후 시트를 **다시 읽어 저장 내용을 검증**한다(쓰기 성공 응답만으로 끝내지 않음).

## 주의사항 / 함정
- 서비스 계정 이메일을 공유할 때는 **이메일만** 노출하면 되고, 키 파일·토큰을 공유할 필요는 없다.
- 식별자 수와 정의(행) 수가 다를 수 있다는 점을 보고할 때 둘 다 명시해야 혼동이 없다("이벤트명
  106개, 앱별 정의 382행"처럼).
- 코드 기준 카탈로그는 과거 수집 공백(운영에 미배포된 계측 등)을 감추지 않는다 — 오히려 코드엔
  있지만 운영에 반영 안 된 이벤트를 드러내는 용도로 쓸 수 있다.
