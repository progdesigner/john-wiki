# 서브도메인 간 세션 이어받기 (일회용 교환 코드 SSO)

## 언제 쓰는가
같은 사용자가 쓰는 여러 서비스가 **서로 다른 서브도메인·독립된 로그인 저장소**를 갖고 있어서(공유
쿠키/세션 스토어 없음), 한 서비스에서 다른 서비스로 이동(또는 되돌아오기)할 때마다 재로그인이
필요하거나 엉뚱한 계정으로 남아 있을 때. 오케스트레이션 허브(여러 서브도메인 작업 공간을 오가는
화면)를 새로 만들 때 특히 필요하다. 신규 서브도메인이라 소셜 로그인(Google 등)이 아직 허용되지
않은 과도기에 임시 우회로도 쓸 수 있다.

## 절차 (단계별)
1. **로그인 토큰 자체를 URL에 넣지 않는다** — 대신 서버가 **짧게 만료되는 일회용 교환 코드**를
   발급해 이동 링크의 쿼리 파라미터로 붙인다.
2. **대상 서비스가 코드를 세션으로 교환**한다 — 대상 도메인이 코드를 서버에 검증 요청해 해당
   사용자 세션(자체 쿠키/토큰)을 새로 발급받는다.
3. **기존 세션을 무조건 교체한다** — 대상 서비스에 이미 **다른 계정**이 로그인돼 있어도, 이동을
   시작한 계정으로 강제 전환한다(암묵적으로 "먼저 로그인된 계정 유지"를 택하면 세션이 꼬인다).
4. **코드는 1회용 + 즉시 만료**로 만든다 — 교환 후 즉시 무효화, 만료 시간도 짧게(재사용·탈취
   윈도우 최소화). 만료·재사용 차단을 자동 테스트로 검증한다.
5. **URL에서 코드를 제거한다** — 교환이 끝나면 브라우저 주소에서 코드 파라미터를 지운다(북마크·
   공유 링크로 재사용되는 것 방지).
6. **로컬/원격 이중 세션이 있는 백엔드 데몬은 둘 다 연결한다** — 예: 로컬 처리용 API와 운영
   업로드용 API가 서로 다른 인증을 요구하면, 한 번의 계정 확인으로 두 세션을 모두 발급받도록
   묶는다.
7. **실제 브라우저로 왕복 검증한다** — 허브→서비스A→허브 이동, 서비스B/C/D로의 이동까지 전부
   같은 계정으로 전환되는지, 코드가 주소에서 사라지는지 확인한다.

## 주의사항 / 함정
- 소셜 로그인 제공자(Google 등)는 **새로 등록한 도메인**의 로그인을 바로 허용하지 않을 수 있다 —
  이미 등록된 기존 도메인에서 로그인한 뒤 이 교환 코드 방식으로 신규 도메인에 세션을 전달하는
  것으로 과도기를 넘길 수 있다(도메인 등록이 완료되면 임시 우회임을 명시해둘 것).
- "다른 계정이 이미 로그인돼 있으면 유지"가 기본 동작이 되지 않도록 명시적으로 테스트한다 —
  가장 흔한 회귀는 조용히 기존 계정이 남는 것이다.
- 로컬 데몬처럼 **두 개의 별도 인증 영역**을 가진 백엔드는 하나만 연결하고 끝내기 쉽다 — 어떤
  세션들이 독립적으로 인증을 요구하는지 먼저 목록화한다.
