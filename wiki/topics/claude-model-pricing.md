## 산정 로직 — 왜 캐싱이 핵심인가
Claude Code는 프롬프트 캐싱을 강하게 쓴다. 그래서 비용의 대부분은 **정가 입력**이 아니라
**캐시 읽기(입력가의 ~0.1배)와 출력 토큰**에서 나온다. "보통 1시간"의 토큰 프로파일 가정:

- 요청 ~40회
- 캐시 읽기 누적 ~12M 토큰 (입력가 ×0.1)
- 캐시 쓰기 ~2M 토큰 (입력가 ×1.25)
- 신규(비캐시) 입력 ~0.4M 토큰
- 출력 ~0.2M 토큰

→ Opus 4.8 ≈ $25, Sonnet 5 ≈ $15, Haiku ≈ $5. 위 표를 범위로 적은 이유는 사용 강도 편차:
- **가벼운 사용**(질문 몇 개·소규모 수정): 위 값의 ~1/3
- **헤비 사용**(대규모 리팩터·장시간 에이전트): 2배 이상

## 편차를 키우는 두 변수
1. **컨텍스트 크기 · effort 설정** — 큰 저장소일수록 캐시 읽기가 늘어 같은 1시간도 비용 편차 큼.
2. **종량제 vs 구독** — API 종량제 대신 Claude Pro/Max 구독으로 Claude Code를 쓰면 시간당
   한도 내에서 추가 과금이 없다. 매일 몇 시간씩 쓴다면 구독이 훨씬 저렴한 경우가 많다.
   - **[[lampas-harness]]는 기본적으로 구독(OAuth) 과금으로 돈다** (2026-07-15 코드 확인). 즉 위 표의
     시간당 API 비용은 하네스 대화엔 청구되지 않고, 구독 5시간/7일 한도만 소진된다. API 종량으로 전환하려면
     2026-07-15에 추가된 "API 사용" 토글을 켠다. 판별·전환·한도조회 절차: [[sdk-claude-code-vs-api-billing]].
     → 세션: [[2026-07-15-과금모드-토글-컨텍스트표시]]

## 정확한 실측 방법
추정 대신 실측하려면 세션 로그의 **`usage` 필드**(입력·출력·캐시 토큰)를 집계해
위 단가를 곱하면 시간당 실제 비용이 나온다. (2026-07-13 세션에선 제안만 하고 미실행.)

## 미해결 — 구독 "주간 사용량 %"의 API 비용 환산
2026-07-17에 "Fable 5 주간 사용량이 1% 늘 때마다 API로 썼다면 비용이 얼마냐"는 질문이 나왔으나
사용자가 어시스턴트 응답 전에 턴을 중지시켜 **답변 없이 종료**됐다([[2026-07-17-fable-주간사용량-api비용환산-질문]]).
이 표의 단가는 재료가 되지만, "주간 한도 100%가 토큰으로 몇 개인가"라는 환산 기준이 아직 위키에
없어 계산을 완성할 수 없다 — 다음에 물으면 그 기준부터 조사할 것 (관련: [[sdk-claude-code-vs-api-billing]]
의 `seven_day` rate limit 훅).
