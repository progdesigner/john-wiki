# 장기기억 아키텍처 (LLM long-term memory)

`[[progdesigner]]`가 LLM 어시스턴트에게 **과거 작업 이력을 기억시키는 방법**을 정리한 주제.
2026-07-08 설계 세션([[2026-07-08-장기기억-provider-연동-설계]])에서 도출.

## 핵심 통찰: "저장 ≠ 조회"

- 사용자가 겪은 문제: "기억에 저장" 아이콘으로 저장은 되지만, 어시스턴트가 그 내용을 **다시 읽지 못함**.
- 진짜 병목은 저장이 아니라 **저장된 것이 컨텍스트로 재주입되거나 검색 가능한가**이다.
- 검증법: 고유 문장을 저장 → 새 대화에서 질문 → 답하면 주입 O, 모르면 주입 X.

## 3계층 저장 전략 (역할 분리)

| 계층 | 무엇을 담나 | 특징 |
|---|---|---|
| "기억에 저장" 아이콘 | 안 변하는 **선호·규칙** | 짧고 명확하게. 긴 이력 금지 |
| `[[john-wiki]]` | 실제 **장기 작업 이력·프로젝트 기록** | 길어도 됨. 검색 대상 |
| `AI_CONTEXT.md` | 매 대화 **자동 주입 요약** | john-wiki 루트, system/developer 메시지로 주입 |

**저장에 좋은 것**: 고정 선호(항상 한국어), 반복 프로젝트 배경, 약어·명칭, 장기 목표, 답변 포맷.
**넣지 말 것**: 임시 지시, 일회성 코드, 인증정보/키, 긴 회의록 전체, 자주 바뀌는 상태값.

## 조회를 붙이는 3가지 방법 (난이도순)

- **A. 요약 붙여넣기** — 대화 시작마다 john-wiki 요약을 직접 붙임. 단순·확실하나 수동.
- **B. `AI_CONTEXT.md` 자동 주입** — AI용 요약 페이지를 만들고 harness가 매번 주입. 추천.
- **C. 검색 tool 연결** — harness에 `search/read/list` tool을 붙여 LLM이 능동 검색. "진짜 장기기억"에 가장 근접. → [[wiki-memory-provider-integration]]

## 안티할루시네이션 규칙

조회 tool을 붙일 때 반드시 모델 지침에 포함:
1. 과거 작업/장기기억을 물으면 먼저 tool로 조회한다.
2. 검색 결과 기반으로만 답한다.
3. 조회 실패·tool 부재 시 **접근 불가라고 명시**한다.
4. **기억에 없는 작업 이력을 지어내지 않는다.**

## 구현 진행 상태 (2026-07-11~12 관찰)

2026-07-08 설계 이후의 상태 점검([[2026-07-11-기억-요약-wiki-경로-확인]]):

- **방법 C(검색 tool 연결)는 아직 미완** — `[[lampas-harness]]` `src/config.ts`에 `wikiDir`+`WIKI_DIR` 설정이 들어와 배선은 착수됐으나, 어시스턴트에 `search/read/list` tool이 노출되지 않아 채팅에서 "기억 요약"·wiki 위치 질문에 여전히 답 못 함. **같은 날 두 개의 독립 채팅에서 재확인됨**([[2026-07-11-기억-요약-wiki-경로-확인]] · [[2026-07-11-기억-저장내용-조회가능여부]]).
- **노출된 파일 tool은 위키가 아닌 코드 저장소로 스코프됨** — 후자 채팅에서 어시스턴트는 대안으로 `search_files`/`list_directory`를 제시했으나 그 범위는 작업 폴더(`lampas-harness`)일 뿐, `[[john-wiki]]` 코퍼스가 아니다. 파일 tool이 있어도 위키 경로에 연결돼야 방법 C가 성립한다.
- **경로 불일치 함정** — `wikiDir` 기본값 `~/Works/llm-wiki`가 실제 저장소 `~/Works/john-wiki`와 다름. `WIKI_DIR` env로 지정 안 하면 없는 경로를 가리킴.
- 교훈: 조회 tool 연결은 "config에 경로 하나 추가"로 끝나지 않는다 — tool 노출·주입·검증(→ [[wiki-memory-provider-integration]] 5~7단계)까지 가야 어시스턴트가 실제로 조회한다.
- **방법 B(AI_CONTEXT.md 주입)도 quick 채팅엔 아직 안 닿음 (2026-07-12 관찰)** — 2026-07-12자 `AI_CONTEXT.md` 상시 주입 결정(커밋 0c05aae) 이후, 같은 날 quick 채팅에서 "하네스가 뭐야"에 CWC·lampas 맥락 없는 **완전 일반 사전식 답변**이 나왔다([[2026-07-12-하네스-뜻-질문]]). quick-chat 경로가 `AI_CONTEXT.md`를 주입하지 않거나 배선 이전 발생 — 주입 배선이 모든 진입 경로(웹/데스크톱 퀵)에 일관 적용되는지 검증 필요.

## 저장(ingest) 측 자동화 — 보관→ingest (2026-07-13)

위 관찰이 주로 **조회(recall) 측** 배선이라면, 2026-07-13 세션은 **저장(ingest) 측**을 자동화했다
([[2026-07-13-보관시-자동-기억저장]]). `[[lampas-harness]]` 보관(🗄) 동작이 `memory-ingest` 잡을
자동 큐잉하게 되어, 대화를 보관하면 위키에 이력이 쌓인다.

- 이제 위키로의 저장 진입점이 **셋**: (1) 수동 `🧠 기억에 저장` 버튼, (2) 보관 🗄 자동, (3) 야간 자동
  ingest 잡. 세 경로 모두 같은 `memory-ingest` 잡을 큐잉하고 `rememberedAt`/source 키로 중복을 막는다.
- 즉 저장 계층(john-wiki에 이력 축적)은 상당히 자동화됨. 남은 병목은 여전히 **방법 C(능동 조회 tool)** —
  쌓인 이력을 어시스턴트가 채팅 중 검색해 읽는 부분.

## 이 위키(john-wiki)와의 관계

이 저장소 자체가 이 아키텍처의 B/C 계층 구현체다. CLAUDE.md의 ingest/query 워크플로가
"조회 가능한 장기기억"을 사서(LLM) 주도로 유지하는 방식이며, `index.md`가 사실상 검색 진입점(A/B),
`raw/` + `wiki/`가 검색 대상 코퍼스(C) 역할을 한다.
