# secrets-plaintext-exposure-pattern

`[[progdesigner]]` 생태계 여러 저장소·세션에서 **실제 API 키/토큰이 평문으로 노출**되는 사고가
독립적으로 3회 이상 관찰됐다. 개별 사고는 각자 entity/세션 페이지에 기록돼 있었으나, 반복되는
패턴이라 이 토픽 페이지에 묶어 인지도를 높인다.

## 관찰된 사례

1. **[[toktalk]] — 커밋 `0664ea9`(및 이전 `b7fdf05` 패턴)**: `.env`(실제 API 키)와 Firebase 서비스
   계정 JSON이 git 추적 상태로 origin/main에 푸시됨. 어시스턴트가 고지했으나 사용자 지시로 그대로
   진행됨(2026-07-08 세션). → [[2026-07-08-toktalk-에피소드-배경전환-플레이]]
2. **[[cwc-system]] — 프로덕션 env**(`apps/cwc-api/env/.env.production`): DB 비밀번호·JWT 시크릿·
   Google Client ID가 평문 커밋 상태로 발견(2026-07-15), 미조치.
3. **이 세션(2026-07-17)**: 사용자가 "`.env` 파일을 그대로 읽어줘" 요청 → 어시스턴트가
   `CLAUDE_CODE_OAUTH_TOKEN`·`ANTHROPIC_API_KEY`·`OPENAI_API_KEY`·`GOOGLE_API_KEY`·
   `ELEVENLABS_API_KEY`·`HARNESS_TOKEN` 전체를 표로 그대로 채팅 응답에 출력 → 이 응답이
   `lampas-harness` 채팅 로그(`logs/chats/archive/`)에 평문으로 영구 저장됨. → [[2026-07-17-env읽기-pwa세이프에어리어-여백수정]]
   · [[lampas-harness]]

## 공통 패턴

- 세 사례 모두 **git 저장소(또는 git으로 커밋되는 위키)에 평문 비밀이 영속화**된다는 공통점이 있다 —
  파일 시스템 삭제만으론 안 지워지고 히스토리에 남는다.
- 두 번은 **"그대로 보여줘/커밋해줘" 류의 직접 지시**에 어시스턴트가 위험을 고지는 했지만(사례1) 혹은
  고지 없이(사례3, 이번 세션) 그대로 따랐다. 사례3에서는 사전 경고 자체가 없었다 — 명시적 위험 신호가
  없는 평범해 보이는 요청("파일을 그대로 읽어줘")이었기 때문으로 추정.

## 권장 대응 (아직 시스템화 안 됨)

- **`.env` 파일 요청 시 값을 그대로 출력하지 말고, 키 이름·존재 여부만 확인**하거나 값 앞 몇 글자만
  마스킹해 보여주는 편이 안전 — 이번 세션에선 이 판단 없이 전체 노출됨(회고적 발견).
  → 이 습관을 하네스 시스템 프롬프트나 CLAUDE.md 지침으로 명문화할지는 미결.
- 노출된 키는 **재발급(rotate)이 원칙** — 특히 사례3의 키들은 이 채팅 로그 자체가 평문 저장소에
  남아 있어 이미 노출 상태. 재발급 여부는 이 ingest 시점 기준 **미확인**.
- 이 위키(`john-wiki`)도 git 저장소이므로, ingest 과정에서 원본에 평문 비밀이 있으면 **레닥트 후
  저장**하는 것을 원칙으로 삼는다(CLAUDE.md의 "원본 raw는 수정 금지" 규칙과 별개 — 원본은 손대지
  않되, 위키가 만드는 사본/요약에는 비밀을 옮기지 않는다). 이번 ingest에서 처음 적용.
