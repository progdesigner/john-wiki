# 하네스의 두 실행 경로 — 채팅 vs 큐

`[[lampas-harness]]`에는 서로 다른 두 실행 경로가 있고, 사용자가 혼동한 지점이라 명시적으로 정리됨.

| 경로 | 큐에 쌓임? | 큐 패널 표시 |
|------|-----------|-------------|
| 웹 채팅 (전송 버튼) | ❌ 파일 큐에 저장 안 됨 | 진행 중일 때만 `채팅 · N초 경과`로 **실시간** 표시, 끝나면 사라짐 |
| `enqueue-task` / "이어하기 ⤵" 버튼 / `harness enqueue` | ✅ `queue/`에 파일로 쌓임 | `대기 → 실행중 → 완료/실패`로 남음 |

- **채팅** = 즉시 실행되는 대화. 라이브 상태만 큐 패널에 표시하고, 끝나면 완료 목록에 남지 않는다.
- **큐** = 데몬이 순차 처리하는 백그라운드 태스크. named job 외에 **ad-hoc 프롬프트 태스크**를 지원하고,
  `--resume`으로 이전 SDK 세션 맥락을 이어받는다. 데몬은 완료/실패 기록에 `sessionId`를 보존하고
  재시작 시 중단 항목을 정리.

## 세션 busy 시 채팅 대기 큐 (FIFO)
채팅 세션이 바쁠 때 새 메시지를 거절하지 않고 FIFO 대기 큐에 넣어, 현재 턴이 끝나면 순차 실행.
대기 메시지는 큐 패널에 내용과 함께 표시되며 개별 취소 가능. (파일 큐와는 별개의 인메모리/세션 큐)

## 설계 선택지 (미결로 제시됨)
1. 현재 유지 — 채팅=즉시 실행(라이브만), 큐=백그라운드 적재.
2. 채팅도 완료 이력에 남겨 나중에 "이어하기" 재개.
3. 채팅을 아예 큐로 넣어 데몬이 순차 처리.
