# 에피소드 beat 플레이 & 배경 전환

`[[toktalk]]`의 에피소드 재생 시스템. 캐릭터 시나리오를 **beat**(지문·대사 단위) 시퀀스로 구성하고,
탭할 때마다 다음 beat를 공개하며, 특정 시점에 **배경(연출 콘텐츠)**을 전환한다.
어드민 스튜디오에서 제작(`talk-web-admin`), 웹앱에서 플레이(`talk-web-app`).

## 핵심 개념
- **beat** — 지문 또는 대사 한 항목. 탭으로 순차 공개.
- **연출(콘텐츠)** — 배경으로 쓰는 이미지/비디오. "배경 구간"(연출 카드에서 시작~끝 beat 지정)으로 화면 배경이 됨.
- **장소 이미지** — 배경 구간이 없을 때의 기본 배경.
- **선택지 연출** — 선택지로 해금하는 연출(크레딧 차감, 예: `5C`).
- **beat 직접 연결** — `EpisodeBeat.actionId`로 beat에 연출을 직접 붙임. **크레딧 차감 없음**. (원래 레거시 `@deprecated`였다가 2026-07-08 정식 기능으로 승격.)

## 배경 결정 로직 (`resolveSceneBackground`)
플레이 히스토리를 훑어 현재 배경을 계산하는 순수 함수. 웹앱(`beatPlay.js`) / 어드민(`beatPlay.ts`) **동일 구현 중복** — 반드시 함께 수정.

정착된 규칙(2026-07-08 기준):
1. beat 공개 시 그 beat의 스크립트 배경(배경 구간·`actionId`)이 있으면 그 배경으로 전환.
2. **없으면 이전 배경을 sticky 유지** — 장소 이미지로 무조건 리셋하지 않는다. (초기 버그: beat마다 "스크립트 배경 없으면 장소"로 재계산 → 선택지 연출이 다음 beat에서 리셋됐음.)
3. **새 배경 구간이 명시적으로 시작될 때만** 이전(선택지) 연출 해제.
4. 우선순위: 연출 카드 "배경 구간" > beat `actionId`. (편집기에 둘 다 지정 시 ⚠ 경고.)

## 배경 선(先)전환 (`pendingSceneShift` + `sceneShift` 히스토리 항목)
배경 전환과 지문/대사를 **분리**해, 탭 1회로 배경만 먼저 바꾼다.
- 다음 beat 공개 시 배경이 바뀌면(= `resolveSceneBackground`로 "다음 beat 공개 상태"를 시뮬레이션해 현재와 비교), `revealNext()`가 채팅에 아무것도 렌더링하지 않고 `sceneShift` 항목만 쌓고 리턴(탭 1회 소비).
- 다음 탭에서 실제 지문/대사가 시작됨.
- 배경 구간 진입·복귀 모두 동일 동작.
- `pendingSceneShift`가 배경을 따로 계산하지 않고 `resolveSceneBackground`를 재사용하므로, sticky 유지 규칙이 선전환 판정에도 반영 → 선택지 연출 직후 불필요한 "장소 복귀 전환 탭"이 사라짐.

## 플레이어 vs 제작자 노출
- **플레이(웹앱)** — 선택지 버튼에서 연출 썸네일·스포일러성 연출 이름 제거. 배지는 `🖼️ 배경 전환 · 5C`(크레딧 안내)만.
- **테스트 플레이(어드민)** — 제작자 도구라 선택지 썸네일 유지.

## 저장 구조
API(`talk-api` studio 모듈)는 beats를 **자유 구조 JSON**으로 저장(`studio.dto.ts`, 스키마 검증 없음). 따라서 클라에서 beat 필드를 추가/의미 변경해도 **서버 변경 불필요**.

## 함정
- **로직 이중화** — `beatPlay.js`(JS, 웹앱)와 `beatPlay.ts`(TS, 어드민)가 별도 파일. 한쪽만 고치면 실제 플레이와 테스트 플레이가 어긋난다.
- **beat마다 배경 재계산 = 리셋 버그** — 배경은 "명시적 전환 이벤트 사이에는 유지"가 기본. beat 공개마다 기본값으로 되돌리면 선택지·직접연결 배경이 깜빡인다.
- 순수 함수라 **Node 시뮬레이션으로 회귀 검증** 가능(전환 후 유지 / 새 구간 전환 / 일반 진행 무변화).
