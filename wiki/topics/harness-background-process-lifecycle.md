# 하네스 백그라운드 프로세스 수명 문제

`[[lampas-harness]]`의 구조적 한계 하나: **에이전트(`[[lampas]]`)가 턴 안에서 띄운 백그라운드
작업은 그 턴/세션이 끝나면 함께 죽는다.** 하네스가 턴 종료 후 프로세스를 내리거나(재활용),
다음 사용자 메시지로 세션이 넘어가면 부모가 사라지면서 자식 프로세스도 HUP으로 종료되기 때문.

> **2026-07-15 갱신 — 채팅 경로는 근본 해결됨.** 아래 원칙은 여전히 유효하지만, 채팅 UI로 건
> Agent/백그라운드 Bash/Workflow는 더 이상 "턴 종료 = 즉사"가 아니다. → 증상 3 참고.

2026-07-08~09 세션에서 이 한 가지 원인이 **두 스레드를 관통**했다 →
[[2026-07-08-스케줄러-로컬llm-사용영역페르소나]].

## 증상 1 — 예약 타이머가 알림을 못 준다
"10초 뒤에 메시지 줘"를 에이전트 턴 안의 `sleep 10` 타이머로 처리하면:
- 세션이 살아 있는 동안엔 배경작업 완료 → 에이전트 재호출 → 능동 메시지까지 **정상 동작**.
- 그러나 턴이 끝나고 하네스가 프로세스를 내리면, 타이머가 끝나도 **재호출해줄 주체가 없어**
  알림이 유실됐다가 다음 사용자 메시지에 묻어서 도착.

**해결 방향**: 타이머를 에이전트가 아니라 **항상 살아 있는 서버에 내장**하고 예약을 파일로 영속화.
→ [[session-independent-scheduler]]

## 증상 2 — 긴 다운로드가 반복 정지
`rapid-mlx pull`(37GB) 다운로드를 에이전트 백그라운드로 돌렸더니 **8GB 부근에서 계속 멈춤**.
세션이 넘어갈 때마다 pull 프로세스가 죽고, 다음에 확인하면 크기가 그대로.
(HuggingFace 이어받기 덕에 처음부터는 아니지만 매번 8GB에서 재개.)

**해결 방향**: `nohup … > log 2>&1 & disown`으로 세션과 완전히 분리 → 턴 넘어가도 생존.
→ [[detach-long-job-nohup]]

## 증상 3 — Fable 5 채팅 세션의 Agent/Workflow 백그라운드 작업이 턴 종료로 끊김 (2026-07-15, 근본 해결)
사용자가 채팅에서 Fable 5로 Agent·백그라운드 Bash·Workflow를 걸어두면, 답변(턴)이 끝나는 순간
같이 죽는 게 재확인됐다. 원인은 증상1·2와 동일 계열이 아니라 **채팅 자체의 구조**: 하네스가
**턴마다 Claude Agent SDK 서브프로세스를 새로 만들고 답변 후 통째로 닫는** 방식이었다 — 배경작업이
그 서브프로세스의 자식이라 부모가 닫히면 함께 죽음.

**해결(우회가 아니라 근본 수정)**: 타이머/detach로 우회하지 않고 **대화당 상주 Claude 프로세스**를
도입 — 턴이 끝나도 프로세스를 안 닫고 유휴(작업 없음) 10분까지 살려둠. 백그라운드 작업이 끝나면
모델이 스스로 깨어나 후속 답변까지 보낸다(닫힌 화면엔 배달 경로로 자동 전달). 상태는 SSE +
`/api/queue` + 활동 표시줄에 노출, 개별 중지 API도 추가. → [[2026-07-15-세션상주프로세스-백그라운드작업생존-구현]]

## 일반 원칙 (교훈)
- **에이전트 턴은 수명이 짧다** — 배경작업이 "턴보다 오래" 살아야 하면 에이전트에 의존하지 말 것.
  - 시각 트리거·반복 작업 → **서버 내장 스케줄러**(파일 영속). 세션 수명과 무관한
    launchd/cron이 하네스 API를 호출해 새 턴을 트리거하는 방식도 안전.
  - 장기 실행 명령(다운로드/빌드) → **`nohup & disown`으로 detach**, 로그 파일로 진행 추적.
  - 채팅 중 Agent/Workflow 배경작업 → (2026-07-15~) **대화당 상주 프로세스**가 유휴 10분까지는
    자동으로 생존시켜준다 — 별도 detach 불필요. 단 유휴 타임아웃을 넘기면 여전히 죽으므로, 그보다
    오래 걸리는 작업은 여전히 `nohup & disown` 또는 스케줄러로.
- 상주가 필요한 서비스(로컬 LLM 서버 등)는 아예 **launchd 서비스로 등록** → [[macos-launchd-daemon]].
- 대조: 이 하네스의 **큐**는 태스크를 파일로 적재해 세션 밖에서 처리하므로 이 문제에 강함 →
  [[harness-queue-vs-chat]]. (채팅 경로의 에이전트 배경작업이 2026-07-15부터는 상주 프로세스로
  훨씬 강해졌지만, 큐는 여전히 유휴 타임아웃도 없는 더 강한 보장.)
