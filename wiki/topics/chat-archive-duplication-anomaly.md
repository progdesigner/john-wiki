# chat-archive-duplication-anomaly — 채팅 아카이브 중복·재사용 이상 정황

[[lampas-harness]]의 채팅 로그(`logs/chats/`, 보관 시 `logs/chats/archive/`)에서 **같은 파일명이
서로 다른 시점의 서로 다른 대화를 가리키거나, 같은 대화 내용이 서로 다른 아카이브 파일·시각으로
중복 기록되는** 현상이 최소 4개 세션에 걸쳐 독립적으로 관찰됐다. 개별 사고는 각 세션 페이지에
"⚠️ 이상 정황"으로 남아 있었으나 전용 페이지가 없어 패턴 자체의 인지도가 낮았다 — 이 페이지로 묶는다
(2026-07-20 lint에서 신설).

## 관찰된 하위 패턴 (서로 구분되는 3가지)

### 1. 파일명(UUID) 재사용 — 같은 이름, 다른 시점의 다른 내용
`quick-5bc3f296-...md`가 [[2026-07-14-은행환불-거래처매칭]](08:52~09:00 UTC, 은행 거래·인보이스
해석)의 소스로 먼저 ingest됐는데, 같은 파일명 경로의 **현재 실제 내용**은 전혀 다른 대화
([[2026-07-14-clara-바바라-위스키분쟁-번역]], 09:03~09:13 UTC, 번역·위스키 분쟁 메일)였다. 두 세션
모두 그대로 유지하고 모순으로만 기록.

### 2. 같은 사건이 다른 아카이브 파일·시각으로 이중 기록
[[2026-07-15-gpt-realtime-음성입력-길게누르기]]의 "6번 항목"(22:28~22:30, 커밋 `938d4e4`로 완료)과
[[2026-07-15-음성입력-3-4초-잘림-수정]](15:29:49~15:33:37, 커밋 언급 없음)는 원인·해결책 서술이
문장 단위로 사실상 동일한데 시각·소스 UUID·커밋 상태가 다르다 — 같은 편집 사건이 서로 다른 아카이브
파일에 다른 시각으로 기록됐을 가능성. 어느 쪽이 "원본"인지 미확정.

같은 계열: [[2026-07-16-srkk-인보이스-james확인-0243]](02:43 UTC)의 사용자 메시지가
[[2026-07-16-srkk-인보이스-james확인]](02:15 UTC)과 **글자 단위로 100% 동일**한 이메일 스레드
번역 요청 — 28분 간격으로 같은 내용이 별도 아카이브 파일로 두 번 ingest 큐에 들어온 사례. 여기선
어시스턴트 응답까지도 형식만 다르고 실질은 같아, 같은 요청이 재실행된 것인지 로그가 이중 기록된
것인지 구분이 어렵다.

### 3. 한 트랜스크립트 안에서 동일 메시지 반복
[[2026-07-16-tts-stream-elevenlabs-구현착수]] 원문에 동일한 사용자 요청 텍스트가 02:42:10~02:47:55
사이 총 6회 그대로 등장(뒤 5회는 40초 안에 몰림). [[idempotent-message-retry]]의 msgId 멱등성이
**실행** 중복은 막았으나(어시스턴트 답변은 1회), **원문 트랜스크립트 자체**엔 중복 항목이 그대로
쌓였다 — 클라이언트 쪽 재전송/재렌더링이 로그 레벨까지 새는 것으로 추정(미확인).

## 공통 관찰

- 4개 사례 모두 **원인이 확정되지 않았다** — 클라이언트 재전송 버그, 아카이브 이동/복사 로직의
  경쟁 상태(race condition), quick 채팅 세션 식별 방식의 결함 등 여러 가설이 가능하나 코드 조사는
  아직 이뤄지지 않음.
- 모두 [[work-folder-sandboxing]]으로 격리된 **quick 채팅**(`chats/`, 보관 후 `chats/archive/`)
  경로에서만 관찰됐다 — 일반 세션(비-quick)에서의 재현 여부는 미확인.
- ingest 시 원칙은 일관됐다: **모순 처리 원칙에 따라 기존 세션 내용은 수정하지 않고 그대로 유지**하며
  새 소스는 별도 세션 페이지로 보관해 이상 정황만 명시 — 어느 쪽이 사실인지 임의로 판정하지 않는다.

## 미해결 — 다음에 조사할 것

- `logs/chats/` 파일명 생성 로직(UUID 발급 지점)과 `archive/` 이동 로직을 코드로 확인해 재사용/
  경쟁 상태 가능성을 검증할 것.
- 클라이언트(웹/quick.html) 쪽 메시지 전송 재시도 로직이 트랜스크립트에 중복 라인을 남기는지 확인할 것.
- 발생 시각이 몰려 있는지(예: 서버 재시작 직후, 네트워크 불안정 구간) 패턴을 찾을 것 — 현재는
  사례별로 시간대가 제각각이라 단일 트리거를 특정하지 못함.
