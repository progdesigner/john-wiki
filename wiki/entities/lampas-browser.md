# lampas-browser (Lampas Browser)

AI가 읽고 조작할 수 있는 Chromium 기반 데스크톱 브라우저. `[[progdesigner]]`가 "Aside 같은" 사이드바
브라우저를 요청하며 시작됐고, **하루 만에 기획→독립 앱 구축→`[[lampas-harness]]`로 완전 이관**까지
끝난 프로젝트다. 최종 위치와 최초 기획 위치가 다르므로 혼동 주의 — 아래 "위치 변천" 참고.

## 위치 변천

- **기획·1차 구축**: `[[lampas-studio]]` 저장소(로컬 `lampas-system`) 아래 `apps/lampas-browser`. 독립
  Electron 앱으로 처음부터 구축, 자체 Claude/GPT API 키·자체 Relay 서버 보유.
- **최종 이관(같은 날)**: `[[lampas-harness]]` 저장소 아래 **`apps/browser`**로 소스 이동. 이 과정에서
  AI 실행 방식이 **자체 모델 API 키 → 하네스의 기존 Codex CLI/Claude Code 로그인·세션 재사용**으로
  완전히 바뀜(별도 API 키·과금 경로 제거). **현재 위치·구조를 기준으로 판단할 것** — 이전(lampas-system)
  버전의 서술은 역사적 기록으로만 참고.
- → 세션 전체 경위: [[2026-09-26-lampas-browser-구축-harness이전]]

## 설계 원칙

- **탭마다 `WebContentsView`** — 웹페이지를 iframe으로 넣지 않고 Electron `WebContentsView`로 실행.
  Electron 메인 프로세스가 탭·세션·다운로드 수명주기를 관리, React 렌더러는 UI(사이드바·주소창·AI
  패널)만 담당.
- **사람의 클릭과 AI의 명령이 같은 제어 모듈을 공유** — 탭 생성·페이지 이동·본문 읽기 등 공통 브라우저
  제어 모듈을 만들어, UI 버튼 클릭과 AI 도구 호출이 동일한 함수를 호출하게 설계.
- **읽기와 조작의 단계적 분리** — 처음엔 페이지 본문·선택 영역만 AI에 전달하는 "읽기"만 구현, 클릭·
  입력·탐색 같은 "조작"은 이후 단계. **페이지 안의 문구를 AI의 명령으로 취급하지 않는 경계**가 필요하다는
  점을 설계 단계에서부터 명시(프롬프트 인젝션 방어 관점).
- **웹 콘텐츠와 앱 권한 철저 분리** — 외부 페이지에는 Node.js·파일시스템 접근을 주지 않고 sandbox +
  context isolation, IPC는 앱 UI가 허용한 명령만 실행.

| AI 패널(페이지 본문·표 수집, 대화형 조작) | 구현 완료, 실 모델 호출은 **모의 응답으로만 검증** |

| 하네스 세션 통합("브라우징" 선택) | `[[lampas-harness]]`로 이관 후 구현 — 아래 절 참고 |

## 하네스 통합 (이관 후, `apps/browser`)

- 하네스 새 세션 화면에 **"브라우징"** 선택지 신설 — 선택 시 그 세션 전용 브라우저 프로세스 + MCP 도구
  연결. **세션마다 브라우저 프로필과 제어 권한 분리**.
- 하네스 화면에서 원격 브라우저의 화면 확인, 표 수집 결과, **작업 승인**(사람 개입 게이트), 결과 파일
  (CSV·다운로드) 다운로드까지 가능.
- **원격 실행 토폴로지**: 브라우저는 항상 `[[lampas-harness]]` 서버(맥미니)에서 로컬로 실행되고, 원격
  접속자는 하네스 화면으로 제어만 한다 — 독립 앱 시절 "로컬 앱이 켜져 있어야 작업 가능"했던 제약이
  서버 상주형 구조로 사실상 해소됨.
- AI 인증: 별도 Claude/GPT API 키 대신 **하네스 세션이 이미 쓰는 Codex CLI/Claude Code 로그인** 재사용.
- 검증: 하네스 테스트 79개 통과, 실 Electron·MCP·웹 화면 통합 검증(탭 이동→표 수집→MCP 시트 수정→
  승인→CSV/영상 파일 반환) 완료 보고. **실제 Claude/Codex 모델에 작업을 지시하는 엔드투엔드 테스트는
  세션 종료 시점까지 미실시** — 어시스턴트가 명시적으로 미검증 구분.

## ⚠️ 배포 상태 — 재시작 대기 중이었음 (2026-09-26 세션 종료 시점)

`apps/browser` 이관·통합 구현은 완료됐으나, 하네스 자체가 이 작업을 수행 중인 서버라 즉시 재시작하면
실행 중인 CLI 세션 3개가 끊길 위험이 있어 **사용자 확인 후 재시작 진행** — 재시작 자체는 세션 소스
안에서 실행됐지만, **재시작 후 실제로 "브라우징" 선택지와 브라우저 기능이 운영 주소에서 정상 노출됐는지는
이 세션 소스만으로 확인 불가**(다음 세션에서 재확인 필요). 같은 재시작으로
[[2026-09-26-threads기능제거-llm위키탐색기-apps-wiki-이전]]이 만든 `apps/wiki`(wiki.html)도 함께
반영될 예정이었다 — 두 기능을 함께 검증할 것.

## 하네스 통합 직후 기능 확장 — 탭·좌표 클릭·원격 직접 입력 (2026-09-26, 이관 세션 바로 다음, 02:43Z)

[[2026-09-26-브라우저탭-좌표클릭-원격직접입력-위키백필-env노출-빌드동기화]] 세션(이관 세션 종료 직후
02:43Z 시작 — 아래 08:29Z "실사용 첫 사례"보다 시간상 앞선다)이 `apps/browser` 패널에 실제 UX·도구를
쌓았다. "AI 전용 브라우저"에서 "사람이 직접 로그인할 수 있는 원격 제어 콘솔"로 범위가 넓어진 시점.

- **탭 UI**: "표 수집"/"CSV 저장" 버튼을 패널에서 제거(AI는 MCP 도구로 계속 사용 가능). 대신 "새 탭"
  버튼으로 여러 사이트를 동시에 열고, 탭마다 × 닫기·활성 탭 강조·로딩 표시(⟳) 추가. 주소창이 옛 URL로
  되돌아가던 경쟁 조건도 수정(활성 탭 URL이 실제로 바뀔 때만 갱신).
- **`click_at` 좌표 클릭 도구**: 프로토콜·Electron 앱·MCP에 신설. 스크린샷 응답에 뷰포트 width/height를
  함께 반환해 AI가 좌표를 계산해 클릭 가능. 웹 패널에서도 캡처 이미지를 클릭하면 그 좌표를 브라우저에서
  클릭하고 재캡처 — 사람·AI 양쪽이 같은 좌표 클릭 경로를 씀. AI가 요청한 좌표 클릭도 기존 클릭 도구와
  동일하게 승인 대상.
- **원격 직접 입력(사용자 전용)**: 주소줄 아래 새 입력 줄 — 캡처 이미지에서 입력칸을 클릭해 포커스를
  준 뒤 텍스트를 적고 "입력"/"입력+Enter"를 누르면 **실제 키 이벤트로 흘려보내는 방식**(DOM 값 직접
  변경 아님)으로 브라우저에 전달된다. 비밀번호 필드에도 들어가고 한글도 그대로 입력됨. 값은 기본
  가려지고 "보이기"로 확인 가능, 전송 후 입력칸은 비워짐. **서버가 요청 출처를 구분해 웹 패널 출처만
  허용** — AI는 호출 자체가 불가능하고 MCP 도구 목록에도 노출 안 됨(스모크 테스트로 확인). 입력값은
  승인 카드·활동 로그·이벤트 어디에도 안 남고 글자 수만 기록됨. 로그인 후 세션별 브라우저 프로필에
  쿠키가 남아 같은 세션 내 재입력 불필요.
- **계정 정보 별도 보관은 설계만 제안되고 미구현** — macOS 키체인에 비밀번호 직접 저장(그 자체가
  암호화 저장소), 서버는 사이트+계정명 JSON만 보관, 채우는 순간에만 키체인에서 꺼내 메모리에서 버리는
  구조로 제안됨. 현재 탭 사이트와 일치할 때만 채우는 피싱 방지 장치, AI는 계정 목록 조회·채우기 불가
  (사용자 전용 규칙 재사용)까지 설계됐으나, 사용자가 승인 여부를 확정하기 전에 세션이 끝남 — **다음
  세션에서 구현 여부 확인 필요**.
- 검증: 브라우저 세션 테스트·서버/Electron 타입 검사 통과, 통합 스모크(실 Chromium, 창 표시 모드)
  전 구간 통과. 전체 하네스 테스트 88개 통과 후 커밋·푸시(아래 [[lampas-harness]] 참고 — 이 푸시
  과정에서 원격 히스토리 `.env` 평문 노출을 발견함, [[secrets-plaintext-exposure-pattern]]).

## 실사용 첫 사례 — Meta 개발자 콘솔 조작 (2026-09-26, 재시작 약 18시간 후)

[[2026-09-26-ai-dalar-인스타그램-토큰발급-메타앱생성]] 세션(08:29Z 시작)이 "Harness 브라우징 패널"의
여러 탭(로그인·개발자 콘솔·OAuth 콜백)을 실제로 열고 조작한 기록을 남겨, 위 "배포 상태" 절이 남긴
재시작 확인 필요 사항에 대한 **최초의 간접 확인**이 됐다 — 브라우징 기능 자체는 살아난 것으로 보인다.
다만 이 세션은 동시에 실사용 한계도 드러냈다:

- **비밀번호 입력 필드는 AI 도구가 조작하지 못한다** — 위 절의 "원격 직접 입력"이 애초에 웹 패널
  출처만 허용하도록 설계됐으므로 예상된 동작. 항상 사람이 브라우징 패널에서 직접 입력해야 함.
- **팝업 기반 OAuth 완료 감지가 안 된다** — 팝업이 별도 탭으로 열려 닫히지 않아, "팝업이 닫히면 완료
  감지"하는 방식의 콘솔 UI(Meta 토큰 생성 등)는 메인 화면이 끝내 완료를 인식하지 못했다.
- **좁은 입력란에 표시되는 값은 `selection`·클립보드 경유 모두로 못 읽을 수 있다** — 복사 버튼이
  실제로 시스템 클립보드에 텍스트를 넣지 않는 경우가 관찰됨.

이 세 가지는 [[lampas-browser]] 설계 자체의 결함이라기보다 **자동화 브라우저가 OAuth 팝업 플로우와
구조적으로 상성이 안 맞는 문제**로 보인다 → 절차화: [[meta-oauth-token-console-popup-unreliable-in-automated-browser]].
단, "실 Claude/Codex 모델에 작업을 지시하는 엔드투엔드 테스트는 미실시"였던 원 세션의 남은 미검증
항목은 이 세션으로도 해소되지 않는다 — 이 세션은 사람이 실시간으로 지시하며 브라우저를 조작한
사례이지, 모델이 자율적으로 브라우징 작업을 완결한 사례는 아니다.
