## 관찰된 작업 방식 / 선호
- 기능을 짧은 반복으로 요청하며 자주 "Commit & Push"로 마무리.
- "재부팅해도 유지", "죽어도 살아남게" 등 지속성/복원력을 반복 강조.
- 히스토리 소실에 민감 — 여러 차례 대화 유지 요구. **장기기억(과거 작업 이력)을 어시스턴트가 기억하길 강하게 원함** → [[long-term-memory-architecture]].
- 답변 선호(제안 세션에서 명시): 항상 한국어, 실행 중심(이론보다 단계), 추측보다 확인, 접근 불가는 명확히 말하기, 작업 요약은 "프로젝트/완료/진행중/다음행동" 형식.

### 확정된 선호 (2026-07-13 auto-memory 이관)
- **응답은 항상 한국어.** 사용자 대면 텍스트뿐 아니라 도구 호출의 사람이 읽는 필드(예 ScheduleWakeup의
  `reason`)까지 한국어. 언어 지시가 코드에 정상 주입돼도 긴 코딩·영어 컨텍스트 중 응답이 일본어로 드리프트한
  전례가 있어 강조됨. 코드 주석·변수명은 기존 컨벤션을 따르되 대화 응답만큼은 한국어를 벗어나지 않는다.
- **기억은 비자명한 것만 저장** — 처음엔 "작업 끝나면 항상 저장"을 요청했으나, 일회성 기록이 인덱스를
  소음으로 오염시켜 중요 기억을 묻는다는 설명에 동의(2026-07-09 절충). 종료 시 기준: (1) 사용자 피드백·선호,
  (2) 코드/git에 안 드러나는 진단 맥락·원인, (3) 진행 중 프로젝트의 목표·제약. git/코드로 알 수 있는 건 저장 안 함.
  → [[long-term-memory-architecture]]의 저장 철학과 동일.
- **스크립트 폴더 분리**: 일회성 probe/test/조회용 개발 스크립트는 `tools/`, 실제 설치·운영 스크립트
  (install/setup/restart/bootstrap/self-update)는 `scripts/`. (2026-07-09 `scripts/`에 섞인 probe 7종을
  `tools/`로 옮기라 지시.) → [[lampas-harness]]
- **사용자 대면 이름은 "람파스"** — 서비스명·에이전트명·UI 노출 텍스트에 "람파스"를 쓴다(내부 식별자는
  `harness`/`lampas-*` 유지). → [[lampas]]
