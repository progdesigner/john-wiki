# lampas-web-copy ("Copy")

`[[lampas-studio]]` 저장소(`lampas-system`)의 스포츠 클립 파이프라인 자매 앱 중 하나. 클립 근거로
SNS 카피·페르소나를 생성하는 웹. `[[lampas-agent]]`(스포츠 클립 라벨링 데몬)·`lampas-web-reels`(클립
편집)·`[[lampas-web-status]]`와 같은 계열 — 2026-09-25 세션들에서 처음 노출됐고, 저장소 루트
`AGENTS.md`(3라인 앱 목록: Lampas/Dalar/Talk)에는 등장하지 않는 앱이다(자세한 불일치는
`[[lampas-studio]]` "스포츠 클립 파이프라인" 절 참고).

## 최초 구현 — 클립→페르소나→카피 4단계 플로우 (2026-09-12, 2026-09-26 뒤늦게 ingest)
이 앱에서 "페르소나"가 처음 등장한 지점은 아래 09-19 이관 절보다 **7일 앞선**
[[2026-09-12-lampas-copy페르소나-clips분야카테고리-스포츠위키-구축]] 세션이다. 클립 선택 →
`POST /v1/copy/personas`(클립 1개당 페르소나 후보 4개: name/description/target/reason 자동 생성) →
`PersonaPicker`로 선택 → 그 목소리로 카피 생성(`personaSnapshot` 컬럼에 스냅샷 저장) → 결과는 카드마다
반복 없이 "클립 X + 페르소나 Y 기반" 한 줄 요약 → 채점 프롬프트가 "무엇이 이 점수를 만들었는지/무엇을
올리면 좋을지" 두 문장 근거를 요구하도록 강화("이 점수인 이유" 라벨)가 이 세션의 최초 구현이다.
이후 같은 세션에서 훅 점수 필터(reels의 `filterHookClips` 이식)·페르소나 localStorage 캐싱·
`copy_persona_sets` 테이블 DB 영속화까지 연속 추가됐으나, **이 페르소나 생성 인프라 전체가 아래
"페르소나 생성 이관" 절이 기록한 2026-09-19 세션에서 Pulse로 이관되며 폐기**됐다(`suggestPersonas`/
`fetchLatestPersonaSet`/`/v1/copy/personas*`/`copy_persona_sets`/`copy_field_personas` 전부 삭제).
카피·채점 자체(4영역 채점, 점수 근거 두 문장 요구)만 이후로도 발전을 이어간다. 이 세션은 또한 Copy에
**ALB 60초 유휴 타임아웃으로 인한 504**가 처음 발현·수정된 지점이기도 하다(카피 생성/채점이 상세
페르소나·톤·힌트로 60초를 넘기면 발생 → 15초 주기 킵얼라이브 스트리밍으로 수정, 항상 200+
`{ok,data}` 봉투로 전환) → [[lb-idle-timeout-keepalive-streaming]]. 그 직후 "결과가 나왔는데 화면에
안 보인다"는 URL 상태 경쟁(race) 버그도 같은 세션에서 발견·수정됨(`?run=` 세팅이 별개의 복원
이펙트를 재트리거해 아직 `suggested` 상태인 런을 `score_failed`로 잘못 덮어쓰던 문제).

## 관찰된 기능
- **2026-09-26 뒤늦게 발견된 선행 시도**: 아래 "페르소나 생성 이관"보다 8시간 앞선 같은 날 세션
  ([[2026-09-19-pulse-분야별mlb페르소나-copy4단계개편-최초구현]], `Tool: codex`)이 이미 Copy를
  "분야 선택 → 클립 선택 → 페르소나 선택·추가 → 카피 생성" 4단계로 개편해 `copy.lampas.io/?field=mlb`
  까지 운영 배포했었다. 이 구현(분야별 사전 정의 페르소나 라이브러리)은 그날 오전 뒤이은 세션의
  배포에서 관련 DB 테이블이 DROP되며 대체됐다 — 상세 → [[lampas-web-pulse]] "이전에 있었던 별도
  시도" 절.
- **페르소나 생성은 이 앱이 아니라 [[lampas-web-pulse]](pulse.lampas.io)가 담당** (2026-09-19 개편,
  [[2026-09-19-pulse-페르소나-단일출처-계정이관-신뢰도개선]]). 그 이전엔 Copy 자체에 페르소나 생성
  로직(`suggestPersonas`/`fetchLatestPersonaSet` 등)이 있었으나 전부 제거되고 `fetchPulsePersonas`로
  대체됨 — 클립 → 분야·카테고리(스포츠 MLB/NBA는 클립에서 자동 추론) → Pulse 라이브러리 가로 스크롤
  스트립에서 선택 → 카피 생성 순서. **그 분야·카테고리에 페르소나가 하나도 없을 때만** "이 클립으로
  페르소나 4개 만들기" 버튼이 예외적으로 뜨고, 결과는 Copy가 아니라 Pulse 라이브러리(`pulse_personas`
  테이블)에 저장된다. `POST /v1/copy/runs`는 `personaId`만 받고 서버가 소유권 확인, 구 엔드포인트
  `/v1/copy/personas*`와 테이블 `copy_persona_sets`·`copy_field_personas`는 삭제됨.
- **카피·채점 자체**는 여전히 이 앱/[[lampas-agent]] 쪽 로직이 담당한다(4영역 8세부항목 채점, 감점
  상한 정책이 사용자 피드백으로 한 차례 뒤집힘 — 아래는 페르소나 저장 위치 이관 *이전*부터 있던
  채점 구조에 대한 설명). 상세 → [[lampas-agent]] "Pulse" 절 · [[2026-09-24-pulse-페르소나-카피점수-구조화-개선]].

## 카피 생성·채점 모델 선택 (2026-09-24~ 세션, API 0.1.142)
"카피·채점도 모델을 선택할 수 있게 해줘" 요청으로, `GET /v1/copy/models`가 기본 모델과 함께 고를
수 있는 `options`(GPT-6 Astra, GPT-5.6 Sol, Claude Opus 5, Claude Sonnet 5, Gemini 3.5 Flash,
Gemini 3.1 Pro, Grok 4.5)를 내려주게 됨. 카피 생성(`POST /v1/copy/runs`)·채점(`POST
/runs/:id/score`)이 선택적 `model` 파라미터를 받는다. 목록 밖 모델이라도 게이트웨이(`[[atlas-cloud]]`
추정, 세션 소스로는 확정 안 됨) 카탈로그에 있으면 허용하고, 그 외는 LLM 호출 전 400으로 거부. 고른
모델이 실패하면 같은 종류의 기본 모델로 한 번 재시도하며, 실제 사용된 모델이 결과에 남는다 —
[[llm-judge-fallback-chain]]의 "판정 폴백"이 아니라 "생성 실패 시 동종 기본값 재시도"라는 변형.
StudioPage에 생성·채점 모델 셀렉트가 붙고, **생성과 채점이 같은 벤더면 "교차 채점이 아님" 경고**가
뜬다(→ [[lampas-web-pulse]]의 "교차 심사" 개념과 같은 우려 — 같은 모델이 자기 결과를 채점하면
편향될 수 있다는 전제). 클립으로 페르소나를 만드는 경로도 생성 모델을 따름. 선택은 localStorage에
저장되고 목록에 없는 옛 값은 기본값으로 폴백 → [[localstorage-ui-preference-persistence]].
API jest 68건(카피·펄스 페르소나 합산) 통과, 운영 `GET /v1/copy/models`가 실제 7개 options 반환
확인. 세션 → [[2026-09-24-voice레퍼런스오디오-소프트삭제-카피페르소나모델선택]].

## `?clip=<id>` 딥링크 (2026-09-18 세션)
Reels UI 단순화(→ [[lampas-web-reels]] "Copy 앱 딥링크" 절)와 함께 추가됨. `?clip=<id>`로 진입하면
그 클립을 1단계에서 미리 고른 상태로 시작(페르소나 후보 자동 로드까지 이어짐). `?run=`이 함께 있으면
기존 run 복원이 우선이고, 클립을 못 찾으면 안내 토스트. 이 세션 시점엔 Copy가 아직 자체
`suggestPersonas`로 페르소나를 만들고 있었다(아래 "Pulse 이관" 절의 이관은 다음날).

## 추가 지시사항·톤 프리셋 — 서버 저장 + 분야·카테고리별 마지막 선택 기억 (2026-09-18 세션)
"다른 브라우저로 가면 추가 지시사항이 사라진다" + "분야/카테고리별로 마지막 선택을 기억해달라"는
요청으로 신설된 독립 API 모듈 `copy-hints`(`/v1/copy-hints`, `copy` 모듈과 무관):
- 테이블 `copy_hint_presets`·`copy_hint_selections`. 범위 키 = 클립의 분야+카테고리(예 `sports:12`,
  `general:none`). `GET /`(프리셋 목록+범위별 마지막 선택), `POST /`(대소문자·공백 무시 중복 병합),
  `PUT /selection {scopeKey, text}`(비우면 해제, 프리셋 사용 횟수 증가), `DELETE /:id`(soft delete).
- 웹: 추가 지시 입력이 "저장된 지시 선택" 셀렉트 + 직접 입력 textarea로 바뀌고 "이 지시 저장"/"저장
  삭제" 버튼 추가. 카피를 만들면 그 클립의 분야+카테고리에 자동 기억, 같은 범위 클립을 고르면 자동
  적용. 순수 로직 `lib/hintScope.ts`.
- **배포가 한 차례 보류됨**: 같은 작업 트리에서 다른 세션(Pulse 이관 세션)이 `copy-api.ts`에서
  `fetchCopyFields` 등을 이미 제거했는데 `StudioPage.tsx`가 아직 import해 컴파일이 깨진 상태였고,
  API를 먼저 배포하면 운영이 의존하는 `/v1/copy/fields`가 사라져 함께 깨질 상황이었기 때문. 그
  세션이 끝나 컴파일이 복구된 뒤 정상 배포됨.
- **후속(같은 세션 §2)**: 사용자가 "톤도 추가지시처럼 저장·선택 삭제되게" 요청 → 프리셋에
  `kind`(`hint`|`tone`) 필드 추가, 선택 유니크를 `(userId, kind, scopeKey)`로, 웹은 공용
  `PresetSelect` 컴포넌트로 통합(저장된 프리셋 셀렉트+직접 입력, "이 톤/지시 저장", "선택 삭제"). 이
  배포에 Pulse 이관분(아래 절)도 함께 실려나감.
- 상세 → [[2026-09-18-lampas-clip-intelligence-brand-kit-대량구현]] §7.

## 모델 업그레이드 + 여러 페르소나 동시 생성 (2026-10-03, 커밋 `055b6304`, agent 1.0.33)
"모델을 더 최신으로, 여러 페르소나로 동시 생성, 더 빨리, UI/UX도 살펴봐줘"라는 4가지 요청을 한 배포에
함께 반영. 새 기본 모델이 이미지+지시문을 받아 정상 응답하는 것까지만 확인(실제 카피 한 세트를 끝까지
돌려보는 것은 운영 로그인이 필요해 못 함).

**모델 표**:
| 역할 | 이전 | 지금 |
|---|---|---|
| 생성 기본 | GPT 6 Astra | **GPT 6.1 Sol** |
| 생성 폴백 | GPT 5.6 Sol | GPT 6 Sol |
| 채점 기본 | Claude Opus 5 | **Claude Opus 5.5** |
| 채점 폴백 | Grok 4.5 | Grok 4.6 |

- GPT 6.1 Sol은 Astra보다 단가 1/5, 짧은 테스트에서 ~2배 빠름(5초 대 9초) — Astra는 창작 특화라
  선택지로 남김. Opus 5.5는 Opus 5보다 단가 20% 낮지만 테스트에서는 더 느림(12초 대 6초) — 속도가
  중요하면 채점을 Opus 5로 되돌리는 편이 나음(아래 "채점 타임아웃" 절에서 실제로 이 느림이 문제가 됨).
  선택지에 GPT 6 Luna(가장 빠르고 저렴)·Gemini 3.8 Flash 추가.
- 새 모델들이 단가표에 없어 임시 단가로 과금되고 있었던 것을 계기로 **단가표 전체 재동기화**(모델
  33개 추가, 5개 제거, 기존 단가 변동은 거의 없음)도 같이 배포.
- 적용 범위는 copy(와 copy 기본 모델을 쓰는 Pulse 페르소나 생성)뿐 — reels AI 선별·세트 심사 모델은
  그대로.

**여러 페르소나 동시 생성**: 3단계에서 페르소나 다중선택+"전체 선택". 페르소나마다 카피 10개 생성→
채점이 동시에 최대 4개까지. 결과는 페르소나별 탭에 진행 상태+최고점 표시, 먼저 끝난 것부터 볼 수
있음. **종합 순위** 탭에서 모든 페르소나 카피를 채점 높은순 한 목록으로. 실패한 페르소나만 재시도
가능, `?runs=`로 같은 결과 재오픈.

**UI 개선**: 모델 선택을 접이식으로(현재 모델은 한 줄 표시). 예상 크레딧 = 고른 모델 단가×페르소나
수(이전엔 기본 모델 고정값). 생성 버튼에 진행 수(`만드는 중… 2/4`) 표시.

**아직 안 한 것**: 클립 여러 개 골라 한 번에 돌리기, 종합 순위 카피를 reels 편집 그룹으로 직접 넘기기,
작업 내역에서 같은 묶음 run을 한 줄로 묶어 보기(지금은 run마다 따로 나옴).

## 생성 중에도 추가 페르소나 생성 (2026-10-03, 커밋 `a6f70492`)
"페르소나 바꿔서 추가 생성이 이미 생성 중일 때는 안 된다"는 제보로 수정. 분야·카테고리·페르소나
선택이 생성 중에 잠기지 않음(클립만 생성이 끝날 때까지 잠김). 페르소나를 더 고르면 버튼이 "페르소나
N개 추가로 만들기 (진행 2/4)"로 바뀌어, 누르면 기존 것은 그대로 돌면서 새 페르소나가 탭으로 추가됨.
**중복 생성 방지**: 같은 클립·목적·톤·지시로 이미 만들었거나 만드는 중인 페르소나는 버튼 대상에서
빠져 "전체 선택" 재클릭해도 다시 돌지 않고 크레딧도 다시 안 씀. 결과 탭마다 "다시 만들기" 버튼으로
그 페르소나만 현재 설정으로 재생성(다른 페르소나가 도는 중에도 가능). 생성이 다 끝난 뒤 톤·목적·
지시를 바꿔 누르면 고른 페르소나 전부를 새 묶음으로 재생성, 생성 중에 바꿔 누르면 기존 결과 옆에
새 조건 결과가 추가됨.

## 채점이 오래 걸리던 문제 — 원인은 바로 오늘 올린 채점 모델 (2026-10-03, 커밋 `1af6902c`/`5c919b79`)
"copy에서 채점이 자꾸 오래 걸린다"는 제보. 원인은 위 "모델 업그레이드" 절에서 그날 올린 Opus 5.5
자체였다 — 카피 10개를 한 번에 채점하면 생각 토큰까지 합쳐 응답 한도를 넘겨 JSON이 중간에 잘림(운영
로그에 파싱 실패 반복). 그 뒤 느린 폴백 모델(Grok 4.6)로 넘어가면서 5분 제한을 넘겨 "timeout of
300000ms"가 발생.

**수정**: 카피를 **2개씩 나눠 5번의 채점을 동시에** 돌림(채점이 카피별 절대 기준이라 나눠도 결과는
같음). 실측으로 2개 묶음 한 번이 Opus 5.5 기준 65~81초, 응답도 안 잘리고 정상 파싱. 5묶음 동시 실행
이라 전체는 1분 남짓 예상. 묶음 하나가 실패하면 그 묶음만 대체 모델로 재채점.

**비용 재측정**: 채점 한 번에 약 500크레딧(대부분 생각 토큰) — 화면의 예상 크레딧도 이 실측에 맞게
고침(이전 표시는 실제보다 훨씬 낮았음). 더 빠르게 하려면 채점 모델을 Gemini 3.8 Flash로 고르면
묶음당 15초·비용 약 1/7이지만 같은 카피에 Opus가 49점 준 걸 68점 주는 등 덜 엄격함 — 모델 선택지
설명에 이 차이를 적어둠. 기본값은 Opus 5.5 유지.

이 실패 패턴("모델 업그레이드 직후 운영에서만 드러나는 배치 크기·응답잘림·타임아웃")은 재사용 가치가
있어 기존 스킬에 새 사례로 편입 → [[llm-batch-inference-timeout-tuning]].
