# lampas-web-edit ("Edit", edit.lampas.io)

`[[lampas-studio]]` 저장소(`lampas-system`)의 스포츠 클립 파이프라인 자매 앱. 클립을 실제로
편집(자막·텍스트 오버레이·이미지·트랙 배치)해 최종 영상으로 렌더링하는 웹 에디터. `[[lampas-web-flow]]`의
5번째 노드(Edit)가 이 앱을 가리킨다.

**시점 정정(2026-09-26 추가 ingest, 두 번째 정정)**: 이 페이지는 처음 "[[2026-09-19-lampas-edit-자막-템플릿-대량기능개발]]
세션에서 위키에 처음 상세 노출됨(0.1.17→0.1.43)"으로 기록했으나, 그보다 **6일 앞선**
[[2026-09-13-lampas-edit-이미지트랙-텍스트효과-원본백업-구현]] 세션(그날의 다른 09-13 세션들 —
CS·시나리오·dalar-web-first — 보다도 이른 06:10Z 시작)이 실제 더 이른 관찰 지점이다. 세션 시작
당시 이 앱은 이미 완전히 영상 전용(mediabunny 디코딩)이었으므로 절대적 기원(0.1.2 이전 히스토리)은
이 소스로도 확인 불가하지만, **이미지 미디어/이미지 트랙/트랙 순서 스왑, 텍스트 자간·장평·기울임,

## edit-sessions 핸드오프 소스 앱 확장 — First 추가 (2026-09-15)
`lampas-api`가 관리하는 edit-sessions·media-exports 화이트리스트에 이미 `[[lampas-web-scenario]]`·
`[[lampas-web-reels]]`가 세션을 만들어 이 앱으로 넘기고 있었고, 이 시점에 **`[[dalar-web-first]]`가
세 번째 소스 앱으로 추가**됐다 — `EditSessionApp` 타입·앱 라벨에 First 추가. First 관리자가 컷별

`access_token`으로 전달(같은 주문·컷은 `<orderId>:scene:<n>` 키로 세션 재사용). 상세는
[[dalar-web-first]] "관리자 → lampas-web-edit 컷 핸드오프" 절 참고 — 세션 전체는

## Auto Reframe(9:16 자동 리프레임) — 모션 무게중심 근사 (2026-09-18 도입, 이후 2회 개선)
인스펙터 "화면 맞춤" 탭의 "피사체 따라 자동 팬" 버튼. 클립 구간을 4fps로 샘플링해 프레임 간 움직임의
무게중심을 구하고, 세로 캔버스에서 보이는 비율 기준으로 그 중심이 화면 가운데 오도록 **팬 키프레임**을
생성한다. **얼굴 검출이 아니라 모션 무게중심 근사**라 스포츠·인물 이동 컷에 맞고, 정적 컷은 팬할
근거가 없어 중앙 고정으로 남는다. 미리보기와 최종 렌더가 같은 보간 함수를 공유.
- **키프레임 수동 조정**(후속 요청): 인스펙터에 키프레임 목록이 추가돼 좌↔우 슬라이더로 위치 조정,
  ✕로 삭제, "+ 현재 위치"로 플레이헤드 시각에 키프레임 추가. 미리보기 드래그 시 예전엔 키프레임
  전체가 해제됐으나, **현재 시각의 키프레임만 갱신**하도록 변경(키프레임이 없는 클립은 기존대로 고정
  팬 이동).
- **분석 시 fit/scale 유지**(후속 요청): 처음엔 분석이 Cover로 강제 전환했으나, "스케일링은 그대로
  둔 채 분석하게" 요청으로 현재 설정된 Cover/Contain과 스케일을 유지한 채 그 상태에서 보이는 창
  기준으로만 키프레임을 생성하도록 수정. 전부 보이는 상태(팬 여지 없음)면 안내만 표시.
- **Contain 모드 팬 버그 수정**: Contain에서 가로 영상은 캔버스 폭에 딱 맞아 팬 범위가 0이었고,
  스케일로 넘친 부분엔 팬이 전혀 걸리지 않았다 — 릴스 기본 레이아웃(Contain + 1:1 확대)이 정확히
  이 상태라 실사용에서 좌우 이동이 막혀 있었다. `clipDrawRect`를 고쳐 스케일 전 넘침이 없는 축에서는
  스케일 후 넘친 만큼에 팬을 적용하도록 수정(팬 0.5=가운데는 두 방식 동일이라 기존 프로젝트 렌더
  결과는 불변). 미리보기 `<video>`도 CSS `objectPosition` 대신 렌더와 동일한 dest-rect 직접 배치로
  전환해 미리보기·렌더가 완전히 같은 공식을 쓰게 됨.

## 브랜드 킷 적용 (2026-09-18 도입)
`lampas-api`의 신규 `brand-kits` 모듈(로고·폰트·자막 스타일·팔레트·CTA·워터마크를 계정 프리셋으로
저장)이 편집 세션에 스냅샷으로 전달되면, 시드 직후 자막 스타일·워터마크·CTA·로고 레이어가 자동
적용된다. 홈에 브랜드 킷 관리 패널 추가. Reels가 세션 생성 시 브랜드킷 **목록 응답 객체를 그대로**
넘겨 `isDefault`/`createdAt`/`updatedAt` 같은 DTO가 허용하지 않는 필드 때문에 검증 오류가 났던 것은
0.1.30(+Reels 0.1.24)에서 스냅샷 필드만 남기도록 수정됨(아래 "배포 인프라" 절 기존 기록).

## 자막 생성(ASR) 청크 분할 수정 — 긴 구간 전사 중간 끊김 (2026-09-18)
"자막 생성 시 모든 내용이 전사되지 않는다" 제보. 원인: 트림 구간 전체를 48kHz 스테레오 WAV 한 파일로
통째 ASR에 보냈는데(`[[lampas-agent]]` 인제스트는 16kHz 모노로 줄여 600초 단위 분할 전송하는 반면
에디터만 예외), 구간이 길면 모델이 앞부분만 전사하고 뒤를 버렸다. 단어 타임스탬프도 클립 기준 큐로
옮길 때 누락되고 있었다. 수정: 트림 구간을 300초 청크로 나눠 청크마다 오디오 추출→16kHz 모노
리샘플→WAV 업로드→전사(빈 결과/실패 시 소음 보정 폴백 모델)→청크 시작 시각 보정 후 이어붙임, 단어
타임스탬프 보존. 리샘플로 업로드 크기 약 1/6 감소. 일반화된 절차 → [[asr-long-audio-silent-truncation]].

## 원칙: 미리보기·렌더 공용 함수
이 앱의 반복되는 설계 원칙 — 자막 그리기(`drawSubtitle`), 큐 선택(`activeCueAt`), 자막 세로
정렬·위치 계산, 텍스트 행간, 레이어 스택 합성을 **미리보기 캔버스와 최종 렌더가 항상 같은 함수를
공유**한다. 그래서 기능을 하나 추가하면 미리보기·결과물이 자동으로 일치하고, 버그도 두 곳에 동시
나타나거나 동시에 고쳐진다(예: 0.1.28 자막 사라짐 버그가 미리보기·렌더 모두에서 동시 발생·동시 수정).

## 자막(Subtitle) 시스템
- **양옆 여백**: `subtitles.sideMargin`(캔버스 폭 대비 0~25%, 기본 5%). 실측 폭(`measureText`) 기준
  어절 단위 줄바꿈으로 교체(기존 "글자당 0.62em" 추정이 한글에서 잘림의 근본원인). 여백보다 큰
  단일 단어는 폰트 비례 축소.
- **세로 위치·정렬 기준**: 프리셋(하단82%·중앙50%·상단14%)은 1회 초기화용, 이후 미리보기 드래그
  또는 슬라이더(5~95%)로 자유 조정 + 가운데 스냅. **세로 기준**(위/가운데/아래) 칩으로 줄 수가
  늘어날 때 어느 방향으로 자랄지 결정.
- **단어 강조(karaoke)**: ASR 단어 타임스탬프 기반. 텍스트를 수정하면 원본 단어와 diff해 같은
  토큰은 원래 시각 유지, 새 단어는 이웃 단어 사이 시간을 글자 수 비례로 분배(0초 방지). 수동으로
  추가한 큐(타임스탬프 없음)는 어절 글자 수 비례로 발화 타이밍을 합성해서 강조 가능(2어절 이상 조건).
- **"다음 자막까지 유지"** 체크박스: 큐 종료 후 다음 큐 시작(또는 클립 끝)까지 화면에 남김.
- **한국어 번역**: 영어 발화 자막을 AI 게이트웨이로 40개씩 배치 번역, 원문은 큐에 보관해 되돌리기
  가능, 큐 시각/단어 타임스탬프는 그대로 둠.
- **타이포**: 투명도·자간·행간(기본120%, 80~250%)·장평(scaleX)·기울임 — 텍스트 오버레이와 값 범위
  공유(자간·장평·기울임의 원출처는 09-13 세션의 텍스트 오버레이 구현, 위 "이미지 미디어·트랙·텍스트
  효과·원본 백업 최초 구현" 절 참고), 레이아웃 템플릿에도 포함되어 함께 저장·적용됨.

## 큐(자막 구간) 편집
- **합치기**: 마지막 제외 모든 큐에 "↓ 아래와 합치기" — 구간·텍스트·단어 타임스탬프를 순서대로 병합.
- **위/아래에 추가**: 인접 빈 시간에 최대 2초 새 큐 삽입, 빈 시간 없으면 해당 큐를 반으로 분할(0.2초
  미만이면 무동작).
- **textarea + 강제 줄바꿈**: Enter로 줄 추가(최대 6줄), 줄바꿈 위치가 자막에 그대로 반영.

## 레이어/트랙
- 영상·이미지·텍스트가 **하나의 스택**으로 합쳐져 종류 무관하게 순서 변경 가능(▲▼). 자막은 가장
  위 클립 레이어 바로 위에 그려져, 텍스트 레이어를 그 위/아래로 옮기면 자막을 덮거나 가려짐.
  **▲▼ 트랙 전체 스왑 자체는 09-13 세션에서 영상·이미지 트랙만 대상으로 처음 구현**됐고(오디오
  트랙 제외는 그때부터 동일), 텍스트까지 같은 스택에 합쳐진 것은 09-19 세션 0.1.25.
- 트랙 이름은 **클릭 즉시 편집**(더블클릭 아님), 순서를 바꿔도 이름은 내부 번호 기준 유지(한 번
  순서기준 번호매김으로 바꿨다가 사용자 요청으로 롤백, 0.1.33).

## 미리보기 상호작용
- 자막·영상 팬 모두 드래그로 위치 조정 가능. 정중앙 근처에서 픽셀 거리(캔버스 짧은 변의 2%) 기준
  스냅 + 점선 가이드. 드래그 우선순위: 꾸미기 텍스트 → 자막 → 선택 클립 팬.

- **이미지 슬롯 fingerprint/url 이원 구조**: 로컬 fingerprint 우선, 없으면 템플릿 `url`(S3/CDN),

## Sound에 mp3 로컬 업로드 추가 (2026-09-26)

  사용. 로그인 시 영상·이미지와 같은 편집 세션 자산 백업으로 S3에 올려 타기기 자동 복구(→
  [[local-asset-fingerprint-s3-backup-recovery]]), 파일이 없으면 "파일 없음"+해당 사운드만 렌더 제외.

- 신규 `apps/lampas-web-edit/src/lib/localSound.ts`(순수 로직+테스트). API 편집 세션 자산 백업
  kind에 `audio` 추가.

  게이트는 영향 없이 정상 통과 — 루트 prisma 커맨드와 배포 스크립트 게이트가 분리되어 있음.

## 에셋(라이브러리 원본) 단위 교체 — "원본 교체" (2026-09-26)
기존 `replaceClipMedia`(타임라인의 클립 하나만 교체)와 별개로, **라이브러리 원본 파일을 바꾸면 그
원본을 쓰는 모든 클립 인스턴스가 한 번에 교체**되는 기능. 에셋 카드 호버 시 "추가" 옆 ⇄ 교체
버튼(바뀔 클립 개수 툴팁 표시), 타임라인 우클릭 메뉴에 "원본 교체 (같은 원본 클립 모두)" 항목 추가.
- **교체 규칙**: 위치·레이어·전환·자막·화면 맞춤·팬 키프레임은 유지. 트림 구간은 길이를 지키며 새
  원본 범위 안으로 clamp(뱅크 클립에 구간이 있으면 그 구간 안으로, 원래 트림이 새 원본보다 길면
  새 원본 전체 사용). 이미지로 바꾸면 이미지 클립, 영상으로 바꾸면 영상 클립으로 종류 전환. 라이브러리
  에선 옛 항목 자리에 새 항목이 들어가고(새 파일이 이미 있으면 옛 항목만 정리), 새 파일은 기존
  반입 경로(OPFS+로그인 시 S3 백업)와 동일하게 처리.
- 신규 `apps/lampas-web-edit/src/lib/replaceMedia.ts`(순수 로직+테스트)+커맨드 `replaceLibraryMedia` —
  단일 클립 교체와 같은 반입 함수를 공유하도록 정리.
- 검증: vitest 603개, tsc 통과. 배포 완료, 커밋 `e0b4661f`(미푸시).

## 템플릿 구조 편집(`/templates`) — 트랙 추가·삭제·순서 변경 (2026-09-26)

## 에디터 타임라인 텍스트 트랙 위/아래 이동·삭제 버그 수정 (2026-09-26)

## 템플릿 구조 편집 화면 신설 — `/templates`, "템플릿 → 구조 편집" (2026-10-01, 0.1.46)

추가·삭제하고 위치·크기·레이어 순서를 편집**하는 별도 화면으로 확장 — "트랙 추가·삭제"(09-26,
위 절)보다 한 단계 더 나아가 배치·크기까지 다루는 전체 구조 편집기다. 기존 Edit 작업대와 같은
미리보기를 보며 구조를 수정하고, 저장하면 **원래 템플릿 레코드 자체가 갱신**된다 — 이미 그 템플릿을

확인용 영역 표시로, 텍스트·이미지는 실제 배치 미리보기로 보여준다.
- 검증: 타입체크·빌드·템플릿 테스트 15개 통과. 배포(공식 스크립트), 버전 `0.1.46`, 전체 테스트

## 영상 영역 가시성 — 2라운드 수정: 검정+흰 라벨 → 출력(검정)/배치(회색) 이원화 (2026-10-01)

Contain으로 들어가는지"가 여전히 구분 안 된다는 재지적 — **출력 캔버스(해상도 전체) 자체는 검정
고정 + 외곽 테두리 + 해상도 숫자 표시**, 그 안에서 **영상이 실제로 배치되는 영역**은 **짙은 회색**으로

불필요하다는 지적으로 제거.

## 정밀 편집 도구 — 1px/10px 이동, 선택 영역 강조, 잠금 가이드 이미지 (2026-10-01, 0.1.5x·테스트 609개)

  테스트로 고정. 겹쳐 그리는 비적용 참조 레이어라는 점에서 재사용 가능한 UI 패턴.
- 브라우저에서 선택 표시·드래그·가이드 투명도·레이어 변경·가이드 제외를 직접 확인 후 배포.

하나에만 의존하던 복구 경로를 **클립 뱅크·영상 소스·저장된 원본 URL까지 포함한 다단계 복구 체인**으로
확장(`[[local-asset-fingerprint-s3-backup-recovery]]` 자동복구 훅의 폴백 소스를 1개→여러 개로 늘린
사례). UI에 **개별 파일 "원본 다시 받기"**와 **"누락 원본 다시 받기"(전체 일괄)** 버튼을 신설.
복구해도 기존 클립의 위치·트림·자막은 그대로 유지, 복구된 파일은 새로고침 후에도 남음. 원본 URL과
서버 백업이 모두 없는 순수 로컬 반입 파일은 복구 불가 — "직접 다시 연결해야 한다"는 안내 메시지로
구분.

## 배포 방식
S3 업로드 + CloudFront 무효화(정적 SPA), API는 PM2. 배포 전 매번 `web-edit` 타입체크+전체
테스트(500~630여 개)를 통과시키는 패턴이 일관됨.
