# lampas-web-pulse ("Pulse", pulse.lampas.io)

`[[lampas-studio]]` 저장소(`lampas-system`)의 스포츠 클립 파이프라인 자매 앱. `[[lampas-agent]]`가
수집한 미션(유튜브 클립·댓글 등)을 사람이 로그인해서 보고, **페르소나를 만드는 단일 출처** 역할을
하는 웹. 2026-09-19 세션에서 전면 개편·정식 엔티티화됨(→
[[2026-09-19-pulse-페르소나-단일출처-계정이관-신뢰도개선]]).

> ⚠️ **이름 중복 주의**: `[[lampas-agent]]`(맥미니 로컬 데몬) 자체에도 "Pulse"라는 탭이 있다(스케줄
> 수집·진행 UI). 이 문서가 다루는 `lampas-web-pulse`(pulse.lampas.io)는 **별도의 클라우드 웹 앱**으로,
> 에이전트가 수집해 API로 보낸 미션을 로그인 계정 기준으로 열람·관리하는 쪽이다. 에이전트의 Pulse 탭이
> "수집 실행"이라면, 이 앱은 "수집 결과 열람 + 페르소나 라이브러리"다.

## 이전에 있었던 별도 시도 — 분야별 MLB 리서치 (2026-09-19 03:16, 같은 날 대체됨)
2026-09-26 뒤늦게 발견: 아래 "개편"보다 **8시간 앞선 같은 날 세션**(`Tool: codex`,
[[2026-09-19-pulse-분야별mlb페르소나-copy4단계개편-최초구현]])이 이미 "분야별 재사용 페르소나 +
Copy 4단계(분야→클립→페르소나→카피)"를 구현·운영 배포했다 — 한국어 MLB 인기 영상 20개를 실제
YouTube 검색으로 수집해 별도 "리서치" 테이블에 저장, `copy.lampas.io/?field=mlb`·
`pulse.lampas.io/fields`까지 배포 완료. 이 세션 끝에 사용자가 "Pulse에서 수집된 건 어디로 가는
거지?"라고 묻자 어시스턴트가 "기존 미션 수집"과 "분야별 리서치"가 분리돼 헷갈리는 구조임을 인정.
아래 11:14 세션은 그 문제를 정확히 겨냥한 재설계처럼 보이지만, 소스에 03:16 세션에 대한 언급이
없다. 그리고 11:14 세션의 배포 1단계가 **"기존 페르소나·리서치 테이블 DROP"**을 명시하고 있어
03:16 세션이 만든 MLB 리서치 테이블·영상 20개는 **운영에 반영된 지 8시간 만에 폐기**된 것으로
확인된다. 메커니즘도 다르다: 03:16 세션은 분야 단위 **사전 정의 라이브러리**였고, 11:14 세션은
미션에서 고른 클립으로 **온디맨드 생성**해 분야·카테고리 단위로 저장하는 방식이다.

## 아키텍처 (2026-09-19 개편 이전 → 이후)
- **이전**: 페르소나는 [[lampas-web-copy]](Copy)에서 만들어졌고, pulse.lampas.io는 로그인 없이(또는
  env 고정 이메일 `PULSE_OWNER_EMAIL` 기준으로) 미션을 보여주는 화면 + "장면 분석(역기획)" 탭이 있었음.
  (위 "이전에 있었던 별도 시도" 절의 분야별 리서치 테이블도 이 "이전" 상태에 포함되며, 아래 개편의
  DDL에서 함께 DROP됨.)
- **이후**: Google 로그인 세션 단위로 동작. 미션은 새 `owner_email` 컬럼으로 귀속되고 읽기 API는 JWT
  이메일로 필터 — **기존 미션(귀속 없음)은 로그인해도 보이지 않게 됨**(사용자가 데이터 폐기 승인).
  분석 탭은 전면 삭제. **페르소나 생성이 Copy에서 이 앱으로 이관**됨: `/personas` 페이지에서 분야+
  카테고리 선택 → 미션 선택 → 수집된 클립 체크박스(조회수 상위 12개 기본 선택, 전체 선택/해제, 힌트
  입력) → "선택한 N개 클립으로 페르소나 4개 만들기" → 라이브러리 카드(원본 배지, 타겟층 설명, 근거
  클립 링크, 삭제, "Copy에서 이 페르소나로 카피 만들기" → `${VITE_COPY_URL}/?persona=<id>`). 새
  테이블 `pulse_personas`(메인 DB, 분야+카테고리 단위 저장), 분류 체계는 `pulse-taxonomy.ts` 한 곳에서
  관리(스포츠 MLB·NBA·KBO·축구, 예능, 뷰티, AI·테크로 시작).
- `[[lampas-web-copy]]`·`lampas-web-reels`는 이제 페르소나를 **자체 생성하지 않고 이 앱의 라이브러리를
  조회만** 한다(Copy는 카테고리가 비어 있을 때만 예외적으로 생성 버튼 노출, 결과는 이 앱 라이브러리에
  저장). 상세 → [[lampas-web-copy]]·[[lampas-web-reels]] 엔티티 페이지.

## 계정간 미션 보내기 (2026-09-19, 같은 세션 후속 요청)
미션 목록·상세에 "계정으로 보내기" 버튼. 받는 사람의 lampas 로그인 이메일을 입력하면 그 계정 소유로
미션이 **복제**된다(이동이 아님 — 보내는 쪽 원본은 그대로 남음). 복제 범위는 미션 행·선별 결과·
에이전트 수집 로그이고, 수집 콘텐츠(클립 등)는 공유 자산이라 참조만 한다. 복제된 미션 파라미터에
보낸 사람 이메일·원본 미션 번호가 기록돼 계보 추적 가능. 이메일 형식 오류·자기 자신에게 보내기는
거부, 미가입 이메일은 명시적 안내로 차단. API `POST /v1/pulse/missions/:id/send`.

## 페르소나 신뢰도 개선 (2026-09-19, 같은 세션 3번째 후속)
당초 "신뢰도 낮음" 배지는 근거 클립 2개 조회수 합을 2~5로 나눈 **고정값**이었음. 사용자 제시 4계층
프레임워크(근거 양·다양성 → 구독자 상한·댓글 검증 등 더 좋은 신호 → 교차 심사 → 실제 성과 피드백)
중 1·2·3번을 구현: 신뢰도를 근거 클립 수·채널 다양성·검증된 타겟 댓글·재관측 횟수·교차 심사
지지도의 가중 합으로 계산(0~100점, 낮음/보통/높음), 다른 벤더 모델(Opus 5, 실패 시 Grok)의 교차
심사가 근거 없는 주장을 플래그, 타겟 반응 댓글은 원문 인용·실제 수집 데이터 검증, 타겟 규모는 근거
채널 구독자 합을 상한으로 잘라냄. **4번(게시 성과 되먹임)은 설계만 하고 미구현**. 이 신뢰도 개선은
**구현·검증까지 끝났으나 배포 여부는 세션 소스에서 확인되지 않음** — 다음 세션에서 배포 확인 필요.
상세 → [[2026-09-19-pulse-페르소나-단일출처-계정이관-신뢰도개선]].
