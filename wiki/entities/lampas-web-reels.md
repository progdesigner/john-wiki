# lampas-web-reels ("Reels", reels.lampas.io)

`[[lampas-studio]]` 저장소(`lampas-system`)의 스포츠 클립 파이프라인 자매 앱. 클립 편집 그룹 보드에서
페르소나·카피를 선택해 편집 그룹을 만들고, 갤러리에 완성된 영상을 Package로 보내는 역할을 한다.
`[[lampas-web-flow]]`의 4·6번째 노드(Reels·Package)가 이 앱을 가리킨다. 이전까지는 다른 엔티티 페이지
안에서 코드체(`lampas-web-reels`)로만 언급됐고 독립 페이지는 없었음 — 이 페이지가 최초 정식 엔티티화
(2026-09-26 ingest, 출처는 여러 날짜의 세션 조각).

## 지워진 클립 복구 — "따로 불러오기" 버튼 (2026-09-12, 옛 SetBoard 위저드 UI 시절)
[[2026-09-12-lampas-copy페르소나-clips분야카테고리-스포츠위키-구축]] 세션이 [[lampas-web-clips]]의
클립/소스 삭제를 하드 삭제→소프트 삭제(`deletedAt`)로 전환하면서(계기 → 아래), 이 앱의
`SetBoard.tsx`/`SetCard.tsx`에 **"뱅크에서 지워진 클립 N개"** 표시 옆에 "따로 불러오기" 버튼을 추가해
`GET /v1/clips?ids=`로 그 정확한 clipId들을 다시 조회하도록 했다.

**계기가 된 조사 결과**: `SetBoard.tsx`의 `clipById` 맵이 "최근 200개 클립(전체 소스 통틀어 최신순)
+ 현재 선택된 소스의 클립 + 우연히 훑어본 폴더의 클립"만 담는 **부분 캐시**라, `!clipById.has(clipId)`로
판정하는 "지워진 클립" 표시가 **실제 삭제 확인이 아니라 추정**이었다 — 오래됐거나 다른 소스의(진짜
삭제되지 않은) 클립도 똑같이 "없음"으로 뜨는 false-positive 메커니즘이 있었다. 클립 목록 자체도
화면 진입 시 한 번만 불러오고 갱신되지 않는 캐시라, 다른 탭(clips.lampas.io)에서 클립을 삭제해도
reels 탭은 여전히 선택 가능한 상태로 남고 서버(`findMany({id:{in:...}})`)가 없는 id를 에러 없이
조용히 드롭해 사용자에게 아무 경고도 없었다. 상세 진단 전체 → 위 세션의 "소프트 삭제 전환" 절.

> **주의 — 이 절이 다루는 UI는 09-18 세션에서 재편되기 전의 옛 위저드 아키텍처다.** 아래 "관찰된
> 기능" 절이 기록한 대로 현재의 6단계 단일화면 플로우는
> [[2026-09-18-lampas-clip-intelligence-brand-kit-대량구현]]에서 `editGroup.ts` 기반으로 다시
> 구현된 것으로 보이며, `SetBoard.tsx`/`minHook` 슬라이더/`filterHookClips`/`clipById` 3종 캐시는 그
> 이전 아키텍처에 속한다. 이 "따로 불러오기" 버튼과 소프트 삭제 대응 로직이 재편 이후에도 동등한
> 형태로 남아있는지는 이 위키 소스만으론 **미확인** — 09-18 세션 상세를 다시 확인하거나 후속 세션
> ingest로 교차 검증 필요.

## 관찰된 기능
- **편집 그룹 생성**: 클립·카피를 선택해 편집 그룹을 만드는 보드. 순수 로직은
  `apps/lampas-web-reels/src/lib/editGroup.ts` — **이 파일과 현재의 단일화면 6단계 플로우(소스 선택→
  클립 선택→페르소나 선택→카피 선택→편집 그룹 생성→목록)는 [[2026-09-18-lampas-clip-intelligence-brand-kit-대량구현]]
  세션의 릴스 UI 단순화에서 최초 구현된 것으로 보인다.** 그 직전엔 AI Clip Intelligence 기반 "AI 선별
  패널"(5축 점수·시간 미겹침 상위 N개 선택·15/30/60/90초 트림·스타일별 훅 문구)과 릴스 자체의 페르소나
  생성 UI가 있었으나, "UI/UX가 너무 복잡해짐"이라는 피드백으로 세트 5개 랜덤 생성·교차 심사·AI
  그룹핑·훅 그룹·폴더 브라우저·페르소나/훅 문구 생성 UI를 전부 제거하고 Copy 앱의 결과를 재사용하는
  현재 구조로 재편했다(서버 세트 API 자체는 남겨둠). "AI 선별로 체크"(클립 선택 단계에서 상위 12개
  일괄 체크)와 "편집 세션 N개 일괄 생성"(선별 결과 배치 편집 세션 생성) 기능은 이 재편 이전 단계에서
  만들어진 AI 선별 패널의 흔적으로 남아 있다. 상세 → [[lampas-clip-intelligence]].
- **Copy 앱 딥링크**(같은 세션 후속): "③ copy에서 페르소나 만들기"·"④ copy에서 카피 만들기" 링크가
  첫 선택 클립(카피 선택 중이면 그 카피의 클립)을 `?clip=<id>`로 실어 [[lampas-web-copy]]를 연다.
  Copy 쪽은 `?clip=`으로 진입하면 그 클립을 1단계에서 미리 선택한 채 시작(페르소나 후보 자동
  로드까지 이어짐), `?run=`이 함께 있으면 run 복원이 우선.
- **페르소나 선택 UI**: 가로 스크롤 카드 스트립 (2026-09-25 밤,
  [[2026-09-25-reels-페르소나-카드스트립-점수정렬]]) — `[[lampas-web-copy]]`의 카드 스트립 디자인을
  그대로 참조. 260px 카드가 오른쪽으로 스냅 스크롤, 카드마다 이름·분야/카테고리 배지·설명 3줄·
  타겟·근거 클립 수 표시, 맨 앞은 "페르소나 없음" 카드. 분야·카테고리별 필터 칩(예 "전체 /
  스포츠·MLB / 스포츠·NBA")으로 목록을 좁히되 이미 선택된 페르소나는 필터와 무관하게 항상 노출.
  선택 시 해당 카드로 스트립 자동 스크롤. **페르소나·카피 점수순 정렬**(같은 세션 후속): API가
  이미 내려주던 `confidence`(신뢰도)·`review`(교차 심사) 값을 그대로 써서 프론트만 수정 —
  페르소나 카드는 신뢰도 내림차순(동일 이름·타겟은 최고점만 남김, 미계산은 맨 뒤 "신뢰도 미계산"),
  카피 run 칩은 최고 점수순("최고 N점" 배지, 첫 칩 자동 선택)으로 정렬. 백엔드 변경 없음.
  - **데이터 출처 이관** (2026-09-19, [[2026-09-19-pulse-페르소나-단일출처-계정이관-신뢰도개선]]):
    이전엔 자체 `suggestPersonas`/`fetchLatestPersonaSet` API로 페르소나를 가져왔으나, Pulse 개편으로
    `fetchPulsePersonas`/`fetchPulseFields`(`[[lampas-web-pulse]]`, `pulse_personas` 테이블)로 교체됨.
    `personaOptions(personas, fields)`가 라이브러리 전체 기준으로 이름+타겟 중복 제거, 클립 범위였던
    `PersonaOption.clipIds`는 `scope` 라벨로 대체. "Pulse에서 페르소나 만들기 ↗" 링크
    (`VITE_PULSE_APP_URL/personas`)가 빈 상태에 추가됨.
- **Package 연동**: 갤러리에 있는 완성 영상을 선택해 [[lampas-web-package]]로 전송 (`[[lampas-web-flow]]`
  6번째 노드). Package 쪽은 2026-09-26 ingest에서 정식 엔티티화됨(이전엔 "소속 미상"으로 기록).
- **Jev 자동 실행과의 연결**(2026-09-20, [[2026-09-20-lampas-flow-만들기]]): Flow의 노드 자동화가
  편집 그룹을 저장하는 과정에서 **카피 연결 정보를 누락**하던 버그가 있었고 수정됨 — Reels 자체
  저장 로직의 결함이 Flow 자동화 검증 중에 드러난 사례.
- **Reels → [[lampas-web-edit]] 세션 생성 오류**(2026-09-19, Reels 0.1.24): Reels가 새 편집 세션을
  만들 때 브랜드킷 **목록 응답 객체를 그대로** `layout.brandKit`에 넣어 보냈는데, 그 응답엔
  `isDefault`·`createdAt`·`updatedAt`처럼 편집 세션 DTO가 허용하지 않는 필드가 섞여 있어 API 검증에서
  거부됐다(사용자에게는 그냥 "오류"로 보임). 세션에 넣기 전에 **스냅샷 필드만 골라 남기도록** 수정 —
  데이터 수정은 필요 없고 재배포 후 재시도만으로 해소됨. → [[2026-09-19-lampas-edit-자막-템플릿-대량기능개발]]
