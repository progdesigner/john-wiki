# lampas-agent (스포츠 클립 에이전트)

`apps/lampas-agent` — `[[lampas-studio]]` 저장소(`lampas-system`) 내 앱. **스포츠 경기 영상을 클립으로
잘라 라벨링·업로드하는 맥미니 로컬 데몬**. 2026-09-25 세션에서 위키에 처음 노출됨.

> ⚠️ **이름 충돌 주의**: 이 "에이전트"는 `[[lampas]]`(하네스에서 코딩·업무를 돕는 Claude 기반 어시스턴트,
> `[[lampas-harness]]`에서 구동)와 **완전히 다른 대상**이다. `lampas-agent`는 `[[lampas-studio]]` 제품군의
> 한 구성 앱(코드명이 우연히 "agent"일 뿐 별도 자동화 프로세스이며, 대화형 AI 어시스턴트가 아니다) —
> 소스 대화에서 "에이전트"라는 말이 두 대상을 가리키며 섞여 쓰이므로 향후 ingest 시 문맥으로 구분할 것.

## 관찰된 구조
- **탭 UI**: Clips · Pulse · Threads · Fixs (2026-09-25 세션 시점, 버전 1.0.28). Threads는 다른 세션이
  같은 날 밤 작업 중이던 기능으로 한때 실수로 함께 빌드됐다가 제거됨(아래 "배포 동시성 함정" 참고).
- **파이프라인**: 라벨링(비전 모델 호출) → (이 세션 이전) 위키 ingest 텍스트 생성·전송 →
  (이 세션 이후) 같은 라벨링 배치에서 경기(game) 구조화 JSON도 함께 추출 → 업로드 뒤 소스 id와 함께
  `lampas-api`의 `sports-wiki` 모듈에 반영.
- **유튜브 영상 수집** — Clips의 원천. `[[lampas-web-flow]]`("Flow")가 Tailscale로 이 데몬을 호출해
  특정 유튜브 URL의 영상 수집을 요청한다(2026-09-20 세션에서 처음 노출). 접속 주소
  `https://lampas-system.tail0e32ab.ts.net/` — 아래 Fixs 절의 `/fixs` 엔드포인트와 같은 호스트.
- **Pulse** — [[lampas-agent]]가 수집한 인기 릴스(캡션·댓글 원문)를 근거로 [[lampas-web-copy]]의
  **페르소나 생성 + SNS 카피 생성·채점**을 담당하는 하위 시스템. 2026-09-20 세션에서 두 번째
  소비처 확인 — [[lampas-web-package]]("새 패키지" 화면)가 같은 페르소나로 릴스 제목·본문·
  해시태그를 자동 작성한다(별도 "톤" 축을 얹어 페르소나와 역할 분리) →
  [[persona-prompt-default-override-audit]].
  - **2026-09-21 선행 수정**(이 위키에 2026-09-26 뒤늦게 ingest — 시점상 아래 09-24 채점 구조 확정보다
    하루 앞선다): "페르소나가 트랜디하지 않다"는 신고로 근거 선정·저장 구조를 고침. 원인 3가지 —
    ① 게시일 없이 **누적 조회수**만 봐서 오래된 고조회수 영상이 최신 트렌드보다 우선됨, ② 모델이
    인용한 **실제 댓글**이 저장 과정에서 사라짐, ③ 페르소나가 하나뿐이면 [[lampas-web-flow]]가 이를
    무시하고 기본 캐릭터로 대체. 수정: 게시일 + 최근 7일 조회수 **증가 속도**를 함께 반영(수집 시점만
    으로 "최신"이라 판단하지 않음), 페르소나에 문장 리듬·훅 구조·카피 예시·피할 표현을 저장해 Copy
    생성·채점까지 전달. 기존 페르소나는 유지되며 새 기준은 재생성해야 적용됨. → [[2026-09-20-lampas-flow-만들기]]
    "Pulse 트렌디 페르소나 근본 개선" 절.
  - **2026-09-24 세션에서 채점 구조 확정**(위 09-21 수정 위에 이어진 것 — 이전엔 "신뢰도 점수 계산
    시스템으로 추정, 상세 미확인" 상태였다가 이 두 세션으로 전모가 드러남):
    - **채점 구조**: 훅 25점(구체적 관찰 15+궁금증·긴장 10) / 이해도 25점(즉시 이해 15+목적 적합성 10) /
      팬층 적합성 25점(욕망·갈등 연결 15+영상 사실 일치 10) / 자연스러움 25점(언어·리듬 15+과장 절제 10),
      항목마다 원문 구절·채점 이유·개선안 표시.
    - **감점 상한 정책이 세션 중 뒤집힘**: 처음엔 "범용 문구·팬층 근거 부족 → 69점 상한"을 도입했다가,
      사용자가 "일반적인 제목이 더 좋아보이는데?"라고 반박해 **철회** — "익숙한 표현"(감점 대상 아님)과
      "근거 없는 빈말/과장"(감점 대상)을 구분하는 게 맞다고 정정. 영상에 없는 사실 주장에 대한 49점
      상한은 유지.
    - 페르소나는 릴스 캡션·댓글 원문을 검증해 팬층의 상황·욕망·갈등·재방문 이유를 정의, 확인 안 된
      해석은 가설로 표시. 조회수÷N 식 "팬덤 인원" 추정 표시는 근거 없다고 판단해 제거.
    - 상세·경위 전체 → [[2026-09-24-pulse-페르소나-카피점수-구조화-개선]]
  - **2026-09-21 "트렌드 분석" Work**: 원본 영상 다운로드 없이 키워드로 수집한 제목·캡션·댓글만

    [[lampas-web-flow]] "트렌드 분석 Work" 절.

## 스포츠 위키 — "경기(game)" 엔티티 (2026-09-25 설계·구현)
`lampas-api`의 `sports-wiki` 모듈은 원래 `player | team` 두 페이지 타입뿐이라 "어떤 선수가 어떤 경기에서
어떤 팀의 승리를 만들었는지"가 구조적으로 쌓일 수 없었다. 진단·설계·구현 전체 과정은
→ [[2026-09-25-스포츠위키-경기엔티티-설계구현]] 참고. 핵심 결론만 요약:

- **역할 분리**: `lampas-agent`(추출, 영상·전사·키프레임을 가진 유일한 주체) vs `lampas-api`(결정적 저장,
  LLM 미사용) vs [[lampas-web-copy]]·`lampas-web-reels`(조회·소비). → 패턴 상세:
  [[deterministic-extraction-vs-llm-rewrite]]
- `POST /v1/sports-wiki/games`로 양 팀·스코어·승리팀·결정적 장면·선수를 저장, 선수/구단 페이지 "최근
  경기" 절은 코드가 병합.
- 실패 가시화: 위키 단계 실패 사유를 체크포인트에 남겨 잡 카드에 경고 표시 + "위키 다시 시도" 버튼.
  `categoryKey` 없는 스포츠 잡은 큐 진입 자체를 차단(`DomainCategoryPicker.tsx`의 카테고리 목록 로드 전
  선택 시 `undefined`가 되어 조용히 skip되던 버그의 재발 방지).

## Fixs 탭 — 최초 신설 (2026-09-21)
Clips·Pulse 옆에 **Fixs**를 신설해달라는 요청으로 시작됨: "apps에서 나는 오류를 자동 수집→Codex가
수정→테스트·빌드 검증→기존 배포 스크립트로 재배포"까지 잇는 구조. 설계 원칙(자동수정/배포 on-off
분리, 별도 worktree 격리+원본 충돌 시 중단, 외부 API 장애는 별도 분류, 오류 로그도 비신뢰 입력으로
취급, 동일 오류 fingerprint 병합으로 무한 재시도 방지, 하루 실행 한도)은 이 앱에 국한되지 않는 일반
패턴이라 별도 정리 → [[self-healing-error-pipeline-design]]. **최초 배포 시 기본값: 자동 수정·자동
배포 모두 활성화, 하루 최대 5회. 테스트 387개 통과.** 기존 앱들의 오류 수집은 이 배포 시점부터
"각 앱의 다음 배포"부터 소급 없이 적용됨. 세션 종료 시점 마지막 질문("모두 배포 했음?")엔 응답 없이
트랜스크립트가 끊겨 실제 최종 배포 확인은 이 소스만으론 불가(후속 세션들이 Fixs를 정상 전제로 다루는
정황으로 볼 때 배포됐을 가능성 높음). → [[2026-09-21-lampas-agent-fixs-신설]]

## Fixs 탭 — 재귀 오류 자동 수집·수정 (2026-09-25 업그레이드)
Fixs는 오류를 수집해 재귀로 자동 수정하는 기능(위 2026-09-21 세션에서 신설). 2026-09-25 하루에만
**서로 다른 세션 2개**가 이 탭을 건드려 v1.0.22 → v1.0.23 → v1.0.25 순으로 배포됐다 — 코딩 도구도
`codex`(오전, 아래 ①②)와 `claude`(저녁, 아래 ③)로 갈렸다.

① **작업 삭제 기능**(v1.0.22, `Tool: codex`) — 대기·완료·실패한 작업은 바로 삭제, **실행 중인 작업은
취소 완료 후에만** 삭제 가능하도록 "작업 삭제" 버튼 추가. 삭제 API 인증·실행 중 삭제 차단·대기열
제거·자동 새로고침 시 재출현 여부까지 검증(테스트 398개). → [[2026-09-25-copy스크롤-fixs삭제-tools모델표시-영상재생버그]]

② **오류 수집 범위 확장**(v1.0.23, `Tool: codex`) — 기존엔 **HTTP 500 이상만** 감지해 [[lampas-web-tools]]
(Tools)의 Kling 생성 거절(HTTP 400)을 놓치고 있었음이 드러남. 400대 응답·네트워크 오류·콘솔 오류까지
수집하도록 확장하고, 웹 프론트 **36개**(33개 재배포 + 3개 소스만 반영)·토스 미니앱 2개(소스만)에
반영 — "전체 프로젝트에 대해" 오류를 Fixs로 보내달라는 요청에 대한 응답. →
[[2026-09-25-copy스크롤-fixs삭제-tools모델표시-영상재생버그]]

③ 이어서 저녁 세션이 경로 그룹핑·Jev 분류를 추가해 v1.0.25(커밋 `900ce062`)로 배포함(아래 절) →
[[2026-09-25-fixs-업그레이드-경로묶음-jev분류]].

- **경로 그룹핑(fingerprint)**: 메시지·스택 안의 uuid·hex·숫자·불투명 토큰·`run_xxx`·번들 해시를
  `:id`/`:hash`로 치환해 비슷한 경로의 오류를 한 건으로 묶는다(`.../prediction/4617ffc8…` →
  `.../prediction/:id`). 리포터가 만든 요청 오류는 스택이 리포터 프레임뿐이라 fingerprint에서 제외.
  데몬 최초 기동 시 기존 레코드 재그룹 — 운영 DB 69건 → 42건. 릴리스가 다르면 여전히 별건 처리.
- **Jev 오류 유형 분류**: 접수된 오류마다 `POST /v1/ai/systemone`에 typed 질문 4개(유형·수정 위치·
  심각도·해결 가능 확률)를 한 번에 질의, 텍스트 생성 없이 구조화 답만 받아 **입력 토큰만 과금**.
  데몬이 5초마다 미분류 1건씩 처리. 상세 → [[jev-typed-classification]].
- 파트너 키가 없어(`AGENT_AI_API_KEY` 비어 있음) `FIXS_AI_API_KEY`에 `[[toktalk]]`의 `talk-api` 운영
  키를 임시로 복사해 사용 중 — `platform.lampas.io`에서 Fixs 전용 키 발급 교체가 후속 과제.
- 접속: `https://lampas-system.tail0e32ab.ts.net/fixs`.

- **[[lampas-web-reels]]**("Reels") — 클립 편집 그룹 보드에서 페르소나·카피를 선택하는 웹.
  `apps/lampas-web-reels/src/lib/editGroup.ts`에 순수 로직. reels.lampas.io. 신뢰도/채점 점수 내림차순
  정렬 기능 보유(2026-09-25 밤 별도 세션, 미정식 ingest — 상세 확인 필요).
- **[[lampas-web-flow]]**("Flow", `flow.lampas.io`) — 위 파이프라인 전체(영상 수집→Clips→Copy→Reels→

  [[lampas-web-flow]] 참고.

## 배포 동시성 함정 (2026-09-25 관찰)
같은 저장소에서 **두 세션이 몇 분 간격으로 같은 앱(`lampas-agent`)을 배포**하면, 빌드 시점의 소스 트리에
상대 세션의 미완료 중간 상태(예: 아직 제거 안 된 실험적 탭)가 섞여 들어갈 수 있다. 07:40 배포는 다른
세션이 아직 지우기 전의 Threads 탭을 포함한 채 빌드됐고, 1분 뒤 그 세션이 소스에서 제거했지만 데몬은
이미 옛 빌드를 서빙 중이었다. 재시작 여부와 무관한 문제이므로 "재시작이 안 됐나?"로 오인하기 쉽다.
어시스턴트 결론: **한 저장소의 배포는 한 세션에서만 수행하는 것이 안전.** → 세션:

## Threads 기능 추가→취소 (2026-09-26)

Fixs 탭 앞에 **Threads 탭**을 추가해 "보관 위키" 데이터를 근거로 SNS(Threads) 글 초안을 자동
생성하고, 사용자가 수정·저장한 글에서 말투·의도(페르소나)를 학습해 다음 글에 반영하는 기능을
요청받아 구현→배포까지 갔다가, **사용자가 전면 취소**했다.

- **데이터 소스 오인 → 정정**: 어시스턴트가 처음엔 "보관 위키"를 이 앱에 이미 연결된 sports-wiki로
  오인해 브라우저 localStorage 저장 방식으로 구현(v1.0.26 배포 전 단계). 사용자가 "llm-wiki"를
  가리켰음을 정정하자, 실제 대상이 `[[john-wiki]]`(`~/Works/john-wiki`, **186개 페이지**)로 확정되고
  저장 방식도 브라우저 로컬 저장 → **서버 DB**(기기/브라우저 무관 이어쓰기, 충돌 검사)로 전환됐다.
  v1.0.26으로 재배포(테스트 437개 통과 후, Clips 위키 코드와 어긋난 기존 테스트를 먼저 갱신).
- **전면 취소**: 곧이어 "Threads 만드는 기능은 취소할게, lampas-agent에서 제거해줘" 지시로 탭 UI +
  API 전체가 삭제되고 v1.0.29로 재배포됨. john-wiki를 "보는" 부분만 살아남아
  `[[lampas-harness]]`의 `apps/wiki`로 이전됨(사람용 위키 브라우저, LLM 기능 아님).
  → 세션: [[2026-09-26-threads기능제거-llm위키탐색기-apps-wiki-이전]]
