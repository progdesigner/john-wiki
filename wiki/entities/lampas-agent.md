# lampas-agent (스포츠 클립 에이전트)

`apps/lampas-agent` — `[[lampas-studio]]` 저장소(`lampas-system`) 내 앱. **스포츠 경기 영상을 클립으로
잘라 라벨링·업로드하는 맥미니 로컬 데몬**. 2026-09-25 세션에서 위키에 처음 노출됨.

> ⚠️ **이름 충돌 주의**: 이 "에이전트"는 `[[lampas]]`(하네스에서 코딩·업무를 돕는 Claude 기반 어시스턴트,
> `[[lampas-harness]]`에서 구동)와 **완전히 다른 대상**이다. `lampas-agent`는 `[[lampas-studio]]` 제품군의
> 한 구성 앱(코드명이 우연히 "agent"일 뿐 별도 자동화 프로세스이며, 대화형 AI 어시스턴트가 아니다) —
> 소스 대화에서 "에이전트"라는 말이 두 대상을 가리키며 섞여 쓰이므로 향후 ingest 시 문맥으로 구분할 것.

## 관찰된 구조
- **탭 UI**: Clips · Pulse · Threads · Fixs (2026-09-25 세션 시점, 버전 1.0.28). Threads는 다른 세션이
  같은 날 밤 작업 중이던 기능으로 한때 실수로 함께 빌드됐다가 제거됨(아래 "배포 동시성 함정" 참고).
- **파이프라인**: 라벨링(비전 모델 호출) → (이 세션 이전) 위키 ingest 텍스트 생성·전송 →
  (이 세션 이후) 같은 라벨링 배치에서 경기(game) 구조화 JSON도 함께 추출 → 업로드 뒤 소스 id와 함께
  `lampas-api`의 `sports-wiki` 모듈에 반영.
- **Pulse** — 페르소나/카피 신뢰도 점수(confidence)를 계산하는 하위 시스템으로 추정(2026-09-25 밤
  별도 세션 `raw/conversations/2026-09-25-reels-페르소나-카드스트립-점수정렬.md`에서 "Pulse 가 계산한
  신뢰도 점수"로 언급됨 — 이 세션은 아직 wiki/sessions로 정식 ingest되지 않은 원본만 존재, 상세 미확인).
- 버전 이력: 1.0.27(2026-09-25 07:40 배포, 경기 엔티티 반영)→1.0.28(같은 날 07:5x경, Threads 탭 제거).

## 스포츠 위키 — "경기(game)" 엔티티 (2026-09-25 설계·구현)
`lampas-api`의 `sports-wiki` 모듈은 원래 `player | team` 두 페이지 타입뿐이라 "어떤 선수가 어떤 경기에서
어떤 팀의 승리를 만들었는지"가 구조적으로 쌓일 수 없었다. 진단·설계·구현 전체 과정은
→ [[2026-09-25-스포츠위키-경기엔티티-설계구현]] 참고. 핵심 결론만 요약:

- **역할 분리**: `lampas-agent`(추출, 영상·전사·키프레임을 가진 유일한 주체) vs `lampas-api`(결정적 저장,
  LLM 미사용) vs [[lampas-web-copy]]·`lampas-web-reels`(조회·소비). → 패턴 상세:
  [[deterministic-extraction-vs-llm-rewrite]]
- `POST /v1/sports-wiki/games`로 양 팀·스코어·승리팀·결정적 장면·선수를 저장, 선수/구단 페이지 "최근
  경기" 절은 코드가 병합.
- 실패 가시화: 위키 단계 실패 사유를 체크포인트에 남겨 잡 카드에 경고 표시 + "위키 다시 시도" 버튼.
  `categoryKey` 없는 스포츠 잡은 큐 진입 자체를 차단(`DomainCategoryPicker.tsx`의 카테고리 목록 로드 전
  선택 시 `undefined`가 되어 조용히 skip되던 버그의 재발 방지).

## 관련 앱 (같은 저장소, 클립 파이프라인 생태계)
- **[[lampas-web-copy]]**("Copy") — 클립 근거로 SNS 카피/페르소나를 생성하는 웹. 2026-09-25 세션에서
  경기 맥락(어느 경기·팀·장면)을 카피 프롬프트 끝에 추가하고 결과 상단에 "이 클립의 경기" 표시 연동.
  reels 앱의 페르소나 선택 UI(가로 스크롤 카드 스트립)가 이 Copy 앱 디자인을 그대로 참조함(같은 날 밤
  별도 세션, `raw/conversations/2026-09-25-reels-페르소나-카드스트립-점수정렬.md` — 미정식 ingest).
- **`lampas-web-reels`**("Reels") — 클립 편집 그룹 보드에서 페르소나·카피를 선택하는 웹.
  `apps/lampas-web-reels/src/lib/editGroup.ts`에 순수 로직. reels.lampas.io. 신뢰도/채점 점수 내림차순
  정렬 기능 보유(2026-09-25 밤 별도 세션, 미정식 ingest — 상세 확인 필요).
- **[[lampas-web-status]]** — 시스템 상태 페이지(`status.lampas.io`), 2026-09-25 세션에서 첫 운영
  배포(테스트 17건). `/v1/status`가 컴포넌트 40개 상태 집계.
- **`lampas-web-admin`** — 관리자 웹, 상태 인시던트 관리 페이지 포함(2026-09-25 재배포분).

## 배포 동시성 함정 (2026-09-25 관찰)
같은 저장소에서 **두 세션이 몇 분 간격으로 같은 앱(`lampas-agent`)을 배포**하면, 빌드 시점의 소스 트리에
상대 세션의 미완료 중간 상태(예: 아직 제거 안 된 실험적 탭)가 섞여 들어갈 수 있다. 07:40 배포는 다른
세션이 아직 지우기 전의 Threads 탭을 포함한 채 빌드됐고, 1분 뒤 그 세션이 소스에서 제거했지만 데몬은
이미 옛 빌드를 서빙 중이었다. 재시작 여부와 무관한 문제이므로 "재시작이 안 됐나?"로 오인하기 쉽다.
어시스턴트 결론: **한 저장소의 배포는 한 세션에서만 수행하는 것이 안전.** → 세션:
