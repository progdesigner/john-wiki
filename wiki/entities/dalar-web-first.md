# dalar-web-first ("First" — AI 돌잔치 인터뷰 영상 서비스)

`[[dalar]]` 제품 라인 소속 앱. 저장소 경로 `apps/dalar-web-first`(같은 `lampas-system` 모노레포,
`[[lampas-studio]]`와 형제 앱) — 경로는
[[2026-09-20-lampas-first-장면가격체계-샘플영상-초대코드]] 세션 본문(가상 아기 프롬프트 기록
경로)에서 직접 확인됨. **이 위키에 이 세션으로 처음 상세 노출**되는 앱으로, 기존 `[[dalar]]`
스텁 페이지가 기록한 6앱(`dalar-web-root/www/cs/app/admin`, `dalar-api`) 목록에 없던 **7번째
Dalar 앱**이다.

- **고객 화면**: `first.dalar.ai` — 아기 인터뷰 형식 세로(9:16) AI 생성 돌잔치 영상 제작·주문.
- **관리자**: `admin.first.dalar.ai` — `/scripts`(대본 편집), `/samples`(공개 샘플 영상 선택),
  `/rewards`(사용자별 초대코드·발급 쿠폰 조회).
- **결제**: 전용 앱이 아니라 `lampas-web-pay`(`pay.lampas.io`) 안에 First 전용 경로로 통합 —
  처음엔 쿼리스트링(`pay.lampas.io/?service=dalar&first=1`)이었다가 이 세션 후반에 정식 라우트
  `pay.lampas.io/first`로 분리됨(아래 "Pay 분리" 절).
- **모순 기록 — AGENTS.md 누락**: 이 세션 시스템 프롬프트에 포함된 `AGENTS.md` 전문(작업폴더
  `lampas-system`, 2026-09-20 시점)에는 **Dalar 앱이 단 하나도 열거되지 않는다**(Lampas 9앱+
  Talk 9앱+Iileex만 있음). 반면 [[2026-09-21-lampas-agent-fixs-신설]] 세션(하루 뒤)의 `AGENTS.md`는
  Dalar 6앱을 포함한다. 즉 **같은 저장소의 `AGENTS.md`가 하루 사이 버전이 다르거나, 이 세션의
  프롬프트가 구버전을 인용**했을 가능성 — `dalar-web-first` 자체도 두 버전 모두에 없어, 문서가
  실제 앱 목록을 상시 못 따라가는 기존 관찰([[lampas-studio]] "구조 괴리" 절)이 다시 확인됨.

### 장면 수 구조적 확장 (6→12)
사용자 제보: "10컷으로 나눴을 때 대사가 점점 빨라졌다." 원인은 `first.worker.ts`가 시나리오
전체를 **한 번의 LLM 호출**로 받는 구조라, 출력 토큰 예산
(`scenarioMaxTokens = min(6000, 1500+sceneCount*450)`)이 `sceneCount=10`에서 정확히 상한
(6000)에 걸려 뒤쪽 씬일수록 남은 예산이 줄어드는 것이었다(연출 문제가 아니라 **토큰 예산
압박**). 씬 수 하드캡도 서비스 메서드 3곳(`actors.service.ts`)에 흩어져 있었다.
"캡·상한 숫자만 올리는 땜빵" 대신 **구조적 해결**을 선택 — 개요(outline) 1회 + 씬마다 독립
호출(`generateStudioScenarioOutline`+`generateStudioScenarioScene`, 씬당 고정 900토큰)로 전환해,
씬이 몇 개든 마지막 씬도 첫 씬과 동일한 예산을 받도록 함. 씬 수 상한을 공유 상수
`SCENARIO_MAX_SCENES`(10→12) 하나로 통일. `lampas-api` 전체 테스트 800개 통과 후 배포(v0.1.79).
→ 절차를 일반화한 스킬 [[llm-per-item-generation-budget]] 참고(이 사건이 원 사례).

### 영상 비율 9:16 전환 + Seedance 2.5 + 텍스트/파라미터 불일치 버그
씬 이미지 생성 API에는 `aspectRatio` 파라미터가 정확히 전달되는데, **같은 요청의 프롬프트
텍스트 지시문**(`orientationHint`/`studioAspectRatioDirective`)이 1:1·3:2 두 값만 명시적으로
처리하고 나머지 7개(16:9 포함)는 전부 "2:3 세로 프레이밍"으로 잘못 안내하는 버그를 조사 중
발견(파라미터와 텍스트 지시가 모순). 사용자 요청("영상 비율 9:16, 모델 시댄스 2.5")에 맞춰
씬 이미지 `aspectRatio: "16:9"→"9:16"`, 영상 모델 `bytedance/seedance-2.5/image-to-video`
추가, ffmpeg 렌더 캔버스 `1280x720→720x1280`으로 함께 수정, 위 텍스트/파라미터 불일치 버그도
`describeStudioAspectRatio` 순수 함수로 일반화해 동시에 고침(퍼스트 모듈 외 다른 곳에도 영향
있던 버그). `lampas-api` v0.1.80 배포.

### admin.first.dalar.ai 서브도메인 — AWS IAM 권한 부재로 1차 중단
`*.first.dalar.ai`(2단계 서브도메인) 커버 ACM 인증서가 필요했으나, IAM 계정 `elevino`에
`acm:RequestCertificate` 권한이 없어 인증서 발급이 막힘(기존 `*.dalar.ai` 인증서는 1단계까지만
커버). 사용자가 권한을 열어준 뒤 재시도로 인증서 발급→DNS 검증→CloudFront 별칭 추가→Route53
레코드까지 완료. `admin.first.dalar.ai`는 `first.dalar.ai`와 **완전히 같은 SPA 번들**(같은
CloudFront 배포)이라 호스트명 분기(`window.location.hostname === "admin.first.dalar.ai"`)로만
관리자 화면이 뜨는 구조 — 이후 `dalar-web-first` 배포 시 둘 다 자동 갱신됨.

### 결제 50,000크레딧과 실제 벤더 비용의 완전 분리 확인
조사 결과: `first.worker.ts`가 호출하는 시나리오/이미지/영상 생성 4종
(`generateStudioScenarioOutline`/`generateStudioScenarioScene`/`generateStudioReferenceShotFromPrompt`/
`atlas.startImageToVideo`) 전부 `deductUsageCredits()`를 거치지 않는다 — DTO 자체에 `userId`
필드조차 없다. 즉 **최초 50,000크레딧 결제는 1회성 정액 요금이고, 실제 AtlasCloud/LLM 벤더
비용은 사용자 크레딧 원장과 완전히 분리**(회사가 부담)돼 있으며, 재생성도 추가 차감이 없다.
동시에 지적된 부작용: 벤더 비용이 `AiUsageRecord`(사용량 원장)에 전혀 남지 않아 재생성 횟수·
씬 수 증가에 따른 실제 원가 증가가 시스템상 보이지 않고 상한도 없었다 — 이후 "실제 사용 크레딧
(추정)" admin 패널(아래)로 보완됨.

### 인터뷰 대본 + 컷별 TTS 나레이션 파이프라인 — 빌드 후 전면 제거
`lampas-web-scenario` 스타일의 고정 12컷 인터뷰 대본(자막·인터뷰어 질문·아기 대사, `{NAME}`
치환)과 컷별 TTS 나레이션을 요구하는 대규모 기능 요청. 3개 조사 에이전트(admin/first 백엔드,
레퍼런스시트/보이스/TTS 백엔드, lampas-web-scenario UI) 병렬 조사 → 설계 에이전트로 상세
구현 계획 수립 → 구현·배포까지 완료했다가, **곧이어 전면 제거**됐다.

- **빌드된 것**(`lampas-api` v0.1.81): 고정 대본 상수(`FIRST_INTERVIEW_SCRIPT_TEMPLATE`), 카메라
  고정 후처리(`lockMotionPrompt`), 컷별 독립 TTS 나레이션(무과금 `AiService.generateAudio`를
  `AiGatewayUser` 없이 직접 호출 — 이 모듈 전체의 "사용자 과금 안 함" 불변식 유지)로 실측 길이
  확정 후 9:16 이미지→Seedance 2.5→ffmpeg 렌더(영상 자체 오디오 0.25 덕킹+나레이션 믹스),
  관리자 컷 편집 API 5종(필드별 잠금 — 사람이 고친 필드는 재생성이 덮어쓰지 않음, 영상이
  바뀌면 DELIVERED 주문도 GENERATING으로 되돌려 워커가 재렌더).
- **대표 음성 도입**: 주문마다 다른 음성이 나오는 문제 해결로 여아=Gemini `Aoede`, 남아=`Puck`,

- **제거 계기**: 사용자가 "lampas-web-scenario 세션 7 영상이 이 보이스를 썼나?"라고 질문 →
  조사 결과 세션 7은 **TTS를 거의 쓰지 않고 Seedance 자체 오디오**(`generate_audio: true`,
  대사는 프롬프트 텍스트로만 전달)로 만들어졌음이 드러남. 사용자가 "필요 없으니 제거" 지시.
- **제거 범위**: `dalar-web-first`/`lampas-api`에서 나레이션·오디오 믹스·줄별 음성 API·대표
  음성·성별 선택 전부 삭제(`childGender` 컬럼은 배포 후 DROP SQL 준비), **동시에**
  `lampas-web-scenario`도 포크 에이전트로 `VoicePicker`/`voice-api.ts` 등 보이스/TTS 기능
  전면 제거(대사 텍스트·감정은 유지) → 상세는 [[lampas-web-scenario]] 참고. 대사는 이후
  web-scenario와 동일한 방식(화자별로 영상 프롬프트에 텍스트 삽입 + 카메라 고정)으로 통일.
- 결제 후 개요 생성 전에 **배경(인터뷰 세트, 사람 없음) → 인터뷰어(마이크 든 손, 얼굴 없음)**
  레퍼런스 이미지를 미리 만들어 개요·컷 이미지 생성 양쪽의 공통 참조로 사용하는 것도 이 시기에
  추가(공간·손 일관성 목적) — admin 주문 화면에 "공통 레퍼런스" 블록으로 노출.

### AtlasCloud 실비용 vs 결제 크레딧 원가 조사 + 대응
lampas-web-scenario 세션 7은 컷당 10~13초라 Seedance 비용이 컷당 ~$1.3~1.7인데, 실사용 주문
`b0385933…`은 컷 길이가 20~30초(대본에 대사가 몰려 LLM 추정치보다 실제 발화가 길어서 실측
보정된 결과)까지 늘어나 컷당 비용이 2~3배로 커진 것을 확인. **사용자 결정**: 컷 길이 상한
유지·대본 유지, **해상도만 480p로 낮춰 원가 절감**, 영상 비율(9:16 세로/16:9 가로)을 주문
시점에 선택하는 기능도 함께 추가(`first_orders.aspectRatio`, 제작 시작 후 변경 불가).

**AtlasCloud 잔액 부족(402) 실사고**: 위와 별개로, 대사가 몰려 컷 길이가 20~30초로 길어진
주문 `b0385933…`의 12번째(마지막) 컷 영상 제출 시점에 계정 잔액이 소진돼 FAILED. 자동
재시도 3회도 같은 402라 소진. 이미 제출된 11개 영상을 버리지 않도록 "완료 판정을 1시간
타임아웃보다 먼저 확인"하는 수정을 긴급 배포(잔액 충전 지연 시 11개를 다시 만들어 ~$40 추가
지출되는 것을 방지).

### 배경 이미지가 첨부 사진을 안 쓰던 문제 → 수정
사용자 확인 질문("배경 이미지, 첨부 사진 기반 맞아?")에 **아니오**로 답변(당시엔 배경·인터뷰어
이미지 모두 텍스트 프롬프트만으로 생성, 첨부 사진은 컷 이미지 생성에만 참조로 들어감) — 이때는
수정하지 않고 확인만 요청받은 대로 답변. 다음 요청에서 실제 수정: 배경 이미지가 **업로드 사진
최대 4장을 참조로 받아 "그 방을 사람 없이 재구성"**하도록 프롬프트·참조이미지 변경, 공통
styleGuide도 "가족의 실제 집, 다른 세트를 지어내지 말 것"으로 일반화. 레퍼런스 시트는 이미
첨부 사진 배경을 유지하는 프롬프트라 변경 불필요했음을 확인.

### 대본 재배분 + 컷 길이 30초 상한
주문 `23927984…`에서 10번 컷에 대사 11줄(139자, 실제 발화 ~37초)이 몰려 LLM이 15초로 짧게
추정한 탓에 급해진 문제, 그리고 대사가 아예 없는 12번(엔딩 자막) 컷을 지적받음. 대본 마지막
3컷(10/11/12)이 이름을 부르며 끝나도록 재배분(엔딩 자막 컷 제거), `estimateLinesSeconds`
(4.5자/초+줄당 0.5초+1초) 기반 **컷 길이 = max(LLM 추정, 대사 길이 추정)**을 개요·컷 상세·
관리자 재생성 전 경로에 적용해 재발 방지, 대본 템플릿의 모든 컷 발화 추정이 30초(Seedance
상한) 이하인지 검사하는 테스트 추가. 이후 별도 요청으로 **컷 길이 30초 하드캡**을 개요 산정·
컷 상세 병합·관리자 PATCH(`@Max(30)`)·대사 길이 추정 전 경로에 일괄 적용.

### admin.first.dalar.ai 전면 개편 — 탭별 URL 분리, CS·크레딧 관리 추가
"CS 대응도 되고 크레딧도 지급할 수 있게" 요청으로 관리자 화면을 3구조로 재편(탭 전환마다 주소
변경):
1. `/users` — 사용자 정보·보유 크레딧·주문 수, **크레딧 수동 지급/차감**(사유 입력,
   `POST admin/users/:id/credits`) + 변동 내역 + 해당 사용자 주문 목록.
2. `/orders` → `/orders/:id` — 주문·결제·원가(추정) 목록, 클릭 시 에디터로 이동(주소 변경),
   "최종 영상 편집(컷 합치기)" 버튼 추가.
3. `/cs` → `/cs/:id` — `first.dalar.ai`(`service=dalar-first`)에서 들어온 문의만 필터링,
   대화 내역·이미지, 답변 전송(Ctrl/⌘+Enter), 종료/재오픈. 기존 `lampas-web-admin`이 쓰는
   동일 CS API를 재사용·확장(`admin/cs`에 `close`·`reopen`·`?service=` 필터 추가).

**1회차 이후 수동 편집 모드**: 첫 회차는 기존대로 자동 합본·제공. 제공이 끝나면 주문이
`manual`로 전환되어, 이후 컷을 다시 손대도(콘티/이미지/영상 재생성) **기존 완성 영상은 그대로
유지**되고 자동으로 다시 합쳐지지 않는다("컷 준비 완료·최종 편집 대기" 상태). 관리자가 "최종
영상 편집"을 눌러야 같은 회차로 다시 제공(구매 확정 기한 갱신). 주문 단위 "재생성 및 고객
재제공"(새 회차, 전체 재생성)은 그대로 유지.

### 회차별 제작 소요 시간 + 이전 영상 보관 + CDN 캐시 버그
- **회차별 시간 기록**(`rounds[]`): 1회차=결제 시각→최종 영상 업로드, 2회차 이후=컷 수정 시작
  (콘티/이미지/영상 재생성 또는 "최종 편집" 요청) 시각→재업로드 시각. admin 주문 상세에 회차별
  표+누적 시간, 진행 중 회차는 실시간 타이머. **버그 1차**: 컷 생성이 끝나 "최종 편집 대기"로
  멈춘(진행 중이 아닌) 상태가 되면 화면이 현재 회차 행을 숨겨 "기록이 사라진 것처럼" 보임(백엔드
  데이터는 유지되고 있었음) → 진행 중 회차는 제공될 때까지 항상 표시하도록 수정, 편집 대기
  시간도 그 회차 소요에 포함.
- **이전 최종 영상 보관**(`progress.films` 누적): 제공할 때마다 영상 URL·시각·회차를 누적, 같은
  회차를 다시 합쳐 덮어써도 이전 영상 URL은 남음(S3는 원래 안 지움). admin "제공 이력"·고객
  "이전에 제공된 영상 N개" 접이식 목록으로 노출.
- **CDN 캐시 버그**: 최종 영상이 매번 **같은 S3 키**(`first/{주문}/{회차}/film.mp4`)에
  덮어써지고 있었는데, CloudFront가 첫 렌더를 계속 캐시해 서빙 — "12번째 영상이 다르다"는
  사용자 제보로 발견(`last-modified`/`x-cache: Hit`/`age` 헤더로 확진). 같은 이유로 "이전 회차
  영상 보관" 기능도 URL이 전부 동일해 실제로는 덮어써지고 있었다. **수정**: 렌더마다 새 키
  (`film-{시각}-{id}.mp4`)를 쓰도록 변경 — 이후로는 캐시 문제가 없고 보관 기능도 실제 파일이
  남아 정상 동작. → 절차를 일반화한 스킬 [[cdn-versioned-key-per-render]] 참고(이 사건이 원 사례).

## 서버 워커 복구 — "페이지 닫아도 계속된다"는데 실제로는 안 됨

사용자 제보로 조사한 결과, 서버 워커 자체는 이미 존재했으나 두 가지 결함이 있었다:

1. **콘티 개요 생성 직전 진행 정보를 덮어쓰는 버그** — 오류 발생 시 이미 만든 배경·참조 자산까지
   재생성되는 낭비 발생.
2. **영상 재시도 횟수가 새 요청 시작 시 초기화될 여지** — 무한 재시도로 이어질 수 있는 경로.

**수정**: 저장된 완료 상태를 기준으로 각 단계를 순차 실행하도록 변경(앞 컷 영상 완료 후에만 다음
컷 시작), 서버 재시작 시 저장된 영상 작업 ID로 결과 조회를 이어감. **관리자 재생성 요청도** 이전엔
즉시 처리(서버 재시작과 겹치면 끊김)였던 것을 **먼저 서버에 작업으로 저장 → 워커가 실행**하는
동일 경로로 통합(2026-09-20 세션 후반). 자동 재시도 후 실패한 주문은 **추가 차감 없이 이어서
제작하는 관리자 복구 버튼** 추가.

- **Jev 세 번째 확인 사용처** — 오류가 나면 Jev(`[[jev-typed-classification]]` 참고)가
  "재시도·대기·관리자 확인"을 판단. Jev 연결 자체가 실패하면 서버 기본 복구 규칙으로 대체.
  외부 생성 요청이 접수됐는지 불명확한 경우(중복 제작비 발생 위험)엔 자동 판단 대신 **관리자
  확인으로 에스컬레이션**. 기존 sports-wiki ingest 게이트·`lampas-agent` Fixs 오류 triage에 이은
  Jev 패턴의 세 번째 독립 사용처.

## 장면 간 톤 일관성 — 레퍼런스 고정 절차

문제 제기: "이미지 생성 시 콘티마다 톤이 달라진다, 한 번에 찍은 것처럼 보이게".

- **원인**: 원본 사진을 "레퍼런스 이미지"로만 전달하고, 정작 **첫 컷을 촬영 기준으로 못 박지
  않아** 이후 컷에서 머리 장식·마이크 크기·카메라 위치·배경 구도가 흔들림.
- **1차 수정**: 원본 사진은 "인물 확인용"으로만 쓰고, **첫 장면을 촬영 기준(외형·조명·의상·
  카메라 구도)으로 명확히 고정**. 자동 생성·관리자 재생성 모두 동일 기준 적용.
- **2차 수정(검수 중 재발 발견)**: 8장면 샘플의 한 컷에서 대본에 없는 배경 소품(선반 장식→
  이후 숟가락)이 반복 등장 — 원인은 **기준 장면 + 여러 보조 참고 이미지가 충돌**하는 것.
  → **기준 장면 + 직전 장면 두 개만 참고**하도록 축소해 재발 방지. 표정·빈손 자세만 지시하는
  식으로 프롬프트도 단순화.
- 절차 스킬 → [[scene-reference-lock-visual-consistency]].

## 가상 인물 샘플 4편 (2026-09-20~09-22 제작, 09-22 추가 4편 재제작)

`image_gen` 스킬로 **한국인 가상 아기 4명**(남아 2·여아 2) 원본 사진 제작 → 4·6·8·12장면
각각에 배정(1차: 남아 4·8장면, 여아 6·12장면)해 실제 제작 워커로 세로 샘플 영상 4편 생성.
전용 테스트 계정을 만들어 잔액을 충전하고 정상 결제 API로 주문을 넣어 실사용 흐름 그대로
검증. 사이트에는 AI로 만든 가상 인물임을 표시.

- **실제 재생 길이(1차 세트)**: 4장면 ≈43초 · 6장면 ≈1분13초 · 8장면 ≈1분29초 · 12장면 ≈3분58초
  — 모두 720×1280 세로, 음성 트랙 포함.
- 장면 연결성(색감·인물·의상·배경·카메라) 검사를 인접 이미지 쌍 단위로 수행 — 1차 세트는
  26쌍, 2026-09-22 재제작분은 30개 장면 전량 비교.
- **First Collection 커버플로우**: 가운데 영상이 크게 보이는 형태로 복원, 4편 모두 **사전 로드**
  (버튼 클릭 시점이 아니라). 가운데 영상 무음 자동재생, 소리는 컨트롤에서 켤 수 있었으나 이후
  요청으로 **네이티브 컨트롤 자체를 숨겨 영상만 노출**. 옆 카드를 덮는 투명 호버 버튼이 공통
  호버 배경색을 상속해 영상을 가리던 버그 수정, 배경을 밝은 크림색으로 바꿔 영상 옆 검은
  여백 제거, 반복 넘김 시 대기 카드가 앞을 가로지르지 않고 **카드 더미 맨 뒤로 이동**하도록 수정.
  가격표 하단 샘플은 처음엔 "샘플 재생" 버튼+썸네일(클릭 시 즉시 로드·재생)이었다가, 이후
  버튼 텍스트 없이 **중앙 재생 아이콘만** 남기는 것으로 정리.
- **2026-09-22 세트 추가**: "5만원부터 20만원까지 한 번씩 더 만들어줘" 요청으로 4·6·8·12장면
  샘플을 각 1편씩 재제작(관리자에서 신·구 샘플 모두 선택 가능하도록 유지). 이 세트 제작 중
  8장면 한 이미지에 장난감이 등장했는데 **대본에 명시된 "장난감을 입으로 확인하는" 행동과
  일치**해 의도된 소품으로 판정·통과시킨 사례 있음(자동 검토 알람을 사람이 원본 대본과 대조해
  기각한 예).
- **6장면 재생성(2026-09-24)**: 사용자가 "인터뷰어가 다른 샘플과 비슷하면 좋겠다, 너무 어색해"
  라고 지적 → 과장된 억양·늘어지는 말끝을 줄이고 다른 세 샘플과 같은 차분한 진행자 말투로
  재생성. 이전 완성본은 보관하고 관리자에서 신·구 버전 모두 선택 가능하도록 보강.
- **관리자 샘플 관리**(`admin.first.dalar.ai/samples`): 가격대별로 완성 주문 영상 중 하나를
  골라 "공개 샘플로 저장". 교체돼도 이전 영상은 계속 선택 목록에 남음(완전 대체 아님).

## 여성 인터뷰어 음성 버그

이 절의 "음성"은 위 09-14 세션에서 전면 제거된 TTS 나레이션이 아니라, **Seedance가 대사
텍스트 프롬프트를 읽고 자체 생성하는 오디오**를 가리킨다(09-14 세션에서 TTS를 걷어낸 뒤의
상태를 전제). 사용자 제보 "여자 아나운서로 특정했는데 자꾸 남자 목소리로 바뀐다". 원인: 실제
영상 생성 프롬프트에는 화자가 단순히 "인터뷰어"로만 전달되고 여성 아나운서 지정이 누락돼 있었음.
**공통 음성 지시(여성 아나운서)가 장면별 개별 지시보다 우선**하도록 수정. 문제 장면 3곳
(6장면 4번째, 8장면 3·6번째)을 찾아 재생성. 이후 QA 절차에 **질문이 있는 모든 장면의 인터뷰어
음성 성별 확인**이 정식 항목으로 추가됨(1차 세트 23개 질문 장면 전수 검사).

## Package 연동

완성된 First 영상을 "Package" 앱(별도 콘텐츠 등록·릴스 채널 게시 도구, 이 세션 소스로는
소속 미상)으로 보내 등록하는 버튼 추가. 영상·제목을 미리 채우고 릴스 채널을 선택하도록 연결,
실제 등록까지 확인(테스트 패키지는 초안 저장, 외부 게시는 하지 않음).

**2026-09-26 ingest 정정**: 위 "소속 미상"은 이 세션 소스만으로는 확인 불가했던 것이고,
2026-09-20 별도 세션([[2026-09-20-lampas-package-pulse페르소나-릴스자동작성-톤선택]])에서
Package 앱이 같은 `lampas-system` 저장소 소속이며 `package.lampas.io`에 배포돼 있음이
확인됨 → 정식 엔티티 [[lampas-web-package]] 참고.

**2026-09-26 후속 세션 — 스포츠 전용 규칙 일반화**: 위 첫 연동은 잘 됐으나, Package의 AI 작성
규칙이 스포츠 클립 파이프라인에서 굳어진 "하이라이트 소개 + 시청 안내" 고정 문체였던 탓에
First 샘플을 올려도 "너무 스포츠 느낌"이 나는 문제가 [[2026-09-26-package-분야별템플릿-first도메인확정-배포]]
세션에서 발견·수정됨. First·뷰티·푸드·교육·스포츠 5개 분야 템플릿(+직접 입력)으로 일반화되고,
관리자 샘플 화면(`admin.first.dalar.ai/samples`)의 "Package로 보내기"가 영상·장면 수를 전달해
돌잔치 영상용 설정·제목·본문(수정 가능)·제작 링크를 미리 채우도록 개선됨. 이 세션에서 Package
쪽이 First 실체를 직접 재조사해 "아기 사진으로 돌잔치 영상을 만드는 서비스"임을 재확인(한 차례
"반려동물 AI 영상"으로 오판했다가 정정). 상세는 [[lampas-web-package]] "분야별 템플릿화" 절.

**제작 링크 도메인 확정**: 같은 세션에서 제작 링크 후보로 `first.lampas.io`가 언급됐으나 DNS
미연결로 확인되고, 기존 운영 도메인인 **`first.dalar.ai`로 최종 확정**(사용자가 세션 끝에
"`first.lampas.io`는 잘못 말한 것"이라 직접 정정) — 이 페이지 위쪽에 기록된 `first.dalar.ai`
단일 운영 도메인 사실과 모순 없이 재확인됨.

## Pay 분리(`lampas-web-pay`)

기존엔 `pay.lampas.io` 기본 진입 화면에 First 상품까지 섞여 나왔다. 요청("`pay.lampas.io`로
바로 들어갔을 땐 예전처럼 크레딧만, First 통해 갔을 때만 다르게")에 따라:

- **`pay.lampas.io/`**: 크레딧 충전 상품만 표시(기존 동작 복원).
- **`pay.lampas.io/first`**: 장면별 제작비·할인 쿠폰만 표시, **크레딧 표시는 보조 정보로 최소화
  하고 총 구매 금액(N만원)을 강조**. First의 결제 버튼이 이 경로로 연결되도록 변경(기존
  `?service=dalar&first=1` 쿼리스트링 진입도 계속 동작).
- 결제 성공/실패 복귀 경로, 쿠폰 적용 흐름 모두 분리 후에도 유지 확인.
