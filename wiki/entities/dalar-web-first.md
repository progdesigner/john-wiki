# dalar-web-first ("First" — AI 돌잔치 인터뷰 영상 서비스)

`[[dalar]]` 제품 라인 소속 앱. 저장소 경로 `apps/dalar-web-first`(같은 `lampas-system` 모노레포,
`[[lampas-studio]]`와 형제 앱) — 경로는
[[2026-09-20-lampas-first-장면가격체계-샘플영상-초대코드]] 세션 본문(가상 아기 프롬프트 기록
경로)에서 직접 확인됨. **이 위키에 이 세션으로 처음 상세 노출**되는 앱으로, 기존 `[[dalar]]`
스텁 페이지가 기록한 6앱(`dalar-web-root/www/cs/app/admin`, `dalar-api`) 목록에 없던 **7번째
Dalar 앱**이다.

- **고객 화면**: `first.dalar.ai` — 아기 인터뷰 형식 세로(9:16) AI 생성 돌잔치 영상 제작·주문.
- **관리자**: `admin.first.dalar.ai` — `/scripts`(대본 편집), `/samples`(공개 샘플 영상 선택),
  `/rewards`(사용자별 초대코드·발급 쿠폰 조회).
- **결제**: 전용 앱이 아니라 `lampas-web-pay`(`pay.lampas.io`) 안에 First 전용 경로로 통합 —
  처음엔 쿼리스트링(`pay.lampas.io/?service=dalar&first=1`)이었다가 이 세션 후반에 정식 라우트
  `pay.lampas.io/first`로 분리됨(아래 "Pay 분리" 절).
- **모순 기록 — AGENTS.md 누락**: 이 세션 시스템 프롬프트에 포함된 `AGENTS.md` 전문(작업폴더
  `lampas-system`, 2026-09-20 시점)에는 **Dalar 앱이 단 하나도 열거되지 않는다**(Lampas 9앱+
  Talk 9앱+Iileex만 있음). 반면 [[2026-09-21-lampas-agent-fixs-신설]] 세션(하루 뒤)의 `AGENTS.md`는
  Dalar 6앱을 포함한다. 즉 **같은 저장소의 `AGENTS.md`가 하루 사이 버전이 다르거나, 이 세션의
  프롬프트가 구버전을 인용**했을 가능성 — `dalar-web-first` 자체도 두 버전 모두에 없어, 문서가
  실제 앱 목록을 상시 못 따라가는 기존 관찰([[lampas-studio]] "구조 괴리" 절)이 다시 확인됨.

## 장면 수 선택 + 가격 체계 (여러 차례 개정)

**콘티 → "장면" 개명**: 사용자 요청으로 고객 화면의 전 용어를 "콘티"에서 "**장면**"으로 교체
(선택 카드·제작 버튼 "N장면"·"N장면 제작 시작", 관리자 내부 명칭은 유지 추정).

- **선택지 4종**: 4·6·8·12장면, 기존 대본을 바탕으로 각 길이에 맞춰 별도 대본 생성. 관리자
  `/scripts`에서 각 대본을 개별 편집 가능. 주문마다 선택 시점의 대본·가격을 스냅샷 저장해
  이후 관리자 수정이 기존 주문에 영향 없음.
- **마케팅 카피**: 12장면 = "돌잔치 영상의 완성"("첫 인사부터 감사 인사까지, 우리 아이의 첫해를
  한 편에"), 8장면 = **"추천" 배지**.
- **선택 UI**: 라디오 버튼 → **박스형 단일행 선택**(줄바꿈 없이 4개 한 줄, 모바일 320px까지
  유지 확인)으로 교체. 가격 카드 4개는 모두 **동일 높이**(12장면 기준)로 맞추고 제작 버튼은
  카드 하단 정렬, 샘플 영상은 접힘 없이 기본 펼침.

### 가격 변천 (2026-09-20 → 09-22, 세 단계)
1. **최초**: 제작비 5/10/15/20만원(내부 명칭), 실제 결제 = 제작비+VAT = **5.5/11/16.5/22만원**.
   내부 적립 크레딧은 25,000/50,000/75,000/100,000(20만원=100,000크레딧, 2026-09-21 사용자
   확인 질문에 대한 답변으로 재확인). 버튼 문구를 "5만원 제작 시작"에서 **"4콘티 제작 시작"**
   형식으로 교체.
2. **크레딧 언어 전면 제거**: "크레딧 얘기는 전부 제거해줘 헷갈리니까"는 사용자 명시 지시.
   고객 화면·Pay 복귀 화면 모두 크레딧 잔액·적립 문구 숨김, 내부 회계에서만 크레딧 계속 사용.
3. **2026-09-22 재조정**: "가격을 부가세 포함으로, 5만원으로 부가세포함 딱 떨어지게" 요청 →
   **결제액 자체를 VAT 포함 5/10/15/20만원**(정수)으로 재설정. **지급 크레딧은 기존
   25,000/50,000/75,000/100,000 그대로 유지**(사용자 명시 지시 "크레딧은 기존 그대로 주고").
   → **미해결 사실 관계**: 이 3단계 재조정 이후 아래 "쿠폰" 절의 50% 할인 금액이 다시 계산됐는지
   이 세션 소스로는 확인 불가. 쿠폰 절이 인용하는 27,500/55,000/82,500/110,000원은 **2단계
   기준(VAT 포함 5.5/11/16.5/22만원의 절반)**이며, 3단계(정수 5/10/15/20만원) 적용 후의 실제
   절반가는 이 세션 이후 재확인 필요.

## 서버 워커 복구 — "페이지 닫아도 계속된다"는데 실제로는 안 됨

사용자 제보로 조사한 결과, 서버 워커 자체는 이미 존재했으나 두 가지 결함이 있었다:

1. **콘티 개요 생성 직전 진행 정보를 덮어쓰는 버그** — 오류 발생 시 이미 만든 배경·참조 자산까지
   재생성되는 낭비 발생.
2. **영상 재시도 횟수가 새 요청 시작 시 초기화될 여지** — 무한 재시도로 이어질 수 있는 경로.

**수정**: 저장된 완료 상태를 기준으로 각 단계를 순차 실행하도록 변경(앞 컷 영상 완료 후에만 다음
컷 시작), 서버 재시작 시 저장된 영상 작업 ID로 결과 조회를 이어감. **관리자 재생성 요청도** 이전엔
즉시 처리(서버 재시작과 겹치면 끊김)였던 것을 **먼저 서버에 작업으로 저장 → 워커가 실행**하는
동일 경로로 통합(2026-09-20 세션 후반). 자동 재시도 후 실패한 주문은 **추가 차감 없이 이어서
제작하는 관리자 복구 버튼** 추가.

- **Jev 세 번째 확인 사용처** — 오류가 나면 Jev(`[[jev-typed-classification]]` 참고)가
  "재시도·대기·관리자 확인"을 판단. Jev 연결 자체가 실패하면 서버 기본 복구 규칙으로 대체.
  외부 생성 요청이 접수됐는지 불명확한 경우(중복 제작비 발생 위험)엔 자동 판단 대신 **관리자
  확인으로 에스컬레이션**. 기존 sports-wiki ingest 게이트·`lampas-agent` Fixs 오류 triage에 이은
  Jev 패턴의 세 번째 독립 사용처.

## 장면 간 톤 일관성 — 레퍼런스 고정 절차

문제 제기: "이미지 생성 시 콘티마다 톤이 달라진다, 한 번에 찍은 것처럼 보이게".

- **원인**: 원본 사진을 "레퍼런스 이미지"로만 전달하고, 정작 **첫 컷을 촬영 기준으로 못 박지
  않아** 이후 컷에서 머리 장식·마이크 크기·카메라 위치·배경 구도가 흔들림.
- **1차 수정**: 원본 사진은 "인물 확인용"으로만 쓰고, **첫 장면을 촬영 기준(외형·조명·의상·
  카메라 구도)으로 명확히 고정**. 자동 생성·관리자 재생성 모두 동일 기준 적용.
- **2차 수정(검수 중 재발 발견)**: 8장면 샘플의 한 컷에서 대본에 없는 배경 소품(선반 장식→
  이후 숟가락)이 반복 등장 — 원인은 **기준 장면 + 여러 보조 참고 이미지가 충돌**하는 것.
  → **기준 장면 + 직전 장면 두 개만 참고**하도록 축소해 재발 방지. 표정·빈손 자세만 지시하는
  식으로 프롬프트도 단순화.
- 절차 스킬 → [[scene-reference-lock-visual-consistency]].

## 가상 인물 샘플 4편 (2026-09-20~09-22 제작, 09-22 추가 4편 재제작)

`image_gen` 스킬로 **한국인 가상 아기 4명**(남아 2·여아 2) 원본 사진 제작 → 4·6·8·12장면
각각에 배정(1차: 남아 4·8장면, 여아 6·12장면)해 실제 제작 워커로 세로 샘플 영상 4편 생성.
전용 테스트 계정을 만들어 잔액을 충전하고 정상 결제 API로 주문을 넣어 실사용 흐름 그대로
검증. 사이트에는 AI로 만든 가상 인물임을 표시.

- **실제 재생 길이(1차 세트)**: 4장면 ≈43초 · 6장면 ≈1분13초 · 8장면 ≈1분29초 · 12장면 ≈3분58초
  — 모두 720×1280 세로, 음성 트랙 포함.
- 장면 연결성(색감·인물·의상·배경·카메라) 검사를 인접 이미지 쌍 단위로 수행 — 1차 세트는
  26쌍, 2026-09-22 재제작분은 30개 장면 전량 비교.
- **First Collection 커버플로우**: 가운데 영상이 크게 보이는 형태로 복원, 4편 모두 **사전 로드**
  (버튼 클릭 시점이 아니라). 가운데 영상 무음 자동재생, 소리는 컨트롤에서 켤 수 있었으나 이후
  요청으로 **네이티브 컨트롤 자체를 숨겨 영상만 노출**. 옆 카드를 덮는 투명 호버 버튼이 공통
  호버 배경색을 상속해 영상을 가리던 버그 수정, 배경을 밝은 크림색으로 바꿔 영상 옆 검은
  여백 제거, 반복 넘김 시 대기 카드가 앞을 가로지르지 않고 **카드 더미 맨 뒤로 이동**하도록 수정.
  가격표 하단 샘플은 처음엔 "샘플 재생" 버튼+썸네일(클릭 시 즉시 로드·재생)이었다가, 이후
  버튼 텍스트 없이 **중앙 재생 아이콘만** 남기는 것으로 정리.
- **2026-09-22 세트 추가**: "5만원부터 20만원까지 한 번씩 더 만들어줘" 요청으로 4·6·8·12장면
  샘플을 각 1편씩 재제작(관리자에서 신·구 샘플 모두 선택 가능하도록 유지). 이 세트 제작 중
  8장면 한 이미지에 장난감이 등장했는데 **대본에 명시된 "장난감을 입으로 확인하는" 행동과
  일치**해 의도된 소품으로 판정·통과시킨 사례 있음(자동 검토 알람을 사람이 원본 대본과 대조해
  기각한 예).
- **6장면 재생성(2026-09-24)**: 사용자가 "인터뷰어가 다른 샘플과 비슷하면 좋겠다, 너무 어색해"
  라고 지적 → 과장된 억양·늘어지는 말끝을 줄이고 다른 세 샘플과 같은 차분한 진행자 말투로
  재생성. 이전 완성본은 보관하고 관리자에서 신·구 버전 모두 선택 가능하도록 보강.
- **관리자 샘플 관리**(`admin.first.dalar.ai/samples`): 가격대별로 완성 주문 영상 중 하나를
  골라 "공개 샘플로 저장". 교체돼도 이전 영상은 계속 선택 목록에 남음(완전 대체 아님).

## 여성 인터뷰어 음성 버그

사용자 제보 "여자 아나운서로 특정했는데 자꾸 남자 목소리로 바뀐다". 원인: 실제 영상 생성
프롬프트에는 화자가 단순히 "인터뷰어"로만 전달되고 여성 아나운서 지정이 누락돼 있었음.
**공통 음성 지시(여성 아나운서)가 장면별 개별 지시보다 우선**하도록 수정. 문제 장면 3곳
(6장면 4번째, 8장면 3·6번째)을 찾아 재생성. 이후 QA 절차에 **질문이 있는 모든 장면의 인터뷰어
음성 성별 확인**이 정식 항목으로 추가됨(1차 세트 23개 질문 장면 전수 검사).

## 초대코드·상호 쿠폰 시스템

- 사용자마다 **개인 초대코드/링크** 발급.
- 초대받은 사람이 **초대코드 입력 → Google 로그인**(순서 고정, 먼저 로그인 후 "친구 초대·쿠폰"
  화면에서 입력도 가능) → **초대한 사람·등록한 사람 양쪽 모두 50% 할인 쿠폰 1장** 발급.
- 쿠폰: **유효기한 1개월**, **First 전용**, **결제 1회당 1장만 적용**.
- 자기 코드 등록·같은 계정 중복 등록 차단. 결제 승인 재시도 시 쿠폰·적립 중복 처리 방지, 승인
  중 취소 요청이 겹치는 경합도 서버에서 처리.
- **관리자**(`admin.first.dalar.ai/rewards`)에서 사용자별 초대코드·발급 쿠폰 리스트 조회.
  **고객**(`first.dalar.ai/rewards`)에서 내 쿠폰 확인.
- 절차 스킬 → [[mutual-referral-coupon-pattern]].

## Package 연동

실제 등록까지 확인(테스트 패키지는 초안 저장, 외부 게시는 하지 않음).

## Pay 분리(`lampas-web-pay`)

기존엔 `pay.lampas.io` 기본 진입 화면에 First 상품까지 섞여 나왔다. 요청("`pay.lampas.io`로
바로 들어갔을 땐 예전처럼 크레딧만, First 통해 갔을 때만 다르게")에 따라:

- **`pay.lampas.io/`**: 크레딧 충전 상품만 표시(기존 동작 복원).
- **`pay.lampas.io/first`**: 장면별 제작비·할인 쿠폰만 표시, **크레딧 표시는 보조 정보로 최소화
  하고 총 구매 금액(N만원)을 강조**. First의 결제 버튼이 이 경로로 연결되도록 변경(기존
  `?service=dalar&first=1` 쿼리스트링 진입도 계속 동작).
- 결제 성공/실패 복귀 경로, 쿠폰 적용 흐름 모두 분리 후에도 유지 확인.

## 관리자 내비게이션 정리

관리자 상단 메뉴를 **"서비스 / 스튜디오"** 두 개로 축소, 별도 홈 버튼은 **관리홈**으로 연결.
스튜디오로 이동해도 공통 헤더·메뉴는 유지.

## 공유(OG) 메타·이미지

First 로고 + 밝은 크림 배경으로 **1200×630 공유 이미지** 제작, Open Graph·X(Twitter) 메타
태그를 **HTML에 직접 삽입**(자바스크립트 실행 없는 공유 수집기도 인식하도록). 운영 배포 후
크롤러 UA로 메타·이미지 응답 정상 확인.

## 데이터 보존 규율

이 세션 전체에서 매 배포 전후로 **기존 주문·영상·제공 이력이 삭제되지 않았는지 반복 확인**하는
패턴이 뚜렷함 — DDL은 컬럼·테이블 **추가만**, 배포 전 운영 DB 백업, 배포 후 기존 주문 건수·
완성 영상 URL 접근 가능 여부를 매번 대조(5→6→11건, 제공이력 6→7→12건, 영상 파일 6→12개로
누적 확인). [[prod-ddl-before-deploy-with-drift-check]] 스킬과 같은 계열의 배포 규율.
